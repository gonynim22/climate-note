# 파일 형식 변환 계약

v4.4는 네 번째 미니앱을 **파일 변환**으로 확장한다. [확정 설계](superpowers/specs/2026-10-20-file-converter-redesign-design.md)와 [현재 구현·검증 기록](work/2026-10-20-file-converter-redesign.md)을 따른다.
아래 HWP 계약과 엔진 3개 모듈은 유지하며 [최초 HWP 구현 기록](work/2026-10-03-hwp-document-converter.md)은 당시 증거다.

## 지원 형식과 공통 표

| 원본 | 결과 | 엔진 |
|---|---|---|
| JPG/JPEG·PNG·WEBP·BMP | 서로 변환·작은 JPG·ICO·사진 PDF 묶기 | Qt 이미지 플러그인·QPdfWriter |
| PDF | 쪽별 PNG·JPG | 기존 qpdf 이미지 플러그인·Qt6Pdf |
| HWP | HWPX | 기존 설치 한글·공식 변환기 |
| CSV·TXT | UTF-8(BOM 포함) ↔ EUC-KR(CP949) | strict codecs |

- `file_conversion.KINDS/TARGETS`가 파일 필터·추천·설정·관계도·출력 이름의 정본이다. 한 번에 한 종류, 최대 100개·파일당 100 MiB, 경로 중복 제거. 폴더 드롭/재귀는 지원하지 않는다. 첫 지원 파일과 다른 종류는 제외 이유를 표시한다.
- 같은 종류의 사진 형식은 섞을 수 있다. 하나의 원본 형식이면 자기 형식을 숨기고, 혼합이면 선택한 결과와 같은 형식의 입력은 실패가 아닌 건너뜀으로 센다. 작은 JPG는 JPG에도 제공한다.
- 동영상·음성·HEIC·RAW·다중 TIFF·GIF 애니메이션·전자책·압축·Office·HWP 역변환/그림 변환은 제외한다. 추가 패키지·외부 엔진·네트워크 호출을 넣지 않는다. QtPdf Python 모듈과 PIL은 빌드 제외를 유지한다.
- DB v18·Export v3·salt·설정 키·바로가기 6슬롯을 변경하지 않는다.

## 사진·PDF·표와 글 변환

- 사진은 `QImageReader.setAutoTransform(True)`로 읽고 기본 256 MiB 할당 한도를 유지한다. 긴 변만 비율 유지·SmoothTransformation으로 줄이며 작은 사진을 키우지 않는다. JPG/BMP의 투명 픽셀은 흰 바탕에 합성한다. 픽셀을 새 표면에 그려 EXIF·위치·원본 텍스트 메타데이터를 넘기지 않는다.
- 작은 JPG의 기본 긴 변은 1920px, 화질 85다. 선택은 긴 변 1920/1280/원래대로·화질 85/95/70이다. PNG 크기는 원래대로/1920/1280, WEBP도 같은 화질 선택을 쓴다.
- ICO는 투명 여백의 정사각 16·32·48·256px PNG 네 항목과 ICONDIR 머리를 직접 묶는다. Qt 단일 ico writer로 여러 크기를 쓰지 않는다.
- 사진 PDF는 QPdfWriter 300dpi, 넣은 순서대로 한 사진 한 쪽, 비율 유지·중앙 정렬이다. A4 세로/가로/사진 크기대로, 여백 좁게 8mm/없음 0/보통 15mm를 제공한다. 사진 크기대로는 사진 비율의 쪽에 여백 공간을 더해 작은 사진의 본문이 빈 쪽으로 사라지지 않게 한다.
- PDF는 QImageReader의 `pdf` reader·imageCount·jumpToImage·setScaledSize를 쓴다. 쪽 포인트 크기 × dpi/72로 150/300dpi를 그린다. PDF당 300쪽·쪽당 50MP를 넘으면 실패하며 암호·손상 PDF를 거부한다. 전체 쪽 결과가 완성된 폴더만 확정한다.
- 인코딩은 UTF-8 BOM → UTF-8 strict → CP949 strict 순서로 판정한다. 바이트를 decode/encode하며 줄바꿈을 변환하지 않는다. UTF-8 결과는 BOM 포함, 화면의 EUC-KR은 CP949(툴팁 포함)다. 표현 불가능한 글자는 대체하지 않고 실패한다.
- 원본 판독·미리보기·인코딩 검사도 격리 worker에서 한다. UI에는 새로 만든 작은 PNG 픽셀과 실제 크기·쪽 수만 전달한다. 판독 임시 폴더는 선택 전 읽기 전용 원본을 지원하기 위해 시스템 임시 폴더에 만들고 소유 작업만 회수한다.

## 공통 출력·일괄 작업 수명

- 사진/PDF/텍스트 변환은 일괄당 하나의 `main.py --file-convert-worker <작업 폴더> <Job 이름>` 프로세스다. 일반 앱의 DB/보안/트레이 import 전에 분기한다. 부모 Job 배정·`go` 파일과 onefile 자식의 직접 Job 가입 확인 후 `QGuiApplication(..., "-platform", "offscreen")`을 만든다.
- `FileConversionRunner`는 `job.json`에 입력·형식·설정을 쓰고 200ms마다 `items/<번호>/result.json`을 수집한다. 출력은 저장 폴더 안 `.climatenote-conv-*`에서 만든다. 원본별 저장 폴더가 다르면 각 폴더에 같은 일괄의 소유 작업 폴더를 만든다.
- 항목·쪽 완료 때만 실제 진행 시각을 갱신한다. 60초 동안 진척이 없으면 현재 항목은 시간 초과, 나머지는 취소다. KILL_ON_JOB_CLOSE로 자기 작업만 종료한다. 실패 후 다음 파일은 계속 처리한다.
- 결과 확정은 부모만 수행한다. `publish_output`은 확장자와 파일/폴더 이름을 받아 Windows `os.rename` 비덮어쓰기와 ` (1)`, ` (2)` 충돌 회피를 적용한다. 기존 HWP `publish_result`는 변경하지 않는다.
- 이름: 일반 `<이름>.<확장자>`, 작은 JPG `<이름> (작게).jpg`, 여러 사진 `<첫 이름>_묶음.pdf`, PDF 쪽별 `<이름>_쪽별/<이름>_001.png`(또는 jpg), 인코딩 `<이름>_UTF-8.csv`/`<이름>_EUC-KR.csv`(원래 확장자 유지). 폴더 충돌도 ` (1)`을 붙이고 폴더 전체를 한 번에 확정한다.
- 취소·숨김·잠금·종료는 Job을 닫고 늦은 결과 확정을 금지한다. 이미 확정된 결과와 원본은 남긴다. 정상/실패/취소 모두 소유 임시 폴더만 정리하고 정리 실패를 표시한다.
- 경로·본문·목록·결과·설정은 DB/지속 로그에 기록하지 않는다. 화면 오류에는 파일 이름과 정해진 이유만 표시한다.

## HWP 설치 조건과 엔진

본 제품은 한컴의 HWP 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다.

위 문구는 [한컴 공개 명세 사용권 안내](https://www.store.hancom.com/support/downloadCenter/hwpOwpml)에 따른 고지다. 설정 → 라이선스의 `HWP 공개 명세·외부 변환기`, 관련 소스 및 사용자 안내에도 제공한다. 한글·HWPX 변환기 자체의 사용권은 별도 설치 제품과 기관 계약에 따른다.

- Windows에 한글과 한컴 공식 **HWPX 변환기**가 설치되어 있어야 한다. 한글 COM 등록의 실제 `hwp.exe`와 공식 변환기의 설치 경로를 각각 확인한다. 한글만 있거나 변환기만 있으면 시작을 막고 부족한 구성 요소를 안내한다.
- 변환은 설치된 `HwpxConverter.exe`에 입력/출력 파일 인수를 전달하는 공식 CLI 방식이다. 임의 실행 파일 선택·외부 코드 로더·자동 설치·네트워크 업로드는 제공하지 않는다. 엔진 EXE/DLL을 기후노트에 묶지 않는다.
- 로컬 확인 환경은 한글 2022와 설치된 공식 변환기다. 다른 버전/기관 DRM 환경은 실제 확인 전까지 호환을 보장하지 않는다. 형식/보호/변환 실패는 파일별로 표시한다.
- [한컴 CLI 도움말](https://help.hancom.com/hoffice120/ko-KR/HwpxConverter/convert/convert.htm)의 실제 실행 파일 이름은 설치 환경으로 확인했다. 연동/배포 조건은 별도 확인 항목으로 남긴다.

## HWP 입력·출력과 원본 보존

- 파일 선택/드롭은 같은 등록 경로를 사용한다. `.hwp` 파일 최대 100개, 파일당 100 MiB 이하이며 중복 경로를 제거한다. 폴더 재귀·폴더 드롭은 제외한다.
- `FileHeader`가 있는 HWP 5 문서를 지원한다. 암호(bit 1/8)·배포용(bit 2)·DRM(bit 4/10)·전자서명(bit 7/9)은 엔진 실행 전에 거부한다. 구형 HWP나 확장자만 HWP인 다른 형식은 거부한다. 속성 비트는 [공식 HWP 5.0 명세](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.pdf)를 따른다. [헤더 설명](https://tech.hancom.com/%ED%95%9C-%EA%B8%80-%EB%AC%B8%EC%84%9C-%ED%8C%8C%EC%9D%BC-%ED%98%95%EC%8B%9D-hwp-%ED%8F%AC%EB%A7%B7-%EA%B5%AC%EC%A1%B0-%EC%82%B4%ED%8E%B4%EB%B3%B4%EA%B8%B0/)
- 원본은 읽기만 한다. 출력 폴더의 작업별 `.climatenote-hwp-*` 폴더에 사본을 만든 뒤 그 사본을 변환한다. 원본 복사 중 크기/수정 시간이 달라지면 중단한다.
- 기본 출력은 각 원본과 같은 폴더이며 지정 폴더를 선택할 수 있다. 정상 결과는 `원본.hwpx`, 충돌하면 `원본 (1).hwpx` 등으로 저장한다. Windows `rename`의 비덮어쓰기 동작을 사용해 이름 검사 뒤의 경합도 기존 파일을 보존한다.
- 결과는 CRC·mimetype·필수 XML/본문 구역을 검사한다. ZIP 전체 해제 크기 512 MiB, XML 하나당 32 MiB 제한이며 파일 시스템에 압축을 풀지 않는다. 이 검사는 서식/내용 동일성 보장이 아니므로 표·그림·수식·쪽 배치는 별도로 확인한다. [HWPX 구성](https://tech.hancom.com/hwpxformat/)
- 정상 종료/실패/취소는 자기 작업 폴더만 정리한다. 정리 실패는 표시하며, OS 강제 종료/전원 차단으로 남은 임시 파일을 다른 사용자 파일과 함께 일괄 삭제하지 않는다. 완료된 결과와 원본은 기후노트 초기화의 삭제 대상이 아니다.

## HWP 작업 수명과 데이터 격리

- 한 번에 하나씩 별도 작업 프로세스에서 수행한다. `main.py --hwp-convert-worker`는 DB/보안/로그/트레이/단일 인스턴스 잠금 import 전에 분기한다.
- 부모가 작업 프로세스를 고유 Windows Job에 배정한 뒤 `go`를 만든다. onefile 부트로더의 자식도 같은 이름의 Job 가입을 확인하고 핸들을 닫은 뒤 입력을 처리한다. 배정 실패/요청 부재 시 파일 접근이나 엔진 실행을 시작하지 않는다.
- frozen 작업 프로세스는 외부 CLI를 시작할 때 번들 DLL 검색 경로/PATH를 해제하고 `finally`에서 복원한다. [PyInstaller 외부 프로그램 실행 지침](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application)을 따른다.
- CLI 제한은 90초, 전체 작업 제한은 105초다. Job에는 KILL_ON_JOB_CLOSE를 적용하며 자기 작업만 종료한다. 프로그램 이름으로 기존 한글 프로세스를 종료하지 않는다.
- 작업 결과 JSON과 검증된 HWPX는 작업 폴더에만 둔다. 최종 이름 확정은 부모가 유효한 완료를 받은 뒤 수행하며, 취소된 작업의 늦은 결과는 확정하지 않는다.
- 실패한 파일 다음 항목은 계속 진행한다. 실패/취소 재시도는 완료 파일을 다시 변환하지 않는다.
- 목록·출력 폴더·상태는 메모리 전용이다. 문서/경로/결과 목록을 DB/Export/백업/지속 로그에 쓰지 않는다. 엔진의 APPDATA/LOCALAPPDATA/TEMP/TMP도 작업 폴더로 격리한다.
- `pywin32==311`은 기존 lock의 버전을 유지하면서 직접 의존성으로 명시한다. HWP 헤더 읽기와 Windows Job 제어에 사용하며 한글 COM 창을 제어하지 않는다. Qt/나머지 의존성 버전도 유지한다.

## UI 계약

- 주머니 네 번째 타일은 `파일\n변환`, 창은 `파일 변환 · 기후노트`, 제목줄/접근성 이름은 `파일 변환`이다. 앱 id와 `document_converter.svg`를 유지하고 보라 그라데이션 위 그림만 맞바꾸는 화살표로 바꾼다.
- 독립 창은 내용 480×620/기본 외곽 528×668, 공용 MiniAppTitleBar와 맑은 고딕을 쓴다. 빈 넣기 화면 → 추천(최대 3장)/다른 형식(4열)/설정 → 결과 비교의 D안이다. 설정 칸은 96px, 모든 설정·저장은 기존 28px·13px ConverterCombo다. 창 전체는 스크롤하지 않는다. 다른 형식 8개까지 펼치고 그 이후에만 해당 칸을 70px로 스크롤한다.
- 관계도와 파일 목록은 본문 안의 가림막·패널이다. 관계도는 공통 형식 표에서 그린다. 닫기에 포커스를 주고 Tab을 패널 안에 가둔다. Esc는 패널 → 설정 팝업 → 창 순서로 닫는다. 숨김·잠금 때 패널과 예약 작업을 폐기한다.
- 진행 중에는 머리 카드·형식·설정·저장·드롭을 끄고 진행/취소를 보인다. 결과 미리보기와 용량 막대는 실제 읽은 값만 사용한다. 목록은 32px 행 4개까지 보이며 실패 행의 재시도는 완료 파일을 다시 변환하지 않는다. 취소는 이미 끝난 결과만 보여 준다.
- 실제 `QFileDialog.open()`을 소유해 비동기로 선택을 받고, 가시성/활성/잠금 상태가 유효할 때만 등록한다. 숨김/잠금 시 선택창을 취소한다. 메뉴 클릭 스택에서 모달을 실행하지 않는다.
- 메인이 창 하나를 재사용한다. 일정 저장 실패는 열기를 막는다. 잠금·트레이·사이드바/메인 숨김·화면 변경·초기화 준비·정상 종료 시 큐/팝업/작업을 취소한다. 초기화 성공 후에만 목록을 폐기한다. 저장 실패로 정상 종료가 보류되면 기존 창을 보존한다.
- 결과 문서를 자동 실행하지 않는다. 현재 UI가 유효할 때 사용자가 누른 `저장 폴더 열기`만 수행한다.
- 메인 연결 `_open/_hide/_discard_document_converter`와 창의 `cancel_conversion`·`hide_owned_popups`·`fit_to_screen`·`shutdown`·`setEnabled`를 유지한다. 출력은 자동 실행하지 않는다. 업무 PC HWP/Excel·실제 혼합 DPI 확인은 자동 검사와 별도로 기록한다.
