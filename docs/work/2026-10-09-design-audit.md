## 결정과 진행

- 2026-10-09: AGENTS.md, UI/아키텍처/검증 계약을 기준으로 읽기와 합성 렌더 중심 점검을 시작했다. 화면을 예쁘게 바꾸기 위한 앱 글꼴/저장 형식/크기 계약 변경은 제안의 기본 전제로 삼지 않는다.
- 기본 화면 묶음 51장, Windows Qt 추가 화면 16장, 100/150% 집중 재현 각 9장, 합계 85장을 생성했다. 초기 보조 스크립트 실패 실행의 33장은 별도로 보존하며 이 숫자에 합산하지 않는다. 모두 합성 데이터의 QWidget 렌더이며 데스크톱·실사용 앱 캡처가 아니다.

- 아래 38개는 개선 후보이며 설계 승인이나 구현 완료를 뜻하지 않는다. P0/P1은 기능 의미·가독성·조작성 문제를 먼저 해결하는 순서, P2는 사용 흐름 개선, P3는 마감 수준 개선이다.

## 먼저 처리할 실제 재현 항목

### 01. P0 — 잠금 배경이 본문을 가리지 않는다

- 관찰: 100%와 150% 모두 PIN 입력은 나타나지만 캘린더와 합성 일정 본문이 그대로 보인다. 잠금 상태의 제목/해제 글자는 흰색이라 흰 바탕 위에서 사라진다.
- 근거: `ui_main.py:731`의 `LockOverlay`는 배경 QSS를 선언하지만 `WA_StyledBackground`가 꺼져 있었다. 오버레이 크기는 `(0, 0, 380, 660)`으로 정상이며, 자식 오버레이에 `WA_DontShowOnScreen`을 주지 않은 별도 재현에서도 동일했다.
- 대조: 점검 프로세스 안에서만 `WA_StyledBackground=True`를 적용했을 때 같은 화면이 불투명 배경으로 가려졌다. 제품 파일은 수정하지 않았다.
- 제안: 오버레이 배경의 실제 그리기를 보장하고, 모든 크기에서 잠금 전 본문 픽셀이 보이지 않는지 렌더 회귀를 추가한다. 잠금 레이아웃의 중앙 정렬·오류 안내도 함께 확인한다.
- [현재 합성 재현](../../output/harness/20261009-231410-design-audit-focus-1/61-lock-baseline.png) / [프로세스 내부 대조](../../output/harness/20261009-231410-design-audit-focus-1/62-lock-styled-control.png) / [150% 재현](../../output/harness/20261009-231410-design-audit-focus-1.5/61-lock-baseline.png)
- 한계: 최종 EXE의 실제 Windows 잠금/복원은 이번에 실행하지 않았다.

### 02. P1 — 시스템 테마와 밝은 표면의 글자색이 충돌한다

- 관찰: 다크 테마로 시작한 설정창에서는 모니터·글꼴 콤보와 크기 선택 글자가 희미해진다. 실행 중 light→dark 전환에서는 설정 행 라벨·버튼, 메인의 선택 날짜·일정 본문까지 흰색으로 바뀐다. 설정창은 활성 상태였다.
- 근거: `main.py`의 테마 감지/주기적 `setTheme`, `ui_settings.py`의 밝은 고정 카드와 Fluent 컨트롤, `ui_main.py`의 흰 일정 영역. cold start와 실행 중 전환을 구분해 재현했다.
- 제안: 흰 캘린더/설정 카드의 foreground와 background를 한 쌍으로 관리하고 테마 재적용 뒤에도 유지한다. 기존 시스템 테마 계약을 무작정 끄는 방식은 피한다.
- [다크 시작](../../output/harness/20261009-231410-design-audit-extra/40-native-settings-dark-cold.png) / [실행 중 전환](../../output/harness/20261009-231410-design-audit-extra/42-native-settings-light-to-dark.png) / [일정 본문 재현](../../output/harness/20261009-231410-design-audit-focus-1.5/63-main-dark-transition.png)

### 03. P1 — 크게 모드 스티키의 삭제 버튼이 잘린다

- 관찰: 버튼은 16×16인데 높이 8px인 헤더 띠의 자식이고 y=-4에 배치된다. 부모와의 실제 교집합은 **16×8px**다. 위쪽이 잘린 X가 카드 가장자리에 붙어 작은 마우스 표적이 된다.
- 근거: `ui_sticky_panel.py:47`, `:56`, `:127`. 100/150% 모두 동일한 논리 크기를 측정했다.
- 제안: 버튼을 카드 본체의 자식으로 옮기거나 전체 히트 영역이 들어가는 헤더 공간을 확보한다. 휴지통 이동 전 저장/확인 계약은 유지한다.
- [150% 카드](../../output/harness/20261009-231410-design-audit-focus-1.5/66-mini-sticky.png)

### 04. P1 — 작은 보조 글자의 명암 대비를 높인다

- 측정: 날짜의 일정 개수 `#9AA0A6`/흰색은 **2.64:1**이며 글자 크기는 9px다. 환산기 ‘다른 단위/최근’은 **3.23:1**, 설정 하단 크레딧은 **2.93:1**, 환산 기준 설명은 **3.85:1**다. 소스 지정 색의 상대 휘도로 계산했다.
- 제안: 사용자 판단에 필요한 개수·조건·상태부터 12px 안팎의 일관된 단계와 충분한 대비를 확보한다. 공간 계약 때문에 크기를 유지해야 하면 먼저 색을 보강한다. 크레딧은 낮은 우선순위다.
- 근거: `ui_main.py:611`, `:640`, `ui_unit_converter.py:226`, `:229`, `:246`, `ui_settings.py:815`.
- 웹 규격을 Qt 앱의 법적 적합성 판정으로 적용한 것은 아니다. 일반 텍스트 4.5:1을 가독성 참고선으로 사용했다. [W3C 명암 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)

## 권장 진행 순서와 유지할 점

1. 잠금 가림 → light/dark 시작·전환 → 스티키 삭제 버튼 잘림을 각각 좁은 수정으로 처리한다. 이는 시각 취향보다 먼저 해결할 실제 재현 문제다.
2. 기능과 다른 문구, 잘못된 오류 색, 작은 상태 글자, 복사/입력 오류 안내를 정리한다.
3. 검색·휴지통의 내용 우선순위와 빈 상태, 날짜/금액/문서/OCR의 결과 읽기 흐름을 개선한다.
4. 크게 모드 배분·중간 일정 칩처럼 기존 크기/표시 계약에 영향을 주는 안은 별도 시안과 계약 갱신을 거친다.

유지할 강점은 네이비 캘린더의 정체성, 앱별 색이 다른 SVG 미니앱 아이콘, 최초 크기 선택의 실제 비율 미리보기, D-Day의 명확한 카운트, OCR의 노란 불확실 표시, 계산 원본과 표시값의 구분이다. 모든 화면에 새 장식·그라데이션·애니메이션을 추가하는 방향은 필요하지 않다.

작은 타깃은 실제 클릭 영역과 인접 간격을 함께 검토한다. 20px 버튼이라는 이유만으로 일괄 규격 위반으로 판정하지 않았으며, 실제로 잘린 16×8px 영역을 우선한다. [W3C 타깃 크기와 간격 설명](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)

## 미해결과 인계

- 남은 문제 / 수동 확인: 위 개선 후보의 실제 구현 및 회귀 검사. 최종 EXE, 실사용 Windows 잠금/복원, 네이티브 제목줄·파일 대화상자, 실제 혼합 DPI/KVM, 스크린리더/키보드 전수 조작은 미확인이다. HWP 실제 변환과 OCR 정확도/실제 화면 캡처도 이번 범위 밖이다.
- 변경한 정본 문서: 없음.
- 다음 행동: 01~03의 재현 문제를 우선 수정하는 작업을 별도로 시작하고 관련 하네스 검증을 수행한다. 사용자의 현재 요청은 진단이므로 제품 수정은 하지 않았다.
- 배포·커밋·push 여부: 수행하지 않음.
