# 작업 기록: 글머리 기호 복원 적용

작성일: 2026-11-06 / 상태: 구현·자동 검사·실제 문서 평가 완료. 커밋·release·push 미수행

## 목표와 범위

- 목표: 공문서 글머리 기호(`■ □ ◇ ㅇ`)를 줄 맨 앞의 화면 모양으로 알아봐 판독 결과에 반영한다. 근거는 [실패 분석 기록](2026-11-05-screen-text-failure-analysis.md)·[기호 시험 기록](2026-11-06-screen-text-bullet-spike.md). 사용자 결정 2026-11-06: 제품에 넣는다, **고리 계열(`ㅇ ◦ ○ o`)은 그냥 내지 않고 확인 필요로 표시한다**.
- 변경 대상: 새 `screen_text/leading_symbols.py`, `engine.py`(`recognize()`가 `_read` 뒤에 적용, 글자 픽셀 판정을 새 모듈로 이동), `layout.py`(`TextBox.unsure_prefix`·`Cell.unsure_prefix`·`Cell.flagged`), `window.py`(표시·집계를 `flagged`로), 새 시험 2개 + `test_screen_text_ui.py` 4개, 문서 `SCREEN_TEXT.md`·`TESTING.md`·`SCREEN_TEXT_LAB.md`·`AGENTS.md`.
- 데이터 영향: 없음. 모델·사전·MANIFEST·DB·설정 키·Export 변경 없음. 결과는 메모리 전용이다.
- 계약 변경: "판독 글자는 바꾸지 않는다"에 예외 하나를 명시했다 — 줄 맨 앞에서 화면의 기호 모양이 분명할 때만 기호를 붙이거나 닮은 글자(`0 o O C c D . : - □ ■ ▪ ○ ● ㅁ`)를 교체한다.
- 제외 범위: `△ ▲` 등 모델 사전에 없는 글자와 사전에 있어도 거의 못 읽는 `⇒ Ⅳ`, `■`/`▪` 구분, 닮은 고리 구분. 버전 번호·EXE·release.

## 결정과 진행

- 2026-11-06: TDD. 모양 분류(순수 합성 이미지 15개) → 레이아웃·실제 모델(Qt 합성 줄) → 창 시험 순으로 시험을 먼저 써서 실패를 확인한 뒤 구현했다. 실제 모델 시험이 빈 껍데기가 아님도 확인했다(기호 복원을 끄면 `■ □`는 기호 없음, `ㅇ`는 `o`로 나와 실패).
- 2026-11-06: 합성 글자를 속이 꽉 찬 막대로 그렸더니 영역의 54%가 검정이라 배경(중앙값)이 검정으로 잡혀 시험이 실패했다. 제품 문제가 아니라 시험 자료 문제라서 획이 있는 글자 모양으로 바꿨다(실제 글자는 영역의 15~40%).
- 2026-11-06: 표 칸 안 한 칸만 표시하려면 칸 단위 `unsure` 하나로는 줄 전체가 노래진다. 그래서 `TextBox.unsure_prefix`(앞 몇 글자)를 두고 글자 탭은 그 글자만, 표 탭은 그 칸을 노랗게 한다. 칸 전체 표시(점수 0.80 미만)가 있으면 그것이 우선한다.
- 2026-11-06: **실제 문서 평가에서 첫 구현의 버그를 찾았다.** 위치 찾기가 기호를 글자와 따로 작은 상자로 자르면 그 상자는 안에 기호밖에 없어 "줄 글자 높이 대비 크기"가 1.0이 되어 `ㅇ`가 `□`로 분류되고, 옆 글자 상자도 같은 기호를 다시 붙여 `□ ㅇ 이해관계집단`처럼 중복됐다(세 번째 자료에서 `□` 오탐 97개). 같은 줄 오른쪽 이웃 상자의 글자 높이를 기준으로 쓰고, 먼저 시작한 같은 줄 상자(겹치면 그 상자) 몫인 왼쪽은 찾지 않으며, 기호만 든 상자는 모델이 읽은 글자를 통째로 기호로 바꾸게 고쳤다. 시험 3개를 먼저 써서 실패를 확인했다.
- 2026-11-06: 네 번째 자료에서 `□`로 분류된 줄의 11%가 실제 `ㅇ`였다(100% 배율의 작은 고리, 높이 비 0.63~0.65). `ㅇ`를 `□`로 틀리면 표시 없이 틀리고 `□`를 `ㅇ`로 틀리면 확인 필요로 표시되므로 경계를 0.63 → 0.72로 올렸다(고리 최대 0.65, 정사각 최소 0.69~0.81의 중간). 시험을 먼저 추가해 실패를 확인했다.
- 평가 자료의 독립성: 임계값과 구조를 여러 단계에서 다듬었으므로(spike의 dev 한 줄 크롭, 전체 쪽 모양 측정, 세 번째·네 번째 자료의 실패 분석) **마지막 평가는 앞선 네 자료와 쪽이 전혀 겹치지 않는 다섯 번째 자료(48쪽 576장)에서 임계값을 정한 뒤 한 번만** 했다.

## 미해결과 인계

- 남은 문제: `△ ▲` 등 모델 사전에 없는 글자(감소 `△`가 사라지면 증가로 읽힘)와 사전에 있어도 거의 못 읽는 `⇒ Ⅳ Ⅴ`, `■`/`▪`·닮은 고리 구분 불가, `◇`가 `□`로 나오는 드문 경우, 같은 줄에 이어 붙은 둘째 항목 기호와 표 칸 첫머리의 이웃 상자 의존.
- 한 문서·한 기관의 서식이다. 한글(HWP)·엑셀 화면, ClearType, 어두운 배경에서는 미측정이다.
- 확인 필요 표시가 많다고 느끼면 `leading_symbols.apply_leading_symbols`의 `flagged = int(kind == RING)` 한 줄이 기준이다(표시를 없애도 `ㅇ` 글자는 그대로 나온다).
- 변경한 정본 문서: `docs/SCREEN_TEXT.md`·`TESTING.md`·`SCREEN_TEXT_LAB.md`·`AGENTS.md`.
- 다음 행동: 커밋, 필요하면 PowerShell `release`로 EXE를 만들어 격리 실행(새 모듈 포함 확인)과 업무 PC 수동 확인.
