## 2. v3.8에 넣을 계산 범위

시안 22분류에서 신발 치수를 제외한 **21분류**를 계획한다. 아래 수는 추정 19항목을 제외한 **147항목 후보**이며, 개별 정의·출처 검증을 마친 항목만 최종 채택한다. 항목 수를 맞추기 위해 확인되지 않은 상수를 넣지 않는다.

| 그룹 | 분류별 시안 항목 수 → 후보 수 | 보류 항목 |
|---|---|---|
| 기본 | 길이 14, 무게 11, 부피 11, 넓이 10→9, 온도 4, 속도 6→5, 시간 9, 데이터 10 | 마지기, 해면 마하 |
| 물리 | 압력 9, 에너지 9, 전력 8, 각도 6, 힘 5, 주파수 5 | 없음. 기준 종류와 계수를 검증 |
| 환경 | 탄소 9→3, 미세먼지 5→4, 방사선 9→6, 조도 4, 소음 4 | 나무·차량·항공·전기·휘발유·소고기 비교, 담배 비교, X선·항공·연간 자연방사선 비교 |
| 생활 | 요리 계량 8→7, 연비 4, 신발 치수 6→0 | 밥숟가락, 신발 치수 전체 |

정의가 필요한 항목은 다음처럼 다룬다.

- 탄소는 `gCO₂e / kgCO₂e / tCO₂e` 사이의 크기 변환만 지원한다. 기본 조합은 `kgCO₂e → tCO₂e`. 배출계수나 온실가스 종류별 CO₂e 계산은 제공하지 않는다.
- 미세먼지는 `ng/m³ / µg/m³ / mg/m³ / g/m³`의 농도 단위만 지원한다. 건강영향으로 해석하지 않는다.
- 방사선은 시버트·렘 계열의 단위 크기만 변환한다. 기본 조합은 `mSv → µSv`. 촬영·비행 횟수 환산은 제공하지 않는다.
- 시안의 ‘소음’은 **음압**으로 명칭을 좁히고 `dB SPL, 기준 20 µPa`를 표시한다. 원본의 음압 배율은 `기준 음압 대비 비율`로 명확히 한다. dBA·전력 dB·체감 크기와 혼합하지 않는다.
- 요리는 `계량컵(200mL)`, `계량컵(240mL)`, `큰술(15mL)`, `작은술(5mL)`처럼 채택한 용량을 이름에 표시한다. 모든 한국/미국 컵의 공통 용량이라고 표현하지 않는다. 액량온스는 `US fl oz` 정의를 명시한다.
- 시간의 개월/년은 `30일 기준`, `365일 기준` 고정 기간임을 드러낸다. 실제 달력의 월·연도 길이 계산으로 사용하지 않는다.
- 자·리·평·되·말·근·관·돈 등은 한국에서 채택할 기준과 출처를 먼저 확인한다. 지역·시대·물품마다 달라질 수 있는 명칭은 기준을 표시하고, 근거를 확정할 수 없으면 해당 항목만 보류한다.
- 쿼트·파인트·갤런·액량온스는 US liquid, 배럴은 US petroleum, 연비 mpg는 US/UK로 구분한다. 열량은 thermochemical cal/kcal와 IT BTU 등 선택한 정의를 이름/도움말에 밝힌다.
- 데이터의 십진 단위와 이진 단위를 구분한다. 각도는 π를 사용하고, 광년은 채택한 연 길이 정의로 계산한다.

보류 항목은 선택 목록에서 제외한다. 이 버전에 동작하지 않는 신발 치수 메뉴를 남기지 않는다.

## 3. 화면·사용 흐름

1. 사이드바의 기존 **미니앱** 버튼을 누르면 300×220 주머니가 열린다.
2. 빈 안내 자리에 아이콘·`단위 환산기` 이름·짧은 설명을 가진 실행 카드 1개를 표시한다. 추가 설치/등록 버튼은 만들지 않는다.
3. 카드 클릭 또는 포커스된 카드의 Enter/Space로 주머니가 닫히고 환산기 창이 열린다. 주머니의 예약 포커스 복원이 새 창의 입력 포커스를 빼앗지 않도록 취소한다.
4. 환산기는 기본 340×460 논리 px의 별도 비모달 도구 창이다. 원본의 100px 분류 목록과 카드 구성을 살리되 실제 앱 글꼴·DPI에서 숫자와 단위가 잘리지 않도록 배치한다.
5. 창을 다시 실행하면 기존 1개 창을 활성화한다. 바깥 클릭으로 환산기를 닫지 않는다. 상단 제목 영역으로 이동하고 X/Esc로 숨긴다. 열려 있는 단위 선택 목록에서 Esc는 목록만 먼저 닫는다.
6. 최근 기록은 숫자 입력창에서 Enter로 추가한다. 원본처럼 최대 12개이며, X로 닫았다 다시 열면 같은 실행 세션의 값·기록을 유지한다. 앱을 종료하면 사라진다는 안내를 최근 영역 툴팁에 둔다.

세부 UI 기준:

- 분류 목록과 다른 단위 목록은 독립 세로 스크롤, 최근 기록은 가로 스크롤을 유지한다.
- 처음 열 때 캘린더가 있는 화면의 작업 영역 안에 배치한다. 오른쪽 공간이 부족하면 왼쪽을 사용하고, 음수 좌표 화면·화면 분리 때도 경계 안으로 보정한다.
- 340×460을 기준으로 실제 배치와 글꼴 메트릭을 검사한다. 긴 단위는 선택 목록에서 전체 이름을 볼 수 있어야 하며, 결과 숫자는 과학 표기와 툴팁으로 보완한다. 창에 맞추려고 글자를 무리하게 축소하지 않는다.
- QSS 글꼴은 정수 px, 본문은 앱 글꼴 설정을 따른다. 주머니와 같은 불투명 도구 UI로 두고 캘린더의 투명도 적용 대상은 넓히지 않는다.
- 카테고리·단위·교환·기록·닫기를 Tab과 키보드로 접근 가능하게 하고 포커스를 표시한다. 별도의 복사 버튼은 추가하지 않고 결과 텍스트 선택·복사를 지원한다.
- 일반 보조 창으로 동작하며 영구 topmost나 별도 Win+D 고정 가드를 추가하지 않는다.

## 4. 계산과 상태 구조

신규 `unit_converter.py`에 UI/DB와 독립된 단위 정의·계산·입력 검증·표시 함수를 둔다. 분류마다 기준 단위 1개를 정하고 아래 유형만 지원한다.

| 유형 | 적용 | 처리 |
|---|---|---|
| 배율 | 길이·질량·부피·데이터 등 | 기준 단위로 변환한 뒤 대상 단위로 변환 |
| 배율 + 오프셋 | 온도 | 절대온도 범위와 경계 부동소수점 오차를 함께 검사 |
| 역수 | 연비 | 0 이하 입력 거부, US/UK 계수 분리 |
| 로그 | 음압 | dB는 음수 허용, 압력/기준 비율은 양수, 연산 범위 검사 |

- 부호·소수점·지수 표기와 올바른 천 단위 쉼표를 지원한다. 예: `-40`, `1,234.5`, `1e6`. `12abc`, `1,23`, `NaN`, `Infinity`, 수식은 유효 입력이 아니다.
- 빈 값·입력 중인 부호/지수는 ‘입력 중’으로 처리하여 원문을 보존하고 결과를 비운다. 유효하지 않은 확정 값에는 입력 가까이에 짧은 이유를 표시한다.
- 입력 길이를 제한하고 중간값/출력의 비유한 값과 언더플로를 검사한다. 오류를 정상적인 0으로 바꾸지 않는다.
- 내부 값은 Python 수치 정밀도를 유지하고 표시는 6자리 유효숫자로 정리한다. 아주 크거나 작은 수는 지수 표기, 불필요한 소수 0과 음의 0 표시는 정리한다.
- 단위 교환은 검증된 계산값을 반올림 없이 새 입력으로 넘긴다. 같은 단위 선택은 항등 변환이며 불필요한 왕복 계산을 피한다.
- 최근 기록에는 분류·단위 ID·입력 원문과 유효 입력값만 둔다. 표시값을 계산 원본으로 재사용하지 않는다.
- 잘못된 분류/단위 조합은 명시적인 오류로 처리한다. 평가기·임의 Python/JavaScript 실행·동적 플러그인 시스템은 만들지 않는다.

환산기 카드는 작은 벡터 아이콘을 사용한다. 신규 SVG가 필요하면 `resources/`에 두고 기존 `resource_root()` 경로로 번들한다. `desgn_claude/` 파일이나 외부 폰트/스크립트에 런타임 의존하지 않는다. 일반 빌드 설정은 정적 import와 기존 resources 묶음으로 충분한지 먼저 확인하고 필요한 경우만 변경한다.

버전 목표는 `APP_VERSION="v3.8"`, EXE `기후노트_v3.8.exe`, Windows `3.8.0.0`이다. `APP_RELEASE_DATE`는 구현 완료 시 실제 출시일로 정한다. 숫자 버전과 파일명은 기존 `app_info.py` → `build_app.py`/`build.spec` 경로에서 파생되므로 중복 상수를 만들지 않는다. DB 스키마 버전은 올리지 않는다.

## 7. 검증 계획

### 계산 검증

- 원본 코드의 계수를 그대로 복사한 기대값 대신, 출처가 있는 독립 기준값으로 검증한다. 단순 왕복 성공만으로 잘못된 계수를 통과시키지 않는다.
- 대표 사례: 인치↔cm, 파운드↔kg, US gallon↔L, 섭씨↔화씨/켈빈, 도↔rad, GB↔GiB, kWh↔J, km/L↔L/100km, dB SPL↔Pa.
- 각 채택 단위의 기준값과 단위 쌍 왕복을 검사하고 연산 유형별 허용오차를 명시한다.
- 0, 음수, 절대영도 경계, 공백·미완성 입력, 올바른/잘못된 쉼표, 지수, 매우 큰/작은 수, 범위 초과, 최근 기록 중복·12개 제한, 반복 교환의 오차 누적을 확인한다.

### UI·데이터 보존 검증

- 카드 실행, 실제 입력·콤보·교환·다른 단위 행·Enter 기록·기록 복원, 반복 열기/닫기, 키보드 포커스를 실제 이벤트로 검사한다.
- 네이티브 창/선택 팝업은 `QTest.qWaitForWindowExposed`와 필요한 `qWaitForWindowActive` 완료를 확인한 뒤 키를 보낸다. 고정 sleep이나 실제 포커스 없는 위젯으로 입력을 보내지 않는다.
- compact/medium/large의 실행, 잠금·트레이·초기화·종료 보류, 사라진 모니터·음수 좌표·작은 작업 영역을 검사한다.
- 합성 DB의 기존 행/암호문·복호화 내용·설정·바로가기 ID/경로·salt·Export 내용을 계산 전후 비교한다. 실사용 AppData와 현재 실행 앱은 검사하지 않는다.
- 각 그룹 화면, 긴 단위 이름, 큰/작은 결과, 오류, 최근 기록을 합성 PNG로 남기고 실제 크기에서 열어 확인한다. 100/125/150% 합성 배율과 실제 혼합 DPI/KVM 확인을 구분한다.

관련 UI 구현 확인 시 사용할 명령:

```powershell
.\.venv\Scripts\python.exe tools/verify.py quick --tests tests/test_unit_converter.py tests/test_ui_unit_converter.py tests/test_ui_mini_apps.py tests/test_ui_data_lifecycle.py tests/test_ui_schedule_emoji.py
```

릴리스 단계에서는 최종 소스에 대해 다음 한 번으로 전체 검사·새 EXE·기존 격리 3개 시나리오를 수행한다. 바로 앞에 `full`을 의무적으로 중복 실행하지 않는다.

```powershell
.\.venv\Scripts\python.exe tools/verify.py release
```

현재 smoke는 기존 시작/저장 계약 검증이므로 새 환산기 UI 통과를 자동으로 뜻하지 않는다. 새 EXE에서 주머니→환산기→계산→닫기를 별도 합성 데이터로 확인하고 소스 UI 검사와 증거를 구분한다. EXE 내부 신규 모듈/리소스·Qt DLL과 SHA-256도 대조한다. 기존 v3.7b EXE는 보존하고 새 이름으로 v3.8 산출물을 배치한다.

후속 구현·커밋·빌드 시에는 사용자 변경을 분리하고 정본 문서를 먼저 갱신한다. 검사 뒤 코드가 바뀌면 관련 검사를 다시 실행한다. 실제 결과는 실행별 `output/harness/<run-id>/summary.md`·`result.json`에 연결하고, 이전 v3.7b 테스트 수나 EXE를 이번 통과 증거로 사용하지 않는다.

## 8. 확인한 외부 기준과 후속 계수 검증

- 일반 환산 정의·열량 종류: [NIST SP 811 Appendix B.9](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b9). 여러 종류의 calorie/BTU가 구별되어 있으므로 원본의 짧은 이름만으로 확정하지 않는다. 이 표의 오래된 상수 값은 최신 기준으로 재확인한다.
- 최신 물리 상수: [NIST CODATA 2022 전체 표](https://physics.nist.gov/cuu/Constants/Table/allascii.txt). 전자볼트처럼 정의 상수가 관련된 단위는 이 기준을 대조한다.
- 로그량과 음압 기준: [NIST SP 811 Chapter 8, §8.7](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-8). 기준값을 명시해야 하며 음압 예시는 20 µPa를 사용한다.
- 240mL 컵·15mL 큰술·5mL 작은술의 용도 구분: [FDA 가정용 계량 단위 안내](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/guidance-industry-guidelines-determining-metric-equivalents-household-measures). 영양표시 목적의 정의를 일반 US customary 용량과 혼동하지 않는다.

이번 분석은 위 기준과 대표적인 결함을 확인한 단계다. 147개 후보의 전 계수 검증 완료를 뜻하지 않는다. 후속 구현에서 채택 단위별 출처·정의·검증값을 코드와 테스트에 기록한다. 외부 자료 확인은 개발 중 검증이며 앱 실행 중 네트워크 요청을 추가하지 않는다.
