# 작업 기록: v4.4b 꼭 고칠 것(검사 도구 보강·글자 따기 숨은 창·Win+D 가려짐)

작성일: 2026-10-24 / 상태: 진행 중

## 목표와 범위

- 목표: v4.5 정식 릴리즈 전에 꼭 고칠 것으로 사용자와 정한 세 묶음을 v4.4b로 고친다.
  1. 검사 도구 보강: [교차검증](2026-10-19-a-report-crosscheck.md) F1(입력 변경 감지 누락)·F2(일정 세부 설정 seed 부재)·F4(EXE BINARY 출처·Qt DLL 대조가 release 밖 수작업)와 각 회귀(F7).
  2. 화면 글자 따기: 캡처 중 화면이 바뀌면 도구 창이 숨은 채 남는 문제.
  3. Win+D: 바탕화면이 이미 활성일 때 Win+D를 누르면 캘린더가 가려지는 문제(실화면 확인 필요).
- 변경 대상: `tools/verify.py`, `tools/smoke_release.py`, 관련 `tests/`, 화면 글자 따기·`show_desktop_guard.py`(원인 확인 뒤 결정), `app_info.py`(v4.4b).
- 데이터 영향: 없음 목표. DB v18·Export v3·salt·설정 키 유지. 검사 seed는 실행별 합성 데이터에만 쓴다.
- 제외 범위: 배포 준비(아이콘·라이선스·설명서)·새 기능(v4.5에서), 급하지 않은 후속(Win+D 되돌림 시 위에 남음, 알림 M3, 공휴일 재시도·검사 추가), 특정 PC 설정/휴지통 멈춤(사용자 확인: 요즘 재발 없음).
- 시작 시 사용자 변경: 추적 파일 변경 없음. 미추적 작업 기록 7개와 `motion/`은 건드리지 않는다.

- 2026-10-24 F1·F2·F4 구현(TDD, 새 시험이 먼저 실패함을 확인). F1: `source_snapshot`이 `git ls-files` 전체에서 `NON_INPUT_PREFIXES`(`docs/work/`·`docs/superpowers/`·`motion/`·`output/`·`security/`)와 루트 숨김 파일만 뺀다(현재 371개, 0.46초). F2: `seed`에 시각+알림(한 달 뒤 09:30·10분 전)·기간(+2일)·반복(매주, 8주 끝, 1주 뒤 건너뜀) 일정 3개를 더하고 `_dataset_snapshot`의 `schedule_options`로 값 비교, `_check_seed_options`·`_check_existing`. F4: `bundle_check`(TOC BINARY 출처·EXE 안 Qt DLL 바이트), 지난 v4.4a release 산출물에 실제 적용해 BINARY 64·밖 0·Qt 15 일치(0.5초). TESTING.md 반영.
- 2026-10-24 글자 따기 숨은 창 원인: 화면 변경 때 `_fit_optional_mini_apps`가 `hide_owned_popups()`로 오버레이를 `notify=False`로 닫아 `_reappear`가 불리지 않았다. 숨김·잠금 경로도 같은 함수 뒤에 `hide()`를 하므로 창 안에서는 구분할 수 없어, 화면 변경 경로만 `restore=True`를 넘긴다(캡처 대기·오버레이 중이고 창이 활성일 때만 화면 맞춤 뒤 다시 보임). 시험 3개 추가·가짜 앱 기대값 갱신, SCREEN_TEXT.md 반영.
- 2026-10-25 Win+D 가려짐 실화면 기록(`output/harness/20261025-win-d-desktop-active/traces/`, `zwatch4.py`=zwatch3+셸 바탕화면·REORDER 이벤트, 합성 데이터 소스 앱 large): 수정 전 `1-desktop-active-win-d.log`에서 바탕화면 클릭(55.38초) 뒤 Win+D(57.66초)는 MINSTART·루트 데스크톱 창(`#32769`) REORDER만 오고 foreground 알림이 없었으며 57.68초부터 다음 Win+D(59.97초)까지 Progman에 가려졌다. 69.8초 시도는 직전 클릭의 settle(350ms)이 우연히 0.09초 만에 되살렸다. 사용자 확인 "win+d를 누르면 처음에 사라져".
- 수정: 두 번째 WinEvent hook `EVENT_OBJECT_REORDER`(callback에서 루트 데스크톱 창만 큐잉), 바탕화면이 활성이고 pulse 중이 아닐 때 `_covered_by_desktop()`(바탕화면 호스트에서 `GW_HWNDPREV`로 올라가며 보이는 감시 창을 모두 만나는지, 1만 회 제한)이면 `_start_topmost_pulse()`. hook 해제는 둘 다 성공한 뒤에만 callback을 놓는다. 시험 6개 추가(실제 z-order 대역 창 3개 포함)·hook 개수 기대값 3개 갱신, 33개 통과.
- 수정 후 `2-fixed-desktop-active-win-d.log`: 바탕화면 클릭 뒤 Win+D 2회(42.72·44.77초) 모두 pulse(top=1)로 위 유지, 일반 Win+D 2회 정상, 기록 전체 가려짐 0회. 66초쯤 트레이 메뉴로 시험 앱이 정상 종료됐다(오류 로그 0바이트).
- 남은 기존 후속(범위 밖): 두 번째 Win+D로 되돌리면 셸이 캘린더를 일반 창 위에 둔다(수정 후 기록 43.52·45.53초에도 그대로).
