## 결정과 구현

1. **버전**: `app_info.py`의 표시 버전 v4.3, 날짜 2026. 10. 18. Windows 버전 4.3.0.0과 EXE 이름 `기후노트_v4.3.exe`는 정본에서 파생하며 관련 기대값도 갱신했다. 새 EXE는 아직 빌드하지 않았다.
2. **일정 반복**: 지연 순회로 남은 첫 발생만 확인한다. 날짜 최솟값·최댓값에서 반복/알림 계산의 초과를 막았다. 손상된 반복 관계는 표시 시 fallback을 적용하되 DB 원본을 쓰지 않는다. Export는 기존 정규화 우선순위를 유지한다.
3. **스티키 저장**: 성공 후 modified를 해제하고, 자동 저장 실패 시 modified를 유지하며 소유한 2초 타이머를 다시 예약한다. 패널 재조회 전 flush는 타이머와 modified를 모두 확인한다. 주기 저장은 현재 모드의 변경된 원본만 저장하고 실패 표시는 다음 성공까지 유지한다. large 패널이 없을 때 숨은 플로팅으로 역덮어쓰지 않는다.
4. **크기 전환**: 최신 스티키 저장을 먼저 확정한다. 인계 실패 시 기존 레이아웃·저장된 크기·설정 선택을 유지/복원한다. 화면 갱신은 finally로 복원한다. 설정 저장 실패도 선택값을 복원한다.
5. **위젯 제한**: large에서 새 스티키 생성은 가시성 대신 등록된 창 수로 제한한다. Import는 기존 활성 위젯을 보존하고 새 위젯만 남은 자리(스티키 10·D-Day 5·집중 1)에 맞춰 연다. 초과 행은 닫힌 상태로 본문·집중 세션 연결을 보존하고 수량을 안내한다.
6. **환산 조건**: 같은 기준 환산에 필요 없는 빈/잘못된 조건은 계산을 막지 않는다. 필요한 교차 환산의 검증은 유지한다. 원래 입력을 유지하며 최근 기록의 None 조건 복원과 문구를 보완했다.
7. **OCR**: 정규화 높이 48 기준 폭 4096, 상자 512개, 배치 패딩 폭×개수 8192·최대 6개를 제한한다. 현재 배치만 할당하며 초과 입력에는 작은 영역 선택을 안내하고 이전 결과를 유지한다. 엔진 생성/검출 전, 연결요소 행과 배치 사이에서 취소를 확인한다. 실행 중인 ONNX 호출을 강제로 중단하지는 않는다. 모델·사전·해시·의존성은 그대로다. 실제 소형 모델 긴 문장 회귀도 통과했다. 최대 RSS 실측은 하지 않았다.
8. **잠금 PIN**: 4자리 입력을 유지하면서 독립 32바이트 salt·PBKDF2-SHA256 200,000회 검증값(`pin$1$...`)과 상수 시간 비교를 사용한다. 기존 PIN은 표시/미리 채우지 않는다. 5회 실패 시 30초부터 최대 300초까지 메모리 대기를 적용한다. 창을 숨겨도 유지되며 앱 재시작 시 초기화된다. 시작 시 기존 평문 PIN은 비회전 `privacy_pin` 보호백업 후 승격하고 신규/초기화 기본값에도 검증값을 쓴다.
9. **이동 파일 암호**: 새 Export UI는 12~128자 암호를 사용하고 공백만 있는 암호는 거부한다. Import는 구 4자리 PIN 파일도 계속 읽는다. `[32B salt][Fernet]`·기존 KDF·JSON v3 형식은 유지한다. 잘못된 암호의 InvalidToken을 UI에서 처리한다.
10. **검증 도구**: 업그레이드 검사는 새 검증값이 이전 PIN을 검증함을 먼저 확인한 뒤 그 설정 하나만 정규화해 나머지 기존 열/설정 해시를 모두 대조한다. 마이그레이션 보호본은 원본 그대로 대조한다. 기존 해시 검사를 일괄 제거하지 않았다. OCR 진단 도구와 테스트 대역도 취소 콜백 시그니처에 맞췄다.

## 유지한 계약과 호환 한계

- 새 잠금 검증값 및 긴 암호 파일의 UI 사용에는 **v4.3 이상이 필요**하다. 구 EXE는 새 PIN 검증값으로 잠금을 해제하지 못한다. DB 버전은 18 유지다. 기존 평문 PIN이 포함된 보호본을 소급 삭제하지 않는다.
- PIN 검증값과 입력 대기는 화면 잠금 개선이며 4자리의 낮은 엔트로피 자체를 바꾸지 않는다. 이동 파일은 별도 긴 암호를 사용한다.
- 구형 날짜 문자열 허용, OCR 글자/표 독립 편집, 본문·salt·6슬롯·선택형 미니앱 제거 계약은 유지했다. 임의 반복 기간 상한이나 원본 일괄 변환을 넣지 않았다.
- `tmp/review_crosscheck_probe.py`는 수정 전 결함 재현 시 통과하는 관찰 코드다. 당시 37개 통과를 수정 완료 근거로 사용하지 않았다.
