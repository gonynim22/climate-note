- 사용자 요청에 따라 원본 확보부터 실행한다. 이전 앱/브라우저 사용 거부를 다른 경로로 우회하지 않는다. 일반적인 작업 재개 요청을 도구 접근 차단 해제의 증거로 해석하지 않는다.

### Edge 연결 확인

- 사용자가 Edge 사용을 제안하여 `cua.listBrowsers()`로 연결 상태만 확인했다. Chrome과 Edge가 모두 확장 연결로 등록되어 있다.
- 마지막 도구 거부는 대체 브라우저를 통한 동일 사이트 접근도 금지했다. Edge 연결 확인을 사이트 접근 허용으로 간주하지 않으며 차단된 PDF의 Edge 열기를 요청하지 않았다. 공식 Chrome 확장 안내에도 지원 브라우저가 사이트 허용/차단 권한을 공유한다고 명시되어 있다.
- 사이트 접근 없이 진행할 수 있는 경로는 사용자가 이미 확보한 로컬 PDF를 직접 표시하고 실제 화면 캡처를 제공하는 것이다. 해당 경우 사용자가 제공한 이미지를 대상으로 정답을 검토하고 P/F를 비교할 수 있다. 첫 대상은 `sources/evaluation-water-2021.pdf` 파일 87쪽(인쇄 84쪽)의 `62ppm` 문장이다.

### 새 대화에서 같은 Chrome/공식 PDF 접근 확인

- 사용자의 재확인 요청에 따라 같은 `cua.createBrowserTab("chrome", ...)` 도구와 같은 공식 PDF URL을 사용했다. 이번 반환은 `Browser is not available: chrome`으로, 이전의 저장된 사용자 권한 차단과 다르다.
- 이어 `cua.listBrowsers()`로 연결만 확인했다. 현재 목록에는 Edge(id `1`) 하나만 있으며 Chrome은 없다. 따라서 **사이트 접근 권한 검사에 도달하지 못했고**, 이전 차단의 해소 여부는 아직 판단할 수 없다.
- [새 대화 확인 증거](../../output/harness/20261011-174518-762c5033d6/browser-access-new-conversation.json). 실제 캡처·정답 확정·OCR 평가는 계속 0건이다. 설정 변경이나 다른 브라우저를 통한 사이트 접근은 하지 않았다.
- 공식 [Chrome 확장 문제 해결](https://learn.chatgpt.com/docs/chrome-extension#troubleshooting)을 다시 조회했다. Chrome 툴바의 ChatGPT 확장 연결·활성 프로필과 Settings > Computer Use의 Chrome 연결 표시를 확인한 뒤, 같은 URL을 재시도한다. 사이트 허용 설정을 반복해서 바꾸도록 요청하지 않았다.
