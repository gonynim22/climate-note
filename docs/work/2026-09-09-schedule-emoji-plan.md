# 작업 기록: 일정 이모지 선택 기능 구현 계획

작성일: 2026-09-09 / 상태: 소스 구현·중단 후 재점검·자동 검증 완료 / 실제 IME·혼합 DPI 실기 미확인

## 목표와 범위

- 목표: 일정 입력·인라인 편집에서 이모지를 쉽게 선택하고, 일정 목록과 중간·크게 모드의 일정 칩에서 중요한 일정을 구분한다.
- 이번 작업: 사용자의 구현 요청에 따라 계획을 코드와 회귀 검사에 반영한다.
- 구현 변경 대상: 신규 `ui_schedule_emoji.py`, `ui_main.py`, 신규 `tests/test_ui_schedule_emoji.py`, `tests/test_edge_cases.py`, UI·아키텍처·검증 정본 문서. 중단 후 재점검에서 `ui_settings.py`의 데이터 작업 보류 안내 문구를 추가로 수정한다.
- 데이터 영향: 선택한 이모지를 기존 `schedules.content` 앞에 일반 Unicode 문자열로 넣고 기존 `security.encrypt()` 경로로 함께 암호화한다. DB v17, Export v2, canonical 색상 3슬롯, 기존 설정 키와 salt를 유지한다. 기존 행 일괄 수정이나 마이그레이션은 없다.
- 제외 범위: 스티키·D-Day의 이모지 기능, 중요도 정렬·필터, 최근 사용 목록, 사용자 지정 이모지 팔레트, 이미지·외부 폰트 번들, 의존성 변경, 앱 버전 갱신, EXE 빌드·게시.
- 시작 시 사용자 변경: `.gitignore` 수정이 이미 있다. 수정·스테이징·커밋 대상에 포함하지 않는다. 기준 HEAD는 `2be9081`이다.

## 계획 작성 당시 구현 (변경 전 관찰)

- [일정 입력·편집](../../ui_main.py): `_build_bottom_panel()`은 색상 버튼·`schedule_input`·추가 버튼을 배치한다. `_on_add_schedule()`과 `_on_edit_schedule()`가 기존 DB 함수를 호출한다.
- [일정 표시](../../ui_main.py): `_add_schedule_item()`은 색상 점과 전체 본문을 표시한다. `CalendarDayButton._make_chip()`은 본문을 오른쪽 말줄임하고 전체 내용 툴팁을 제공한다.
- [검색](../../ui_search.py): 본문 검색 결과와 툴팁에 저장된 내용을 사용하므로 선두 이모지도 같은 문자열로 전달할 수 있다. 검색 종류의 색상 배지는 유지한다.
- [저장](../../database.py): 일정 추가·수정은 본문 문자열을 암호화한다. 날짜별·월별 조회, 검색, Export/Import는 같은 본문을 주고받는다.
- [기존 Unicode 검사](../../tests/test_edge_cases.py): `TestScheduleEdgeCases.test_content_unicode_emoji`가 이미 이모지 포함 일정의 저장·조회 계약을 검사한다. 이번에는 실행하지 않았으므로 현재 통과 증거로 사용하지 않는다.
- 인라인 편집의 `focusOutEvent`는 즉시 편집을 종료한다. 이모지 버튼·팝업으로 이동하는 포커스를 외부 이탈과 구분해야 한다.
- `_on_date_selected()`는 선택 날짜를 먼저 바꾼다. 편집 완료 시 날짜 칩을 갱신할 때는 편집을 시작한 날짜를 캡처해야 한다.
- `_lock()`은 활성 팝업을 닫는다. 새 선택창도 이 경로로 닫히고 이후 선택 콜백이 저장·재표시하지 않도록 연결한다.

## 제안하는 사용 방식

입력 행 예시:

```text
[색상 ●] [이모지 선택] [📌 주간 업무보고                  ] [+]
```

1. 기존 색상 버튼과 입력창 사이에 작은 이모지 선택 버튼을 둔다. 입력창에는 이모지를 포함한 전체 문자열이 그대로 보인다.
2. 버튼을 누르면 4×4 선택창과 `없음` 항목이 열린다. 한 번에 선택하는 선두 표식은 하나다.
3. 선택하면 입력창 앞의 표식이 추가·교체되고 입력을 계속한다. 이 시점에는 DB에 저장하지 않는다.
4. 기존 Enter·추가 버튼으로 저장한다. 저장 성공 시 입력창이 비워지므로 다음 일정은 이모지 없이 시작한다. 실패 시 입력 내용은 유지한다.
5. 기존 일정의 더블클릭·우클릭 `편집`에서도 같은 버튼과 선택창을 제공한다.
6. `없음`은 도우미가 인식한 선두 표식만 제거한다. 본문에 직접 입력한 이모지는 자유롭게 사용할 수 있다.

초기 팔레트 제안은 다음 16개로 고정하고, 한국어 툴팁과 접근성 이름을 제공한다.

| 이모지 | 이름 | 이모지 | 이름 |
|---|---|---|---|
| 📌 | 중요 | ⭐ | 특별 |
| 🔥 | 긴급 | ⏰ | 마감 |
| 🤝 | 협의 | 👥 | 회의 |
| 📞 | 전화 | ✉️ | 메일 |
| 📝 | 작성 | 📄 | 문서 |
| 📊 | 보고 | 🎯 | 목표 |
| 📚 | 교육 | 🚗 | 출장 |
| 🏠 | 재택 | 🎉 | 행사 |

색상과 이모지는 독립적으로 선택한다. compact는 기존 날짜·색상·개수 3행을 유지하고 하단 일정 목록에서 이모지를 보여준다. medium/large는 일정 목록과 날짜 칸의 일정 칩에서 함께 표시한다.

## 저장 표현과 호환성

별도 `emoji` 컬럼 대신 기존 본문 문자열을 사용한다. 첫 버전은 이모지 전용 검색·정렬이 필요하지 않고, 현재 저장 형식이 이미 Unicode를 지원하기 때문이다. 새 컬럼은 조회·건강 검사·Export/Import·스키마 버전까지 변경 범위를 늘리므로 이번 계획에는 포함하지 않는다.

- 선택 결과 예: `주간 업무보고` → `📌 주간 업무보고`.
- 도우미가 관리하는 형식은 **팔레트에 있는 이모지 전체 문자열 + ASCII 공백 한 칸**으로 시작하는 경우다. 여러 코드 포인트로 구성된 `✉️`도 문자열 전체를 비교한다.
- 알려진 선두 표식 하나만 교체·제거한다. 본문 중간 이모지, 미지원 이모지, 공백 없는 `📌회의`, ZWJ·피부색·국기 조합을 임의로 분해하거나 정규화하지 않는다.
- 기존 사용자가 직접 입력한 `📌 회의`도 같은 선두 표식으로 인식한다. 별도 메타데이터가 없으므로 도우미로 만든 표식과 구별하지 않는다는 점을 명시한다.
- 읽기·검색·보기 전환·팝업 열기만으로 저장값을 변경하지 않는다. 실제로 선택·제거하거나 본문을 수정할 때만 사용자의 편집으로 취급한다.
- 이모지를 선택하지 않은 기존 일정은 이전과 같은 본문·색상·ID·생성시각을 유지한다. 수정하지 않은 행의 암호문도 바꾸지 않는다.
- 선택 도우미에는 팔레트 제한이 있지만 일반 본문에는 기존처럼 임의의 Unicode를 입력할 수 있다. 기존의 이모지만 있는 일정도 계속 읽고 편집할 수 있게 한다.
- 본문 안에 함께 저장하므로 일반 텍스트 검색·복사·내보내기에도 이모지가 포함된다. 별도의 중요도 데이터는 생성하지 않는다.

예상 결과:

| 입력 | 선택 | 결과 |
|---|---|---|
| `회의` | 📌 | `📌 회의` |
| `📌 회의` | ⭐ | `⭐ 회의` |
| `📌 회의` | 없음 | `회의` |
| `회의 후 🎉 행사` | 없음 | 변경 없음 |
| `👩🏽‍💻 업무` | 📌 | `📌 👩🏽‍💻 업무` |
| `📌회의` | 없음 | 변경 없음 |

## 구현 순서

### 1. 선택 도우미와 문자열 처리

- `ui_schedule_emoji.py`에 고정 팔레트, 정확한 선두 표식 인식·치환 함수, 재사용할 선택 버튼·팝업을 둔다. 저장 계층에는 UI 의존성을 넣지 않는다.
- 본문 전체를 숨겨진 이모지·제목 상태로 이중 관리하지 않고 기존 입력창 문자열을 단일 편집 원본으로 사용한다.
- 선택 동작은 입력창의 선두 구간 교체 한 번으로 처리하여 Undo로 되돌릴 수 있게 한다. Qt 선택 범위의 UTF-16 위치와 Python 문자열 인덱스를 혼용하지 않는다.
- 문자열 `setText()`로 전체 내용을 매번 재설정하여 Undo·선택 영역을 잃는 구현을 피한다. 선두 표식 밖의 내용·공백은 그대로 둔다.

### 2. 새 일정 입력 연결

- `_build_bottom_panel()`에 버튼을 추가하고 `schedule_input`에 연결한다.
- 기존 입력 검증·색상 선택·Enter·추가 버튼 경로를 재사용한다. 별도 일정 저장 함수는 만들지 않는다.
- compact 최소 폭에서 버튼 때문에 추가 버튼이나 한글 입력 영역이 잘리지 않는지 확인한다.

### 3. 인라인 편집과 팝업 수명 연결

- 인라인 편집 영역에 본문 입력창과 이모지 버튼을 함께 둔다. 현재 라벨 위치를 숫자 인덱스로 찾는 부분은 필요한 범위에서 명시적 참조로 바꾼다.
- 입력창 → 같은 편집 영역의 버튼·선택창 이동은 편집 종료로 처리하지 않는다. 이벤트 처리 후 실제 포커스 대상과 팝업 소유자를 확인한다. Qt는 팝업을 포함한 포커스 이동 원인을 제공한다: [QFocusEvent](https://doc.qt.io/qt-6/qfocusevent.html).
- 팝업에서 선택하거나 Escape로 닫으면 원래 입력창으로 복귀한다. 팝업이 열려 있을 때의 Escape는 팝업만 취소하고, 닫힌 편집창에서의 Escape는 일정 수정을 취소한다.
- 편집 영역 밖으로 이동하면 기존처럼 저장한다. 날짜 이동·목록 재생성 전 명시적으로 편집을 마치는 경로도 유지한다.
- 저장할 일정 ID와 날짜는 편집 시작 시 캡처한다. 이모지 변경 후 올바른 날짜 칩을 즉시 갱신한다.
- 저장 실패 시 DB와 표시 라벨을 성공 상태로 바꾸지 않고 편집 원본을 유지한다. 날짜 이동·목록 재구성이 실패한 편집을 폐기하지 않도록 완료 결과를 호출부가 확인한다. 이 변경은 새 일정 편집 경로에 한정한다.
- 선택창은 하나만 열고 닫힌 뒤 `deleteLater()`와 소유 참조 해제를 수행한다. 버튼·편집창 폐기 뒤 예약 콜백은 무효화한다.
- 잠금·트레이 숨김·초기화로 선택창이 닫힐 때는 강제로 편집창에 포커스를 돌리거나 창을 다시 표시하지 않는다. 잠금 중 새 선택·변경도 차단한다.

### 4. 표시와 폰트 확인

- 일정 목록·날짜별 칩·검색 결과는 이모지가 포함된 같은 본문을 사용한다. 별도 이모지 배지를 다시 붙여 중복 표시하지 않는다.
- 중간/크게 모드의 기존 칩 높이·글꼴 크기·`+N 더`와 본문 전체 툴팁을 유지한다. 긴 제목은 오른쪽부터 말줄임한다.
- 선택창의 이모지에는 시스템 `Segoe UI Emoji`를 사용하고 본문은 기존 앱 글꼴과 Qt 폴백을 유지한다. 외부 폰트·이미지는 추가하지 않는다.
- 실제 Windows/검증된 Qt 버전에서 팔레트 16개가 잘리지 않고 식별되는지 확인한다. 색상 렌더링·기준선·대체 글꼴은 자동 문자열 검사만으로 통과 처리하지 않는다.
- 팝업은 호출 버튼이 속한 모니터의 작업 영역 안에 배치한다. 음수 좌표와 화면 가장자리에서도 모든 선택지가 보여야 한다.
- `ui_search.py`는 기본적으로 변경하지 않는다. 현재 본문 표시만으로 결과가 충족되는지 회귀 검사한다.

### 5. 검증과 정본 문서 반영

- `tests/test_ui_schedule_emoji.py`: 실제 입력창·팝업 이벤트·일정 DB를 연결하는 UI 회귀와 선두 표식 변환 경계를 검사한다.
- `tests/test_edge_cases.py`: 이모지 일정의 수정·검색·PIN `.enc` 왕복과 기존 데이터 보존을 검사한다. DB·salt는 합성 데이터만 사용한다.
- 구현 완료 후 [UI 계약](../UI_PATTERNS.md)에 입력·선택·편집·표시 동작을, [아키텍처](../ARCHITECTURE.md)에 본문 접두 표현과 DB/Export 형식 유지 결정을 반영한다.
- [검증 지침](../TESTING.md)에 따라 최종 `full`을 실행하고 실제 `summary.md`·실행 ID·입력 해시를 이 기록에 남긴다.
