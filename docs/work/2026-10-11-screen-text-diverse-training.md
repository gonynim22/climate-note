- 첫 목표: 새 train 256문구·selection 64문구, Qt 8조건과 실제 앱 화면. 원래 6,000장/1,200문구 목표 전체 완료로 세지 않는다. 실제 확보량·제외 사유는 자료 manifest로 확정한다.
- 사전은 기존 확장 21기호에 ○·★·₂를 추가한 24기호 후보를 준비한다. 기존 문자/공백 ID를 대응 복사하고 새 클래스가 확률에 끼치는 영향도 확인한다. 사전만 수정한 제품 교체는 하지 않는다.
- 학습 설정은 자료·실제 폭·환경 사전검사 후 추론 평가 전에 고정한다. 기존 BN 통계 고정·단일 소형 인식 구조를 유지하고 추가 큰 모델이나 상시 다중 추론을 넣지 않는다.
- 채택 검토: 공개 문단·업무 문구에서 공백 제외 오류 감소, 숫자/단위 새 손상과 기존 정답 퇴행 확인, 메모장/기존 합성 회귀, 15MB 이하·CPU 중앙/p95 1.10배 이내. 개발 자료 개선을 독립 일반화로 주장하지 않는다.
- 실행 ID: `20261011-202756-20ab404c28`. 자료 생성·앱 접근·학습·변환·품질 실패를 구분해 남긴다.
- 첫 학습 설정(새 선택/기존 비교 평가 전 고정): 원본 B24 초기 가중치, batch 4, 3 epoch, 최대 학습률 `2e-5`, 5% warmup 후 cosine, seed `20261011`, BN running statistics 고정. 과거보다 문맥을 늘리고 원래 인식을 훼손할 위험을 줄이려 낮은 학습률을 사용한다. 중간 선택 점수로 종료 시점이나 체크포인트를 고르지 않는다.

### 실제 문자 비교

공백을 제외한 편집 오류 문자 수다. 새 Qt와 한글 자료는 같은 64문구를 다른 조건에 표시한 것이므로 독립 문서 576개로 세지 않는다. 공개 표에는 읽기 순서와 인식 결과에 따른 상자 포함 여부의 영향도 남아 있다.

| 새 한글 화면 64줄 / 1,588자 | 62 | 62 | 16 | 0 |

- 새 한글 화면의 완전 일치는 27/64→50/64였지만, 메모장은 26/48→12/48로 감소했다. 띄어쓰기가 맞아져 공백 포함 오류가 줄더라도 실제 글자 오독이 늘 수 있다. 공개 문단은 공백 포함 오류 133→61인 반면 공백 제외 오류는 26→54다.
- 원본 화면을 다시 읽어 공개 문단의 `531ppm→531pp™`, `4.31점→431점`, `4.38점→438점`을 확인했다. 메모장의 `request_id=7ab09c31-42de-501f` 끝은 새 F에서 `501월`이 됐다. 새 한글 문구에서도 원문의 `○`를 `℃`로 출력했다.

- 공개 문단·메모장 각각 오류 20% 이상 감소, 다른 자료 오류 비증가, 기존 정답 손실 0, 새 중요 토큰 손상 0, 공백 포함 오류 비증가의 사전 기준이 모두 실패했다. **새 F는 미채택**이다. 이 결과에 맞춰 기준·라벨·학습 분할을 바꾸거나 평가 오류 문장을 학습으로 옮기지 않았다.
