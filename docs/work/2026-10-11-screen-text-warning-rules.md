## 결정과 진행

- 이전 경고 분석은 채점 1,919개(Unicode 정규화 1개 제외), 기존+불일치의 정상 오경고 60개, 실제 오류 위치 적중 180~189개였다.
- 고정 recipe를 추론 전에 작성했다. 점수는 모델 CTC 점수이며 보정된 정답 확률이 아니다. 누락 자리의 점수는 인접 문자 점수로 구분한다.
- 10분류별 원문 그룹을 고정 seed 해시로 정렬해 75% 조정/25% 확인에 배정한다. 파생 조건을 다른 분할에 넣지 않는다. 모두 이전에 관측한 dev이므로 확인용도 새 독립 평가가 아니다.
- 채택 기준은 조정용에서 기존+불일치 대비 오류 화면 경고와 확실한 오류 위치 적중을 각각 95% 이상 유지, 정상 오경고 20% 이상 감소, CLI 확실 적중 90% 이상 유지다. 통과 후보 중 오경고 최소→확실 적중 최대→표시 위치 최소→ID 순서로 한 개를 고정한다. 없으면 기존 규칙을 유지하고 탈락 이유/대안의 손실을 보고한다. 확인용은 같은 기준으로 평가하되 규칙을 다시 고르지 않는다.
- HTML은 기존 틀을 재사용한다. 기존 브라우저 정책 차단을 우회하지 않으며 정적 검사와 구분한다.

## 결과와 해석

원문 그룹 120개/40개를 조정/확인으로 배정했다. 조정 1,440개 중 NFC 위치 문제 1개를 제외한 1,439개, 확인 480개를 채점했다. 확인 480개는 기존 dev의 일부이며 이전 단계의 별도 holdout이 아니다.

| 조정용 조건 | 정상 결과 오경고 화면 | 확실한 오류 위치를 발견한 화면 | CLI 확실 적중 화면 |
|---|---:|---:|---:|
| 모든 불일치 표시(기준) | 44 | 147 | 38 |
| 원문 문자 점수 ≤0.8 | 32 | 101 | 32 |
| 불일치 편집 거리 ≤2 | 43 | 144 | 38 |
| 대안 점수 이득 ≥0.03 | 24 | 76 | 21 |

점수 ≤0.8은 오경고를 27.3% 줄이지만 확실한 오류 위치 발견도 31.3% 감소한다. 거리 ≤2는 확실 적중 98.0%를 유지하지만 오경고 감소가 2.3%에 그친다. 19개 조건(기준 포함) 어느 것도 사전 채택 기준을 모두 충족하지 못했다. 따라서 `selection.json`에 `all`, `passed_tune_gate=false`, `eligible_count=0`을 먼저 고정하고 확인용을 평가했다. 확인용에서 탈락 후보를 추가 비교하거나 재선택하지 않았다.

| 범위 | 채점 수 | 오류 화면 경고 / 놓침 | 정상 오경고 / 정상 무경고 | 실제 오류 위치 적중 화면(확실~가능) |
|---|---:|---:|---:|---:|
| 조정 | 1,439 | 171 / 174 | 44 / 1,050 | 147~154 |
| 확인 | 480 | 45 / 50 | 16 / 369 | 33~35 |
| 전체 | 1,919 | 216 / 224 | 60 / 1,419 | 180~189 |

기준과 선택 결과가 같으므로 이번 단계의 경고 개선은 0이다. 원문은 고치지 않았고 제품 코드도 바꾸지 않아 제품 문자 정확도 변화도 없다. 점수가 높은 오답까지 제거되는 사례가 있어 **이번에 시험한 점수·차이·누락 조건으로는 채택할 개선을 얻지 못했다**. 다른 검증 신호까지 실패했다고 일반화하지 않는다.

- [원본 이미지와 경고 손실 HTML](../../output/harness/20261011-071006-cfc3edcacb/tradeoffs.html): 이미 탈락한 두 조건을 조정용에서만 설명. 오경고 제거와 실제 오류 경고 손실 7개 예시(원본 PNG 6개)를 포함한다.
- [전체 19개 비교 HTML](../../output/harness/20261011-071006-cfc3edcacb/report.html): 조정용 전체 규칙, 선택 고정과 확인/전체 결과.
- [설명용 예시 근거](../../output/harness/20261011-071006-cfc3edcacb/tradeoff-examples.json): 원본 PNG 해시와 전후 표시·채점. 별도 후보 채택에 사용하지 않았다.

1,920개 예측 쌍의 원문·표·복사·상자/점수·블록·기존 경고와 UTF-16 범위를 이전 기록과 전수 대조했다. worker는 정답/태그 없는 요청을 받아 격리 사용자 폴더에서 실행하며, 원문·모델/사전·제품 코드의 전후 해시를 유지한다. 문자 점수·해시 수집과 고정 영역 판독이 포함된 실행 시간은 제품 지연시간이 아니므로 새 속도 개선을 주장하지 않는다. 공백/표 구조/픽셀 문자 위치 평가와 사용자 실제 화면 평가는 이번 범위 밖이다.
