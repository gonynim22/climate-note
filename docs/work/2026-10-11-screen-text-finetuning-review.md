## 결정과 진행

- 2026-10-11: 요청 범위는 추가 학습 **검토**다. 설치·학습을 시작하지 않고 공식 자료와 로컬 읽기 전용 검사로 실행 가능한 다음 단계를 정한다. 기존 대형 모델 비교의 기준 미달은 현재 모델 학습 불가능의 근거가 아니다.

### 판단

후속 [에이전트 실행 계획](2026-10-11-screen-text-finetuning-plan.md)은 사용자 지정 업무 화면(한컴 한글·PDF·Word·메모장)을 우선한다. 추가 검토에서 NRTR의 실효 길이는 설정 25일 때 23자, 기본 warmup은 5 epoch임을 확인해 아래 초기 파일럿안을 보완했다. 단위 기호 확장과 충분한 본 학습도 별도 단계로 포함하며, 아직 설치·학습은 시작하지 않았다.

**현재 소형 모델의 화면 글자 특화 추가 학습은 실험할 근거가 있다. 다음 실행은 학습 전에 공식 가중치의 원본 출력 재현부터 한다.** 공개 학습 가중치·설정·사전·Windows용 도구가 있지만, 현재 제품 ONNX와 가중치/출력까지 같다는 확인은 아직 없다. 정확도 향상량이나 4GB GPU에서의 학습 시간을 약속할 수 없다.

같은 CTC 추론 구조·사전·정밀도를 유지하면 약 13.4MB 규모를 유지할 가능성이 높다. 이는 구조에 근거한 예상이며 재변환 파일 크기는 미측정이다. 학습 체크포인트는 보조 NRTR 분기를 포함하므로 111MB이며 이 파일을 제품에 넣는 방식이 아니다.

### 1. 공식 자료와 제품의 대응

PaddleOCR 소스는 기존 모델 고지와 같은 고정 커밋 `dab3fe35379033fdcb2d0e9572fac0b36c9a9ebf`, 공식 추론 모델은 HF 리비전 `c02ecaf1f22bfd1c618cce154fd19185b47e663a`를 사용했다. [공식 한국어 모델 안내](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.html)의 학습 파일을 개발 출력 폴더에만 받았다. 내려받은 가중치를 로드하거나 실행하지 않았다.

### 2. 그대로 학습하면 생기는 문제

- 공식 설정의 `max_text_length=25`를 그대로 쓰면 긴 줄이 제외된다. 이미 평가한 메모장 **dev 48장/24그룹의 정답 150줄 중 54줄이 25자를 넘고 최대 48자**다. 같은 원문의 100/150% 파생이 포함된 숫자이며 독립 문장 150개가 아니다. 이 자료에는 줄 상자 주석이 없으므로 화면 PNG와 전체 정답을 그대로 줄 인식 학습쌍으로 넣을 수도 없다.
- [`BaseRecLabelEncode`](https://github.com/PaddlePaddle/PaddleOCR/blob/dab3fe35379033fdcb2d0e9572fac0b36c9a9ebf/ppocr/data/imaug/label_ops.py)는 길이 초과를 `None`으로 제외하고 사전 밖 글자는 건너뛴다. 제품 사전에는 `℃`와 `₩`가 없고 역슬래시(U+005C)는 있다. 기존 dev 정답에도 `℃` 2자가 있다. **사전을 고정한 추가 학습으로 이 두 `℃`를 그대로 출력하게 만들 수 없다.** `°C`로 정답을 바꾸거나 제외해 점수를 좋게 만들지 않는다. 원화처럼 보이는 역슬래시의 글리프 모호성은 문자 클래스 부족과 별도 문제다.
- 학습 자료 사전검사에서 OOV·빈 정답·길이 초과·깨진 이미지·CTC로 표현 불가능한 길이(반복 인접 글자에 필요한 blank 단계 포함)를 전부 집계한다. OOV가 있는 학습쌍은 원문을 보존한 채 별도 보류하고 누락된 학습량을 공개한다. 평가에는 OOV를 포함한 전체 점수와 지원 문자 점수를 함께 남긴다. 사전 확장은 출력층 크기·기존 가중치·제품 계약을 바꾸는 별도 실험으로 둔다.
- 학습 loader는 가중치 키/shape 불일치에 경고 후 진행할 수 있다([원본](https://github.com/PaddlePaddle/PaddleOCR/blob/dab3fe35379033fdcb2d0e9572fac0b36c9a9ebf/ppocr/utils/save_load.py)). `load pretrain successful` 한 줄을 재현 성공으로 세지 않는다. 누락/초과 키와 shape를 전수 대조하고 예상하지 못한 불일치는 중단한다.
- 학습은 한 줄 crop을 사용하고 실제 제품의 검출 오차·여백·배치 패딩도 평가한다. 검출기·줄/표 조립·전처리를 동시에 바꾸지 않는다. crop 점수 상승과 앱 전체 점수 상승을 구분한다.

### 3. 별도 환경 후보

현 PC에서 GTX 1650 **4,096MiB**, compute capability **7.5**, 드라이버 **591.86**을 읽었다. 제품은 Python 3.13이며 `py` 실행기는 PATH에 없다. 모든 설치 경로를 조사한 것은 아니므로 Python 3.12가 PC에 전혀 없다고 단정하지 않는다.

- 첫 후보: `output/screen_text_lab/` 아래 **별도 CPython 3.12 x64 환경**, PaddlePaddle GPU **3.2.2 / cu118**, Paddle2ONNX **2.1.0**, 위 고정 PaddleOCR 소스. 설치 전에 전체 의존성 해석 결과와 wheel 해시를 별도 lock에 고정한다. 프로젝트 `.venv`/`requirements-lock.txt`, 전역 PATH/드라이버를 바꾸지 않는다.
- [공식 Windows 안내](https://www.paddlepaddle.org.cn/documentation/docs/en/install/pip/windows-pip_en.html)는 3.2.2 GPU 설치 경로와 Windows 분산 학습 미지원을 명시한다. [공식 wheel 목록](https://www.paddlepaddle.org.cn/packages/stable/cu118/paddlepaddle-gpu/)에는 3.2.2·3.3.0의 cp312/cp313 Windows 파일이 모두 있다. 안내와 배포 목록의 최신 버전 표기가 다르므로 자동으로 최신 버전을 고르지 않는다.
- [Paddle2ONNX 2.1.0 PyPI](https://pypi.org/project/paddle2onnx/2.1.0/)에는 Windows cp312 wheel이 있지만 cp313은 없다. **Python 3.12 선택 이유는 변환 도구까지 함께 맞추기 위해서다.** Paddle2ONNX의 onnx 1.16.1~1.17.0 제약도 별도 환경에서 해결한다.
- [Paddle2ONNX v2.1.0 안내](https://github.com/PaddlePaddle/Paddle2ONNX/blob/v2.1.0/README.md)는 Paddle 3.0.0을 권장하고 영문은 3.0.0b2로 표기가 다르다. 따라서 위 3.2.2 조합은 **실행 후보이지 호환 검증 완료 조합이 아니다.** DLL 로드·`paddle.utils.run_check()`·1회 변환이 선행 조건이다. 실패하면 원인과 고정 버전을 다시 검토하며 프로젝트 환경으로 옮겨 설치하지 않는다.
- GPU 메모리는 모델 파일 크기만으로 판단하지 않는다. 공식 배치 128/worker 8 대신 단일 GPU·worker 0·FP32·배치 4로 50 step 측정하고 OOM이면 배치 2를 딱 한 번 확인한다. 2에서도 실패하면 종료·기록한다. CUDA/cuDNN 실제 로드 및 처리량은 아직 측정하지 않았다.

### 4. 다음 실행: 학습하지 않은 원본 재현

1. 별도 환경과 공식 소스/가중치의 해시를 고정하고 앱 코드·모델·환경의 시작 전 해시를 저장한다. 학습/평가 중 외부 다운로드를 끄고 실사용 AppData/캡처를 읽지 않는다.
2. 공식 `.pdparams`를 같은 사전/원본 설정으로 로드해 키·shape 전수 일치를 확인한다. 학습 step 없이 평가 모드로 `.json + .pdiparams`를 내보내고 ONNX로 변환한다. 공식 HF 추론 파일도 별도 변환해 **학습 가중치 → 공식 추론 → 제품 변환본**의 어느 구간이 다른지 구분한다.
3. 고정된 dev 줄 crop에서 **동일 float32 BGR 정규화 tensor**를 각 경로에 넣는다. 문자 사전 순서·N/W 동적 입력·CTC blank=0/공백 마지막·출력 정규화·제품의 비율 절삭을 확인한다. 공식 전처리와 제품 전처리의 차이를 가중치 차이로 해석하지 않는다.
4. 이미지/좌표/tensor 해시, 출력 최대·평균 절대 차이, top-1 단계 차이, 디코딩 문자열/점수 차이를 보존한다. 시작 허용오차 제안은 `atol=1e-4, rtol=1e-3`, 문자열은 전부 일치다. 작은/큰 폭과 서로 다른 폭을 함께 넣는 배치 1/6을 포함한다. 파일 바이트 동일은 요구하지 않는다. 불일치가 나면 학습 전에 원인을 조사하고 허용오차를 결과에 맞춰 몰래 넓히지 않는다.
5. 전체 dev에서 동일 검출/전처리/디코더로 원본 재수출 모델과 현재 제품의 텍스트·표·0.80 경고가 같음을 확인한다. 여기까지 통과해야 추가 학습 효과를 원본 재변환 효과와 분리할 수 있다. 변환/원본 차이를 해소하지 못하면 후속은 '동일 모델 미세학습'으로 주장하지 않는다.

이 단계는 아직 실행하지 않았다. 설치·전체 원본 재현의 작업 예산은 최대 2시간으로 제안하며, 환경을 바꾸며 무제한 시도하지 않는다. 주석 없는 실제 48장 대신 출처가 고정된 기존 합성 dev의 줄 주석을 우선 재현 입력으로 쓸 수 있다.

### 5. 제한된 추가 학습 실험안

아래 수량·시간·설정은 **후속 실행 전 고정할 제안**이다. 준비된 자료나 학습 완료 실적이 아니다.

| 단계 | 제안 범위 | 통과 또는 중단 조건 |
|---|---|---|
| 학습 자료 | 새 원문/템플릿 그룹 1,200개 × 화면 조건 5개 = 합성 줄 6,000장. 별도 동의된 실제 줄 crop 200장 이상 보강 목표 | 렌더 전에 그룹 분할, 줄/crop 정답 검토. 실제 자료를 못 모으면 합성 연구 결과로 한정 |
| 선택용 자료 | 새 그룹 200개 × 5조건 = 합성 1,000장 + 별도 실제 100 crop/50화면 그룹 이상 목표 | train과 문서·문구 템플릿·파생 이미지·중복/유사 원문 분리 |
| 최종 평가 | 새 그룹 200개 × 5조건 + 실제 200 crop/100화면 그룹 이상 목표, 앱 4종 이상 | 사람의 독립 정답 대조, 후보 고정 전 정답/예측 미열람. 제품 흐름용 원본 화면과 줄 crop 둘 다 보관 |
| smoke | 원본 재현 후 64개 학습쌍, 50 step. 메모리/초당 처리/손실 유한성/파라미터 변화 확인 | 정확도 개선 근거로 쓰지 않음. 배치 4→2 외 자동 탐색 없음 |
| 본 실험 | LR `1e-5`·`5e-5` 두 개, 동일 seed·자료 순서, 각 5 epoch 또는 60분 중 먼저 도달할 때 종료 | 선택용만으로 선택, 중간 결과가 좋아도 기준/자료/후보를 추가하지 않음 |
| 재현 | 선택 후보만 두 번째 seed로 같은 예산 1회 | 성능이 방향까지 뒤집히면 불안정으로 보류, 이후 후보 1개를 고정 |

- 원문은 한글 문장·한영 혼합·숫자/날짜/단위·CLI/경로·기호를 균형 있게 구성한다. 화면용 글꼴·10~24px·밝음/어두움·낮은 대비·100/125/150%·다양한 여백을 조합한다. Qt 합성 배율과 실제 Windows DPI/ClearType 캡처는 구분한다. 글꼴 이용조건과 캡처 자료 사용 범위를 기록한다.
- 최초 길이 상한은 64자, 높이 48px를 제안한다. 가로폭은 원본 글자 비율을 보존하며 긴 줄이 320px에 과도하게 눌리지 않도록 구간별 폭을 설계한다. CTC 출력 단계가 정답을 수용하는지 검사하고, 64자 초과 원문을 임의로 잘라 정답을 손상시키지 않는다. 길이/폭 변경으로 NRTR 가중치 shape가 바뀌는지는 선행 로드 검사로 확인한다.
- 첫 실험은 backbone·CTC·학습 보조 NRTR 구조를 유지한 소폭 전체 미세학습으로 한정한다. 과한 자연사진 왜곡/문장 합성 `RecAug`·`RecConAug`는 첫 화면 특화 실험에서 끄고, 평가 전처리는 제품 규칙으로 고정한다. 실제 학습 구현 전에 48px/폭 bucket을 지원하는 loader 설정과 모든 파라미터를 파일로 고정한다.
- 기존 합성 1,920 dev와 이미 사용한 480 holdout은 **회귀 자료**다. 새 독립 검증으로 부르지 않는다. 기존 실제 dev 48장/24그룹도 회귀 전용으로 두고 학습에 섞지 않는다. 남은 실제 holdout 12장은 학습·선택에 쓰지 않으며 후보 확정 뒤 보조 최종 평가로만 쓴다. 한 앱/AI 검토 정답이라는 한계가 있어 새 독립 실제 평가를 대체하지 않는다.
- 최종 자료는 한 번 열면 후속 튜닝용으로 재사용하지 않는다. 실패 후 다시 실험하려면 새 최종 자료를 준비한다. 반복 검토한 COUNT/갬 등의 특정 기존 문구를 복제해 학습시키고 그 문구 개선을 일반 정확도로 주장하지 않는다.

### 6. 후보 선정과 제품 적용의 분리

후속 실험의 선택용/독립 최종 평가에서 동일하게 적용할 기준을 먼저 고정한다. 각 자료 종류를 별도 보고하며 합성 대량 표본으로 실제 퇴행을 희석하지 않는다.

- 모든 사례 성공·잘림 0, **공백 제외 오류 20% 이상 감소**, 공백 포함 오류 비증가, 기존 비공백 완전 정답 사례의 신규 오답 0. 전체/OOV 포함 점수가 기준이며 지원 문자 점수는 보조다. 이 유한한 자료에서 신규 오답이 없다는 뜻이지 모든 사용 상황의 무퇴행 보장은 아니다.
- crop 판독뿐 아니라 고정 검출을 거친 전체 텍스트·표 셀/구조의 퇴행 0을 요구한다. 자료가 빈약한 앱/숫자/경로 분류는 평가 완료로 처리하지 않는다. 경고 점수 분포가 달라질 수 있으므로 기존 0.80 경고에서 놓친 오류와 정상 오경고도 별도로 비교하고, 악화하면 제품 적용을 보류한다.
- 동일 CPU/스레드/입력에서 워밍업 후 순서를 교대해 각 5회 비교한다. 제안 한도는 인식 시간 중앙/p95 각각 기존 대비 1.10배 이하, ONNX 15MB 이하이며 초기 로드/프로세스 메모리도 별도 보고한다. GPU 학습 시간과 제품 CPU 시간을 섞지 않는다.
- 개선이 확인되어도 실제 UI·혼합 DPI·캡처 차단·제품 회귀·새 MANIFEST/변경 고지·EXE 검증은 별도 작업이다. 제품 모델과 이전 모델을 되돌릴 수 있게 보존한다. **이번 검토의 제품 적용 정확도 개선량은 0**이다.
