## 결정과 진행

- 2026-11-01: 분석([위험도 문서](2026-10-31-root-file-cleanup-risk.md))의 B안을 v4.5a로 진행하기로 사용자가 결정했다. 원칙은 "이동 따로, 기능 따로"다.
- 분석 패치(`output/root-cleanup-risk-20261031/b-plan-fixes.patch`)를 기준으로 하되 세 곳을 바꿨다.
  - F5 `app_paths._SOURCE_ROOT`는 `parents[1]` 대신 예외가 없는 `.parent.parent`.
  - F12 실험실 경로는 작업 프로세스별 `PYTHONPATH` 대신 `tools/screen_text_lab/__init__.py` 한 곳에서 넣는다. 부모·작업 프로세스와 `python -m tools.screen_text_lab.<모듈>`이 모두 이 패키지를 먼저 읽는다. 앱 모듈은 import하지 않아 import 부작용 보호 시험과 부딪치지 않는다.
  - `pytest.ini`의 `pythonpath = src`는 넣지 않는다(conftest 하나로 충분, 분석 실측에서 차이 없음).
- 보호 장치(G1·G2·G4·G5)는 `tests/test_source_layout.py`, G3는 `tools/verify.py`의 `app_module_check`(release에서 추적 중인 `src/*.py`가 모두 EXE PYZ에 있는지 확인). G6(README 링크)은 2단계 때 넣는다.
- 순수 이동 커밋 `fc2c09a`(52개 모두 100% rename).
- 걷어내기 보호 시험에 `src/ui_text.py`의 `import screen_text` 위반을 일부러 넣어 실패하는 것을 확인하고 되돌렸다. 실험실 패키지를 거쳐 `screen_text`를 import하면 `src/app_paths.py`를 찾고 합성 `LOCALAPPDATA`에 아무것도 만들지 않았다.
- 수정 커밋 `2d00b77`에서 full·release·새 clone full이 모두 통과했다(아래 표). release의 공휴일 단계는 최신 확인(`up_to_date`, 2025~2028년)이라 `src/holidays.py`는 바뀌지 않았다.
- 새 EXE와 배포된 v4.5 EXE 대조(`output/v4.5a-clone-full-20261101/compare_exe.py`·`deep_diff.py`·`entry_diff.py`):
  - PYZ 541개 이름 같음. 코드가 다른 모듈은 `app_info`(상수 `v4.5`→`v4.5a`, 출시일만)·`app_paths`(모듈 본문, 상수·이름 동일)·`ui_settings._get_startup_cmd`(상수·이름 동일)뿐이다. 진입 스크립트 `main`은 18,509→18,882 bytes(src 경로 블록).
  - PKG 항목 이름 같음. 바이트가 다른 것은 `icon/climate_note_style16_continents_final.svg`(줄바꿈만 다름: v4.5 빌드 때 LF, 지금 체크아웃은 CRLF)와 `base_library.zip`(항목 이름·내용 동일, 압축 정보만 다름)뿐이다.
