# 작업 기록: 정부 공문서 AI 데이터 API 실물 확인

작성일: 2026-10-11 / 상태: API 인증·자료 구성 조사 완료, 실제 앱 캡처는 별도 대기

## 목표와 범위

- 사용자가 `.env`에 등록한 `publicDoc` 인증키로 공공데이터포털 정부 공문서 AI 학습데이터 API를 소량 조회한다.
- 다운로드 파일의 실제 구성, 원본 HWP/PDF·문서 이미지·원문 텍스트의 제공 여부를 확인하고 실제 화면 OCR 평가에 쓸 범위를 결정한다.
- 공식 명세: <https://www.data.go.kr/data/15125451/openapi.do>. HTTPS `apis.data.go.kr/1741000/publicDoc/`만 인증키와 함께 호출한다.
- 변경 대상은 이 기록과 `output/harness/20261011-173802-641dea6283/`의 개발 조사 산출물이다. `.env`·제품 코드/모델/사전·DB·salt·의존성은 유지한다. 시작 당시 dirty/untracked 기존 변경을 보존한다.
- 키·키를 포함한 요청 URL을 출력·로그·보고서·Git에 남기지 않는다. 응답을 저장하기 전에 키 문자열을 제거하고 예외에도 URL을 표시하지 않는다.
- [실제 캡처 기록](2026-10-11-screen-text-public-document-capture.md), [진단 계약](../SCREEN_TEXT_LAB.md), [검증](../TESTING.md)을 따른다. API 수집과 실제 앱 캡처를 구분한다.

## 결정과 진행

- `.env`가 Git ignore 대상임을 확인했다. 값은 출력하지 않고 `publicDoc` 항목을 선택했다. 음력용 기존 키는 사용하지 않는다.
- 보조 에이전트 3개는 여전히 사용량 제한 상태이므로 총괄이 조사한다.
- 먼저 `getDocAll` 첫 페이지 5건만 조회한다. 파일 크기를 확인한 뒤 필요한 표본만 받으며 대용량 묶음을 자동 전량 다운로드하지 않는다.
- API 기반 원문은 그대로 화면 이미지 정답이 되지 않는다. 원본 문서/이미지 대응·표 구조·글자 위치가 확인되기 전 학습·OCR 채점은 실행하지 않는다.
- `getDocAll`은 인증/조회 성공(코드 00)으로 `publicDocAll.zip` 1개를 반환했다. API가 알린 파일 크기는 89,148,867 bytes(약 85 MiB)다. 끝부분만 받는 HTTP Range를 서버가 지원하지 않아 크기를 확인한 이 묶음 하나를 받았다(개발 수집 상한 100 MiB). 로컬 SHA-256은 `50449417ac86c32a732413bf65ae197d1ada156a56e7822911575a9bf105e94c`이며 제공처의 공개 체크섬 대조는 할 수 없었다.
- ZIP 안 **30,278개 전부 JSON**이다. HWP/HWPX/PDF/DOC/DOCX·래스터 이미지 파일은 각각 0개다. 전체 항목 CRC 및 JSON 읽기를 확인했다. 유형별 보도자료 29,760 / 연설문 353 / 발간사 20 / 정책보고서 103 / 행사회의계획 42건이며, 동일 내용/템플릿의 독립성 검증은 아직 하지 않았다.
- `data.text`와 `data.task`가 전 기록에 있다. HTML 표 포함 15,166건, 외부 그림 링크 포함 28,732건, ppm 포함 13건, 원시파일명 값이 있는 기록 4,165건이다. 페이지/글자 좌표가 있는 OCR 주석은 확인하지 못했다.
- 유형별 앞 4건씩 **20개 표본**과 `ppm`이 있는 **13개 원문 JSON**을 보관했다. ppm 묶음은 특정 실패를 재검토하기 위한 후보 원문이며 독립 최종 평가가 아니다. 첫 보도자료의 연결 그림 3개를 내려받아 직접 확인했으며 표어·기관 로고·공모전 포스터였다. 전체 외부 그림의 유형을 전수 확인한 것은 아니다.
- 일부 본문 연락처에 `000` 치환 흔적이 있다. 원본 화면과 대응하지 않은 API 텍스트를 자동 정답으로 쓰면 실제 글자를 오류로 채점할 수 있으므로, 정답 작성 시 원본 대조를 유지한다.
- API 요청 총 4회: 전체 목록 1회 성공, 빈 필수 필터의 계획/보고서 조회 2회는 코드 11 실패, 실제 제목·참석자를 넣은 계획 조회는 1건 성공. 표본 보고서의 필수 담당자 값이 비어 있어 후속 보고서 조회는 보내지 않았다. 원 응답/실패를 보존했고 인증키를 HTTP 다운로드 URL에 전달하지 않았다.
- 판단: **업무 문장·표의 학습용 원문 공급원으로 채택 가능**하다. 다만 원본 HWP/PDF 및 실제 앱 캡처를 추가 확보해야 하며, JSON에서 재작성한 문서는 재구성 자료로 구분한다. 이번에는 추가 학습과 OCR 평가를 하지 않았다.

## 미해결과 인계

- 실제 한글/Word/브라우저 캡처의 이전 접근 차단은 이 API 조회로 해소된 것이 아니다.
- 재현 명령: 프로젝트 `.venv/Scripts/python.exe -X utf8`로 실행 폴더의 `probe.py`, `inspect_archive.py`, `audit_content.py`, `probe.py getDocPlan matched`, `finish_report.py`. `probe.py`는 실제 API를 호출하고 나머지는 받은 자료를 검토한다. 키는 `.env publicDoc`에서만 읽는다.
- 다음 단계: 표본/ppm 원문의 제목·날짜·기관·원시파일명을 이용해 공개 원본 문서를 대응하고, 허용된 실제 앱 화면에서 캡처 후 P/F를 비교한다. 30,278건 전량을 검수 없이 학습에 넣지 않는다.
- 학습·제품 반영·커밋·push: 수행하지 않음.
