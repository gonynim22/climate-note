## 현재 결론

마지막 후보의 공백 제외 오류는 43.9% 줄었지만 `묶음→묵음/묵묶음`, `ppm→pp`가 새로 생겼다. `℃` 누락·`㎜→㏊`와 `㈜`·`₩` 오독도 남았다. 기존 메모장 캡처 48장의 전체 검출→인식→배치 회귀에서는 공백 제외 오류가 129→258, 새 비공백 오답 16건으로 증가했다. 합성 평균 개선을 업무 기호 학습 성공으로 해석할 수 없다.

후속 원본 점검에서 `ppm→pp`는 **이 문구의 10px·밀착 문장부호 조건**으로 범위를 좁혔다. 같은 크기의 `ppm ;`/문장부호 제거/띄운 `/`, 같은 원문의 12px·16px에서는 마지막 후보가 정상 판독했다. 원문 PNG/정답 손상은 확인되지 않았지만 실무 대표성이 검증되지 않은 작은 합성 조건이다. 이 사례를 모든 `ppm` 인식 문제나 실제 업무 오류율로 일반화하지 않는다. 아래 문장부호 대조 기록을 따른다.

## 결정과 진행

- 2026-10-11: 사용자가 계획 실행을 승인했다. 총괄이 공용 연결/문서/검증을 소유하고 학습·자료·평가 3개 에이전트가 전용 경로를 병렬 구현한다. GPU는 학습 담당 한 작업만 사용한다. 통합 하네스/CPU 성능 측정은 총괄이 순차 실행한다.
- 최초 데이터는 직접 만든 업무 문구와 새 합성 이미지다. 최종 실제 업무 성능은 사람 정답 검토와 새 실제 앱 자료가 확보되기 전에는 완료로 주장하지 않는다. 그 전에도 환경·도구·합성 자료·학습 실험은 진행한다.
- `karpathy-guidelines`의 변경 범위 제한·명시적인 성공 조건을 적용한다. 학습·대량 평가를 통상 테스트/빌드에 연결하지 않는다.
- 첫 pilot은 `output/screen_text_lab/training_data/pilot-20261011-140803-7188648e/`이며 아래 보강 버전으로 대체했다. 학습 400장(80문구/20작성 가족), 선택 100장(20문구/12작성 가족), 본문/표 셀/숫자·단위/메모 비중은 35/35/25/5다. 이 첫 버전의 현재 사전 A 학습은 340장이었고 OOV 60장의 원문은 보존했다. 선택 평가에는 OOV를 포함한 100장 전체를 쓴다. 사전 확장 B에는 전체 원문을 사용한다.
- 이 pilot은 합성 줄 crop이며 실제 한글·PDF·Word·메모장 캡처가 아니다. 6,000/1,000장과 독립 가족 수 목표·실제 앱/DPI·사람 정답 검토는 미달 상태다. 숫자 치환이나 배율만 바꿔 독립 원문 목표를 채우지 않는다.
- 최초 생성 버전에서 기존 공개 합성 문구와 유사한 2개 원문을 검출했다. 실패 버전을 보존하고 새 문구로 새 버전을 만들었다. 정본은 원본/crop 픽셀 왕복·분할/기존 공개 자료 중복·글리프/잘림/길이·모든 실제 사용 폭의 제품 CTC 단계 검사를 통과했다. loader 검증은 학습 단계에서 별도로 한다.
- 제품 P의 선택 100줄 기준: 공백 포함 186/3,460 글자 오류, 공백 제외 57/2,640 글자 오류, 완전 일치 41/100줄(공백 제외 82/100줄). 공백 포함 오답 59줄 모두 현재 평균점수 0.80 경고가 없었다. 이는 합성 단일 줄 진단이며 실제 전체 화면의 정확도/경고/표 구조 수치가 아니다.
- 공식 학습 가중치는 968개 키/shape가 맞았고 CPU·GTX 1650 GPU 고정 입력 실행에 성공했다. Paddle 재수출은 첫 실행의 이름 중복 오류 후 새 프로세스에서 성공했다. PaddleGPU 3.2.2와 Paddle2ONNX 2.1.0의 DLL procedure 오류는 실제 확인한 실패이며, 공식 권장 계열 Paddle 3.0.0 변환 전용 환경을 분리해 해결 중이다.
- B의 추가 21기호 중 6기호가 학습 문구에 없어 train의 숫자·단위 6문구를 보강한 새 정본 `pilot-20261011-141312-9287d44d`를 동결했다. 이전 버전은 보존한다. 400/100장 및 분류 비중을 유지하며 A는 325/90장, B는 400/100장이다. 선택 100장의 원본/PNG/좌표/정답/태그/군집과 라벨 해시는 이전과 동일하다(`revision-comparison.json`). 새 manifest로 제품 P를 다시 실행해 100개 출력/채점이 이전과 모두 같음을 확인했다.
- 실제 앱 경로 확인: 설치 등록상 Word/한글/메모장/Edge가 있으며 Computer Use의 반환 앱 목록에서도 한글 2022/Word를 확인했다. 자체 작성 `office-probe.txt`를 준비했지만 `sky.launch_app`의 한글 2022 실행이 자동 승인 검토에서 `Computer Use was not approved to use 한글 2022`로 거부됐다. 앱 조작을 중단했고 다른 자동화로 우회하지 않았다. 실제 문서 열기/캡처/OCR 0회다. 이 제한은 GPU 학습·파일 평가와 독립적이다.
- 원본 재현 확정: Python 3.12/PaddleGPU 3.2.2 학습 환경과 PaddleCPU 3.1.0/Paddle2ONNX 2.1.0 변환 환경을 분리했다. 변환은 `optimize_tool=None`으로 명시해 자동 의존성 설치가 없는 깨끗한 환경에서 수행했다. 앞선 자동 설치가 발생한 개발 환경은 실패 증거로 보존했다. R ONNX는 13,421,069바이트다. 21종 고정 tensor의 P/R 수치·실제 글자·기존 0.80 경고 비교가 통과했고 P→R ONNX 최대 절대 차는 약 `3.80e-5`다.
- 별도 선택 100줄에서 P→R은 공백 포함 오류 186→186, 공백 제외 57→57, 완전 일치 41→41, 신규 오답 0이다. 원본 재현 성공은 학습 개선이나 전체 화면 제품 적합성 통과를 뜻하지 않는다.
- A 325줄은 실제 공식 `MultiLabelEncode`에서 누락 없이 통과했다. NRTR 설정 66에서 64자 허용/65자 거부를 실제 확인했다. B 모델의 NRTR 출력은 문자 encoder 수 외에 추가 1행이 있어 실제 원본 11,951행이다. 사전 ID 표(공백 포함 11,950토큰)와 모델 행 수를 구분해 확장 시 추가 행도 보존한다.
- 실제 학습에서 추가 제약 발견: 공식 `PPLCNetV3.forward()`는 train일 때 마지막 특징을 `[1,40]`으로 압축하므로 긴 라벨의 CTC 길이가 부족했다. 제품/고정 공식 소스는 보존하고 lab에서 이 train pooling만 제품 eval의 `avg_pool2d([3,2])`와 같게 적용한다. BN/train 상태와 파라미터 구조는 유지하며 eval 동등성·실효 CTC 길이를 검사한다. 기존 추론 단계 측정만으로 학습 가능하다고 판정하지 않는다.
- A smoke(`smoke-a-batch4-v3`) 50 step/200노출: 첫 최대폭 1,408의 forward/backward 2.96초, 총 54.6초, 중앙 step 0.825초, 최대 GPU 할당 3,873,217,792바이트(약 3.61GiB). 유한한 손실/기울기/파라미터·CTC 가중치 갱신·새 모델/Adam 객체의 저장 상태 동일 복구·CPU/GPU 복원 eval 대조에 통과했다. 정확한 중단 지점의 global step/샘플 순서/RNG까지 이어가는 resume은 아직 미지원이며 이번 pilot은 매번 원본에서 시작한다.
- 실제 앱 실행/캡처는 자동 승인 거부 사유를 설명하고 사용자에게 별도로 확인을 요청했다. 명시 답변 전에는 해당 앱 조작을 재시도하지 않으며 독립적인 학습·파일 평가는 진행한다.
- 원본에서 각각 시작하는 A/B × 학습률 `1e-5`/`5e-5`의 5 epoch pilot 4회를 순차 실행한다. A는 325줄/410 step, B는 400줄/500 step이며 조건 내 seed·학습 순서·노출 수를 고정한다. A 첫 실행 180/410 step까지 유한 손실로 진행했으며 최대 GPU 할당은 약 3.75GiB다. 이 값은 앞선 smoke의 3.61GiB와 별도 측정이다.
- 사전 확장 전후 차이는 학습하지 않은 B 초기 모델 `R_B`를 별도 평가해 구분한다. 기존 클래스뿐 아니라 사전에 없지만 softmax/label smoothing에 참여하는 NRTR 끝 클래스도 대응 위치로 복사한다. 새 클래스 초기화만으로 생긴 변화와 실제 학습 효과를 혼합하지 않는다.
- 종전 공개 실제 dev 48장은 24개 원문 묶음의 메모장/CLI 회귀이며 표 정답이 없다. 새 후보의 검출→인식→배치 회귀에만 사용할 수 있고 이번 업무 문서·표 목표의 최종 증거로 쓰지 않는다. 보류 12장에는 접근하지 않는다.
- P 기준선의 분류별 공백 제외 오류는 본문 4/1,380, 표 셀 3/595, 숫자·단위 50/610, 메모 0/55다. 숫자 분류 25장에서는 숫자열 자체 변경은 관측되지 않았지만 `₩→#`, `℃→C`, `㈜→(주)`, `㎜→mm` 등 기호 오류가 있었다. 전체 100장의 평균 CTC 점수는 0.836~0.994로 기존 0.80 경고가 모두 비활성이었다. 평균 점수를 정답 확률로 해석하지 않는다. 본문/표 셀의 비공백 오독은 10px 작은 글씨에 집중됐다.
- 에이전트 교차 검토로 crop runner의 요청 파일 전후 해시·반환 정답/군집/이미지 식별자·재채점 일치 검사를 추가한다. R/F 후보 등록은 출처 문자열만으로 신뢰하지 않고 실제 재현/변환 보고서와 연결 파일의 해시를 검사하도록 보강한다.
- 해당 보강 후 P/R_A/R_B를 같은 선택 100줄로 실행했다. 미학습 사전 확장 R_B도 P와 출력/오류/완전 일치가 같고 새 오답은 0이다. 이는 새 기호를 배웠다는 뜻이 아니라 초기화로 기존 결과가 달라지지 않았다는 관측이다.
- 첫 A `1e-5` 5 epoch는 410 step/1,625회 노출·365.3초로 완료했고 모델/Adam 복원과 출처 전후 검사를 통과했다. 그러나 선택 자료 strict 오류 186→428, 공백 제외 57→283, 완전 일치 41→14, 새 strict 오답 32건으로 **품질 실패**했다. 공백 제외 새 오답은 58조건/16원문/9작성 가족, 복구 0이며 삭제 오류가 3→222로 급증했다. 기준 크기에서도 `117개→17개`, 낮은 대비에서 `16:15→6:15` 등 실제 값 손실이 있었다. 이 후보는 제품 반영 대상에서 제외한다.

## 미해결과 인계

### 2026-10-11 후속: ppm·묶음 동일 입력 재실행

- 사용자 요청: 가장 나았던 B `5e-5`·BN 통계 고정 후보에서 `ppm`과 `묶음`이 다시 같은 방식으로 틀리는지 확인한다. 재학습/보정 없이 같은 모델·사전·이미지·CPU 4 threads·제품 줄 전처리/CTC/0.80 경고를 사용했다.
