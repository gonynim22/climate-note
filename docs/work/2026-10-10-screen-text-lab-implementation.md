## 결정과 진행

- 2026-10-10: 사용자 지시에 따라 첫 구현 묶음에 착수. karpathy-guidelines와 frontend-design 지침을 적용한다. 제품·공용 verify 실행 경로는 변경하지 않는다.
- 첫 버전은 `generate`, `validate`, `run`, `compare`와 bootstrap/standard 자료 선택을 제공한다. 대량 stress 생성 및 단계별 원인 관측은 계획의 후속 단계로 남긴다.
- 첫 실제 모델 실행에서는 부모가 진행 파일을 읽는 동안 worker의 원자적 교체가 Windows `PermissionError`로 실패했다. 완료 7개와 미실행 93개를 보존했다. 진행 상태를 append JSONL로 바꾸고, 읽는 중의 미완성 JSON/UTF-8 행만 기다리도록 수정했다. 전체 행의 손상은 오류로 처리하며 동시 읽기/쓰기 회귀를 추가했다.
- 텍스트가 맞아도 표 구조가 다르면 사례를 오류로 표시한다. 문자열 완전 일치와 표 포함 일치를 별도 필드로 남기고 무경고 오류에도 표 오류를 포함한다.
- 실제 입력 변경 검사는 엔진/layout·모델·경로 처리·공유 실행 도구·진단 코드/재료/자체 검사·의존성에 적용한다. 무관한 캘린더 UI 작업은 실험 입력에서 제외하되 Git HEAD와 dirty 상태는 기록한다.
- 개발 중 다른 작업이 `ui_main.py`·설정·위젯과 UI 테스트를 변경했다. 원래 폴더의 full에서 UI 검사 1건 실패와 `inputs_changed`가 발생하여 성공 근거로 쓰지 않는다. `HEAD 2b17cee`의 분리 worktree `output/screen-text-lab-verification-20261010/`에 이번 도구/자체 검사/안내만 복사하고 동일 원본 `.venv` Python으로 full을 실행한다. 다른 작업의 변경을 되돌리지 않는다.
- 최종 합성 자료: `output/screen_text_lab/corpus/20261010-210941-0be5f524/`. 100개 화면, 원본 그룹 82개, 모두 개발용 합성이다. 같은 양식에서 숫자가 바뀐 표는 각 양식별 한 그룹으로 묶었다. 실제 프로그램 캡처나 보류 자료는 포함하지 않는다.
- 최종 기준/반복 실행은 각 100/100 처리·채점, 문자열 완전 일치 41/100, 공백 포함 CER 149/3003 = 약 4.96%, 무경고 오류 58/59였다. 두 실행의 문자열·표·경고가 100개 모두 동일했다. 합성 결과를 전체 업무 정확도로 일반화하지 않는다. 실행 시간은 다른 격리 검사도 진행되던 개발 PC에서 1회씩 측정한 관측값이며 성능 비교 근거로 삼지 않는다.
- 10개 사례는 어댑터와 별도로 실제 `OcrEngine.recognize()`와 제품 layout/복사 함수를 호출해 글자·좌표·TSV·HTML·경고를 대조했다. 보고서 303페이지의 로컬 참조 2,121개와 외부 참조 0개, JavaScript 문법을 검사했다. 합성 CLI/표 PNG는 직접 열어 글자와 여백을 확인했다.
- 격리 worktree의 최종 full은 1,906개 통과·실패 0·skip 0이다. 기존 qfluentwidgets/scipy DeprecationWarning 1건이 있으며 진단 도구 실패가 아니다. 현재 폴더와 격리본의 진단 코드/재료/자체 검사 13개 파일 해시가 모두 같다. 실제 명령·입력 해시·검증 범위는 아래 실행 증거를 따른다.

## 미해결과 인계

- 실제 원본 수집, 원본 약 1,000개 확대, 단계별 진단과 혼합 DPI는 후속 범위다.
- 브라우저에서 보고서를 직접 열어 필터·확대·좁은 화면을 확인해야 한다. 정적 검사와 소스 PNG 확인만으로 화면 배치를 확인했다고 하지 않는다.
- 정본 문서: [사용법](../SCREEN_TEXT_LAB.md), [검증](../TESTING.md), [화면 글자 따기](../SCREEN_TEXT.md).
- 격리 worktree와 모든 실패/완료 실행 결과는 출력 폴더에 보존했다. 사용자의 기존 수정·제품 엔진·모델·lock·빌드 설정을 변경하지 않았다.
- 배포·커밋·push: 수행하지 않음.
