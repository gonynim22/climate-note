## 결정과 진행

- 기존 release 3,095개 통과는 기준 증거다. 이번 검토는 검사 목록 밖의 경계·실패 경로를 코드로 확인하고 필요한 재현을 추가한다. 사용자 '다 좋아'는 사용상 긍정 피드백으로 기록하되 개별 실기 검사의 세부 증거를 임의로 통과 처리하지 않는다.

### 확인한 결함

1. **P1 — 잘못된 위젯 좌표/크기 Import 뒤 시작 실패**. 가져오기 사전검증은 SQLite int64만 검사해 `x_pos=2147483648`을 허용했다. Import 커밋 후 `MainCalendarWindow → _load_open_sticky_notes → StickyNoteWindow.setGeometry`에서 `OverflowError`가 발생한다. 본문은 남지만 같은 데이터로 시작할 수 없다. 합성 재현 `output/harness/20261027-review-geometry/reproduce.py`와 `result.json`에 경로를 남겼다. Qt int32 밖의 위치/크기를 전체 쓰기 전에 거절하도록 수정했다. 기존 DB/salt를 보정하거나 삭제하지 않는다. 이미 외부에서 잘못 저장된 DB의 자동 복구는 추가하지 않았다.
2. **P2 — 일시 DB 조회 실패 때 일정 알림 누락**. 조회 예외를 빈 목록으로 바꿔 마지막 확인 시각이 앞으로 이동하고, 다시 알림은 확인 전에 목록에서 제거했다. 정상화 후에도 그 알림을 건너뛸 수 있다. 조회 실패를 전파해 확인 경계에서 기록·재예약하고 모든 조회 성공 후 상태를 반영하도록 수정했다. 여러 다시 알림 중 뒤 항목 조회만 실패해도 앞 항목을 보존한다. 기존 최대 12시간 조회·메모리 전용 다시 알림 계약은 유지한다.

두 결함 모두 v4.5 변경 이전부터 존재한 경로에서 발견했으며, v4.5 검토본에도 적용된다. 데이터 삭제/암호문 손실은 재현되지 않았다. P1/P2는 이번 검토의 우선순위 판단이다.

P2 추가 경로: 시작 때 `schedule_alarm_seen_at` 읽기가 실패하면 키 없음으로 처리해 놓친 알림을 잃었다. `output/harness/20261027-review-alarm-start/result.json`에서 저장 시각 09:58·알림 09:59·시작 09:59:59 조건으로 재현했다(예상 1건, 실제 0건). 초기 기준 조회도 성공할 때까지 재시도하며, 키가 실제로 없을 때는 최초 시작 시각을 보존한다. 이 확인 때문에 진행 중 release를 에이전트가 중단했으며 해당 실행은 통과로 쓰지 않는다.
