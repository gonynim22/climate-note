## 결정과 진행

### 구현 착수 시 확정 범위

- 사용자가 계획 완료 후 구현·빌드·AGENTS 갱신·커밋을 요청했다. 수질 밀도 환산, 온도차 모드, 기체 농도의 질량/부피 환산과 전체 분류의 기준 표시를 v3.8a에 포함한다. 아래 초기 계획/후보 검토는 이 결정으로 구체화한다.
- 수질에 ppm/ppb, 기체에 mg/m³/µg/m³를 추가해 25분류·182항목으로 한다. 기준 상태 유량·압력 기준 전환은 이번 추가 계산 범위에서 제외하고 현재 환산 기준을 표시한다.
- 기체는 몰분율 기본 ppm↔ppb를 유지한다. 질량 농도 선택 때 물질 선택(6종+몰질량 직접 입력)을 표시하며, 선택 전에는 교차 환산 결과를 내지 않는다. 기본 25°C·101.325kPa(절대압)를 명시하고 온도/압력 입력은 접어 둔다. 이상기체 가정을 결과/기준 설명에 표시한다.
- 기체 공식은 `mg/m³ = 몰분율 × P(Pa) × M(g/mol) × 1000 / (R × T(K))`, R=8.31446261815324이며 T>0K, P>0, M>0을 검증한다. 같은 기준의 단위 변환은 기체 조건 없이 가능하다.
- 온도값/온도차는 기존 온도 분류의 두 가지 모드다. 온도차는 오프셋 없이 배율만 적용하고 음수·0도 허용한다. 모든 조건과 모드는 최근 12개 기록에 포함하고 메모리에서만 유지한다.

### 0. 전체 단위의 조건 검토 — 사용자 후속 질문 반영

수질만 예외적인 것이 아니다. 현재 코드의 25분류 전체를 확인했으며, 아래 항목은 서로 다른 종류의 문제다. 추가 숫자가 필요한 계산, 정의를 선택하는 계산, 별도 모델이 필요한 계산을 같은 설정 화면으로 합치지 않는다.

| 현재 분류 | 확인한 기준·혼동 가능성 | 계획상 대응 |

| 길이 | 리는 척관법 36정, 광년은 율리우스년 기준 | 선택한 단위 이름/설명으로 기준 전달 |
| 무게 | 현재 계산은 질량, 근은 600g·온스는 상용질량 | 단위 정의 표시, kg↔N을 같은 환산으로 혼합하지 않음 |
| 부피 | US liquid 갤런, 석유 배럴, 척관법 되/말 | 단위 선택에서 정의 확인 |
| 넓이·속도·각도·조도 | 현재 채택한 단위끼리는 고정 배율 | 추가 조건 입력 없이 유지 |
| 온도 | 온도값과 온도차는 다름 | 온도값/온도차 선택 추가. 온도차에는 절대영도 제한을 적용하지 않음 |
| 시간 | 개월=30일·년=365일은 고정 기간이고 실제 달력 계산과 다름 | 고정 기간 기준 유지·표시, 시작 날짜 입력은 별도 기능 |

수질 밀도 환산·온도차 모드·기체 질량 농도를 v3.8a에 포함했다. 기준 상태 유량은 후속 후보로 남긴다. 나머지는 현재 정의와 선택 단위가 눈에 보이도록 개선했다. 초기 수질 전용 계획의 180항목에서 최종 182항목으로 확정했다.

공통 UI 원칙:

- 고정 정의의 차이는 단위 이름/선택에 담는다. 이미 US/UK 갤런이나 200/240mL 컵을 고를 수 있는 곳에 중복 설정을 만들지 않는다.
- 온도값/온도차처럼 계산 의미가 달라지는 항목은 짧은 모드 선택을 사용한다.
- 밀도·몰질량·온도·압력처럼 결과를 바꾸는 조건은 해당 환산을 선택했을 때만 입력을 제공하고 적용값은 접힌 상태에서도 보인다.
- 기본값을 합리적으로 정할 수 있는 조건은 명시한 기본값으로 시작한다. 기체의 물질/몰질량처럼 임의로 정하면 다른 물질의 결과가 되는 값은 명시적 선택을 받는다.
- 원리 설명은 펼쳐 읽게 하고 현재 적용 조건과 선택하지 않은 필수 값은 숨기지 않는다.

### 1. 기본 사용 흐름

- 수질 농도를 처음 고르면 입력 단위 ppm, 결과 단위 mg/L를 기본값으로 한다. 기존 mg/L·µg/L·ng/L·g/L·mg/mL·kg/m³·g/m³ 선택도 유지한다.
- 별도 확인창 없이 용액 밀도 1 kg/L를 명시적으로 적용한다. 접힌 조건 줄은 `물 기준 · 밀도 1 kg/L`와 `밀도 설정` 버튼으로 구성한다.
- 물 기준을 적용하는 질량분율↔질량/부피 결과에는 `≈`를 붙인다. 예: `10 ppm → ≈ 10 mg/L`. ppm↔ppb, mg/L↔µg/L처럼 밀도와 무관한 환산에는 이 근사 표식을 붙이지 않는다. 표시 문자는 계산 원본에 섞지 않는다.
- 정확한 안내는 `환산 기준 ⓘ`를 클릭하거나 키보드로 열어 읽을 수 있게 한다. 툴팁만으로 필수 조건을 전달하지 않는다.

### 2. 필요한 경우에만 밀도 수정

- `밀도 설정`을 누르면 같은 화면에서 숫자 입력 한 줄만 펼친다: `용액 밀도 [1] kg/L`와 `물 기준 복원`.
- 밀도 단위는 kg/L 하나로 고정한다. 물질 선택·온도 입력·별도 설정창은 추가하지 않는다.
- 직접 입력한 값은 즉시 계산에 반영한다. 패널을 접어도 `직접 입력 · 1.2 kg/L`처럼 현재 조건이 보이고 값이 유지된다.
- 여기서 밀도는 용질 자체가 아닌 용액 전체의 밀도다. 이 설명과 고농도/해수 등에서 물 기준 근사가 달라질 수 있다는 설명은 펼친 영역에 둔다.
- 빈 값이나 입력 중인 소수/지수는 이전 결과를 남기지 않는다. 유효하지 않은 밀도를 수정하는 동안 수질 계산 결과·교환·기록 추가를 보류하고 입력 바로 옆에 짧게 표시한다. 밀도는 유한한 양수만 허용하며 임의의 좁은 범위를 정하지 않는다.
- 다른 분류를 다녀오거나 창을 숨겼다 열어도 세션의 밀도와 적용 방식은 유지한다. 앱 종료 및 초기화 성공 시에는 기존 메모리 상태와 함께 폐기한다.

### 3. 계산과 기록

- 수질 ppm·ppb는 질량분율로 정의한다. `mg/L = ppm × 밀도(kg/L)`, `µg/L = ppb × 밀도(kg/L)`이며 역방향은 밀도로 나눈다.
- 기존 선형 단위의 계수에 밀도 1을 고정해서 섞지 않는다. 계산 함수에는 선택적인 밀도 인자를 추가하고, 질량분율과 질량/부피 사이를 넘는 계산은 명시적 밀도 없이 실패시킨다. UI가 물 기준 1 또는 사용자의 값을 전달한다.
- 수질에서 질량분율끼리 환산할 때는 밀도와 무관하다. 기존 mg/L 계열끼리의 환산도 기존 호출/계약을 유지한다.
- 음수 농도는 거절하고 ppm 1,000,000/ppb 1,000,000,000(100%) 경계를 검증한다. 질량/부피 입력을 분율로 환산한 결과가 100%를 넘으면 해당 결과를 표시하지 않는다. 같은 기준의 기존 질량/부피 환산까지 불필요하게 차단하지 않는다.
- `다른 단위`도 같은 계산 함수를 사용한다. 모든 표시와 교환은 원래 정밀도를 유지하고 결과 표시만 6자리 유효숫자를 적용한다.
- 최근 12개에 밀도와 물 기준/직접 입력 구분을 추가한다. 중복 판정·재계산·복원에 이 조건을 포함한다. 직접 밀도를 사용한 기록은 짧은 밀도 표시와 상세 설명으로 구분한다. 기록 복원 중 임시 다른 조건으로 결과가 표시되지 않도록 조건과 단위를 함께 복원한다.

### 4. 설명과 화면 구성

- 기존 환경 분류의 긴 상단 문장을 짧은 현재 기준으로 줄인다. 기체는 `몰분율 기준`, 질량비는 `질량분율 기준`, 유량은 `실제 부피 기준`을 표시하고 정의·제약은 펼쳐 읽는 설명에 둔다.
- 수질은 현재 밀도와 적용 방식이 항상 드러나게 한다. 사용자가 바꾸어 계산에 영향을 주는 값은 설명 속에 숨기지 않는다.
- 기존 창 크기·입력/결과 카드·교환·다른 단위·최근 기록 순서를 유지한다. 조건을 펼칠 때 추가 공간은 본문 스크롤로 확보하고, 패널을 접으면 기본 배치로 돌아온다.
- 구현은 수질·기체·온도 조건을 담는 작은 상태/입력 영역으로 한정한다. 범용 화학 계산 엔진이나 설정 프레임워크를 만들지 않는다.

### 5. 구현·검증 순서

1. 계산 함수와 수질 정의, 독립 기준값 검증을 추가한다. 대표값: 밀도 1에서 10 ppm→10 mg/L, 밀도 1.2에서 10 ppm→12 mg/L, 밀도 0.8에서 8 mg/L→10 ppm, 밀도 1에서 10 ppb→10 µg/L. 밀도 0/음수/NaN/무한대, 범위 초과와 부동소수점 경계도 검사한다.
2. 접는 밀도 입력과 요약/근사 표시를 적용한다. 실제 키보드/클릭으로 기본 환산·직접 입력·오류 수정·물 기준 복원·단위 교환을 확인한다.
3. 최근 기록에 조건을 연결한다. 같은 입력의 밀도 1/1.2 기록이 구별되고 당시 조건이 복원되는지 검사한다. 기존 모든 분류의 계산·메모리 수명·잠금·DB dump/Export/salt 보존도 확인한다.
4. 관련 quick와 125/150% 합성 배율 검사를 수행한다. 새 기능의 상태별 렌더를 직접 검토하고 작은 화면에서 조건 입력/결과가 가려지지 않는지 확인한다.
5. 버전을 `app_info.py`의 v3.8a로 바꾸고 출시일은 실제 릴리스 준비일에 맞춘다. 기존 버전 변환 규칙으로 Windows 버전은 3.8.1.0, EXE는 `기후노트_v3.8a.exe`가 된다. 정본 계약을 갱신한 뒤 release로 전체 검사·신규 빌드·격리 3개 시나리오를 수행한다.
6. 실제 EXE의 코드/리소스·Qt DLL·버전·해시를 대조하고 산출물과 수동 미확인을 남긴다. 기존 사용자 변경을 제외한 구현/문서를 커밋하며 EXE/output은 포함하지 않는다. 원격 push/게시는 별도다.

계획한 명령:

```powershell
.\.venv\Scripts\python.exe tools/verify.py quick --tests tests/test_unit_converter.py tests/test_ui_unit_converter.py tests/test_ui_mini_apps.py tests/test_packaging.py
.\.venv\Scripts\python.exe tools/verify.py release
```

### 근거와 정본 반영 대상

- [EPA 농도 단위 설명](https://archive.epa.gov/epawaste/hazard/testmethods/web/html/faqs_data.html): 질량 ppm=mg/kg, 일반 수용액에서는 1L≈1kg를 가정한다. 이 정의에서 위 밀도 환산식을 도출한다.
- [USGS 지침](https://water.usgs.gov/water-resources/memos/memo.php?id=992)은 부유 퇴적물 혼합물에 관한 밀도 보정 지침이다. 그 특정 혼합물의 보정 계수를 일반 용액의 계수로 가져오지 않는다.
- [단위 계약](../UNIT_CONVERSION.md), [UI 계약](../UI_PATTERNS.md), [아키텍처](../ARCHITECTURE.md), [검증](../TESTING.md), [릴리스 이력](../RELEASE_HISTORY.md), [AGENTS](../../AGENTS.md)를 구현된 동작에 맞춰 갱신했다. ppm↔mg/L 금지는 명시적 조건을 받는 계산으로 확장하며 무조건 1:1 등식을 도입하지 않는다.
