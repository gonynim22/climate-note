# 작업 기록: 미니앱 버튼과 주머니 구현 계획

작성일: 2026-09-20 / 상태: 계획 당시 구현 미착수

후속 구현·검증·커밋·빌드는 [미니앱 작업 기록](2026-09-20-mini-app-pocket.md)을 따른다.

## 목표와 범위

- 사이드바 최상단에 `미니앱` 버튼을 추가하고 기존 바로가기 6개를 아래로 배치한다.
- 버튼을 누르면 개발자가 제공하는 미니앱 목록을 담을 작은 주머니 팝업을 연다. 이번에는 빈 상태까지 구현하고 단위 환산기는 후속 요구사항으로 다룬다.
- 이번 턴의 변경 대상은 이 계획 문서뿐이다. 제품 코드·DB·실사용 데이터·EXE는 변경하지 않는다.
- 구현 시 예상 대상: `ui_main.py`, 새 `ui_mini_apps.py`, 관련 UI 테스트, `docs/UI_PATTERNS.md`·`docs/ARCHITECTURE.md`·`docs/TESTING.md`·`AGENTS.md`.
- 데이터 영향: 바로가기 `id=1..6`과 이름·경로·순서를 유지한다. 새 DB 테이블/컬럼/설정 키, 마이그레이션, DB 버전·Export 버전·salt·암호화 변경은 필요 없다.
- 시작 시 기존 사용자 변경: `.gitignore`, `AGENTS.md`, `docs/RELEASE_HISTORY.md`, 미추적 작업 기록 `2026-09-11-local-security-audit.md`, `2026-09-11-v3.7a-version.md`, `2026-09-17-release-status-docs.md`. 그대로 보존한다.
- 제외 범위: 단위 환산 로직, 사용자 앱 등록/설치/삭제, 외부 EXE·스크립트 로딩, 다운로드/업데이트, 범용 플러그인 시스템, 버전 갱신, 이번 턴의 커밋·빌드·push.

## 확인한 현재 구조

- `ShortcutSidebarWidget`은 폭 80px, 좌우 여백 8px, 상하 여백 16px, 항목 간격 10px다. 현재 `바로가기` 제목 아래 6개 `ShortcutSlot`을 둔다.
- 슬롯은 64×82px이며 그 안의 클릭 버튼은 64×64px다. 슬롯은 배열 위치와 DB ID 1~6에 연결되어 있으므로 미니앱 버튼을 이 배열에 넣거나 ID를 재배정하면 안 된다.
- compact는 보통 높이 660px이며 저장된 `show_sidebar` 설정을 따른다. medium/large는 사이드바를 항상 표시한다. 작은 작업 영역/medium에서는 세로 여유가 더 적을 수 있다.
- 팝업은 잠금·트레이·보기 변경 때 정리해야 한다. 진행 중인 일정 인라인 편집의 저장 실패는 새 UI 열기를 보류하고 편집 원본을 유지해야 한다.

## 제안할 화면과 동작

1. **사이드바**
   - 맨 위에 폭 64px·높이 48px를 시작값으로 잡은 `미니앱` 버튼을 둔다. 단순한 테두리형 앱 격자 아이콘과 `미니앱` 텍스트를 함께 표시한다.
   - 기존 남색/블루 계열의 옅은 채움과 실선 테두리를 사용한다. 열려 있는 상태는 테두리와 배경으로 표시한다.
   - 아래에 짧은 구분선과 기존 `바로가기` 제목, 기존 슬롯 6개를 순서대로 둔다. 기존 64×64px 클릭 크기를 유지하고 간격을 약 6px로 줄여 기본 660px에서 6개 모두 보이도록 렌더로 조정한다.
   - 짧은 작업 영역에서는 미니앱 버튼을 고정하고 바로가기 목록에만 세로 스크롤을 제공한다. 사이드바 폭 80px와 본체 크기 계산을 유지하며 가로 잘림/가로 스크롤은 허용하지 않는다.
   - compact에서 사용자가 사이드바를 숨겨 두었다면 미니앱 버튼도 함께 숨긴다. 사용자 표시 설정을 자동으로 켜지 않는다.

2. **미니앱 주머니**
   - 버튼 오른쪽에 붙는 작은 비모달 팝업을 추천한다. 초기 목표 크기는 약 300×220px이며 불투명 흰 배경, 얇은 테두리, 둥근 모서리로 기존 앱과 맞춘다.
   - 제목 `미니앱`, 닫기 버튼, 빈 상태 문구 `미니앱을 준비하고 있어요.`를 표시한다. 단위 환산기 타일은 아직 넣지 않는다.
   - 클릭하면 열고, 같은 버튼 재클릭·바깥 클릭·Esc·닫기 버튼으로 닫는다. 동시에 하나만 존재하도록 관리한다.
   - 버튼의 실제 화면 좌표와 해당 모니터 작업 영역으로 위치를 계산한다. 오른쪽 공간이 부족하면 왼쪽으로 펼치고, 여전히 부족하면 화면 안으로 보정한다.
   - Tab → Enter/Space로 열 수 있고 닫은 뒤 유효한 이전 포커스로 돌아간다. 잠금·트레이 전환 뒤에는 포커스를 복원하거나 팝업을 다시 띄우지 않는다.

3. **입력과 창 수명**
   - 주머니를 열기 전 진행 중인 일정 인라인 편집은 기존 `_save_schedule_edit()` 성공 여부를 확인한다. 실패하면 팝업을 열지 않고 편집을 보존한다. 새 일정 입력칸의 미등록 초안도 유지한다.
   - PIN 잠금·트레이 숨김·사이드바 숨김·크기/화면 변경·데이터 초기화·앱 종료 때 팝업을 닫고 참조를 정리한다. 잠금/숨김 상태에서는 새로 열지 않는다.
   - 주머니 열림 상태는 저장하지 않는다. 앱을 다시 시작하면 닫혀 있다.

## 구현 순서와 완료 조건

1. `ui_mini_apps.py`에 빈 주머니 UI와 닫기/위치 계산만 분리한다. 이 모듈은 DB에 접근하지 않는다. 단위 환산기용 공통 실행 규약이나 플러그인 로더는 지금 만들지 않는다.
2. `ShortcutSidebarWidget` 최상단에 버튼과 열기 요청 신호를 추가한다. `self.slots`는 기존 6개 슬롯만 유지하고 등록/삭제/드롭 동작은 재사용한다.
3. `MainCalendarWindow`에서 팝업 하나를 소유하고 열기 가드·편집 저장 게이트·닫기·잠금/트레이/레이아웃 변경 정리를 연결한다.
4. 관련 테스트와 합성 렌더로 확인한 뒤 UI 계약/아키텍처/검증 문서와 AGENTS.md에 확정된 동작을 기록한다. 영구 계약은 구현 이후 정본 문서에 반영한다.

- [x] 현재 코드·관련 UI/데이터/검증 계약 확인 및 계획 작성.
- [ ] 기본 660px에서 미니앱 버튼과 기존 바로가기 6개 표시, 짧은 작업 영역에서도 전부 접근 가능.
- [ ] 세 크기·100/125/150% 합성 배율에서 겹침/잘림 없는 배치와 주머니 렌더.
- [ ] 실제 마우스/키보드 열기·닫기·재클릭·바깥 클릭·반복 열기와 화면 가장자리 위치 보정.
- [ ] 잠금/트레이/사이드바 숨김/보기 변경/초기화 뒤 팝업이나 지연 포커스가 남지 않음.
- [ ] 편집 저장 실패 시 원본 유지·주머니 열기 보류, 미등록 일정 초안 보존.
- [ ] 합성 데이터의 기존 6개 바로가기 ID/이름/경로/순서와 등록/실행/이름 변경/경로 복구/삭제/드롭 회귀 통과.
- [ ] 편집 중이 아닌 상태에서 반복 열기/닫기 전후 DB 행·암호문·설정·salt 불변. Export/Import 기존 계약 유지.

## 검증 계획과 현재 증거

구현 후 기본 검사:

```powershell
.\.venv\Scripts\python.exe tools/verify.py quick --tests tests/test_ui_mini_apps.py tests/test_ui.py tests/test_ui_data_lifecycle.py tests/test_ui_schedule_emoji.py tests/test_ui_calendar_move.py tests/test_ui_screen_change.py
```

- `tests/test_ui_mini_apps.py`는 구현 시 추가한다. 관련 기존 테스트 파일은 현재 저장소에서 확인했다.
- 배율별 검사는 새 UI의 배치/포커스 대상에 한정해 별도 실행하고 PNG를 남긴다. 기존 데이터는 실행별 `output/harness/` 아래의 합성 fixture로만 검증한다.
- 구현/검사 범위가 저장 로직까지 넓어지면 `data`를 추가한다. EXE 빌드까지 진행하는 단계에서는 `release`로 전체 pytest와 새 EXE 3개 격리 시나리오를 검증하며 `full`을 중복 실행하지 않는다.

| 범위 | 현재 상태 | 실행 ID / 결과 | 유의사항 |
|---|---|---|---|
| 현재 사이드바/DB/잠금/설정 계약 확인 | 완료 | 소스와 정본 문서 읽기 | 현재 코드 기준 계획이며 실행 검사 아님 |
| 계획 문서의 링크·대상 파일·범위 확인 | 완료 | 해당 없음 | 제품 코드 변경 없음 |
| UI 자동 검사·합성 렌더·EXE | 미실행 | 해당 없음 | 구현 전 계획 단계; 이전 775개 결과를 이번 기능 근거로 재사용하지 않음 |
| 실제 혼합 DPI/KVM/Win+D | 미실행 | 해당 없음 | 후속 구현의 수동 확인과 구분 |

## 미해결과 인계

- 단위 환산기의 항목·계산 방식·화면·저장 필요 여부는 사용자 후속 명세를 기다린다. 이번 버튼/빈 주머니 구현을 막는 조건은 아니다.
- 64×48px 버튼과 300×220px 팝업은 제안 시작값이다. 기존 UI에서 렌더해 실제 글자/여백을 보고 조정한다.
- 변경한 정본 문서: 없음. 제품 구현·커밋·빌드·push: 수행하지 않음.
