## 목표와 범위

- 목표: 공휴일 첫날 3일 전부터 마지막 날까지 캘린더 머리줄·오늘 칸·D-Day 커버·스티키 머리띠·집중 위젯 바탕을 공휴일 색과 장식으로 자동 전환한다. 대상은 13개 공휴일(대체공휴일 포함)이다.
- 변경 대상: 새 `src/holiday_theme.py`(판정·색표), `src/ui_main.py`·위젯·설정창의 화면 연결(Task 2 이후), `tests/test_holiday_theme.py` 등. 세부는 구현 계획을 따른다.
- 데이터 영향: 없음. 테마는 화면 전용이며 유일한 쓰기는 설정 스위치의 `app_settings` 키 `holiday_theme_enabled`(`"1"`/`"0"`, 키가 없으면 켜짐)다. DB v19·Export v4·salt·암호문·기존 설정 키·D-Day 저장색·스티키 색과 본문은 바꾸지 않는다.
- 제외 범위: 음력·공휴일 계산(날짜는 `holidays.KOREAN_HOLIDAYS`만 사용), A안(남색 유지 + 가장자리 장식), 설정창 크기 변경(800×560 유지).
- 시작 시 사용자 변경: `docs/work/` 아래 추적되지 않은 기록 15개와 `motion/` 폴더가 이미 있었다. 이번 작업에서 건드리지 않았고 커밋에도 넣지 않았다.

- 2026-11-01: Task 3 완료 — 컨트롤러 `src/ui_holiday_theme.py`(`HolidayThemeController`)와 메인 캘린더 연결(`ui_main.py`), `tests/test_ui_holiday_theme_calendar.py`. 확정 사항:
  - 컨트롤러는 `holiday_theme.current_match()`를 모듈 속성으로 부르고, `(key, 첫날, 마지막 날, in_holiday)`가 달라질 때만 `themeChanged`를 보낸다. 설정 스위치는 읽기만 하며(키 없음=켜짐) 설정을 읽지 못하면(`sqlite3.Error`·`OSError`) 화면을 그대로 두고 경고만 남긴다. `set_paused`/`pausedChanged`/`is_paused`는 만들었지만 아직 아무도 부르지 않는다(Task 6이 잠금/해제에 연결).
  - 컨트롤러는 `_build_ui()` 앞에서 만들고(달력을 처음 그릴 때 `match()`를 읽는다) 첫 `refresh()`는 화면을 다 만든 뒤에 한다. 테마가 없는 평소 시작에서는 신호가 나가지 않아 달력을 다시 그리지 않는다.
  - `_apply_holiday_theme(match)`는 머리줄 스타일(`header_section_qss`)·인사말·달력 다시 그리기까지다. 달력은 칸을 만들 때 오늘 색·공휴일 바탕·점을 정하므로 `_refresh_calendar()`로 다시 그린다. Task 4~6이 같은 메서드에 위젯 전달을 더한다. 메뉴 hover 남색과 선택 칸 `rgba(1,41,95,20)`, `ui_first_run.py`는 바꾸지 않았다.
  - 공휴일 칸은 `match.dates`에 든 날짜(오늘 제외)만 바탕 `tint`와 6×6 점(`holidayThemeDot`, 오른쪽 위 5px 안쪽, 마우스는 칸으로 통과)을 받는다. 고른 칸의 선택 바탕이 테마 바탕보다 우선하고, 오늘 칸은 오늘 색만 쓴다. 숫자 글자색(공휴일 빨강)은 그대로다.
  - 인사말은 `HolidayGreetingLabel`(`BodyLabel`)이고 공휴일 당일마다 전체 문구로 보인다(R11, 말줄임·툴팁 없음). 날짜 줄(`date_row`, 개수 라벨 바로 앞)에 들어가면 거기, 안 들어가면 숨기지 않고 바로 아래 둘째 줄(`_greeting_line`, 오른쪽 정렬)로 라벨을 옮긴다. 라벨은 하나라 `text()`는 늘 전체 문구다. 실측: 기본 크기 패널은 356px, 중간·크게는 창이 자리를 잡는 동안 300~343px(안쪽 여백 12+12)인데, 음력을 켜고 공휴일 당일에 일정이 있으면 날짜 줄 글자만으로 이미 빠듯하다(성탄 날짜 114+음력 86+공휴일명 64+개수 31+인사말 80+간격 32=407px). 판단은 `MainCalendarWindow._fit_holiday_greeting()`이 라벨 글자 폭(`sizeHint`)과 패널 폭으로 하고 (`_place_holiday_greeting`이 라벨을 옮김), 일정 패널의 크기·배치 요청 이벤트(`_SizeEventFilter`)와 테마 적용 때마다 다시 본다. 판단이 라벨 위치와 무관해 옮겨도 되돌려지지 않는다. 라벨 최소 폭은 0이고 자기 폭이 글자보다 좁으면 그리지 않아 판단이 늦는 순간에도 토막 글자가 없다. 날짜·음력·공휴일명·개수 라벨은 인사말 때문에 줄지 않는다. 문구가 없을 때(테마 없음·예고 기간·스위치 끔)는 라벨을 숨기고 날짜 줄에 두어 둘째 줄 항목이 비어 간격도 생기지 않는다(날짜 줄과 입력 줄 사이 8px 그대로). 둘째 줄은 높이 15px+간격 8px이라 일정 목록이 23px 줄어든다(실측: 기본 크기·음력 켬·성탄 당일·일정 3개에서 목록 116→93px, 세로 스크롤 막대가 나타남, 넘침 1px).
  - 테마 판정·적용 경로에는 `database` 쓰기가 없다(쓰기 함수 전부를 예외로 패치한 테스트로 확인). 날짜가 바뀌는 지점(`_check_day_rollover`·`_sync_to_today_if_changed`→`_on_today`)은 `refresh()`를 부르고, 테마가 바뀐 날에는 달력을 한 번 더 그린다(하루 한 번).
  - 에이전트 확대 확인: 합성 데이터로 기본 크기 창 그림 2장(설날 2027-02-07·성탄 2026-12-25, 음력 켬, 일정 3개)을 눈으로 보았다 — 머리줄 색, 설날 6·7·8·9일 연분홍 칸과 점, 성탄 25일 칸의 점, (초판 말줄임 방식의) 인사말. 중간·크게는 그림을 보지 않았고 머리줄 오른쪽 위 픽셀이 테마 `header`와 같음(±1)과 (초판) 인사말 폭만 6개 조합(기본·중간·크게 × 2일)에서 측정했다. 그림은 임시 폴더에 있고 커밋하지 않는다. 실제 EXE·사람 눈 확인은 수동 확인 대기.
  - 후속(컨트롤러 규정 R9·R10): `tests/conftest.py`의 `app_dir`가 `holiday_theme.current_match`를 `lambda today=None: None`으로 패치해 모든 UI 테스트가 실제 날짜와 무관하게 테마 없음으로 시작한다(테마 테스트는 이 위에 다시 패치). 실제 오늘을 성탄 공휴일로 만드는 임시 플러그인으로 확인: 패치가 있으면 `test_ui_calendar_cells.py`·`test_ui.py` 134개 통과, 패치를 빼면 `test_ui_calendar_cells.py` 5개 실패(남색 오늘 칸 검사). 인사말 규칙은 R10(모자라면 숨김)에서 R11(공휴일 당일에는 숨기지 않고 둘째 줄)로 바뀌었고, 위 항목과 새 테스트(들어가면 날짜 줄 전체 폭·안 들어가면 둘째 줄에 오른쪽 정렬 전체 폭·날짜 줄 폭 불변·일정 추가 삭제와 패널 폭에 따라 오감·공휴일 당일이 아니면 둘째 줄 없음·둘째 줄이 있어도 목록과 인라인 편집 배치 유지·토막 안 그림)로 고정했다.
