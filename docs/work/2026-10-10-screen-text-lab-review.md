# 작업 기록: 화면 글자 따기 진단 자료 등록·검토

작성일: 2026-10-10 / 상태: 등록·검토 구현 및 관련 자동 검사 완료, 실제 자료 수집은 후속

## 목표와 범위

- 목표: PNG를 여러 개 등록하고 원본과 대조해 문자/표 정답과 환경 조건을 입력하는 별도 개발 도구 창을 제공한다.
- 변경 대상: `tools/screen_text_lab/`, 관련 자체 검사, `docs/SCREEN_TEXT_LAB.md`.
- 데이터 영향: 명시적으로 선택한 시험 PNG를 새 `output/screen_text_lab/corpus/<ID>/`에 복사한다. 기존 corpus와 평가 결과는 변경하지 않는다. 앱 DB·salt·설정·실사용 AppData에 접근하지 않는다.
- 제외 범위: 자동 화면 캡처, OCR 정답 자동 채택, 제품 엔진/모델 개선, 1,000개 자료 확보, 빌드·배포.
- 시작 시 사용자 변경: AGENTS·제품 UI·관련 검사·다른 작업 기록의 진행 중 변경을 보존한다. 이전 진단 도구 파일은 미추적 상태다.

## 결정과 진행

- 2026-10-10: 기존 진단의 스키마·미검토 채점 제외·오프라인 계약을 재사용한다. Qt는 기존 의존성을 사용하며 별도 설치하지 않는다. 저장은 전체 자료의 새 snapshot으로 만들고 원래 PNG/manifest는 덮어쓰지 않는다.
- 2026-10-10: 기존 HTML 보고서 브라우저 확인은 이전 도구의 `file://` 정책 차단 때문에 미실행 상태를 유지한다. 이번 등록 창은 새 기능이며 보고서를 우회 표시하는 기능을 넣지 않는다.
- 2026-10-10: `review_store.py`에서 선택 이미지의 SHA-256·PNG 크기를 검사하고 중복 바이트 이미지를 제외한다. 여러 입력 중 오류가 있으면 해당 등록 묶음을 반영하지 않는다. 편집은 메모리에 두고 저장마다 전체 사본을 고유 임시 폴더에 작성·검증한 뒤 새 버전 폴더로 바꾼다. 실패 시 이 호출의 임시 폴더만 정리하고 원본/기존 버전과 편집 내용을 유지한다.
- 2026-10-10: `review_ui.py`는 이미지/문자/TSV/출처·조건을 편집하며 실제 OCR·제품 앱·DB를 로드하지 않는다. 검토 상태와 다음 사례 버튼은 작은 창에서도 하단에 고정한다. 조건과 정답 영역은 스크롤로 접근한다. 원본 그림은 드래그 이동과 확대/맞춤을 지원한다.
- 2026-10-10: 첫 두 quick은 pytest-qt가 fixture finalizer보다 먼저 창을 닫으며 저장 확인창을 여는 문제로 중단했다. 세 번째는 20초 제한의 stack dump로 같은 정리 경로를 확인했다. 제품의 닫기 보호를 바꾸지 않고 테스트의 `before_close_func`에서 종료 직전 시험 상태를 정리했다. 이후 관련 129개가 통과했고 시각 점검 후 하단 고정 변경을 적용해 다시 검사했다.

## 미해결과 인계

- 실제 화면 자료는 아직 수집하지 않았다. 원본 그룹 단위 dev/holdout 구성과 다양한 환경 확보는 후속 단계다.
- Qt 창은 실제 표시/입력·렌더를 검사했지만 한국어 IME와 사용자의 네이티브 파일 선택은 별도 수동 확인이다. 기존 HTML 보고서의 브라우저 시각 확인 미실행 상태는 그대로다.
- 다음 행동: `python -m tools.screen_text_lab review`로 Windows Terminal·브라우저·문서·표의 시험용 PNG를 원본 그룹별 등록하고 정답 검토 후 저장된 버전을 명시적으로 `run`한다. 전체 1,000개/보류 집합 확보 완료로 처리하지 않는다.
- 정본: [진단 도구 사용법](../SCREEN_TEXT_LAB.md).
- 배포·커밋·push: 수행하지 않음.
