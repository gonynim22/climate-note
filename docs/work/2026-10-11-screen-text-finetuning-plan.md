## 결정과 진행

### 1. 이번에 보완한 핵심

`training_plan`, `dataset_plan`, `evaluation_plan` 세 에이전트가 읽기 전용으로 검토했고 총괄이 아래 사실을 다시 확인했다. 에이전트 수를 늘리는 것 자체가 평가 자료의 독립성이나 정답 품질을 보장하지 않는다.

1. 공식 `max_text_length=25`에서 보조 NRTR 경로는 **실제로 최대 23자**만 허용한다. 기존 dev 48장 정답 150줄 중 **76줄이 23자를 초과**한다(같은 원문의 두 배율 포함). 64자 지원을 원하면 특수토큰 여유를 포함한 값(예: 66)을 쓰고 실제 encoder 경계 입력으로 확인한다. 25자 초과 54줄이라는 이전 통계도 참이지만 학습 거부 범위를 충분히 설명하지 못했다. [고정 공식 encoder](https://github.com/PaddlePaddle/PaddleOCR/blob/dab3fe35379033fdcb2d0e9572fac0b36c9a9ebf/ppocr/data/imaug/label_ops.py)
2. 공식 `warmup_epoch=5`를 둔 5 epoch 실험은 준비 학습 기간만 소진할 수 있다. update 수·warmup·LR 감소·평가 간격을 실험별로 고정한다. **60분 종료는 학습 완료나 효과 없음의 판정이 아니다.** [고정 공식 설정](https://github.com/PaddlePaddle/PaddleOCR/blob/dab3fe35379033fdcb2d0e9572fac0b36c9a9ebf/configs/rec/PP-OCRv5/multi_language/korean_PP-OCRv5_mobile_rec.yml)
3. 현재 사전에는 `㈜ ℃ ₩ ㎎ ㎏ ㎍ ㎥ ㎡ ㎜ ㎝ ㎞ ㏊ ㏈ ℓ ㎖ ㏙ ㎐ ㎾ ㎸ ㎃`가 없다. 이는 이번에 조사한 업무 기호 목록의 결과이며 모든 OOV의 전수 목록은 아니다. `μ µ ³ ² % ‰ ± ≤ ≥ − ·`는 있다. 따라서 **사전 유지 미세학습 A와 업무 기호 확장 B**를 같은 프로젝트 안의 별도 실험으로 계획한다.
4. 현재 corpus는 dev/holdout만 지원하고 한 manifest 안의 그룹·동일 이미지·정확 문구 중복을 주로 검사한다. 학습용 train/selection/final 분할 및 자료 묶음 간 문서·템플릿·유사 문구 감사가 추가로 필요하다.
5. 현재 `compare.classify()`의 종합 improved는 문자 오류가 줄면 표 퇴행을 가릴 수 있다. 제품 채택은 문자·숫자/단위·표·경고·시간을 **각각** 통과해야 한다.

### 2. 에이전트 역할과 작업 소유권

동시 작업은 총괄 1명 + 전문 에이전트 3명으로 유지한다. 전용 경로 이름은 구현 시작 시 고정하며 아래는 제안이다.

| 담당 | 소유 범위 | 인계 산출물 |
|---|---|---|
| 총괄/통합 | 공통 인터페이스·recipe, 작업 기록/정본 문서, 기존 runner/corpus/CLI 연결, 제품 `screen_text/` 및 통합 테스트 | 단계 판정, 고정 후보 선택 근거, 통합 패치와 전체 검증 |
| 학습·변환 | `tools/screen_text_lab/training/`, 전용 학습 테스트, 별도 환경/학습 출력 | 환경 lock·원본 재현 보고서·학습 곡선/로그·checkpoint·ONNX/사전/manifest |
| 자료 | `tools/screen_text_lab/datasets/`, 전용 자료 테스트, train/selection 자료 | 출처·분할·crop/정답·길이/OOV/누출 감사·coverage 보고서 |
| 평가·반증 | `tools/screen_text_lab/evaluation/`, 전용 평가 테스트, 별도 final 평가 묶음 | 고정 평가 recipe·원문 비교 HTML·지표별 판정·신뢰구간·퇴행 목록 |

- 같은 파일은 한 담당만 수정한다. 공용 파일 수정은 총괄에게 패치 요구사항으로 인계한다. 제품 모델을 각 에이전트가 임의 교체하지 않는다.
- 시작 시 dirty/index와 입력 해시를 기록하고 현재 미커밋 lab 코드까지 포함한 허용 목록 snapshot을 만든다. HEAD만 복제한 worktree에 미추적 lab 도구가 빠지는 문제를 피한다. 사용자 변경을 stash/reset하거나 무관한 파일을 복원하지 않는다.
- **GPU 학습/변환은 한 작업씩**, CPU 성능 측정 동안 다른 렌더/OCR/하네스를 정지한다. Qt/통합 하네스와 EXE 검증은 총괄이 순차 실행한다. 자료 설계·코드 작성·정적 검토는 병렬로 진행한다.
- 학습 담당은 final 이미지/정답/오류 요약을 후보 고정 전 읽지 않는다. 평가 담당도 final의 OCR/집계는 후보 고정 후 한 번만 실행한다. 자료 작성·정답 검토 접근과 모델 평가 접근을 기록한다. 공유 폴더 역할 분담은 기술적인 접근 차단이 아니므로 접근 범위·해시·시간을 남긴다.
- run마다 source/config/environment/dataset/model/dictionary hash, seed, 유효 step/샘플 수, 내보내기 옵션, baseline, 실패·제외 수, `summary.md`·`result.json`·HTML을 인계한다.

### 3. 실행 순서와 통과 조건

| 단계 | 병렬/담당 | 할 일 | 다음 단계로 넘어가는 조건 |
|---|---|---|---|
| 0. 기준 고정 | 총괄 + 세 담당 | 자료 분류, 모델/사전/소스 snapshot, 후보 수·지표·산출물 형식·파일 소유 확정 | 제품/원본 기준선과 train/selection/final 경계가 문서화됨 |
| 1. 환경·원본 재현 | 학습 / 자료·평가는 병렬 설계 | 별도 Python 3.12 후보 환경, 공식 가중치 로드·학습 없는 ONNX export·제품 대조 | 키/shape/문자 ID 확인, 결과 차이의 위치와 의미 확정 |
| 2. 자료·도구 기반 | 자료 + 평가 / 학습은 loader 검증 | 300~500줄로 생성→crop→사전검사→학습/평가 연결, 이후 1차 자료 확정 | 조용히 사라지는 샘플 0, 누출 감사, 라벨/그림 검수 통과 |
| 3. 학습 동작 확인 | 학습 단독 GPU / 평가 검토 | 폭별 forward/backward·50 step·checkpoint 저장/복구 | 유한 loss/gradient, 실제 parameter 변화, 최대 폭 메모리·처리량 확인 |
| 4. A 파일럿 | 학습 + 평가 | 현재 사전으로 LR 2개, 같은 자료 노출량으로 비교 | 학습 효과와 과적합 여부 판단 가능. 시간 부족은 미완료로 기록 |
| 5. B 기호 확장 + 본 학습 | 학습 / 자료는 범주 보강 / 평가는 반증 | 업무 기호를 명시 매핑, 자료/예산 재고정 후 충분한 학습 | selection·회귀에서 문자/표/핵심 숫자/경고 기준 충족, seed 안정성 |
| 6. 독립 최종 평가 | 평가 단독 채점, 총괄 판정 | 모델/사전/임계값/recipe hash 고정 후 새 final과 종전 보류 12장 평가 | 새 실제 자료의 개선·퇴행·불확실성·CPU 성능을 각각 통과 |
| 7. 제품 통합·EXE | 총괄, 평가 재검수 | 모델 묶음·계약/고지·테스트·PowerShell release·수동 확인 | 현재 코드/EXE의 실제 결과가 남고 원복 가능한 상태 |

환경·데이터·평가 도구를 먼저 병렬 준비한 뒤 학습을 수행한다. 학습 결과를 기다리는 동안 최종 자료를 미리 채점하거나, 결과가 좋은 자료만 골라 평가하지 않는다.

### 4. 원본 재현과 별도 환경

- 후보는 선행 검토의 Python 3.12 x64 + Paddle GPU 3.2.2/cu118 + Paddle2ONNX 2.1.0이며 **호환 검증 완료 조합은 아니다**. 전체 wheel/버전 해시를 별도 lock에 고정하고 프로젝트 `.venv`/lock·전역 PATH/드라이버는 유지한다. 설치 성공, DLL 로드, `run_check`, CPU/GPU forward, export·ONNX 추론을 확인한다.
- 비교를 **P: 현재 제품**, **R: 공식 가중치의 미학습 재수출**, **F: 추가 학습 후 재수출**로 구분한다. `R→F`는 학습 효과, `P→F`는 제품 이득이다.
- 원본 설정에서 같은 BGR tensor로 수치(`atol=1e-4, rtol=1e-3` 제안), 디코딩 문자열, 제품 텍스트/표/0.80 경고의 동등성을 각각 측정한다. 동적 폭·배치 1/6·패딩·긴 입력을 포함한다. 검사 입력/허용오차는 실행 전에 고정한다.
- 예상하지 못한 가중치 누락/shape/사전 불일치·재현 불안정은 해결 전 학습을 중단한다. 수치 차이만 있으나 행동이 같은 경우는 구분해 검토한다. 공식 checkpoint가 제품과 다른 것으로 남으면 **동일 원본 미세학습이라는 주장을 버리고 공식 소형 모델 기반 새 후보**로 경로를 명시할 수 있다. 이 경우 R/P 두 기준선을 계속 유지하고 최종 제품 비교를 생략하지 않는다.
- 환경 2시간은 첫 점검 시점이다. 그때 재현되지 않으면 로그·시도 조합·다음 가설을 정리한다. 시간 경과를 학습 불가능의 증거로 쓰거나 자동으로 최신 패키지/드라이버 설치를 확대하지 않는다.

### 5. 공무원 업무 화면에 맞춘 자료

우선 배분안은 **공문서 본문·항목/머리말 35%, 표와 셀 35%, 숫자·금액·날짜·단위 25%, 짧은 메모/제목 5%**다. 분류는 대표 용도 한 가지로 중복 집계하지 않되 숫자·단위 태그는 본문/표에도 붙인다. 사용자 업무 우선순위를 반영한 설계값이며 실제 사용빈도 조사 결과가 아니다.

- 한컴 한글·PDF·Word·메모장 4앱을 다루고, 새 최종 자료는 앱별 최소 할당을 둔다. 설치·사용 가능한 앱에서 시험 문서를 표시해 **PNG 직접 캡처**한다. 같은 문서의 앱/배율/테마 변형은 같은 그룹이다. 여러 앱에 같은 원문을 띄운 것을 독립 문서 수로 늘려 세지 않는다. 접근 불가/캡처 차단은 우회하지 않고 해당 앱은 미검증으로 남긴다.
- PDF는 텍스트형 PDF의 화면 표시와 스캔형/저해상도 페이지를 별도 층으로 둔다. 문서 파일에서 텍스트를 직접 추출해 OCR 출력으로 대체하는 기능은 이번 범위가 아니다.
- 작은 표 글씨, 얇은 획/명조체, 표 테두리와 셀 여백, 합계/소수점/음수/쉼표/백분율, 날짜·문서 번호·예산 금액, `mg/L`, `μg/m³`, `㎎/L`, `㎡`, `℃` 같은 단위가 섞인 실제 표기를 포함한다. 숫자와 단위는 원문 그대로 정답을 작성한다.
- 글꼴·10~24px·밝음/어두움·낮은 대비·앱 확대율·Windows DPI를 태그로 분리한다. Qt 합성 배율은 실제 DPI/ClearType 재현이라고 표시하지 않는다. 요청/실제 글꼴, 글리프 누락과 fallback, crop 잘림·인접 줄 혼입도 검사한다.
- 길이는 1~12/13~23/24~48/49~64자로 나눠 충분히 포함하고 64자 초과는 별도 스트레스 자료로 보존한다. 긴 원문을 임의로 끊어 정답을 손상시키지 않는다.

| 묶음 | 1차 준비 목표 | 용도 |
|---|---|---|
| train | 새 원문/템플릿 그룹 1,200개 × 5조건 = 합성 줄 6,000장, 실제 학습 crop 200장 이상 보강 목표 | 첫 파일럿. 6,000 독립 문구라는 뜻이 아님 |
| selection | 새 200그룹 × 5조건 = 합성 1,000장, 실제 100 crop/50화면 그룹 이상 | 설정·checkpoint·A/B 후보 선택 |
| final | 별도 새 합성 200그룹 × 5조건, **실제 300~500개 독립 문서/원문 그룹** 준비 목표 | 효과·퇴행을 확인할 평가. 실제 앱별 최소 50그룹, 동일 문서 중복은 1그룹 |
| regression | 기존 합성 1,920 dev + 이미 사용한 480 holdout + 실제 dev 48장 | 이전 정답 보존. 새 독립 평가로 주장하지 않음 |
| 종전 보류 | 실제 12장 유지 | 후보 확정 후 한 번 보는 보조 최종 평가 |

이는 자료 준비 **목표**다. 지금 확보된 수량이 아니다. 300~500그룹도 자동으로 충분한 표본은 아니며 selection의 오류율·그룹 간 변동으로 탐지 가능한 개선 폭과 필요 수를 추정해 final 공개 전에 규모를 고정한다. 자료가 부족하면 부족한 분류를 공개하고 제품 적용 판정을 보류한다.

학습 manifest는 기존 진단 형식과 별도로 train/selection/final을 지원하고 `document_id`, `template_family_id`, `source_group_id`, 원본 화면/좌표/문구/이미지 해시, 출처·이용범위, renderer/font/seed, `reviewer_kind`·검토 범위/날짜를 담는다. 렌더 전에 문서/템플릿 가족 단위로 분할하고, 숫자만 바꾼 문장·유사 문구·파생 이미지·이전 실험 원문과의 중복을 여러 묶음 전체에서 감사한다. 비교용 정규화는 정답 원문을 변경하지 않는다.

OOV·깨진 PNG·빈 정답·길이 초과·crop 범위·실제 폭별 CTC 출력 단계 부족을 사전에 차단한다. 인접 반복 글자에 필요한 blank도 계산한다. 제외 이유/수량을 남기며 loader가 조용히 버린 샘플을 정상 학습량에 넣지 않는다. OCR 예측을 정답으로 자동 채택하지 않는다.

사람의 독립 검토는 최종 실제 자료와 모호한 기호에 우선 배정한다. 원문이 알려진 시험 문서도 표시/클리핑/폰트 치환을 이미지와 대조해야 한다. 사람 검토 전에는 합성 생성·환경·시험 학습·기존 회귀를 진행할 수 있지만 독립 실제 업무 개선을 확정하지 않는다. AI 에이전트끼리의 교차 검토는 사람 검토와 구분한다. 기존 review 창은 줄 상자 편집을 지원하지 않으므로 우선 좌표/정답/이미지 HTML atlas와 주석 입출력 도구를 만든다.

### 6. A/B 학습과 예산

**A — 현재 사전 유지:** 기존 문자 정확도를 개선하는 대조 후보다. OOV가 있는 학습쌍은 원문을 보존해 명시 보류하고 평가에서는 OOV 포함 전체 점수를 유지한다.

**B — 업무 기호 확장:** A의 재현/학습 도구가 안정되면 위 20개 OOV 조사 목록과 신규 train/selection coverage를 바탕으로 최소 확장 목록을 고정한다. final을 보고 문자를 추가하지 않는다. 한글·숫자 기존 문자와 추가 기호를 함께 학습한다. A가 이미 제품 채택 기준에 도달해야 B를 시작하는 것은 아니다.

- 사전 뒤에 공백을 붙이는 공식 규칙 때문에 새 문자를 추가하면 공백 ID가 이동한다. CTC 출력층/bias, NRTR embedding/output을 **문자→ID 대응표**로 복사하고 blank/공백/특수토큰을 모두 검증한다. 앞쪽 가중치만 잘라 붙이거나 shape 경고를 무시하지 않는다.
- 기존 문자 공간에서 가중치 복사·logit 동등성을 확인한다. 새 클래스가 포함된 softmax는 자동 동등하지 않으므로 새 클래스 마스킹 검사와 실제 전체 클래스 평가를 구분한다.
- `㈜→(주)`, `℃→°C`, `㎎→mg`, `₩→역슬래시`처럼 원문을 치환해 성공으로 세지 않는다. NFKC 정규화로 호환 단위 문자를 합치지 않는다. 원화로 보이는 U+005C와 실제 U+20A9를 구분한다.
- B는 클래스와 해당 학습 자료가 함께 늘어난 후보이므로 순수한 사전 확장만의 효과라고 주장하지 않는다. 두 후보의 공유 지원 문자 평가와 OOV 포함 업무 평가를 모두 비교한다.

학습 예산은 다음처럼 단계적으로 확정한다.

1. **smoke:** 단일 GPU·FP32·worker 0·배치 4, 최대 폭을 포함한 50 step과 저장/복구. OOM이면 배치 2를 확인한다. 그래도 실패하면 가설을 바꿀 별도 기술 검토로 전환한다. AMP/gradient accumulation/NRTR 삭제를 한꺼번에 넣지 않는다.
2. **파일럿:** LR `1e-5`·`5e-5` 두 개, 같은 seed/order·유효 샘플 노출량으로 비교한다. 첫 목표는 5 epoch이며 warmup은 전체 update의 5%를 시작안으로 두고 scheduler·평가 간격을 실행 전 고정한다. 6,000장·배치 4·5 epoch면 단순 계산 약 7,500 update다(실제 sampler/drop-last에 따라 재계산). 50-step 측정으로 예상 시간을 제시하고 평가/저장 비용도 포함한다. 60분에 잘렸으면 미완료이며 완료 후보와 동등한 학습으로 비교하지 않는다.
3. **본 학습:** 유망 설정과 업무 기호 후보를 대상으로 coverage 부족분을 **새 원문/새 조건**으로 보강한다. 단순 배율 복제를 늘리지 않는다. 자료 재고정 후 각 후보의 update 상한, selection 평가 간격, 정체 중단 조건을 정한다. warmup 이후 최소 5 epoch 분량의 유효 샘플 노출을 확보하고, 아래 checkpoint 선정 순위가 5회 연속 평가에서 개선되지 않을 때 조기 종료하는 것을 제안한다. CER 하나만 정체했다고 숫자/표/경고 퇴행이 회복되는 학습을 끊지 않는다. 평가 간격과 최대 update는 파일럿 처리량으로 실행 전에 확정한다. 최종 후보는 최소 2개, 목표 3개 seed로 안정성을 확인한다.
4. 본 학습의 총 GPU 시간은 파일럿 뒤 산정한다. 12~24시간을 최초 예산 검토 범위로 삼을 수 있으나 완료 보장/효과 보장은 아니다. 예산 변경은 데이터 버전/recipe에 남기며 새 자료·장시간 실행·외부 유료 GPU를 무단으로 확대하지 않는다. 기본 실행 장소는 이 PC다.

최선 checkpoint는 selection의 지표별 게이트 충족 여부 → 공백 제외 CER → 공백 포함 CER → 기존 정답 손상 수 → 고정 ID 순서로 정한다. 모두 게이트 미충족이면 실패/잘림 수 → 숫자·단위/표의 신규 퇴행 수 → 신규 무경고 오답 수 → 기존 정답 손상 수 → CER 순으로 연구용 최선을 기록한다. 이 순서도 recipe에 고정하며 미충족 후보를 채택하지 않는다. 최종 자료에서 좋은 seed를 골라 내지 않는다. 시간 상한·OOM·수치 불안정·품질 미달·평가 자료 부족을 다른 상태로 기록한다.

### 7. 독립 평가와 채택 조건

- 공백 제외/포함 CER, 완전 일치, 기존 정답→오답/복구 전이, 실행/잘림/빈 화면 허위 문자, 전체/OOV/지원 문자별 결과를 낸다. 줄 crop과 고정 검출을 거친 전체 화면 점수를 분리한다.
- **목표:** 새 실제 자료에서 공백 제외 오류 점추정 20% 이상 감소, 공백 포함 오류 비증가, 성공/잘림 기준 통과. 원문/문서 그룹 단위 paired bootstrap 95% 구간으로 개선 방향도 확인한다. 구간이 개선 없음에 걸리면 효과 불확실로 보류한다. '최소 20% 개선 확증'은 구간 하한까지 20% 이상일 때만 표현한다.
- 기존 고정 회귀에서 신규 완전 오답 0을 차단 기준으로 둔다. 숫자·금액·날짜·단위, 표 셀 내용과 행/열 구조의 새 퇴행도 별도 차단한다. 새 실제 평가의 신규 완전 오답은 모두 열람·집계하고 최초 채택안은 0을 요구한다. 이는 유한 자료의 관측이며 모든 미래 화면의 무퇴행 보장이 아니다.
- micro CER와 그룹 평균, 앱/본문·표·숫자/크기·글꼴·배율별 결과를 함께 본다. 같은 원문 변형을 독립 표본으로 세거나 합성 대량 평균으로 실제 퇴행을 상쇄하지 않는다. `--intersection` 부분 비교를 최종 통과에 쓰지 않는다.
- 경고는 우선 기존 0.80과 숫자 열 규칙을 유지한 채 놓친 오류·정상 오경고·신규 무경고 오류를 별도로 비교한다. 최초 제안 한도는 **신규 무경고 오답 0, 기존 정답 그룹의 새 오경고 0, 고정 전체 자료의 무경고 오류 수와 100화면당 오경고 수 비증가**다. 수/전체 화면당 비율/오류 조건부 비율을 함께 보고 정확도 변화에 따른 분모 변화를 구분한다. 한도와 기준 집합은 selection 단계에서 recipe에 확정하며 final을 본 뒤 완화하지 않는다. 점수를 정답 확률로 부르지 않는다. 보정이 필요하면 selection을 모델 선택/경고 보정용으로 미리 분리하고 모델+임계값을 같이 고정한다. 임계값 변경은 별도 제품 계약 변경으로 기록한다.
- CPU/스레드/입력 동일, 워밍업 후 교대 5회 이상으로 시간과 분산을 측정한다. selection에서 앱·표 밀도·줄 수·짧음/긴 영역별 고정 workload를 만들고 각 반복의 동일 사례 전체에서 중앙/p95와 반복 간 변동을 계산한다. 느린 사례를 결과를 본 뒤 빼지 않는다. 제안 한도는 중앙/p95 각각 기존 대비 1.10배 이하·ONNX 15MB 이하이며 초기 로드/프로세스 메모리도 별도 보고한다. 경계 결과는 측정 불확실성을 표시하며 GPU 학습 속도를 제품 CPU 성능으로 대체하지 않는다.
- 모델·사전·전처리·경고·recipe·source hash가 고정된 후보 **하나**만 final을 연다. 실패 후 수정하면 사용한 final은 회귀 자료로 전환하고 다음 채택에는 새 final을 마련한다. 종전 보류 12장은 독립 실제 대규모 검증을 대신하지 않는다.

### 8. 통합·검증·인계

- 최초에는 기존 검출기/전처리/줄·표 조립을 고정한다. 재학습 후에도 검출 누락이나 표 구조가 지배적이면 별도 원인 분석 결과로 남기고 검출/레이아웃 수정은 다른 실험으로 분리한다.
- lab 후보 등록은 고정된 model+dictionary hash만 허용하고 임의 경로/외부 코드 로더를 제품에 추가하지 않는다. 학습·대량 평가 명령은 수동 개발 도구로만 두고 일반 pytest/quick/data/full/release/빌드에 자동 연결하지 않는다.
- 새 자체 검사는 작은 합성/가짜 모델로 분할 누출·문자 매핑/공백·길이/CTC 경계·손실 제외·지표별 판정·보고서 이스케이프를 검증한다. 실제 원본 재현/학습/대량 평가는 별도 실행 ID를 쓴다.
- 제품 반영 때 ONNX·사전·MANIFEST·변경 고지를 일관된 묶음으로 검사한다. 사전 확장으로 필요한 charset 상수/회귀 변경은 총괄이 처리한다. 종전 묶음/EXE를 보존해 원복 가능하게 한다.
- 관련 UI/모델 통합 변경은 `quick --tests tests/test_screen_text_engine.py tests/test_screen_text_layout.py tests/test_screen_text_capture.py tests/test_screen_text_ui.py tests/test_screen_text_guide.py tests/test_optional_mini_apps.py`에 새 관련 검사 파일을 추가한다. 공용 실행기/테스트 격리 변경은 `full`이다. 최종 배포 산출물은 PowerShell `release`로 검증하며 같은 최종 코드에 full을 중복 실행하지 않는다.
- release 이후 새 EXE SHA-256·포함 모델/사전/Qt·네이티브 바이너리 출처를 대조한다. 혼합 DPI·KVM·캡처 차단·한글/Word/표 붙여넣기와 최종 UI는 수동 미확인/통과를 구분한다.
- 제품은 CPU 오프라인·캡처 메모리 전용·본문 로그 없음·차단 우회 금지·10개 창 수명 지점·기존 데이터 불변을 유지한다. 개발 자료/환경/학습 checkpoint를 EXE에 넣지 않는다. 자동 검사 통과와 배포 승인은 구분한다.

## 미해결과 인계

- 첫 착수 묶음: 총괄의 소유권/입력 snapshot 고정 → 학습 담당의 원본 재현, 자료 담당의 업무 문서 데이터 설계, 평가 담당의 지표별 채택 도구를 병렬 진행.
- 사용자 자료를 읽거나 클라우드에 올리지 않는다. 새 실제 평가 자료의 사람 검토와 사용할 앱 환경은 자료 준비 단계의 확인 사항이다. 그 전에도 환경/합성/도구 개발은 진행할 수 있다.
- 사전 유지 A만으로 업무 기호 문제는 해결되지 않는다. B의 문자 매핑·학습·평가까지 계획에 포함하되 효과가 없으면 제품에는 적용하지 않는다.
- 변경한 정본 문서: 진단 계약에 이 계획을 연결한다. 제품 데이터/런타임 계약은 이 계획만으로 변경하지 않는다.
- 설치·학습·빌드·배포·커밋·push: 이번 계획 수립에서는 수행하지 않음.
