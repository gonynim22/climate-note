## 결정과 진행

- [표 구성 개선](2026-10-11-screen-text-table-layout.md)의 고정 코드/검사를 사용한다. 해당 개발 표본의 결과를 독립 일반 정확도로 표현하지 않는다.
- [자료 확대 추가 학습](2026-10-11-screen-text-diverse-training.md)은 품질 실패로 미채택이다. 결과를 보존하며 더 학습하지 않는다. 실험 자료/도구는 기존대로 개발 출력/도구 폴더에 두고 EXE에 포함하지 않는다.
- `release`에 전체 검사가 있으므로 먼저 같은 quick/full을 중복 실행하지 않는다. 실제 테스트 실패는 원인과 범위를 확인하고 수정 후 관련 검사를 다시 수행한다.
- 새 EXE 확인은 하네스가 소유한 합성 데이터·Windows Job만 사용한다. 기존 실행 중인 사용자 앱을 종료하거나 사용자 AppData를 읽지 않는다.
- 빌드와 내용 검사가 끝나면 동일 이름의 이전 `dist` 파일은 보호 사본으로 보존한 뒤 교체한다. 사용 중이라 교체할 수 없으면 기존 프로세스를 종료하지 않고 별도 검증 폴더에 새 파일을 제공한다.
- 사전 확인 실행은 `20261011-212131-feadc1b31a`다. `layout.py`·관련 검사 해시는 앞선 채택본과 일치하고 모델 3파일은 MANIFEST의 크기/SHA-256과 같다. 확인 시점에 루트 `dist/기후노트_v3.9a.exe`는 없었다. 직전 검증 EXE는 `output/harness/20261011-175917-ae4cf6864f/dist/`에 있으므로 파일·크기 비교 기준으로 삼고 그대로 보존한다.
- PowerShell `release` 실행 `20261011-212137-470e230764`가 통과했다. 2,437개 검사(실패/오류/skip 0), 새 EXE 빌드, fresh/existing/blocked 격리 실행이 완료됐다. 검사 중 입력 변화는 없었다. qfluentwidgets의 기존 SciPy import 경고 1개는 실패와 구분한다.
- EXE의 프로젝트 모듈 50개(표 구성·인식 엔진·DB/보안·메인 포함)를 현재 소스에서 컴파일한 코드와 대조해 일치했다. 모델/사전 3개와 MANIFEST는 원본 해시와 정확히 같고, 네이티브 파일 64개는 현재 빌드 원본 및 직전 EXE와 같다. Qt DLL은 프로젝트 환경의 6.11.2이며 Git/mingw DLL 혼입은 없다.
- 처음 파일 비교는 직전 깨끗한 Git 사본 빌드와 현재 작업 폴더 빌드의 리소스 raw byte 차이 때문에 실패했다. 41개 라이선스/SVG 파일을 각각 대조하여 CRLF/LF만 다른 것을 확인했다. 원래 실패 기록/검사 코드를 보존하고, 해당 파일만 줄바꿈을 통일한 내용 동등성으로 구별했다. 현재 EXE의 리소스 91개는 현재 소스와 바이트 단위로 같다. 모델·바이너리는 줄바꿈 정규화 없이 비교했다. 제품 코드·리소스를 검사 통과용으로 바꾸지 않았다.
- EXE의 Python/파일 목록에 `screen_text_lab`, Paddle 학습 런타임, torch, 새 학습 자료/모델이 없다. 실제 채택은 기존 인식 결과의 표 재구성 변경이며 모델 인식률 향상을 주장하지 않는다.
- 루트 `dist` 목적 파일이 여전히 없음을 확인한 뒤 새 파일을 비덮어쓰기 복사하고 SHA-256을 재검사했다. 직전 EXE와 현재 release 원본은 그대로 보존했다. 실행 중인 사용자 앱·실사용 AppData/DB/salt를 조작하지 않았다.
