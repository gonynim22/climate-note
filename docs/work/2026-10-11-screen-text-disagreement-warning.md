## 결정과 진행

- 이전 모의 분석은 화면 전체 기준 9→217개 오류 발견, 11→60개 정상 오경고였다. 이번에는 위치를 검증하며 문자 정확도 개선으로 표현하지 않는다.
- 주 비교 규칙은 공백 제외 최소 편집 거리(동률은 대각선→삭제→삽입). 경고 생성에 정답을 사용하지 않는다. 정답 평가는 모든 최소 정렬에서 가능한/확실한 위치를 구분해 반복 문자열의 임의 정렬로 성능을 부풀리지 않는다.
- HTML은 기존 보고서 틀을 재사용한다. 기존 브라우저 정책 차단을 우회하지 않으며 정적 검사·실제 PNG 확인과 브라우저 시각 확인을 구분한다.
- 구현: 순수 `disagreement.py`·수동 분석/HTML `disagreement_report.py`·소유 worker 성능 진단 `disagreement_benchmark.py`와 CLI 두 명령. 기존 `read_regions()`의 증거 해시를 선택적으로 생략하되 tensor/결과가 같음을 검사했다. 공용 하네스·제품 파일은 변경하지 않았다.
- 두 판독만으로 표시를 만든 뒤 정답을 평가한다. 최적 정렬의 모든 경로에서 가능한/확실한 오류 위치를 경로 수로 구한다. `a/b` 길이 0~3의 모든 225쌍을 별도 편집 스크립트 전수 열거와 대조했다. 실제 원문은 HTML 텍스트·UTF-16 슬라이스로 재검사했다.

### 결과와 판단

- 같은 160개 원문에서 파생한 1,920개 PNG의 개발 자료 재분석이다. `cond-document-015--dark`의 제품 출력 `Ω`는 NFC 정규화 시 `Ω`로 바뀌므로 원문 위치/NFC 채점 혼동을 피하고자 **1건을 위치 채점에서 명시적으로 제외**했다. 이 제외로 이전 화면 단위 441개 오류/217개 경고와 이번 440개 오류/216개 경고는 분모가 다르다. 원본·출력·불일치 표시 자체는 그대로 보고서에 남겼다.
- 채점 1,919개 = 오류 440개 + 공백 제외 정상 1,479개. 29개는 정답 최소 정렬이 여러 개라 위치 결과를 범위로 표시한다. 공백/표 구조 오류 및 그림의 개별 글자 픽셀 위치는 이 평가에 포함하지 않는다.

| 지표 | 기존 경고 | 신규 불일치만 | 기존 + 불일치 |
|---|---:|---:|---:|
| 오류 화면에서 경고 | 9 | 213 | 216 |
| 오류 화면에서 경고 없음 | 431 | 227 | 224 |
| 정상 화면 오경고 | 11 | 50 | 60 |
| 실제 오류 위치에 적중한 화면 | 6 | 177~186 | **180~189** |
| 표시한 문자/삽입점 수 | 76 | 320 | 391 |
| 확실/가능한 오류 위치 적중 수 | 7 | 203~215 | 207~219 |
| 어느 정렬에서도 오류 아닌 위치 | 69 | 105 | 172 |

- 신규 표시 자체의 위치 적중률은 **63.4~67.2%**다. 현재 경고는 칸 전체를 표시하므로 문자 단위 정밀도 7/76과 신규 문자 표시를 같은 세밀도의 UI처럼 비교하지 않는다. “화면에 오류가 있고 경고도 있음”이 곧 오류 위치 적중이라는 해석을 피한다.
- 기존 경고에 합치면 정상 화면의 오경고는 11/1,479(0.74%)→60/1,479(4.06%)다. CLI에서는 실제 오류 위치 적중 화면 2→45개이나 정상 오경고 21개가 남는다. 전체 평균만으로 CLI 해결을 주장하지 않는다.
- 처리 시간: 기존 중앙값 **33.43ms** / 이중 판독 **64.24ms**, P95 **75.85/135.60ms**. 같은 PNG끼리의 추가 시간 중앙값 **29.04ms**, P95 **62.42ms**, 쌍별 배율 중앙값 **1.84배**. 각각의 중앙값 차이와 쌍별 차이의 중앙값은 다르다.
- 600쌍 전부 원문·표·HTML/TSV·상자/점수·기존 경고가 원래 호출과 동일했다. 두 번째 판독도 기존 ink-light 실행과 전 필드 해시가 일치했다. 모델 로드/PNG 읽기·실제 캡처/UI 시간은 측정값 밖이며 큰 문서 성능 보증이 아니다.
- **판단: 검토 신호로는 개선되지만 자동 적용은 보류.** 224개 오류 화면은 여전히 무경고이고, 경고한 오류 화면 일부에서도 다른 위치를 표시한다. 원문 정확도 개선은 0이다. 불일치가 없음을 “오류 없음”으로 해석하지 않는다.
- 중간 속도 실행 [20261011-040302-61474a09a4](../../output/harness/20261011-040302-61474a09a4/summary.md)는 중앙값 33.92/64.19ms였으며, 중간 위치 분석 [20261011-040422-72ba4ebd9e](../../output/harness/20261011-040422-72ba4ebd9e/summary.md)과 최종 위치 통계는 같다. 같은 표본 재측정을 고유 자료 수/독립 반복 실험처럼 더하지 않는다.
- 최종 검토에서 서로 다른 모델/사전 해시 또는 제품/입력 코드의 비교를 거부하고, 실행 중 입력 변경을 명령 실패로 전파하도록 보강했다. **보강 뒤 242개 자체 검사·600쌍 실제 반복·1,920개 위치 분석을 다시 실행**했다. 이후에는 결과 기록/산출물 검사만 추가했다.
- 실제 OCR 실험 실패/테스트 실패 없음. 문서 삽입 위치를 찾지 못한 패치 1회는 적용되지 않았고 수정된 패치로 반영했다.
- 최종 산출물 보조 검사 첫 회는 아직 생성하지 않은 자신의 `verification.json`에 대한 문서 링크를 검사해 실패했다. 검사 시작에 `running` 상태 파일을 만들고 모든 검사가 끝난 경우에만 `passed`로 갱신하도록 산출물 전용 스크립트를 수정해 다시 실행했다. 제품/진단 코드·실험 입력·자체 검사에는 변경이 없다.
