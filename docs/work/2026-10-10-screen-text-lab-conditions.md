## 결정과 진행

- 2026-10-10: 시험 원문 200종 중 80종은 기존의 직접 작성한 bootstrap 문구를 재사용하고, 새 문구 100종과 서로 다른 구조/내용의 표 20종을 추가한다. 숫자만 바꾼 문구로 원본 수를 채우지 않는다. 200종은 장기 계획의 원본 1,000개 목표 중 합성 자료 중간 확대다.
- 2026-10-10: 12조건은 사전에 고정한다. 조건별 픽셀/글꼴 정보와 변형 부모를 기록한다. 합성 배율은 QPainter의 렌더 조건이며 실제 OS 배율/ClearType/프로그램 캡처로 표현하지 않는다.
- 2026-10-10: 보고서의 이전 `file://` 브라우저 정책 차단은 우회하지 않는다. 원본 PNG 확인과 HTML 링크/구조 검증을 수행하고 브라우저 조작 확인은 미실행으로 남긴다.
- 2026-10-10: `conditions.py`/`recipes/conditions.json`과 `condition_analysis.py`를 추가하고 생성 CLI 및 기존 실행 보고서에 연결했다. 기준 조건과 동일 원문/그룹/분할/정답의 채점된 쌍만 비교한다. 기존 점수 규칙·제품 인식 함수는 유지했다. 조건 분석 오류도 사례 JSONL을 보존한 `report_error`로 남긴다.

- 전체 조건 혼합의 공백 포함 오류는 3,791 / 58,788자(6.45%), 공백 제외는 744 / 46,692자(1.59%)다. 문자열 완전 일치는 672/1,920이며, 공백 제거 시 같아지는 오류 사례는 807개다. 전체 점수는 시험 조건의 동일 비중 평균이며 실제 사용 빈도를 반영하지 않는다. 문자 탭의 연속 공백 정규화 등 의도한 표시 계약과 실제 누락을 구분해야 한다.
- 공백 제외 오류 사례 441개 중 432개가 제품 경고 0곳이었다. 표/공백을 포함한 기존 전체 오류는 1,249개 중 1,239개가 무경고다. 이는 모델 평균 점수를 정답 확률로 볼 수 없다는 관측이며 경고 임계값을 올리면 해결된다는 근거는 아니다.
- 10px의 공백 제외 오류 수는 기준보다 60원문에서 늘고 5원문에서 줄었다(95개 동일). [CLI 예시](../../output/harness/20261010-222229-7b5dcff630/cases/cond-cli-013--font10.html)는 `warning → marning`, `줄바꿈 → 즐바꿈`, 마침표 누락을 평균 점수 약 0.94/0.95로 출력하면서 경고하지 않았다. 원본 PNG에서 정답과 잘림 없음도 확인했다.
- 넓은 선택 영역은 16원문 악화·14원문 개선·130원문 동일이다(공백 제외). 증가한 오류 53자 중 47자는 [URL 문장 한 사례](../../output/harness/20261010-222229-7b5dcff630/cases/cond-symbols-013--wide.html)의 대량 누락에 해당한다. 이 한 사례의 영향이 크므로 넓은 선택이 항상 나쁘다고 일반화하지 않는다. 같은 원문에서 인식 상자 높이가 기준 21px → 넓은 영역 42px로 달라졌고 원문 59자에서 50자 누락이 발생했다. 검출 범위/인식 crop의 영향은 다음 단계에서 분리해야 한다.
- 어두운 배경은 공백 포함 점수는 나아졌지만 공백 제외 오류는 늘었다. 24px·합성 배율도 일괄 개선이 아니므로 색 반전/확대를 제품 기본값으로 바로 적용하지 않는다.
- 위 시간은 단일 실행의 처리 구간 약 90초이며 제어된 성능 벤치마크가 아니다. 모든 시험 입력은 Qt로 그린 합성이다. Windows CLI 실물/ClearType·실제 DPI·JPEG·회전·빈 화면은 이 자료로 검증하지 않았다.
