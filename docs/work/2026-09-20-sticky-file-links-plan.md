아래 체크 목록과 미실행 표기는 계획 작성 당시의 상태다. 이후 사용자가 구현·v3.7b 버전 갱신·AGENTS.md 갱신·커밋을 요청했으며 실제 구현 결과와 계획 조정은 위 후속 기록에 남긴다.

- 제외 범위: 기존 보안 검사 전반 수정, 위젯 구조 리팩터링, 일반 URL 자동 링크화, 파일 감시 서비스, 자동 경로 복원, 일괄 링크 재연결, 버전 번호 확정·EXE 게시·push.

## 확인한 현재 구조

- `ui_sticky.py`의 `_TodoTextEdit`를 플로팅과 `ui_sticky_panel.py`의 `_PanelTodoEdit`가 함께 쓴다. 다만 플로팅 헤더와 패널 `StickyFormatToolbar`의 버튼 배치는 서로 다르므로 두 곳에 연결 버튼을 배선한다.
- 스티키 본문은 `toHtml()` → `database.update_sticky_note()` → 기존 Fernet 암호화로 저장한다. 구형 평문은 `setPlainText()`, HTML은 `setHtml()`로 읽는다. DB와 Export가 본문을 문자열로 다루므로 링크 메타데이터를 본문 안에 보존하는 방식을 우선한다.
- 할 일 문자는 Font Awesome `\uf0c8`/`\uf14a` 및 `☐`/`☑`이며 별도 페인팅으로 표시된다. 클릭 영역·Enter 연속 입력·체크 토글·취소선·Undo와 링크가 충돌하면 안 된다.
- 기존 스티키 `save()`는 내용이 같아도 `toHtml()`을 저장하며 Fernet 암호문은 재암호화 시 바뀔 수 있다. **기존의 정상 저장 경로에서 생기는 암호문 변화와 이번 기능의 불필요한 쓰기를 구분**한다. 상태 표시·호버·파일 확인만으로 저장을 추가하지 않으며, 일반 저장의 동작을 이번에 전면 개편하지 않는다.
- 현재 `_on_export()`는 대기 중인 편집 저장 없이 DB를 먼저 읽는다. 링크 추가 직후 내보내기에도 최신 내용이 들어가야 하므로 기존 `_prepare_data_change()`를 Export snapshot 전에 재사용하는 최소 수정을 포함한다. 이는 현재 메모와 일정의 최신 편집을 함께 보존하기 위한 직접 관련 수정이다.

## 사용자 동작과 표시

| 상황 | 동작/표시 |
|---|---|
| 문구 선택 후 연결 버튼 | 선택 문구는 유지하고 파일을 연결. 선택이 없으면 커서 위치에 파일명 삽입 |
| 탐색기에서 파일 드롭 | 놓은 위치에 파일명 링크 삽입. 파일 내용/이미지를 본문에 삽입하지 않음 |
| 일반 클릭·드래그·더블클릭 | 기존 커서 이동·선택·편집 동작 유지 |
| Ctrl+왼쪽 클릭 또는 우클릭의 열기 | 사용자가 명시적으로 선택한 해당 파일만 기본 연결 프로그램으로 열기 |
| 정상 링크 | 파란 글씨 + 밑줄 |
| 다른 환경·파일 없음·확인 실패 | 파란 글씨 + 밑줄 유지, 링크 옆에 작은 노란 주의 아이콘. 원인은 툴팁/관리 메뉴에서 설명 |
| 다시 연결 | `파일을 다시 연결해 주세요` 창에 표시 문구와 이전 경로, `취소` / `파일 다시 선택` 제공 |
| 다시 연결 성공 | 선택한 링크 범위의 경로·현재 환경 표식만 갱신. 표시 문구·다른 링크는 유지 |
| 링크 해제 | 링크 정보만 제거하고 문구·굵기·글꼴·체크박스·주변 서식 유지 |
| 연결 실패/취소 | 기존 링크와 메모를 보존하고 변경·파일 실행 없음 |

- 사용자 후속 제안(2026-09-20)을 반영한다. 이전에 제안한 주황색 점선 밑줄 대신 **파란 글씨·밑줄 + 주의 아이콘**을 사용한다.
- 우클릭에는 기존 편집 메뉴와 함께 `파일 열기`, `파일 위치 열기`, `다시 연결`, `링크 해제`를 제공한다. 미확인 환경에서는 이전 경로의 파일/폴더를 바로 열지 않고 재연결로 안내한다. 키보드 메뉴 키/Shift+F10으로도 관리할 수 있게 한다.
- 파일 선택창은 선택 범위·대상 메모를 기억하고, 취소 시 본문을 수정하지 않는다. 여러 줄/여러 링크/체크박스 표식을 걸친 선택은 묵시적으로 합치지 않고 한 문구를 선택하도록 안내한다.
- 여러 로컬 파일 드롭은 파일명별 링크를 줄 단위로 추가하고 한 번의 Undo로 되돌린다. 지원하지 않는 항목이 섞이면 변경 전에 안내해 부분 삽입을 피한다. 기존 텍스트/HTML 붙여넣기는 유지하고 과거 문구·경로·외부 anchor를 자동 변환하지 않는다.
- 링크 바로 뒤에서 이어 쓰는 일반 문자는 링크를 의도치 않게 상속하지 않게 한다. 연결/해제는 텍스트를 지우고 다시 삽입하지 않고 선택 범위의 anchor 속성만 다룬다.
- 주의 아이콘은 문자열·이모지·이미지·임베디드 객체로 본문에 삽입하지 않는다. 링크가 있는 편집기에만 표시 여백을 확보하고 해당 링크의 마지막 표시 줄 옆에 벡터로 그리는 방식을 먼저 검증한다. 한 줄에 여러 문제 링크가 있으면 같은 위치의 표시를 묶고 툴팁/메뉴에서 각각 구별한다. 줄바꿈·스크롤·DPI·선택 영역·본문 클릭을 가리지 않는 것이 배치 완료 조건이다.
- 파란 표시도 문서 저장 서식과 분리해 기존 텍스트 색·밑줄을 해제 시 복구할 수 있게 한다. 완료된 할 일의 취소선은 유지하고 링크 식별 표시는 계속 제공한다. 기존 체크박스 마스킹과 충돌하지 않게 공용 표시 경로에서 적용한다.

## 저장과 다른 PC 판별

### 기존 데이터 무변환

- 테이블·컬럼·설정 키·Export 항목·salt 파일을 추가/삭제/변경하지 않는다. `migrate()`, 암호화 키 유도, 구형 Export 복호화, 백업 회전 정책은 유지한다.
- 기존 메모를 시작 시 순회해 변환하거나 재저장하지 않는다. 새 기능이 알아보는 링크는 사용자가 명시적으로 만든 링크뿐이다. 기존 HTML의 일반 anchor·경로 텍스트·Unicode는 그대로 보존한다.
- 경고/확인중/정상 상태는 현재 화면의 파생 상태다. 상태가 바뀌어도 `textChanged`, dirty 상태, Undo 기록, DB 저장을 만들지 않는다.
- 링크 정보는 기존 `sticky_notes.content`와 함께 암호화된다. 원본 파일 바이트는 DB·`.enc`·`.cnbak`에 담지 않으며 백업은 연결 정보를 보존한다.

### 권장 저장안과 먼저 검증할 조건

- HTML의 `<a href="...">표시 문구</a>`를 사용한다. `href`에는 버전이 있는 앱 내부 표현으로 파일 경로와 연결한 환경의 식별 표식을 담는다. 내부 표현은 OS에 프로토콜로 등록하지 않고 외부 실행기로 그대로 전달하지 않는다.
- 예시 구조는 `climatenote-file://v1?path=<URL 인코딩한 로컬 절대경로>&origin=<환경 표식>`이다. 경로의 한글·공백·`&`·`#`·`%`·따옴표·이모지를 표준 URL/문자열 API로 인코딩하고 검증한다. 임의 HTML 문자열 조립이나 정규식 기반 본문 전체 치환은 하지 않는다.
- Qt가 지원하는 anchor 속성만으로 저장한다. 임의 `data-*` 속성이나 메모리에만 있는 `QTextFormat.UserProperty`의 HTML 왕복 보존을 가정하지 않는다. 최종 표현은 아래 1단계의 Qt 6.11.2 합성 왕복 검사 후 확정한다. 실패하면 스키마를 즉시 확장하지 않고 형식 설계를 다시 검토한다.
- 환경 표식은 링크를 연결한 PC·Windows 사용자 환경을 비교하는 비밀이 아닌 식별값이다. 기존 장치/사용자 식별 로직을 재사용하되 링크 전용 구분 문자열로 별도 해시한 읽기 전용 helper를 둔다. MachineGuid 원문·사용자명·암호화 키·PIN·salt를 링크에 넣지 않는다. 기존 키 유도·캐시·salt 생성은 호출/변경하지 않는다.
- 환경을 확인할 수 없거나 표식이 없고 형식이 손상된 신규 링크는 `연결 확인 필요`로 처리한다. 식별값은 인증 수단이 아니며 링크 내용을 신뢰해 자동 실행하지 않는다. OS 재설치/계정 변경 등에는 재연결이 필요할 수 있으나 본문은 보존한다.
- 같은 PC·사용자에서 백업을 가져오면 표식을 유지한다. 다른 환경이면 같은 경로에 파일이 있어도 주의 아이콘을 표시하고 명시적 재선택 전에는 열지 않는다. Import가 링크를 현재 환경으로 자동 승인하거나 내용을 바꾸지 않는다.
- 재연결은 선택한 링크 한 곳에만 적용한다. 표시 문구·체크박스·다른 링크·다른 메모를 바꾸지 않는다. 원본 파일의 이동/재연결도 사용자가 선택한 경로만 저장한다.
- 구형 앱에서 새 링크의 표시 문구와 기존 메모를 읽을 수 있어야 한다. 구형 앱이 링크를 실행하거나 메타데이터를 재저장까지 보존하는지는 별도 합성 호환 검사로 확인하며, 검증 전에는 구버전 재편집까지 완전 호환이라고 주장하지 않는다.

## 저장·UI 수명·실패 처리

- 파일 열기는 검증한 로컬 경로를 `QUrl.fromLocalFile()`로 만든 뒤 기본 연결 프로그램에 전달한다. 내부 href·명령줄 문자열·웹 URL을 셸에 직접 넘기지 않는다. 파일 존재 확인 성공과 외부 프로그램의 실제 열기 성공은 구분하고, 파일을 열지 못해도 링크를 삭제하지 않는다.
- 링크 경로는 사용자 문서이므로 앱 데이터 폴더 밖에 있을 수 있다. 이를 허용하려고 기존 `security.validate_app_path()`의 DB/salt 경계 검사를 완화하지 않는다. 링크용 경로 검사는 별도로 둔다.
- 링크 없는 메모에는 파일 검사나 새 주기 타이머를 붙이지 않는다. 링크 있는 메모의 표시/다시 활성화, 호버, 명시적 열기 시 필요한 항목만 지연 확인하며 결과를 캐시한다. 전체 파일 검색·백업 파일 검색·전체 DB의 링크 스캔은 하지 않는다.
- 파일 상태 조회는 GUI를 멈추지 않도록 처리한다. 경로 조회 실패·시간 초과·권한 오류는 `확인할 수 없음`으로 구분하고 무조건 `파일 없음`으로 표시하지 않는다. 아직 확인하지 않은 상태를 정상 확인으로 오인시키지 않는다. 드롭/선택/열기 전에 로컬 경로 대상 여부를 확인한다.
- 비동기 결과에는 문서 세대·메모 ID·대상 href를 연결한다. 사용자가 링크를 지우거나 바꾼 뒤, 패널 재생성·잠금·트레이·초기화·종료 뒤 도착한 결과는 무효화한다. worker에서 QWidget/DB를 직접 조작하지 않는다.
- 파일 선택·재연결 창·메뉴의 대상은 처음 요청한 편집기와 선택 범위로 고정한다. 파일 창이 닫힌 뒤에도 현재 등록된 편집기인지, 잠금/읽기 전용/폐기 상태인지 다시 확인한다. 초기화로 ID가 재사용되어도 이전 요청을 새 메모에 적용하지 않는다.
- 잠금·트레이 숨김·원본이 바뀌는 모드 전환·초기화 시 새 팝업/파일 대화상자와 예약된 결과 반영을 취소한다. 기존 `MainCalendarWindow`의 수명 관리 진입점에 필요한 호출만 추가한다.
- 복호화 실패 메모는 링크 추가/수정/드롭/열기 대상에서 제외하고 원본 암호문을 유지한다.
- 링크 편집도 기존 2초 저장·재시도·종료 저장을 사용한다. 실패한 편집 내용은 현재 편집기에 남고 종료·휴지통·모드 전환·가져오기·초기화는 기존 저장 게이트로 보류한다. large에서는 미니 패널이 유일한 최신 원본이다.
- Export는 PIN 입력 검증 → 잠금/현재 편집 저장 확인(`_prepare_data_change()`) → DB snapshot → PIN 암호화 → 기존 원자 파일 저장 순서로 한다. 저장 실패 때 출력 파일 생성/교체를 시작하지 않는다. 이미 존재하는 백업과 저장 실패한 편집 원본은 보존한다.

## 구현 순서와 단계별 통과 조건

1. **합성 보존 기준·저장 표현 검증**: 기존 평문/HTML/체크박스/여러 서식 메모와 합성 링크를 준비한다. Qt의 toHtml/setHtml·앱의 PIN Export v1/v2 호환·모의 PC A/B 표식·한글/특수문자 경로 왕복을 검사한다. 앱 코드 편입 전에 새 DB 컬럼 없이 표현을 보존할 수 있는지 확정한다. 실제 장치 정보·사용자 파일은 사용하지 않는다.
2. **공용 링크 편집과 데이터 보존**: 파서와 편집 동작을 구현하고 플로팅/미니 패널에 같은 기능을 연결한다. 선택 본문·주변 서식·Undo/Redo·링크 끝 추가 입력·체크박스 상호작용을 먼저 검증한다. 링크 없는 입력은 기존 이벤트 처리로 그대로 전달한다.
3. **상태 표시·재연결·파일 열기**: 파란 글씨/밑줄과 저장되지 않는 주의 아이콘, 지연 파일 확인, 현재 링크만 재선택, Ctrl+클릭/키보드 메뉴를 구현한다. 자동 파일 열기는 없고 모든 외부 실행 테스트는 호출을 가로채 합성 경로 인자를 검사한다.
4. **저장 경계·수명 통합**: Export의 최신 저장 게이트를 먼저 적용한 뒤, 잠금/트레이/보기 전환/가져오기/초기화와 선택창·비동기 결과의 교차 시나리오를 검증한다. 저장 실패를 주입해 사용자 편집과 기존 백업 보존을 확인한다.
5. **전체 회귀·배포 판단 분리**: 현재 입력으로 full 또는 release를 실행하고 기존 사용자 업그레이드 시나리오·두 보기·구형 Export·실제 EXE 표시를 확인한다. 모든 필수 보존 검사가 통과하기 전에는 배포 준비 완료로 표시하지 않는다.

### 명령과 증거

- 환경: `.\.venv\Scripts\python.exe tools/verify.py doctor`.
- 개발 중 관련 UI 검사: `quick --tests tests/test_sticky_file_links.py tests/test_ui_sticky_file_links.py tests/test_ui_sticky.py tests/test_ui_sticky_panel.py` (신규 테스트 파일 작성 후 사용).
- 저장/Export 중간 검사 필요 시 `data`; 새 테스트는 관련 quick 또는 전체 검사에 포함한다.
- 기능 완료: `full` 1회. 같은 입력으로 바로 배포 산출물까지 검사할 때는 `release`로 전체 pytest→새 EXE→격리 smoke를 수행한다. `full`/`release` 전에 하위 프로필을 의무적으로 중복 실행하지 않는다.
- 새 EXE를 검증할 때는 현재 release의 기존 합성 메모와 함께 링크 있는/없는 메모의 보존을 확인하고, 문서에 현재 산출물 SHA-256·내부 Qt 버전·실제 EXE UI 확인 결과를 기록한다. 현재 `dist`는 검증 전 덮어쓰지 않는다.
- 매 실행의 `output/harness/<run-id>/summary.md`·`result.json`을 이 기록에 연결한다. 모든 기능 테스트는 실행별 합성 AppData/파일을 사용하고 실제 문서나 실행 중 앱을 열거나 정리하지 않는다.
- 수동: 실제 한글 IME, 파일 선택/드롭/기본 프로그램 열기, 접근 불가 파일, 실제 Windows 잠금·Win+D·혼합 DPI/KVM. 미확인은 자동검사 통과와 구분한다.
