## 결정과 진행

- 사례는 이미 사용한 200원문 corpus에서 받침·CLI·유사 영숫자·기호·표의 고정 원문 15종, 기준/10px/12px/어두움/넓은 영역 각 5조건과 표 125% 한 사례로 선택한다(76개). 오류를 알고 선택한 진단 표본이며 전체 정확도 추정이나 독립 최종 평가가 아니다. 기존 holdout은 사용된 자료임을 명시한다.
- actual `_rec.run` 출력과 제품 `ctc_decode` 입력의 공유 메모리·순서를 확인하고, 제품 반환값은 바꾸지 않는다. raw 전체 확률은 파일에 저장하지 않고 단계별 상위 5개/blank·연속 구간·요약을 기록한다. 진단 시간은 별도 표시하며 관측 중 처리 시간은 제품 성능 비교에 사용하지 않는다.
- beam은 width 8, timestep 상위 5개+blank+각 prefix 끝 글자를 고정하며 사전/언어 모델/정답 문자열을 사용하지 않는다. 가지치기한 근사 탐색이므로 최고 정확도나 정확한 MAP 결과라고 주장하지 않는다.
- 정답 점수는 추론 이후 평가에만 사용한다. 명확히 1:1 대응하는 주석만 사용하며 없거나 겹친 경우 제외한다. 공백 차이에 가려진 글자 오류를 위해 공백 클래스를 blank와 합친 분포의 문자열 log mass를 별도 계산한다. 이것은 문자열의 정답 확률이나 원인 확정값이 아니다. 같은 픽셀 입력/모델 분포에서 오답을 선호한다는 단서이며 입력 잘림·전처리와 모델 자체를 단독 분리하지 않는다.
- CTC의 반복/blank 규칙과 greedy/sequence mass 구분: [Graves 등 원 논문](https://www.cs.toronto.edu/~graves/icml_2006.pdf). 공식 greedy 구현 대조: [PaddleX release/3.7](https://github.com/PaddlePaddle/PaddleX/blob/release/3.7/paddlex/inference/models/text_recognition/processors.py). 외부 코드를 프로젝트에 복사하지 않고 작은 독립 구현을 완전 탐색으로 검증한다.
