## 결정과 진행

- 2026-10-10 측정 14: 머리줄 실제 글자 색은 날짜 `#1a1a1a`, 음력 `#2e7d32`(굵게), 공휴일 `#d32f2f`, 개수 `#757575`였다. 점검 보고서의 "개수 파랑"은 ClearType 글자 번짐으로 보인 것이라 개수는 이미 회색이었다. 음력만 회색·보통 굵기로 바꿨다.
- 결정 10: 계약("6개 슬롯 DB 행 유지, 64px 버튼, 기존 X 삭제 지원")을 지키며 덜어 냈다. 빈 칸은 숨길 뿐 DB 행은 그대로이고, 첫 빈 칸이 '+ 추가'(이름 `추가`)다. 칸이 바뀔 때 `ShortcutSlot.changed` 신호로 사이드바가 다시 고른다(등록·삭제·드래그 모두 `update_data`를 거친다). 숨긴 빈 칸에는 끌어 놓을 수 없지만 보이는 추가 칸에 끌어 놓으면 된다. 빈 칸·강조 파랑은 앱 색(`#9AA6B5`/`#2563EB`)으로 맞췄다.
- 결정 13: `ScheduleRow`가 마우스 올림·현재 줄 여부로 삭제 버튼을 보이고, `setRetainSizeWhenHidden`으로 자리를 남겨 글자가 밀리지 않는다. 키보드로 줄을 고르면(`currentItemChanged`) 보인다. 우클릭 메뉴의 삭제는 그대로다.
- Ruling: 기존 시험 3개를 바뀐 동작에 맞췄다 — (1) 사이드바 로드 시험은 ×가 처음엔 숨고 마우스를 올리면 보이는지로, (2) 삭제 시험은 지운 칸 이름이 `추가`인지로, (3) 짧은 화면 스크롤 시험은 여섯 칸을 모두 채운 뒤 여섯 번째 칸 접근을 본다(빈 칸이 하나만 보이므로) — 원래 확인하던 X 삭제 지원·DB 갱신·6번째 칸 접근은 그대로 검사한다.
- 전/후 캡처: `output/design/design-audit-20261009/img/fix1014/`(수정 전 = main `56cc3da`의 `ui_main.py` 사본), 마우스를 올린 상태 포함. 보고서 "10·13·14번 수정 결과" 절.
