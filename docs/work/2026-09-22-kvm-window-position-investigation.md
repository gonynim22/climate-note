## 결정과 진행

- 관련 정본: [UI 계약](../UI_PATTERNS.md), [아키텍처](../ARCHITECTURE.md), [검증](../TESTING.md).
- `_on_screen_changed()` → `_apply_calendar_geometry()`는 일시 화면에 맞춰 보정한 자유 위치를 `calendar_x/y`에 저장한다. 이후 원래 화면이 복구되어도 원래 좌표를 잃을 가능성이 있다.
- `_get_target_screen()`은 물리 화면 식별값 없이 `QApplication.screens()`의 저장된 숫자 인덱스를 사용한다.
- `3935b46` (2026-08-19)은 목적지 화면에 맞는 크기 재계산을 추가했다. 기존 검사는 화면 안에 들어오는지 확인하며, 분리→재연결 왕복의 좌표 보존과 화면 목록 재정렬은 검사하지 않는다.
- `5cd3e38` (2026-09-20)은 large에서 막던 드래그를 이동 토글 ON일 때 허용했다. 드래그 완료는 `calendar_position_mode=free`를 저장한다. 기존 자유 좌표 저장 결함이 large에서도 더 쉽게 드러날 수 있다는 가설이며, 회사 PC의 직접 원인으로 확정하지 않는다.
- 재현 파일 이름은 `test_*.py`가 아니므로 일반 전체 검사에 자동 포함되지 않는다. 명시적으로 실행하면 기대하는 위치 보존 계약의 실패를 보고하며 xfail로 숨기지 않는다.
- 사용자 추가 관측: 오류 발생 후 앱 이동 버튼을 누르고 수동으로 조절하면 원위치로 되돌릴 수 있다. 설정 모니터/모서리 재선택 결과나 OS의 실제 분리 이벤트가 확인된 것은 아니다.

### 확인한 원인과 영향 범위

1. **자동 보정 좌표가 사용자가 지정한 좌표를 덮어쓴다.** `ui_main.py:3440`의 화면 변경 처리에서 `1439`의 기하 적용 함수를 호출한다. 자유 위치이면 임시 보정값까지 `calendar_x/y`에 저장한다. 화면 제거 후 500ms 타이머가 발동할 만큼 임시 구성이 지속되면 원래 위치를 잃을 수 있다. 모니터가 돌아와도 마지막 임시 좌표를 새 작업 영역으로 clamp하므로 원래 여백이 복구되지 않는다. 이동 ON/OFF는 수동 드래그 허용만 바꾸므로 이 문제를 막지 않는다.
2. **대상 화면을 순번으로만 기억한다.** `ui_main.py:3395`는 `screens[target_idx]`를 사용한다. 두 모니터의 목록 순서를 바꾸면 free/corner × 세 크기 모두 물리적으로 다른 화면을 선택한다. 회사 KVM에서 실제 목록 재정렬이 일어나는지는 미확인이다.
3. **기존 검사의 공백이다.** 기존 화면 변경 검사는 `_get_target_screen`을 직접 지정하고 한 번의 목적지 크기/화면 내부 여부만 검사한다. 원래 화면의 정체성이나 분리→재연결 후 좌표 복구는 보장하지 않는다. 기존 검사가 통과하면서 새 재현이 실패했다.

합성 환경은 왼쪽 가로 `(0,0,1920,1080)`, 오른쪽 세로 `(1920,0,1080,1920)`, 96 DPI다. 숨겨진 실제 `MainCalendarWindow`와 격리 DB를 사용하고 Qt 화면 목록 조회를 합성값으로 치환했다. 실제 KVM 이벤트/Win32 창 이동/혼합 DPI를 재현했다고 주장하지 않는다.

| 자유 위치 크기 | 전환 전 (x,y,w,h) | 오른쪽 분리 중 | 재연결 후 | 결과 |
|---|---|---|---|---|
| compact | 1940,20,380,660 | 1540,20,380,660 | 1920,20,380,660 | 원래 x 좌표 손실 |
| medium | 1940,20,648,1152 | 768,20,1152,648 | 1920,20,648,1152 | 원래 x 좌표 손실 |
| large | 1940,20,1040,1880 | 40,20,1880,1040 | 1920,20,1040,1880 | 원래 x 좌표 손실 |

large는 좌우 20px 여백이던 창이 왼쪽 0px/오른쪽 40px로 바뀌어, 화면 안에 들어와도 중앙에서 20px 벗어난다. 이동 ON/OFF 양쪽에서 동일했다. 목록 순서가 같은 모서리 모드 왕복 3건은 원위치로 복구됐다. 이는 모든 KVM 상황에서 모서리 모드가 안전하다는 뜻은 아니다(순서 변경 3건은 실패).

Qt도 화면 제거 시 별도 처리가 없으면 기본 화면으로 창을 이동한다고 명시한다. [QGuiApplication::screenRemoved](https://doc.qt.io/qt-6/qguiapplication.html#screenRemoved). 화면 복원 설계에서 장치 식별자를 추가할 때 `QScreen.name()` 하나를 고유 ID로 쓰면 안 된다. [QScreen::name](https://doc.qt.io/qt-6/qscreen.html#name-prop).
