# 작업 기록: large 캘린더 요일 열 너비 조사

작성일: 2026-09-11 / 상태: 원인 조사 완료 (앱 수정 미실시)

이 기록은 수정 전 조사 결과다. 후속 구현·검증·커밋·push는 [요일 열 너비 수정 기록](2026-09-11-calendar-column-width-fix.md)을 본다.

## 목표와 범위

- 목표: 세로 모니터의 large 보기에서 금·토 열이 좁아지고 월 이동 후 오늘로 돌아오면 회복되는 원인을 재현·설명한다.
- 변경 대상: 조사 기록과 합성 데이터 진단 코드. 앱 동작 수정은 이번 원인 조사 범위에서 제외한다.
- 데이터 영향: 실행별 격리 AppData만 사용한다. 실사용 DB·salt·설정·실행 중 앱에 접근하지 않는다.
- 시작 시 사용자 변경: `.gitignore` 수정이 있으며 보존한다.

## 결정과 진행

- 2026-09-11: `CalendarDayButton._make_chip()`은 현재 컨테이너 폭으로 문자열을 말줄임하고 QLabel에 저장한다. 그리드는 열 stretch/minimum을 지정하지 않는다. 화면 변경은 창 크기를 바꾸지만 월 이동은 날짜 셀 전체를 재생성한다. 이 세 경로의 상호작용을 조사한다.
- 2026-09-11: `diagnostics/calendar_columns_probe.py`로 현행 앱 코드를 불러와 합성 일정·합성 작업 영역·Qt offscreen 플랫폼에서 측정했다. 매 실행 전에 LOCALAPPDATA를 새 `output/harness/<run-id>/appdata`로 지정한다. `baseline` 외 옵션의 변경은 진단 프로세스 안에서만 적용하며 앱 파일을 수정하지 않는다.

## 확인한 원인

일정 칩의 **현재 표시 폭 → 말줄임된 QLabel 문자열 → 셀 최소 권장 너비 → 그리드 열 너비**가 순환한다. 화면의 최종 크기와 일정 데이터가 같아도 셀을 생성·갱신한 경로에 따라 다른 너비에 머무를 수 있다.

1. `ui_main.py:589`의 `_make_chip()`은 `self._chips_container.width() - 12`로 말줄임한 문자열을 `QLabel.setText()`에 넣는다. 라벨의 가로 size policy는 기본값이며 문자열의 크기 요구가 상위 레이아웃까지 전달된다.
2. `ui_main.py:613`의 `set_events()`는 칩을 폐기·재생성하고, `resizeEvent()`에서도 같은 함수를 부른다. 넓은 열의 긴 문자열은 큰 최소 권장 너비를 계속 요구하고 좁은 열의 새 문자열은 짧게 잘린 결과로 다시 측정된다.
3. `ui_main.py:1545`의 날짜 그리드는 7열의 stretch/minimum을 명시하지 않는다. Qt는 자식 위젯의 최소 너비를 열의 최소 너비로 반영한다. stretch만 동일하게 지정해도 서로 다른 최소 너비는 남는다. [Qt QGridLayout 공식 설명](https://doc.qt.io/qt-6/qgridlayout.html#details)
4. 일정 추가는 `ui_main.py:2187`의 `_refresh_cell_for_date()`에서 해당 셀만 갱신한다. 금·토 열이 이미 좁으면 새 일정도 그 폭에서 `…`로 잘리고 작은 최소 권장 너비로 남아 열이 회복되지 않는다.
5. 월 이동·오늘은 `ui_main.py:1961`의 `_refresh_calendar()`에서 모든 날짜 셀을 폐기·재생성한다. 기존 너비 계산 이력이 끊기므로 같은 데이터로도 다른 열 배분이 나온다. `ui_main.py:3300`의 화면 변경은 창의 기하만 변경하고 이 셀 재생성 경로를 실행하지 않는다.
6. 요일 제목은 `ui_main.py:1866`의 별도 QGridLayout이다. 일정에 따라 날짜 열이 달라져도 제목 열은 연동되지 않으므로 제목과 날짜 중심의 어긋남도 함께 나타난다.

금·토에 별도 축소 규칙이 있는 것은 아니다. 이번에는 월~목의 긴 일정이 너비를 차지하고 비어 있던 일·금·토가 좁아진 패턴을 사용해 사용자 증상을 재현했다. 모든 요일에 같은 긴 일정이 있는 대조 입력에서도 재생성·화면 변경 경로에 따라 열 배분이 달라져, 일정 분량만으로 정당화되는 차이가 아님을 확인했다.

### 핵심 재현 (논리 작업 영역 864×1536)

1080×1920 화면의 125% 배율에 대응하는 논리 크기를 합성했으며, 실제 회사 모니터 설정을 확인한 것은 아니다. 작업표시줄 차감·실제 DPI 전환도 이 입력에 포함하지 않는다.

월~목에 긴 합성 일정 → 첫 표시 → 금·토에 새 일정 추가 → 다음 달 → 오늘. 단위는 Qt 논리 px, 열 순서는 일·월·화·수·목·금·토다.

| 상태 | 열 너비 |
|---|---|
| 첫 표시 | 31 / 79 / 79 / 79 / 79 / 30 / 31 |
| 금·토에 일정 추가 | 31 / 79 / 79 / 79 / 79 / 30 / 31 |
| 같은 데이터로 월 이동 후 오늘 | 26 / 64 / 63 / 64 / 64 / 63 / 64 |

일정 추가 직후 금·토 칩에는 실제로 `…`만 표시된다. 이미지와 각 셀·칩의 geometry/minimumSizeHint/text는 해당 실행의 PNG와 `result.json`에 보존했다. 1080×1920 논리 크기에서도 첫 표시의 금·토 70/69px가 월 이동 후 99/100px로 바뀌었다.

### 원인 분리 실험

| 진단 프로세스에만 적용한 조건 | 결과 |
|---|---|
| `baseline`: 현행 코드 | 위 증상 재현 |
| `stretch`: 그리드 7열에 stretch=1만 설정 | 현행과 동일한 30/31px 축소 및 월 이동 후 회복 |
| `ignored`: 일정 칩 가로 size policy를 `Ignored`로 설정 | 첫 표시·일정 추가·월 이동·가로→세로 전환 모두 58/59px 유지 |
| `both`: 위 두 조건 결합 | 동일하게 58/59px 유지 |

`Ignored`는 문자열 sizeHint를 가로 배분 입력에서 제외하는 대조 조건이다. [Qt QSizePolicy 공식 설명](https://doc.qt.io/qt-6/qsizepolicy.html#Policy-enum). 이 조건은 원인 분리 실험이며 출시용 수정 검증을 뜻하지 않는다.

수정 방향은 칩의 말줄임 결과가 열 최소 너비에 역으로 영향을 주지 않게 하고, 날짜 열과 요일 제목에 안정적인 너비 배분을 적용하는 것이다. 이후 실제 배치된 칩의 말줄임·툴팁·높이·오버플로와 compact/medium 호환까지 회귀 검증해야 한다.
