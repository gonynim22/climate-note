## 결정과 진행

- 사전 후보: 검출 입력의 비율 유지+32배수 패딩(`det-aspect`), 인식 최소320패딩+전체 CTC(`rec-320`), 균일한 어두운 배경만 반전(`rec-light`), 균일 배경의 실제 글자 픽셀 경계+글자 높이 20% 여백(`rec-ink`). 마지막 두 후보도 최소320패딩과 전체 CTC를 사용한다. 고정2배 확대/일괄 unclip 축소는 앞 실험에서 퇴행해 제외한다.
- 균일 배경 판정·대조도 문턱·여백은 코드에 고정한다. 정답으로 결과를 선택하거나 단어를 교정하지 않는다. dev 개별 후보의 근거가 충분하면 유효한 처리들을 결합해 dev에서 다시 평가한다.
- 수용 기준: 공백 제외 CER와 엄격 CER 모두 감소, 완전 일치 사례 증가, 숫자·날짜 합계 오류 및 표 셀 오류 증가 없음, 중앙 처리 시간 1.5배 이하. 신규 오류를 숨기지 않으며 개선이 특정 한 사례에 집중되는지 확인한다. holdout에서도 같은 기준을 만족해야 제품 적용한다. 미달 시 제품 적용을 보류하고 실제 수치와 이유를 보고한다.
- holdout은 후보 고정 뒤 baseline과 최종 후보만 실행하고 결과로 추가 튜닝하지 않는다. 합성 200원문×12조건의 결과이며 실제 업무 화면 정확도라고 일반화하지 않는다.
- 대규모 진단은 수동 명령 전용이며 통상 테스트/빌드에 연결하지 않는다.
- dev 1차: det-aspect는 공백 제외 오류 744→660/표 셀 오류 45→42, rec-320은 745/65, rec-light는 743/64, rec-ink는 634/69였다. rec-320/rec-light는 제외한다. rec-ink의 인식은 개선되지만 패딩의 표 퇴행이 있어, 기존 배치 폭·CTC 절삭을 유지하는 `rec-ink-native`와 det-aspect 결합 `det-ink-native`를 추가한다. 글자 높이 4px 미만 및 인식 정규화 폭이 원래보다 2배를 넘는 변환은 건너뛰어 가는 선의 입력 폭 폭증을 막는다. holdout 미실행 상태에서 고정했다.
- 일괄 정규화의 숫자 분류 퇴행 8개를 확인했다. 7개는 O/0/I/1/l 혼합 식별자의 서로 다른 변형, 1개는 작은 글자의 ‘허용→허응’이며 일부는 정규화 뒤 점수도 낮아졌다. 일괄 적용 대신 기존 평균 점수 <0.97인 상자만 픽셀 정규화로 한 번 재인식하고, 비어 있지 않은 새 결과의 점수가 최소 0.02 높을 때만 교체하는 `rec-selective`도 후보로 사전 고정한다. 점수가 정답 확률이라는 가정은 하지 않으며 실제 오류로 검증한다. 임계값 탐색/정답 기반 선택/단어 규칙은 하지 않는다. dev 선별 뒤 하나만 holdout 평가한다.
- `rec-selective`는 비공백 오류 744→666, 표 오류 45→45, 숫자·날짜 62→59, 중앙 시간 1.27배였지만 엄격 오류는 3791→3864로 늘었다. 평균 점수로 공백만 달라진 결과를 선택하면서 띄어쓰기가 손상됐다. `rec-selective-stable`은 두 결과의 공백 제외 글자가 같으면 원래 문자열과 점수를 보존한다. 정답을 입력하지 않는 선택 규칙이며 새 공백을 만들어 넣지 않는다. 저장된 출력의 같은 규칙 대조에서 엄격 오류 3721/표 오류38이었으며 별도 실제 모델 실행으로 확인한다. holdout은 여전히 미사용이다.
- 여러 번 디코딩한 사례의 문자별 최소 점수는 거절된 후보까지 포함하므로 `score_scope=all_hypotheses`로 구분하고 최소 점수 기반 모의 경고 분석에서 제외한다. 제품의 실제 경고 수와 무경고 오류 채점은 유지한다.

- dev의 감소 78자 중 47자는 이전 넓은 URL 한 사례다. 해당 사례를 빼면 순감소는 31자로 개선이 일부 어려운 사례에 집중된다. holdout도 전체 오류 7자 감소 중 6자가 `<label>` 문자열 한 사례에서 나왔다. 개선 사례만으로 일반 정확도 상승을 주장하지 않는다.
- 원문 묶음 단위 paired bootstrap 10,000회(seed 20261010)의 공백 제외 CER 감소 95% 백분위 구간: dev +0.0380~+0.3915%p, holdout **-0.0463~+0.1947%p**. 12변형을 독립 표본으로 세지 않았다. holdout은 0을 포함해 개선 방향도 확증하지 못했으며 실제 업무 화면으로의 일반화를 뜻하지 않는다.
- holdout 신규 오류: `cond-batchim-017--font10`은 원래 맞던 문장의 마침표가 누락됐고, `cond-table-018--scale125`는 단위 `s`가 `S`가 됐다. CLI `cond-cli-020--font12`의 반복 `#` 누락은 4→6자로 악화됐다. 마지막 두 원본 PNG를 직접 열어 확인했다. 작은 글자·반복 문자·기호의 재인식 점수 상승이 정답을 보장하지 않았다.

- 정본 문서: `docs/SCREEN_TEXT_LAB.md`, `docs/TESTING.md`, `docs/SCREEN_TEXT.md`. 모델/사전/의존성/제품 코드/EXE와 사용자 DB·설정은 그대로다.
