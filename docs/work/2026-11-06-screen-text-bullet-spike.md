# 작업 기록: 글머리 기호 복원 시험(spike)

작성일: 2026-11-06 / 상태: 시험 완료. 사용자 승인으로 제품에 반영함(2026-11-06, [적용 기록](2026-11-06-screen-text-bullet-symbols.md)). 고리는 확인 필요 표시로 결정

## 목표와 범위

- 목표: 공문서 글머리 기호(`□ ㅇ ■`)가 줄 첫머리에서 거의 읽히지 않는 문제를, 줄 맨 앞 덩어리의 **모양**으로 분류해 복원할 수 있는지 확인한다. 근거와 문제 크기는 [실패 분석 기록](2026-11-05-screen-text-failure-analysis.md)(남은 글자 오류의 51%가 기호, `■` 95%·`□` 100%·`ㅇ` 54% 못 읽음).
- 변경 대상: 없음. 제품 코드·테스트·문서를 바꾸지 않았다. 시험 코드는 `output/screen_text_lab/analysis-20261105/scripts/bullet_post.py`이며 평가 도구가 제품 `_read`의 결과에 덧씌운다.
- 데이터 영향: 없음. 글자 판독은 바꾸지 않고, 줄 맨 앞의 기호 모양 덩어리만 기호로 낸다.
- 제외 범위: 제품 반영, 테스트 작성, 기호 표시 방식 결정.

## 방법(spike)

- 상자 왼쪽 최대 상자 높이의 2.5배(왼쪽 이웃 상자가 있으면 그 오른쪽까지만)를 포함한 영역에서 글자 픽셀을 찾아 왼쪽부터 덩어리로 나눈다. 표 테두리·괄호처럼 가늘고 긴 덩어리(가로/세로 < 0.4, 높이 ≥ 0.6)는 건너뛴다.
- 첫 덩어리가 다음 글자와 폭의 절반(최소 3px) 이상 떨어져 있고 모양이 맞으면 기호로 본다.
  - 속이 찬 정사각(채움 ≥ 0.85, 중앙 ≥ 0.9, 가로세로 0.7~1.4) → `■`
  - 속이 빈 정사각(중앙 ≤ 0.1, 가로세로 0.75~1.3): 네 모서리 점유가 0.37 이상이면 `□`, 아니면 `ㅇ`
- 덩어리가 상자 안이고 모델이 `0 o O ㅇ C c D . : - □ ■ ▪ ○ ● ㅁ` 중 하나로 읽었으면 교체하고, 그 외이거나 상자 밖이면 앞에 붙인다.
- 임계값은 dev 한 줄짜리 크롭 36줄의 특징값으로 정했다. 평가는 **새로 뽑은 쪽**(앞선 평가 자료 99쪽과 겹치지 않는 59쪽, 708장, `pdf-eval2-20261106/`)에서 했다.

## 결과 (새 쪽 708장, 제품 코드 = 공백 복원만 vs spike)

| 지표 | 제품 | spike |
|---|---|---|
| `■` 못 읽음 (334개) | 315 (94%) | 28 (8%) |
| `□` 못 읽음 (289개) | 289 (100%) | 22 (8%) |
| `ㅇ` 못 읽음 (804개) | 445 (55%) | 71 (9%) |
| 글자 누락·오독, 관대 / 엄격 | 2.77% / 4.21% | **2.29% / 3.92%** |
| 단어 일치율, 관대 / 엄격 | 86.5% / 81.7% | **88.2% / 83.0%** |
| 한두 줄 크롭 완전 일치, 관대 / 엄격 (236줄) | 82 / 55 | **112 / 77** |

- dev 294장(임계값을 정한 자료)에서는 글자 누락(관대) 2.99% → 2.21%, 한두 줄 완전 일치 30 → 46/98로 효과가 더 컸다.
- 한 줄짜리 크롭 110개(새 쪽): 기호가 없는 줄 90개 중 **잘못 붙인 것 0**, 기호 줄은 `■` 4/4, `ㅇ` 11/12, `□` 2/4(오판 1·놓침 1).
- 쪽·블록 전체에서 "잘못 더해진" 기호는 `□` 80·`ㅇ` 118·`■` 4개로 센다. 판독이 기호로 시작한 줄을 정답의 같은 내용 줄과 맞춰 보면 `□` 272줄 중 241줄, `ㅇ` 710줄 중 574줄, `■` 295줄 중 247줄이 맞고, 틀린 것의 대부분은 정답 글자 레이어가 **모양이 비슷한 다른 기호**(`◦` 작은 고리, `○`, 글꼴 기호 `o`, `◇`, `①`)를 쓴 줄이다. 진짜 모양 혼동(`□`↔`ㅇ`)은 약 15줄이다.

## 한계와 위험

- 모양만 보므로 `ㅇ ◦ ○ o ◇`는 구별하지 못하고 모두 `ㅇ`(또는 크기에 따라 `□`)로 나온다. `■`와 `▪`도 구별하지 못해 `■`로 낸다. 크기로 `ㅇ`와 `□`를 가르는 경계(모서리 0.37)는 글꼴·배율에 민감할 수 있다.
- 줄 중간에 이어 붙은 항목의 기호(같은 줄에 두 항목)와 표 칸 안 첫 글머리는 이웃 상자 경계에 의존한다.
- 시험 구현은 판독 문자열을 후처리한다. 제품화하려면 `_read` 안에서 CTC 위치와 함께 처리해 이중 공백을 막고, 기호를 노랗게 표시할지(확인 필요) 정해야 한다.
- 한 문서·한 기관의 서식이다. 한글(HWP)·엑셀 화면, ClearType, 어두운 배경에서는 미측정이다. 새 쪽 평가는 임계값을 정한 뒤 처음 본 자료지만 앞선 평가와 같은 PDF다.

## 결정 대기(사용자)

1. 제품에 넣을지(추천: 넣는다). 구현 시 `_read` 안에서 처리하고 TDD로 시험(순수 함수 + Qt 합성 줄), `docs/SCREEN_TEXT.md` 갱신, quick/release.
2. 닮은 고리 기호(`◦ ○ o ◇`)를 `ㅇ`로 내도 되는지, 아니면 노랗게 '확인 필요'로 표시할지.
3. `△ ▲ ㎡` 등 사전에 없는 글자와 사전에 있어도 거의 못 읽는 `⇒ Ⅳ Ⅴ`는 이 시험의 범위 밖이다(미해결).
