## 결정과 진행

- 2026-11-11: B의 9건을 코드에서 다시 짚었다.
  1. `update_check.proxy_for`가 프록시 주소의 스킴을 보지 않아 `socks5://…`도 HTTP 프록시로 넘긴다.
  2. `build_app.OPENSSL_FILE_NAMES`에 Git Bash의 `libcrypto-3-x64.dll`·`libssl-3-x64.dll`이 없다(release 검사는 잡지만 빌드 거르기는 놓친다).
  3. `verify.openssl_check`가 UPX로 압축돼 글자를 볼 수 없는 파일을 보고만 하고 통과시킨다.
  4. `test_closed_proxy_is_connection_error`가 포트 9를 닫힌 포트로 가정한다.
  5. `winhttp_get._get`이 1ms 미만 제한을 `int()`로 0(WinHTTP에서 무한)으로 만든다.
  6. `WinHttpSendRequest`에 헤더 길이를 파이썬 글자 수로 넘긴다(UTF-16 길이와 다를 수 있다).
  7. `run_without_openssl.py`의 종료 코드 3 문구가 무엇 때문인지 밝히지 않는다.
  8. `test_module_has_no_qt_db_or_openssl`·`test_source_never_relaxes_certificate_checks`가 소스 글자를 찾는다(주석에 걸리고 별칭·숫자 옵션은 놓친다).
  9. `exe_handoff_check.py` 맨 위 설명이 실제로 대조하는 것(데이터 불변·건강 검사)과 다르다.
- A는 초기화 경로도 같은 문제가 있어(인터넷 스위치만 맞춘다) 함께 고친다. 초기화 뒤 일정 색 선택기가 예전 색을 보이면 한 칸만 바꿔도 나머지 칸의 예전 색이 저장되므로 일정 색도 다시 보인다.
- A 구현: `SettingsWindow._show_saved_settings()`가 처음 열 때와 같은 규칙(`_saved_monitor_index`·`_saved_font_index`로 뺐다)으로 컨트롤을 DB 값으로 맞추고 신호를 막는다. 기존 시험 `test_reset_succeeds_even_if_key_cannot_be_read_back`이 '초기화는 끝났는데 다시 읽다 실패해 초기화 실패로 보이면 안 된다'를 지켜, 다시 읽기는 `_show_saved_settings_safely()`로 감싸 실패해도 감사 로그만 남기고, 초기화는 DB를 읽지 않고 인터넷 스위치부터 끈다(가져오기도 같은 시험을 새로 넣었다).
- B 구현: 1 http·https 밖 스킴은 ValueError(요청 없이 `connection`). 2 `-x64` 두 이름 추가. 3 UPX 압축 파일이 있으면 `VerificationFailure`(지난 release는 0개). 4 `_closed_port()`. 5 제한 시간은 0보다 큰 유한한 값만 받고 1ms 아래로 깎지 않는다(감시로 `(0, 0, 0, 0)`을 넘기던 것을 확인). 6 헤더 값은 인쇄할 수 있는 ASCII와 탭만 받아 글자 수가 곧 UTF-16 길이다. 7 먼저 불린 모듈과 막지 못한 까닭을 문구에 적는다. 8 소스 글자 대신 AST의 import·속성 이름(update_check), 실제 요청에서 넘긴 옵션 번호(winhttp_get: 63·84만)로 시험한다. 9 도구 설명을 실제 대조 항목으로 고쳤다.
- 정본 문서: `docs/UI_PATTERNS.md`(설정창 다시 읽기), `AGENTS.md`·`docs/CODING_STANDARDS.md`(프록시 스킴·헤더·제한 시간·`-x64`·UPX), `docs/TESTING.md`(UPX 실패).
