## 결정과 진행

- 기존 엔진 `_detect → _read → ctc_decode → build_blocks`의 결과를 관측만 한다. 모델 입력에는 이미지/좌표만 들어가고 정답은 출력 후 채점한다. 실제 원본 앱이나 실사용 데이터는 열지 않는다.
- 선택 진단 대상은 `real-doc-09/12/15/34`의 ppm이며 오류를 본 뒤 고른 개발 사례임을 명시한다. 같은 처리로 전수 16영역을 재실행해 검출/입력의 일치를 확인한다.
- 수질표 36/37의 상자 좌표상 병합 셀 라벨이 기존 행 경계를 넓혀 다음 행을 흡수하는 가설을 세웠다. 표 선 인식은 제품에 없으며 이번에 추가하지 않는다.
- **실행 전 고정한 단일 실험**: 기존 세로 겹침 조건에 `상자 중심과 현재 행 중심의 중앙값 차이 ≤ 작은 쪽 높이의 0.5배`를 추가한다. 행 높이도 구성 상자 높이 중앙값을 쓴다. 글자/점수/상자 좌표는 그대로 두고 줄 묶기만 소유 worker에서 한 호출 동안 교체한 뒤 복원한다. 정답/문서 ID/단어를 줄 묶기에 사용하지 않는다. 실험 결과를 보고 임계값을 탐색하지 않는다.
- 판정: 공백 제외 편집 오류, 문단/표별 변화, 표 셀/전체 일치, 악화 사례를 모두 확인한다. 이 부분 개발 표본의 개선만으로 제품 변경을 채택하지 않는다. 병합 셀·헤더 정답과 plain/TSV 차이를 구별한다.

### 확인된 원인

- **F 인식 퇴행**: P/F 32회 모두 기존 저장 결과와 완전히 일치했다. 두 모델의 실제 검출 좌표는 16/16쌍, 인식 입력 tensor는 50/50배치가 일치했다. `531ppm→531ppr`, `(ppm)→(pp)`, `599ppm→599pp`는 같은 글자 영역과 전처리에서 F에 생긴 오류다. p/m은 양쪽 사전에 있다. F의 `531ppr` 마지막 r 출력 시점에서 r=0.7612, m=0.00397이었으며 모델 출력값을 보정된 정답 확률로 취급하지 않는다.
- **절삭 원인 제외(선택 범위)**: 4영역의 CTC 48건을 관측했다. 기존 절삭과 전체 길이 greedy 결과가 전부 같아 출력 절삭 해제로 복구되지 않았다. 학습 데이터·가중치 변화 중 어떤 요인이 이 결과를 만들었는지는 이번 범위에서 확정하지 않는다.
- **표의 행 흡수**: 병합 셀 라벨 때문에 현재 행의 세로 합집합이 넓어진다. 예를 들어 `real-doc-37`의 첫 행이 y=0..32로 넓어진 뒤, 다음 행 상자와 14px 겹쳐 10.5px 기준을 넘으면서 합쳐졌다. 이후 x만으로 정렬되어 서로 다른 행의 숫자가 뒤섞였다. P는 두 수질표 본문의 수치/대시를 각 24/24개 읽었다(순서 무시 token 대조이며 셀 정확도를 뜻하지 않음).
- **사전 미지원**: `○` 7개·`★` 36개·`₂` 1개가 양쪽 사전에 없다. 연료표 `real-doc-12`는 별표 4묶음의 위치를 검출했으나 두 모델이 빈 문자열을 냈다. 검출 17개 중 빈 판독 4개가 빠져 최종 상자는 13개다. 실제 검출 포함률은 시각 주석 대비 97.4~100%다. 최종 인식 상자에 없다는 이유로 검출 누락으로 분류하지 않았다. 사전 미지원 때문에 고정 정답을 바꾸지 않았다.
