# 작업 기록: 문서 형식 변환 미니앱 계획

작성일: 2026-10-02 / 갱신일: 2026-10-03 / 상태: HWP 전용 구현 승인 — 개발 진행

## 목표와 범위

- 목표: 미니앱 주머니의 네 번째 칸에 문서를 개방형 형식으로 변환하는 도구를 추가한다. 가칭은 **문서 형식 변환**, 첫 기능은 **HWP → HWPX**다. 문서 내용을 읽어 새 형식으로 저장하는 기능이다.
- 사용자 요청: “파일 확장자 변경”은 임시 이름이며 HWP를 HWPX 같은 개방형 포맷으로 바꾸는 기능의 계획을 요청했다.
- 확정 조건(2026-10-03): 사용자는 한글이 설치된 PC에서만 변환하기를 원한다. HWP → HWPX는 설치된 한글과 지원 기능을 확인한 경우에만 활성화한다. 한글 미설치 PC용 독립 엔진은 범위에서 제외한다. 실제 설치 버전과 자동화 가능 여부는 아직 확인하지 않았다.
- 범위 확정(2026-10-03): 사용자가 HWP 전용 구현·AGENTS.md 갱신·커밋·빌드를 요청했다. XLS 등 다른 형식은 후속으로 보류한다. 이번 개발에는 HWP → HWPX 한 가지 기능만 포함한다.
- 변경 대상(향후): 변환 규칙/실행기/UI/테스트 신규 파일, `ui_mini_apps.py`, `ui_main.py`, SVG 리소스, 필요 시 `main.py`와 `build.spec`, 관련 정본 문서.
- 데이터 영향: 사용자가 선택한 문서를 읽고 선택한 출력 위치에 새 파일만 만든다. 원본과 기존 결과 파일은 덮어쓰거나 삭제하지 않는다. DB v17·Export v2·salt·설정 키·기존 바로가기 6슬롯을 유지한다. 목록·작업 결과·출력 폴더 선택은 실행 중 메모리에서만 유지한다.
- 제외 범위: XLS/DOC/PPT 계열, HWPX → HWP 역변환, PDF/OCR, 폴더 재귀 탐색, 예약 변환, 클라우드 업로드, 암호 입력/보호 해제, 원본 일괄 교체. 아래 XLS 조사는 후속 참고 자료로만 보존한다.
- 시작 소스: `e152faa` / v3.8d. 새 기능의 표시 버전과 출시일은 구현·출시 단계에서 정하며 이번 계획에서 변경하지 않는다.
- 시작 시 사용자 변경: `AGENTS.md`, `docs/RELEASE_HISTORY.md`의 기존 미커밋 수정과 아래 미추적 기록을 보존한다.
  - `2026-09-11-local-security-audit.md`, `2026-09-11-v3.7a-version.md`
  - `2026-09-17-release-status-docs.md`, `2026-09-24-unit-converter-redesign-concepts.md`

## 조사한 근거와 아직 확인하지 않은 점

1. HWPX는 XML 기반 개방형 문서 형식이며 OWPML은 KS X 6101에 정의되어 있다. [한컴 공식 안내](https://www.hancom.com/news/notice/detail/10924)
2. 한컴 HWPX 변환기 도움말은 파일/폴더 입력과 출력 위치를 받는 명령줄 변환을 설명한다. 다만 예시에 `HwpxConverter.exe`와 `HwpConverter.exe`가 혼용된다. 실제 설치 제품의 실행 파일·버전·동작을 확인해야 하며 도움말만으로 무인 실행, 종료 코드, 미설치 PC 지원을 보장하지 않는다. 암호 문서에는 한글 접근 승인과 암호 입력이 필요하다고 안내한다. [공식 명령줄/암호 문서 도움말](https://help.hancom.com/hoffice120/ko-KR/HwpxConverter/convert/convert.htm)
3. 한글 오토메이션은 외부 프로그램에서 한글을 제어하는 별도 후보다. 공식 개발 가이드는 로컬 파일 접근/저장 시 보안 승인과 승인 모듈을 설명하고, 개인 비상업 목적과 상업 이용 조건을 구분한다. 기관 내 무료 EXE 배포에 적용되는 조건을 자체 해석으로 확정하지 않는다. [공식 오토메이션 안내](https://developer.hancom.com/hwpautomation)
4. 무료 배포 응용 프로그램의 이용 조건에 대한 공식 포럼 답변도 지원 센터 확인을 안내한다. 배포 단계에서 사용 방식과 적용 조건을 확인할 항목으로 둔다. [공식 포럼 답변](https://forum.developer.hancom.com/t/topic/3182)
5. 현재 저장소는 `requirements-lock.txt`에 `pywin32==311`을 포함하지만 직접 의존성 목록에는 없다. COM 방식을 채택하면 직접 의존성/패키징을 명시하고 검증한다. `build.spec`는 `xml`, `multiprocessing` 등을 제외하므로 출력 XML 검사와 작업 프로세스 구현이 EXE에도 포함되는지 확인해야 한다.

## 제안하는 사용자 흐름

1. 미니앱 주머니의 `준비 중` 칸을 **문서 형식 변환**으로 교체한다. 현재 2×2 타일과 기존 세 앱의 순서를 유지한다.
2. 창에서 `HWP → HWPX`와 사용 가능 여부를 보여 준다. 한글이 설치되지 않았거나 지원 기능을 확인하지 못하면 해당 사유를 안내하고 HWP 변환 시작을 막는다. 기후노트의 다른 기능은 그대로 사용할 수 있다. XLS를 포함하게 되면 Excel 설치/지원 여부도 따로 표시하는 방식을 제안한다.
3. `파일 추가`로 여러 `.hwp`를 고르거나 창에 끌어 넣는다. 두 경로는 같은 등록 함수를 사용한다. 같은 파일 중복 등록은 제거하고 지원하지 않는 입력은 이유를 표시한다. 폴더 드롭은 첫 버전에서 등록하지 않는다.
4. 출력은 기본 `원본 파일과 같은 폴더`, 선택 사항으로 `지정 폴더`를 제공한다. 예: `보고서.hwp` → `보고서.hwpx`. 같은 이름이 있으면 `보고서 (1).hwpx` 등으로 분리한다. 서로 다른 입력 폴더의 동명 파일도 충돌하지 않아야 한다.
5. `변환 시작` 후 파일별 대기/변환 중/완료/실패/취소와 `완료 3 / 전체 10`을 표시한다. 파일 하나의 실패가 다른 파일의 결과를 지우지 않는다. 한 번에 하나씩 처리한다.
6. `취소`는 아직 시작하지 않은 항목을 중단하고 현재 작업을 안전하게 회수한다. 이미 검증·확정된 변환본은 유지한다. 실패 항목만 재시도할 수 있다.
7. 완료 뒤 `저장 폴더 열기`를 제공한다. 결과 문서는 자동으로 실행하지 않는다. 파일명·경로와 결과 목록은 앱 재시작 후 복원하지 않는다.

## UI와 기존 앱 통합

- 기존 도구 창과 같은 제목·테두리·그림자·글꼴을 사용한다. 내용 480×620px을 시작점으로 하되 첫 기능은 하나이므로 불필요한 왼쪽 모드 메뉴를 넣지 않는다. 상단에 변환 형식, 가운데 파일 목록, 하단에 출력 위치·진행·시작/취소를 배치한다. 목록만 스크롤하며 하단 조작부는 항상 보이게 한다.
- 네 번째 SVG는 예비 보라 계열 `#9775FA→#6741D9`와 문서/변환 화살표를 사용한다. [AGENTS.md](../../AGENTS.md)의 48px 아이콘·QtSvg Tiny·100/125/150% 규칙을 따른다.
- 메인 창이 단일 인스턴스를 소유하고 다시 열면 같은 창을 보여 준다. 일정 편집 저장 실패 시 열기를 보류한다.
- 잠금/트레이/사이드바 숨김/초기화/종료 때 파일 선택창·예약 포커스·늦은 작업 결과 표시를 정리한다. 변환 중인 프로세스와 창의 수명은 계산형 미니앱보다 길므로 명시적으로 관리한다.
- 잠금·숨김·폐기 시 새 파일 처리를 중지하고 현재 작업에 취소를 요청한다. 본 앱이 소유한 실행만 회수한다. 완료된 결과는 남기며 자동 재시작이나 뒤늦은 팝업을 금지한다. 실행 중인 기존 한글 문서는 닫지 않는다. 이 동작을 보장할 수 있는지 엔진 시험에서 확인한다.
- 초기화 성공 때만 목록/기록을 폐기하며, 기후노트 초기화가 외부 원본이나 변환본을 삭제하지 않는다.
- 네 번째 앱이므로 공통 창 틀 추출을 검토한다. 제목·그림자·화면 보정·팝업 수명처럼 실제로 같은 부분만 후보로 삼고 기존 세 앱의 계산/화면을 광범위하게 재작성하지 않는다.
- 이번 v3.8d의 메뉴 수명 계약을 지킨다. 메뉴 클릭 처리 도중 모달 선택창을 직접 실행하지 않으며, 실제 파일 선택창의 확인/취소를 회귀 검사한다.

## 구현 순서와 완료 기준

### 1단계: 변환 엔진 시험 — 본 UI 구현보다 먼저

우선 **설치된 공식 HWPX 변환기의 명령줄 방식**을 시험한다. 기후노트에서 입력·출력·종료·취소를 안정적으로 관리할 수 없으면 **설치된 한글 오토메이션**을 비교한다. 첫 버전에는 검증한 방식 하나만 채택하며, 실패할 때 사용자 모르게 다른 방식으로 재변환하지 않는다.

- 합성 문서로 실제 HWP → HWPX 저장, 종료/오류 상태, 한글 경로·공백, 출력 위치와 충돌을 확인한다.
- 한글/변환기 제품 및 버전별 설치 조건, 32/64비트 조합, 접근 승인창·보호 문서·회사 DRM의 동작을 확인한다.
- 취소·시간 초과·비정상 종료 시 작업 프로세스만 정리되는지 확인한다. 기존 한글 창을 열어 둔 상태에서도 미저장 문서가 보존되어야 한다. COM 서버가 단순한 자식 프로세스라고 가정하지 않는다.
- 한글 미설치 PC에서는 HWP 변환을 비활성화한다. 설치 흔적만으로 사용 가능하다고 판단하지 않고 실제 지원 기능까지 확인한다. 온라인 전송이나 독립 엔진으로 대체하지 않는다.
- **통과 기준**: 지원 환경에서 원본 보존·유효한 결과·기존 한글 작업 보존·취소 회수·UI 비차단이 확인되고, 연동/배포 조건을 설명할 수 있을 것. 지원 최소 버전과 엔진 선택은 이 결과로 정한다.

### 2단계: 원본 보존과 작업 실행

- `hwp_conversion.py`: 입력 검증, 중복 제거, 결과 이름, 작업 상태 등 Qt/DB 없는 규칙.
- `hwp_conversion_runner.py` / `hwp_conversion_worker.py`: 검증한 엔진을 별도 프로세스로 실행하고 진행·오류·시간 제한·취소를 관리한다. UI 스레드에서 변환 API를 동기 실행하지 않는다. 실행 인수는 배열로 전달하며 `shell=True`를 사용하지 않는다.
- 입력 확장자만 보고 정상 문서로 단정하지 않는다. 실제 열기 실패와 출력 형식 불일치를 구분한다. 지원하지 않는 암호/배포용/DRM 보호 문서는 원본을 유지한 채 건너뛰고 이유를 표시한다. 보안 승인이나 DRM을 임의로 우회하지 않는다.
- 선택한 출력 폴더의 작업 전용 임시 파일로 변환한다. 엔진 성공 결과와 HWPX 패키지/필수 XML 구조를 검사한 뒤 덮어쓰기 없는 방식으로 최종 이름을 확정한다. 파일이 생겼거나 종료 코드가 0이라는 이유만으로 성공 처리하지 않는다.
- HWPX 구조 검사는 열 수 있는 형식인지 확인하는 검사이며 원본 서식과의 동일성 보장은 아니다. 내용/표/그림/쪽 구성 확인을 별도 수행한다.
- 실패/취소 때 본 작업의 미완성 임시 파일만 정리한다. 강제 종료 뒤 남은 파일도 사용자 파일과 명확히 구별되는 작업 식별자로 관리한다. 정상 변환본·원본·다른 앱 임시 파일은 정리하지 않는다.
- 로그에는 본문·암호를 쓰지 않는다. 파일별 사유는 창에서 확인하고 지속 로그에 전체 경로를 불필요하게 남기지 않는다. 작업 큐와 문서 내용은 DB/Export/백업에 들어가지 않는다.

### 3단계: 미니앱 연결

- `ui_document_converter.py`, `resources/icons/mini_apps/document_converter.svg`와 관련 UI 테스트를 추가한다.
- `ui_mini_apps.py`에 네 번째 실행 신호/타일, `ui_main.py`에 소유/재사용/숨김/잠금/초기화/종료 처리를 연결한다.
- 자기 EXE의 `--hwp-convert-worker` 작업 모드를 `main.py` 일반 앱 초기화 전에 분기한다. 이 작업이 원본 사본과 공식 CLI를 다루며 캘린더/트레이/실사용 DB를 다시 시작하지 않는다.
- 새 의존성은 엔진 선택 후 필요한 것만 명시한다. 한컴 실행 파일/DLL을 기후노트에 묶는 것은 별도의 배포 조건 확인 없이 진행하지 않는다.

### 4단계: 검증과 문서화

- 단위 검사: 원본 바이트 보존, 기존 결과 비덮어쓰기, 동명 입력, 한글/공백 경로, 쓰기 권한 실패, 디스크 오류, 손상/확장자 불일치 입력, 잘못된 HWPX 출력, 취소/시간 초과/재시도.
- UI 검사: 파일 선택과 드롭의 같은 동작, 실제 선택창 확인/취소, 중복 시작 방지, 작업 중 잠금·숨김·초기화 성공/실패·종료, 늦은 콜백 무효화, 다른 미니앱 및 기존 바로가기 유지.
- 실제 엔진 검사: 일반 본문·표 병합·그림·수식·머리말/꼬리말·각주·쪽 번호가 있는 합성 문서를 변환하고 다시 열어 확인한다. 필요 시 시험용 역변환도 사용하되 원본 파일에 쓰지 않는다. 원본 해시와 비교 가능한 텍스트/개체 보존을 검사하고 화면·인쇄 배치 차이는 별도로 확인한다.
- 실제 엔진을 사용할 수 없는 환경의 모의 실행 테스트를 제품 변환 성공으로 간주하지 않는다. 설치 없음/지원 안 됨도 정상 안내되는지 검사한다.
- 회사 PC의 한글 버전·DRM·망 분리 환경과 실제 EXE에서 추가 설치/인터넷 없이 사용 가능한 지원 조합을 확인한다. 지원하지 못하는 조합은 명시한다.
- UI 관련 `quick --tests <신규 파일 및 미니앱 관련 파일>`, 공용 실행/격리를 변경하면 `full`, 배포 EXE는 PowerShell `release`로 검증한다. `release`가 포함하는 전체 검사를 불필요하게 중복 실행하지 않는다. 모든 검사에 실행 ID와 `summary.md`를 남긴다.
- 영구 계약은 `docs/ARCHITECTURE.md`, `docs/UI_PATTERNS.md`, `docs/TESTING.md`, `AGENTS.md`에 반영한다. 엔진/원본 보존 계약이 길어지면 `docs/DOCUMENT_CONVERSION.md`를 별도 정본으로 추가한다.

## 보류: XLS → XLSX 조사 (이번 구현 제외)

- 가능 여부: Excel은 XLS를 열어 XLSX 등 새 통합 문서 형식으로 저장할 수 있고 `Workbook.SaveAs`로 출력 형식을 지정할 수 있다. 설치된 Microsoft Excel의 자동화를 우선 후보로 삼는다. [Excel 지원 형식](https://support.microsoft.com/en-us/excel/file-formats-that-are-supported-in-excel), [SaveAs API](https://learn.microsoft.com/en-us/office/vba/api/excel.workbook.saveas)
- 프로그램별 조건 제안: HWP는 한글 설치/기능 확인, XLS는 Excel 설치/기능 확인을 각각 적용한다. 한글 설치 여부만으로 Excel 변환까지 가능하다고 표시하지 않는다. XLS 기능은 아직 제안 단계다.
- 한셀도 XLS/XLSX 저장을 지원하지만, 기후노트에서 사용할 자동화 경로와 수식·차트·서식 호환성은 별도 시험이 필요하다. 첫 Excel 엔진의 자동 대체품으로 취급하지 않는다. [한셀 다른 이름으로 저장](https://help.hancom.com/hoffice/multi/ko_kr/cell/file/save_as/save_as.htm)
- 일반 XLS는 원본과 별도의 XLSX를 만든다. 값·수식·시트 구성·셀 병합·날짜 표시·차트·인쇄 설정을 합성 문서로 비교한다. 외부 연결은 자동 갱신하지 않는 설계로 시험한다.
- XLSX는 VBA와 Excel 4.0 매크로 시트를 저장할 수 없다. 첫 범위에서는 매크로가 있거나 포함 여부를 확실히 판별하지 못한 파일은 건너뛰고 이유를 표시하는 방식을 제안한다. XLSM 보존 변환은 별도 선택 기능으로 추후 검토하며 사용자 모르게 매크로를 삭제하거나 출력 형식을 바꾸지 않는다.
- 입력을 여는 동안 매크로를 실행하지 않도록 설계한다. Excel의 `AutomationSecurity`에는 Excel 4.0 매크로 예외가 있으므로 단일 옵션으로 모든 매크로가 차단된다고 가정하지 않는다. 해당 파일의 사전 판별·열기 거절·승인창 취소를 엔진 시험에 포함한다. [Microsoft 공식 동작 설명](https://learn.microsoft.com/en-us/office/vba/api/excel.application.automationsecurity)
- 취소/시간 초과/종료 시 작업 소유 Excel만 정리하고 기존 Excel 인스턴스와 미저장 통합 문서를 보존한다. HWP와 같은 원본·결과 비덮어쓰기, 작업별 임시 파일, 오프라인 처리 원칙을 적용한다.
- 구현한다면 HWP와 공통 파일 목록/결과/취소 UI를 사용하고 실행 엔진을 분리한다. 공용 실행기에 무관한 문서 파싱 규칙을 섞지 않는다. 혼합 파일 등록과 설치된 엔진에 따른 기능 활성화는 XLS 범위를 확정한 뒤 상세화한다.
