## 최종 산출물과 추가 확인 범위

- 구현 커밋: `186a679`. 기존 설정 테스트 갱신 커밋: `2c0f27b`. 이 두 번째 커밋 상태에서 최종 release를 수행했다.
- 표준 산출물: [`dist/기후노트_v3.8.exe`](../../dist/기후노트_v3.8.exe), **57,978,063 bytes**.
- SHA-256: `02CD0D0534102356131AB065A42DCD2CF7266EF460DB5F0D697AAFFBEB758A2D`.
- 표시 v3.8 / 출시일 2026. 9. 21. / Windows 3.8.0.0 / Qt 6.11.2.0.
- 이전 v3.7b EXE는 [이전 release 폴더](../../output/harness/20260920-231715-72ee145267/dist/기후노트_v3.7b.exe)에 보존되어 있다. 새 파일 배치 당시 루트 dist에는 기존 EXE 파일이 없어 덮어쓴 파일은 없다.
- 소스 Qt 실제 렌더: [100%](../../output/harness/20260920-235445-e80ad20245/unit-converter-len.png), [125%](../../output/harness/20260921-000008-99cfe23ac6/unit-converter-len.png), [150%](../../output/harness/20260921-000130-dde0cefbf2/unit-converter-fuel.png). 해당 실행별 환경/입력은 각 보고서를 따른다. 새 EXE 직접 클릭 캡처로 표시하지 않는다.
- **추가 EXE 확인의 관찰**: 화면 자동화 연결을 기다린 장시간 합성 실행에서는 열린 스티키 1개의 일반 문자열이 Qt HTML로 저장되고 크기 300×400이 기존 스냅 동작에 따라 306×396으로 갱신됐다. 따라서 이 추가 실행의 전체 raw/복호화 행 해시는 불변으로 기록하지 않는다. 본문 글자·ID·salt는 유지됐고 나머지 7개 테이블은 같았다. 환산기는 열리지 않았으며 새 UI 입력은 없었다. v3.7b와 v3.8의 실제 EXE에서 `ui_sticky`·`database`·`security` 바이트코드가 동일함을 대조했다. 기존 스티키의 시작 후 저장/기하 정규화 관찰로 보존하며 이번 환산기 변경에서 저장 방식을 수정하지 않았다.
- 하네스 3개 smoke의 통과와 추가 UI 확인 미실행을 구분한다. 실제 EXE의 정상 UI 종료, 혼합 DPI/KVM/Win+D·회사 PC 확인, Defender·서명·SBOM·GitLab 게시/push는 완료로 처리하지 않는다.
