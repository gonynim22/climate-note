# 작업 기록: 실제 CLI 화면 수집 묶음 준비

작성일: 2026-10-11 / 상태: 수집 준비·등록 경로 검증 완료 (아래 확보량은 이 준비 단계 시점)

후속: Computer Use 복구 뒤 사용자의 수동 촬영 없이 실제 메모장 시험 자료 60개를 수집하고 dev 48개를 평가했다. 실제 CLI 촬영과는 구분한다. 현재 결과는 [메모장 수집·비교 기록](2026-10-11-screen-text-computer-use-capture.md)을 따른다. 아래의 캡처 0개·촬영 필요 기록은 당시 상태를 보존한 것이다.

## 목표와 범위

- 목표: 첫 실제 Windows CLI 캡처 30개를 확보할 수 있도록 새 시험 문구·표시·파일명·정답 초안·원본 그룹 분할을 준비하고 기존 검토 도구에 연결한다.
- 변경 대상: `tools/screen_text_lab/`의 수동 수집 준비/등록 명령과 recipe, 관련 자체 검사·사용법. 제품 엔진/UI·DB/salt·설정·모델/사전·의존성·빌드 변경 없음.
- 데이터 영향: 새 `output/screen_text_lab/capture/` 묶음과 검토용 corpus 사본만 생성. 지정한 PNG 이외의 파일·실사용 AppData·기존 실행 앱을 읽거나 변경하지 않는다.
- 제외 범위: 자동 화면 수집, 대체 합성 이미지를 실제 캡처로 집계, 캡처 차단 우회, 미검토 정답 채점, 후보 개선/배포 완료 주장.
- 시작 시 사용자 변경: AGENTS.md·RELEASE_HISTORY.md와 기존 미추적 진단 도구/기록을 보존한다.

## 결정과 진행

- 2026-10-11: 사용자가 다음 계획의 진행을 요청했다. 캡처 보관 위치 질문에는 '없음'으로 답했다. 실제 자료 수집부터 필요하다.
- 기존 자료 등록·확대·정답 검토 창을 재사용한다. 수집 묶음의 표시 원문은 정답 초안이며, 줄바꿈/잘림/글리프 표시를 원본 PNG로 대조하기 전 자동 검토 완료하지 않는다.
- 현재 세션에 native Windows 컴퓨터 제어용 node_repl/sky 도구가 없고 cua의 native 기능도 비활성이다. computer-use SKILL.md를 읽어 진입점을 확인했으며 별도 캡처 우회 코드는 만들지 않는다. 사용자 터미널에서 명시적으로 실행할 자료를 제공한다.
- 첫 30개는 수집 절차와 조건 확인용이다. 기존 원본 1,000개·5,000~10,000조건 목표의 완료나 통계적 충분성을 뜻하지 않는다. 보류 6개는 인식하지 않고 나중에 새 원문 그룹과 함께 확대한다.
- karpathy-guidelines의 작은 변경·검증 기준을 적용한다. 제품 캡처 이미지의 메모리 전용 계약과 수동 진단 실행을 유지한다.
