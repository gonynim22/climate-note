## 원인과 근거

클릭 등록의 메뉴 객체 수명과 동기 파일 선택창의 이벤트 처리 충돌을 재현했다. `ui_main.py:1020/1023`은 메뉴 액션에서 `_select_file/_select_folder`를 동기 호출하고, `:1029`는 메뉴가 닫히면 `deleteLater()`를 예약한다. 사용 중인 Fluent Widgets 1.11.1의 `RoundMenu._onItemClicked`(`menu.py:664`)는 메뉴를 닫은 뒤 `action.trigger()`를 실행한다.

관측 순서:

1. 실제 메뉴 항목의 마우스 클릭 처리가 시작된다.
2. 메뉴 `closedSignal`에서 삭제를 예약한다.
3. 같은 클릭 처리 안에서 `QFileDialog.getOpenFileName/getExistingDirectory`가 열린다.
4. 선택창이 열려 있는 동안 메뉴와 내부 목록의 `destroyed`가 발생한다.
5. 확인하면 선택 결과 반환과 `_persist`의 DB 저장·아이콘 갱신까지 성공한다.
6. 이미 삭제된 메뉴/목록의 클릭 처리로 돌아오며 native access violation이 발생한다. QtTest 경로의 종료 코드는 `3221225477 (0xC0000005)`다.

드롭은 `_assign_path → _persist → update_data`만 거쳐 메뉴/선택창을 만들지 않는다. 선택 취소(저장·아이콘 조회 없음)에서도 충돌하고, 메뉴 없이 같은 선택창을 직접 열면 정상이다. 따라서 이 재현의 원인은 DB 저장 실패나 파일 아이콘 조회가 아니라 메뉴 수명 문제다. 특정 C++ 명령 주소/심볼까지 분석한 crash dump는 없으며, 삭제 시점·접근 위반·대조 실험으로 원인을 특정했다.

Windows native 선택창과 `AA_DontUseNativeDialogs`를 쓴 Qt 선택창 양쪽에서 발생했다. native dialog만 비활성화하는 변경으로는 해결되지 않는다. 일반 Python 예외가 아니라 native 접근 위반이므로 앱의 `sys.excepthook` 기반 error.log가 비어 있어도 이 원인을 배제할 수 없다.

Qt도 동기 `QDialog.exec()`가 추가 이벤트 루프를 만들어 부모 삭제 등 수명 문제를 일으킬 수 있다고 설명한다: [QDialog::exec](https://doc.qt.io/qt-6/qdialog.html#exec), [QObject::deleteLater](https://doc.qt.io/qt-6/qobject.html#deleteLater). 구체적인 삭제 시점은 중첩 루프/이벤트 전달 조건에 달려 있으므로 이 분석은 일반화된 추정 대신 실제 `destroyed` 로그를 근거로 한다.

## 대조 실험과 수정 방향

- **원본 메뉴 → 파일 확인/취소, 폴더 확인**: 모두 `0xC0000005` 종료.
- **원본 메뉴 → Qt 파일 선택창 확인**: 동일 종료.
- **메뉴 없이 native/Qt 파일 선택창 직접 호출**: 정상 저장·생존.
- **선택창 호출을 `QTimer.singleShot(0, callback)`로 다음 이벤트 처리에 예약**: native 파일/폴더 및 Qt 파일 모두 정상 저장·생존. 메뉴 클릭 반환 → 메뉴 폐기 → 선택창 순서가 로그에 나타난다.
- **메뉴의 deleteLater 연결을 실험에서만 생략**: 정상. 수명 원인을 분리하는 대조군이며 메뉴 누적 때문에 제품 해결책으로 채택하지 않는다.
- **QCoreApplication.postEvent 마우스 전달**: 원본은 동일 access violation 로그 후 제한 시간 내 프로세스 종료가 완료되지 않아 Job으로 정리했다. 지연 호출 대조군은 정상이다.
- **Win32 PostMessage 마우스 전달 시도 2건**: 메뉴만 닫히고 선택 액션이 실행되지 않아 재현 입력 실패로 제외한다. 제품 정상/실패 근거로 사용하지 않는다.

권장 수정은 메뉴 클릭 처리에서 대화상자 호출을 분리하고, 다음 이벤트에서 실행할 때 슬롯/메인 창의 생존·잠금·숨김 상태를 확인하는 것이다. 메뉴 정리 연결은 유지한다. 같은 직접 연결 패턴의 `이름 변경`(`:1036`, `QInputDialog.getText`)도 수정 시 함께 점검해야 한다(이번에는 별도 재현하지 않음). 실제 메뉴 클릭과 대화상자 확인/취소를 별도 프로세스로 검사하는 회귀가 필요하며, 기존 선택창 monkeypatch 테스트만으로 완료하지 않는다. 제품 코드는 변경하지 않았다.
