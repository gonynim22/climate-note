# 화면 글자 따기 계약

다섯 번째 미니앱이며 **걷어낼 수 있는 선택형 앱**이다. 설계는 [설계 문서](superpowers/specs/2026-10-08-screen-text-capture-design.md), 최초 구현·검증은 [작업 기록](work/2026-10-08-screen-text-capture.md)을 따른다. v4.0은 최초 소형 모델을 유지하고 아래 줄·표 재구성을 개선한 버전이며, 현재 빌드 결과는 [v4.0 기록](work/2026-10-11-v4.0-release.md)에 남긴다.

## 동작
- 주머니 타일 → 도구 창 → [영역 고르기] → 화면이 멈추면 끌어서 선택(Esc·오른쪽 클릭 취소, 시작한 화면 안으로 제한) → 같은 창에 결과.
- 탭 [글자]/[표 모양]. 표가 감지되면 표 모양이 기본이다. 표 모양 복사는 탭 구분 글자와 HTML 표를 함께 넣고, 글자 복사는 일반 텍스트만 넣는다.
- 표 탭을 고치면 아직 손대지 않은 글자 탭이 다시 만들어진다. 글자 탭에서 고친 내용은 표 탭에 반영하지 않는다.
- 불확실한 곳은 노랗게 표시만 하고 자동으로 고치지 않는다. 글자는 절대 바꾸지 않는다.
- 다시 고르기를 취소하거나 새 인식이 비었거나 실패하거나 캡처가 막히면 이전 결과(고친 내용 포함)와 미리보기를 그대로 둔다. 이전 결과가 있으면 결과 화면에 안내 줄만 띄우고, 없으면 처음 화면에 안내한다. 모델 오류는 [영역 고르기]·[다시 고르기]를 모두 막는다.
- 좁은 표에 맞추려고 채운 빈 칸은 읽기 전용이다.
- 사용법 안내(v3.9a): 처음 화면에는 [영역 고르기] 아래에 벡터 애니메이션(영역 고르기 → 글자 읽기 → 표로 붙여넣기, 6초 되풀이)과 팁 두 줄을 둔다. 결과 화면의 [사용법]은 같은 애니메이션이 있는 사용 방법 화면을 열고 [돌아가기]는 결과를 다시 채우지 않고 그대로(고친 글자·표·탭·상태) 돌려놓는다. 애니메이션은 그림 파일 없이 QPainter로 그리며 화면에 보일 때만 돌고(숨기면 멈춘다), 누르면 처음부터 다시 보여 준다. 새 설정 키·파일·네트워크를 쓰지 않는다.

## 줄·표 재구성
- **줄**: 상자 중심 y로 정렬하고, 세로 겹침이 작은 쪽 높이의 50% 이상이면 우선 같은 행으로 묶는다. 이 행을 중심/높이 중앙값으로 나눈 물리 줄 사이에 독립적인 열 대응이 2개 이상 반복되면 분리하여 병합 라벨이 다음 숫자 행을 흡수하지 않게 한다. 한 열의 여러 줄만으로는 행을 쪼개지 않는다. 한 셀 안의 글자는 물리 줄 순서(위→아래, 줄 안 왼쪽→오른쪽)를 따른다.
- **표 규칙**: 2칸 이상인 줄 2개 이상·열 띠 2개 이상을 사용한다. 겹쳐 이어진 문장 조각만으로 새 표를 시작하지 않는다. 작은 x 구간의 절반 이상 겹치는 열을 우선 대응시키고, 강한 대응이 없으면 기존의 실제 겹침을 쓴다. 강한 대응 옆의 작은 접촉 때문에 표를 끊거나 열을 합치지 않는다. 한 구간이 여러 열에 대응하면 표를 끝낸다. 한 열 안에 완전히 들어가고 서로 겹치는 판독 조각은 같은 셀로 모으며, 그 밖의 한 열→여러 구간 대응은 표를 끝낸다.
- **병합 머리글**: 본문에 더 많은 칸이 있는 줄이 있고, 머리글 상자의 위치/폭이 본문 열 묶음의 중앙과 열 사이 경계에 맞을 때만 묶음 첫 칸에 넣는다. 본문에서 먼저 열을 확인해 머리글 자체가 가짜 열을 만들지 않게 한다. 별도 머리글을 표에 붙일 때는 본문과의 간격도 상자 높이 이내인지 확인한다. 병합 범위를 표시하는 rowspan/colspan이나 표 선 검출은 쓰지 않으며 덮인 칸은 빈칸으로 둔다. 글자·점수·상자는 수정하지 않는다. 구현/검증은 [표 구성 기록](work/2026-10-11-screen-text-table-layout.md)을 따른다.
- **숫자 열**: 열의 비어 있지 않은 칸 중 절반 이상이 "숫자 같은" 칸이면 숫자 열이다. 분류에만 `l I → 1`, `O o → 0`, `S → 5`, `B → 8`로 닮은 글자를 바꿔 본다.
- **불확실 표시**: (1) 인식 점수가 0.80 미만인 상자, (2) 숫자 열에서 숫자 같으면서 숫자를 포함하고 닮은 영문자도 포함한 칸. 표시만 하며 글자는 그대로 둔다.
- 글자 탭의 불확실 표시는 칸마다 따로 위치 커서로 추적한다. 칸 끝에서 공백·마침표·Enter를 입력해도 표시 범위는 늘지 않으며, 칸의 글자를 실제로 고쳐야 표시가 풀린다.

## 엔진
- 모델·사전·런타임 고지 목록은 `screen_text/licenses/components.json`에 두고 설정 → 라이선스에서 원문을 읽는다. PaddleOCR 원저작권을 보존한 `models/LICENSE`, 원 모델/변환본/고정 리비전/변경 여부를 구분한 `licenses/MODEL-ATTRIBUTION.txt`, ONNX Runtime/NumPy 원문을 함께 번들한다. 폴더가 없으면 목록과 원문도 함께 제외한다. 고지 정비로 모델·사전·MANIFEST 해시나 인식 동작을 바꾸지 않는다.
- PP-OCRv3 mobile det + korean PP-OCRv5 mobile rec ONNX(Apache-2.0), onnxruntime CPU, numpy만 사용한다. 모델은 `screen_text/models/MANIFEST.json`의 크기·SHA-256이 맞을 때만 불러온다.
- 2026-10-11 사용자 결정: 검증한 표 구성 개선을 적용하고 현재 소형 인식 모델을 유지한다. 추가 학습 후보는 실제 자료의 새 오독으로 미채택했으며 추가 학습을 보류한다. 실험 도구·자료·후보 모델은 제품에 포함하지 않는다. 적용/EXE 검증은 [빌드 기록](work/2026-10-11-screen-text-table-build.md), 미채택 근거는 [학습 기록](work/2026-10-11-screen-text-diverse-training.md)을 따른다.
- 엔진은 처음 인식할 때 작업 스레드에서 불러오고, 사용자가 창을 닫거나 초기화·종료하면 내린다. 첫 불러오기 중에 창을 닫으면 모델을 보관하지 않는다. 텔레메트리를 끈다. 네트워크를 쓰지 않는다.
- 엔진 모듈을 불러오지 못하면 "모델" 오류로 안내한다.

## 데이터와 보안
- 찍은 화면 전체는 선택·취소 즉시 버린다. 잘라낸 영역과 결과는 메모리에만 두며 임시 파일을 만들지 않는다. 로그에는 오류 종류만 남긴다.
- DB v17·Export v2·salt·설정 키·바로가기 6슬롯을 바꾸지 않는다. 새 설정 키를 만들지 않는다.
- 캡처가 막히면(거의 검은 화면) 안내만 하고 우회하지 않는다. 못 찍었거나 막힌 화면에는 오버레이를 띄우지 않고, 남는 화면이 없으면 막힘으로 안내한다. 빈 영역은 취소처럼 처리한다.

## 수명 처리
- 공용 연결부(`optional_mini_apps.py` → `ui_main` 선택형 미니앱 메서드)를 따른다. 연결 지점은 10곳(열기, 사이드바 숨김, 크기 변경, 데이터 초기화 전, 초기화 성공, 트레이 숨김, 종료, 화면 변경, 잠금, 메인 창 Hide 이벤트)이다.
- 잠금: 취소·숨김·비활성(결과 유지). 트레이·사이드바·크기 변경·초기화 전·메인 창 숨김: 취소·숨김. 화면 변경: 오버레이 닫기·화면 맞춤. 초기화 성공·종료: `shutdown()` 후 폐기.

## 개발용 정확도 진단 도구

별도 개발 도구 `tools/screen_text_lab/`는 [개발 계획](work/2026-10-10-screen-text-lab-plan.md)의 자료 검증·채점·제품 기준 실행·오프라인 HTML 비교와 조건별 합성 자료·후보 비교·주석 영역 직접 인식 진단을 제공한다. [사용법과 현재 범위](SCREEN_TEXT_LAB.md)를 따른다. 2026-10-11 합성 1,920개 dev/480개 최종 평가에서 선택적 재인식 후보는 전체 글자 오류를 일부 줄였지만 완전 일치·표의 채택 기준에 미달해 제품에 적용하지 않았다([평가 기록](work/2026-10-10-screen-text-accuracy-improvement.md)). 원본 1,000개 확대·실제 업무 캡처와 혼합 DPI·새 원문 최종 평가 집합은 후속 범위다. 대규모 진단은 명시적인 별도 명령으로만 실행하고 일반 테스트/빌드/앱 시작에 연결하지 않는다. 가벼운 자체 검사와 기존 소규모 모델 회귀의 경계는 [검증 지침](TESTING.md)을 따른다.

개발용으로 생성하거나 등록한 시험 자료만 별도 출력 폴더에 보존한다. 제품의 캡처 이미지 메모리 전용·로그 본문 미저장·오프라인·자동 글자 교정 금지 계약은 그대로 유지한다.

모델 출력·CTC 진단(`run --diagnose-ctc`)도 수동 개발 도구다. 기존 합성 선택 표본 76개의 [원인 진단](work/2026-10-11-screen-text-ctc-diagnosis.md)에서 반복/blank 처리와 독립 계산이 일치했고 출력 절삭을 해제해도 문자열이 같았다. 디코딩만 바꾼 가상 비교는 일부 오류만 줄였으며 제품에는 적용하지 않았다. 실제 캡처·새 원문 독립 평가는 별도 후속 범위다.

입력/모델 비교(`run --recognizer ... --input-profile ...`)는 [사용법](SCREEN_TEXT_LAB.md)의 수동 개발 도구로만 제공한다. 2026-10-11 개발용 1,920개에서 대체 한국어 v3/EasyOCR g2는 현재 모델보다 오류가 많았고, 입력 정규화는 기존 개선 효과를 재현했지만 신규 오류/표 퇴행으로 적용하지 않았다([비교 기록](work/2026-10-11-screen-text-model-input-comparison.md)). 외부 모델은 개발 출력 폴더에서 해시 검증 후 오프라인으로만 실행하며 번들·제품 의존성을 변경하지 않는다. 결과 불일치 경고의 모의 분석은 제품 동작/정확도 개선으로 적용한 결과가 아니다.

두 판독이 다른 글자/삽입점을 표시하는 후속은 개발용 `disagreement`·`benchmark-disagreement` 명령으로만 진단한다. 화면 전체 경고와 실제 표시 위치 적중·정렬 모호성·추가 시간을 구분하며, 제품 원문/경고 UI/복사에는 적용하지 않았다. [사용법](SCREEN_TEXT_LAB.md)과 [진단 기록](work/2026-10-11-screen-text-disagreement-warning.md)을 따른다.

불일치 경고의 문자 점수/차이/누락 조건 비교도 `warning-rules` 수동 진단에 한정한다. 기존 원문과 경고를 유지하며 조정용에서 조건을 고정한 뒤 확인용의 오경고와 놓친 오류를 함께 평가한다. 기존 dev의 재분할은 새 독립 검증이 아니다. [조건 비교 기록](work/2026-10-11-screen-text-warning-rules.md)에 증거를 남기며 제품 UI에는 아직 적용하지 않았다.

## 알려진 한계
- 띄어쓰기를 사용자가 확인해야 한다. 소형 모델은 마침표·쌍점 뒤와 일부 어절 사이의 공백이 빠진다(예: `2026. 7. 1.` → `2026.7.1.`).
- 합성 표본 측정(개발 PC, 공백을 무시한 글자 정확도): 소형 모델 0.996, Windows 내장 OCR 0.575. 공백까지 따지면 전체 0.940, 본문만 0.887이다. 표 칸은 따로 나뉘어 공백 영향이 적다. Windows OCR의 0.575에는 표를 열 단위로 내보내는 읽기 순서 불이익이 들어 있다. 순서를 무시하면 약 0.68이고 남은 차이는 누락된 칸이다.
- 인식 시간은 3~5줄 표본에서 최대 0.23초, 24~48줄 영역에서 약 1.3~1.4초였다. 페이지 크기 영역의 시간은 업무 PC에서 따로 본다.
- 큰 영역은 느리고 덜 정확하다(개발 PC, 실제 모델, 합성 표본). 1920×1080·2560×1440의 13~16px 글자는 공백을 무시하고 100% 맞았고 2.2~3.4초였다. 3840×2160의 16px 글자는 상자 990개(정답 840개), 정확 일치 49%, 6.5초였다. 위치 찾기가 긴 변을 960px로 줄여서 하기 때문이다. 4K·전체 화면보다 필요한 영역만 골라 읽는다.
- 병합 셀의 범위를 항상 복원하지는 못한다. 여러 줄 머리글·행을 가로지르는 단위 표기·비어 있는 일정 열은 여전히 잘못 나뉠 수 있다. 못 읽은 기호나 빈 행을 추정해 넣지 않는다. 많이 기울어진 스캔본은 지원하지 않는다.
- 글자 탭의 불확실 표시: 실행 취소(Ctrl+Z)는 풀린 표시를 항상 되살리지는 않는다(일부 글자만 고친 뒤 되돌리면 글자는 돌아와도 표시는 풀린 채 남는다).
- 합성 표본 기준이라 실제 스캔 문서의 성능, 보안 프로그램의 캡처 차단, 한글 표 붙여넣기, 혼합 DPI는 업무 PC에서 확인한다.
