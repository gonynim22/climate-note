# 새 버전 알림(인터넷 접속을 켠 PC만) 설계

작성일: 2026-11-04 / 상태: 사용자 승인(2026-11-04) / 구현: 시작 안 함 / 계획: [구현 계획](../plans/2026-11-04-update-check.md)

시안(확정): Claude Design 캔버스 「기후노트 앱 업데이트 안내창」 — https://claude.ai/artifact/6CqTGa7jfa5pxaFqo7mDeU
- '받는 곳 안내창' 쪽: B안(좌우 타일, 연하게·초록/파랑)과 B안 온나라 안내 — 이미 `src/ui_update.py`에 구현됨([작업 기록](../../work/2026-11-04-update-guide-two-way.md), 커밋 6deb21b).
- '새 버전 알림' 쪽: ①~⑤ 다섯 화면이 이 문서의 대상이다.

## 1. 의도와 이유

- 기후노트는 GitLab(외부 접속 가능)·GitHub에 공개 저장소가 생겼다. 그동안 사용자는 새 버전이 나왔는지 스스로 온나라 게시판을 찾아봐야 했다.
- 인터넷이 되는 PC의 사용자에게는 앱이 새 버전을 알아서 알려 주면 좋겠다(사용자 요청). 업무망 PC는 그대로 오프라인이다.
- 컴퓨터에 익숙하지 않은 사람도 '앱 업데이트' 창에서 어느 단추를 눌러야 할지 헷갈리지 않아야 한다(사용자 지적: "GitLab에서 받기 버튼을 눌러야 할지 말아야 할지 모를 것" → 강조 애니메이션).

## 2. 목표 · 비목표 · 반목표

**목표**
- 설정 › 시스템의 **인터넷 접속** 스위치를 켠 PC만, GitLab 공개 Release 정보에서 **최신 버전 번호 하나**를 받아 현재 버전과 비교한다.
- 새 버전이 있으면: ① 캘린더 위 알림 한 장, ② 더보기(⋮) 단추의 빨간 점, ③ 더보기 메뉴 '앱 업데이트' 아이콘의 빨간 점, ④ 앱 업데이트 창의 '현재 → 새' 꼬리표와 GitLab 타일 강조.
- 받는 동작은 지금처럼 **기본 브라우저로 GitLab 최신 Release 페이지를 여는 것**뿐이다.

**비목표**
- 자동 내려받기·자동 설치·EXE 교체. 앱은 알리기만 한다.
- 온나라 게시판 확인(앱이 온나라에 접속하지 않는다). 업무망 PC용 감지.
- 공휴일 자료 등 다른 데이터의 온라인 갱신. '인터넷 접속' 스위치는 지금은 새 버전 확인에만 쓰인다.
- 브라우저로 주소를 여는 기존 기능(AI 법령검색, 앱 업데이트 창의 'GitLab에서 받기')은 이 스위치와 무관하게 지금처럼 동작한다(앱이 접속하는 것이 아니라 브라우저를 여는 것).
- 버전 번호 올리기·EXE 빌드·Release 게시(이 기능이 들어갈 버전은 따로 정한다).

**반목표(동작해도 실패로 보는 것)**
- 스위치를 켜지 않은 PC에서 네트워크 요청이 한 번이라도 나가는 것.
- 일정·메모·설정 등 사용자 데이터나 PC 식별 정보를 보내는 것.
- 확인 실패(망 차단·시간 초과)를 오류 창·알림으로 사용자에게 보이는 것.
- 알림 때문에 캘린더 조작이 막히거나, 잠금 화면 위에 알림·점이 보이는 것.
- 설정창이 800×560 무스크롤을 넘는 것.

## 3. 제약(지켜야 할 계약)

- **오프라인 계약 변경(사용자 결정)**: "앱 런타임은 오프라인 전용이다(설정에서 인터넷 접속을 켠 경우는 제외)". 바꿀 문서: `AGENTS.md`(런타임 문장, 공휴일 테마 단락의 '오른쪽 열 40px 유지'), `docs/ARCHITECTURE.md`(오프라인 전용 줄·모듈 표), `docs/CODING_STANDARDS.md` §6 마지막 문장, `docs/UI_PATTERNS.md`(설정·업데이트 안내), `docs/TESTING.md`(테스트 네트워크 차단 언급).
- **보안 코딩**: `CODING_STANDARDS.md` §6 — 고정 HTTPS 주소와 전용 `urllib.request.OpenerDirector`(HTTPS 프록시·Unknown·HTTPS·HTTPDefaultError·HTTPErrorProcessor 처리기만). 리디렉션 처리기를 넣지 않는다(3xx는 실패). `urlopen(...)`·`http.client`·`nosemgrep` 금지. `tests/test_security_scan_rules.py`가 `urlopen` 재발을 검사한다. push 서버 보안 검사(Semgrep 등)를 통과해야 한다.
- **빌드(계획 작성 때 확인)**: `build.spec`의 `excludes`에 `http`·`email`이 있어 EXE에는 `urllib.request`가 들어가지 않는다(빌드 TOC로 확인). 두 항목을 빼지 않으면 빌드는 성공하고 EXE만 실패한다. `_ssl.pyd`·`libssl-3.dll`·`libcrypto-3.dll`은 이미 들어 있다.
- **데이터**: 설정 키 추가만 허용(마이그레이션에 넣지 않음, 키 없으면 꺼짐). DB v19·Export v4·salt·암호문·기존 키는 바꾸지 않는다.
- **설정창 800×560 무스크롤**: 실측 결과 '인터넷 접속' 줄을 그대로 더하면 필요 높이 587px(27px 초과). 오른쪽 열(데이터·보안·시스템) 줄 높이를 왼쪽 열처럼 40→36px로 맞추면 551px로 들어간다(시안 ⑤가 이 상태를 실제 앱 코드로 그린 것). 공휴일 테마 때 왼쪽 열을 36px로 줄인 방식과 같다.
- **잠금·숨김**: PIN 잠금 중에는 알림을 띄우지 않고 잠금 화면 위에 점·알림이 보이면 안 된다. 잠금·숨김·초기화·종료 때 진행 중 애니메이션과 예약을 멈춘다.
- **움직임**: Windows '애니메이션 효과'를 끈 PC(`ui_holiday_decor.motion_allowed()`가 False)에서는 움직이지 않는다.
- **공휴일 테마**: 머리줄 색이 테마마다 바뀐다(13개 모두 어두운 색). 점 테두리는 그때의 머리줄 색을 따른다.
- **테스트**: pytest는 실제 네트워크를 쓰지 않는다. 합성 데이터 폴더에서만 검증한다.

## 4. 사용자가 정한 것

- 인터넷 접속은 **설정에서 켠 사람만**(기본 꺼짐). 켠 PC만 새 버전을 감지한다.
- 알리는 방식: 처음 발견했을 때 짧은 알림 한 번 + 그 뒤로 남는 점. 점은 **빨간색**.
- 앱 업데이트 창은 확정한 B안 그대로, 새 버전이 감지됐을 때 **GitLab 타일을 애니메이션으로 강조**.
- 다섯 화면(①~⑤) 확정: "응 이렇게 하자".

## 5. 화면 사양(시안 ①~⑤ 기준, 기본 크기 460×660 창)

색: 남색 머리줄 `#01295F`(테마 때 그 머리줄 색), 강조 파랑 `#2563EB`/진한 파랑 `#1D4ED8`, 연한 파랑 `#DFE8FD`, 빨간 점 `#F04438`, 본문 `#1F2A3D`, 보조 `#5B6678`, 제목 `#0F1E36`. 제목 글꼴 Pretendard Bold, 본문 맑은 고딕, 글자 크기는 정수 px.

### ① 처음 발견 — 캘린더 위 알림(토스트)
- 위치: 머리줄 바로 아래, 캘린더(사이드바 제외) 가로 가운데. 기본 크기에서 x 96·y 112, 폭 348px. 흰 바탕, 1px `#D7E3FB` 테두리, 둥근 12px, 그림자.
- 내용: 왼쪽 32px 원(`#DFE8FD`) 안 위쪽 화살표(`#1D4ED8`), 제목 "새 버전 v<새 버전>이 나왔습니다"(14px Bold), 보조 "지금 쓰는 버전 v<현재>"(11px), 파란 **받기**(32px 높이, `#2563EB`, 흰 글자), 닫기 ×(32px, `aria`/접근성 이름 "알림 닫기").
- 받기 → 브라우저로 GitLab 최신 Release 페이지(`ui_update.GITLAB_LATEST_URL`)를 열고 알림을 닫는다. × → 닫기만. 10초 뒤 저절로 사라진다(공휴일 자료 만료 알림과 같은 시간).
- 띄우는 때: 새 버전을 확인한 순간 창이 보이고 잠금이 아니면 바로. 그때 숨김·트레이·잠금이면 다음에 창이 보이고 잠금이 풀린 때 한 번.

### ② 그 뒤 — 더보기(⋮) 단추의 점
- 머리줄 더보기 단추(32×32) 오른쪽 위, 단추 기준 (18, 2)에 지름 8px 빨간 점 + 2px 머리줄 색 테두리(전체 12px). 마우스 입력을 막지 않는다.
- 새 버전이 확인된 동안 계속 보인다. 스위치를 끄거나 같은/더 높은 버전을 쓰게 되면 사라진다.

### ③ 더보기 메뉴 — '앱 업데이트' 아이콘의 점
- 메뉴 폭(170px)에 글자 꼬리표가 들어가지 않아, '앱 업데이트' 아이콘(`arrow_sync_color`) 오른쪽 위에 지름 7px 빨간 점 + 2px 흰 테두리(전체 11px)를 얹는다. 메뉴 아이콘 칸은 14px이라 시안처럼 칸 밖으로 걸치게 하려면 아이콘에 그릴 수 없으므로, 메뉴 목록 viewport의 자식 위젯으로 항목 왼쪽 위 기준 (27, 3)에 둔다(계획 작성 때 시험으로 시안 위치 확인). 메뉴 항목 순서·문구는 그대로.

### ④ 앱 업데이트 창 — 새 버전이 있으면 GitLab 타일 강조
- 새 버전을 모르면 지금 B안과 똑같다(변화 없음).
- 새 버전을 알면:
  - 위 꼬리표: `현재 v4.6` → 화살표 → `새 v<새 버전>`(진한 파랑 바탕·흰 글자 꼬리표).
  - GitLab 타일: 테두리 2px `#1D4ED8`, 위 가장자리 가운데에 걸친 꼬리표 **"여기서 받으세요"**(진한 파랑 바탕·흰 11px Bold, 위로 12px 걸침), 아래 안내 문구 "v<새 버전> 받으러 가기 ↗".
  - 움직임: 타일 둘레에서 파란 물결(`rgba(29,78,216)` 불투명도 0.55→0, 0→14px 퍼짐)이 1.6초마다 반복, ↗ 화살표가 1.6초마다 오른쪽 위로 2px 오르내림.
  - 움직임 끔(Windows 설정)이면 물결·화살표 움직임 없이 테두리·꼬리표만.
  - 창이 닫히거나 숨겨지거나 잠기면 움직임을 멈춘다.
- 온나라 타일·온나라 안내·닫기 동작은 그대로.

### ⑤ 설정 › 시스템 — 인터넷 접속
- 시스템 묶음에서 '바탕화면 고정'과 '앱 글꼴' 사이에 **인터넷 접속** 스위치 줄. 기본 꺼짐.
- 툴팁: "켜면 하루 한 번 GitLab 공개 저장소에서 새 버전이 있는지만 확인합니다. 일정·메모는 보내지 않습니다. 업무망 PC는 꺼 두세요."
- 오른쪽 열(데이터·보안·시스템) 모든 줄 높이 36px. 창 800×560 유지, `layout().minimumSize().height() ≤ 560`.

## 6. 동작

- **켜져 있을 때 확인 시점**: 메인 창이 뜬 뒤 60초에 한 번, 그 뒤 앱이 켜져 있는 동안 24시간마다. 스위치를 켠 직후에는 5초 뒤 한 번.
- **실패**: 조용히 넘어간다(오류 기록만 남김). 실패하면 1시간 뒤 한 번 더, 그래도 실패하면 다음 정기 확인까지 기다린다.
- **비교**: 태그 형식 `v<주>.<부>[영문 소문자 한 글자]`(예: v4.6, v4.5a, v4.10). (주, 부, 글자)로 비교하며 글자 없음 < a < b. 받은 값이나 현재 `APP_VERSION`이 형식에 맞지 않으면 새 버전 없음으로 본다. `upcoming_release`가 참인 Release는 무시한다.
- **끌 때**: 키 저장 → 예약 취소 → 진행 중 요청의 늦은 결과 무시 → 알게 된 새 버전 정보 지움(점·꼬리표·강조 사라짐).
- **잠금·숨김·트레이**: 확인 자체는 예약대로 해도 되지만 화면 표시(알림)는 ①의 규칙을 따른다. 잠금 중 점이 잠금 화면 위로 보이지 않는다(점은 머리줄의 자식이므로 잠금 덮개 아래).
- **초기화(Factory Reset)**: 설정이 지워져 꺼짐이 된다 → 예약·표시를 끄는 경로를 탄다.
- **가져오기**: 이 키는 내보내기에서 빠지므로 가져오기가 바꾸지 않는다.

## 7. 데이터 계약

- 새 설정 키: `SETTING_INTERNET_ACCESS = "internet_access_enabled"` — `"1"`/`"0"`, 키가 없으면 꺼짐. 마이그레이션에 넣지 않는다.
- `EXPORT_EXCLUDED_SETTINGS`에 추가한다(PC마다 망이 다르므로 다른 PC로 옮겨 가 켜지지 않게).
- 그 밖에 저장하는 것 없음: 확인 시각·발견한 버전·알림 표시 여부는 메모리 전용(앱을 다시 켜면 다시 확인하고, 새 버전이면 알림이 다시 한 번 뜬다).
- 이 기능의 어떤 경로도 `database`의 다른 쓰기 함수를 부르지 않는다(스위치 저장만 `save_setting` 한 번).

## 8. 네트워크 계약

> 통신 구현은 2026-11-10 설계로 바뀌었다(v4.9): `OpenerDirector`·`ssl` 대신 Windows 내장 WinHTTP(`src/winhttp_get.py`)를 쓴다. 주소·헤더·시간·크기·해석·실행 계약은 그대로다. [EXE에서 Python용 OpenSSL 빼기 설계](2026-11-10-openssl-free-exe-design.md)

- 주소(고정, 입력으로 만들지 않음): `https://gitlab.aigov.go.kr/api/v4/projects/647/releases?per_page=1&order_by=released_at&sort=desc`
  - 2026-11-04 확인: 로그인 없이 200, 리디렉션 없음, JSON 배열 1개, `tag_name` = `v4.6`, `upcoming_release` = false, 약 4KB, 0.2초.
- 요청: GET, 헤더는 `Accept: application/json`과 고정 User-Agent(예: `ClimateNote-UpdateCheck`)만. 쿠키·인증·사용자 데이터 없음. 시간 제한 10초. 응답은 최대 256KB까지만 읽고 넘으면 실패.
- 처리기: §3의 HTTPS 전용 `OpenerDirector`(리디렉션 처리기 없음). HTTPS 프록시와 `no_proxy`는 시스템 설정을 따른다. 인증서는 `ssl.create_default_context()`(Windows 인증서 저장소).
- 해석: JSON 배열 → 첫 항목 dict → `tag_name` 문자열이 태그 형식에 맞을 때만 사용. 그 밖의 필드는 쓰지 않는다.
- 실행: GUI 스레드를 막지 않는다(작업 스레드 하나 + 결과를 GUI로 넘기는 신호/큐). 요청마다 결과 큐를 새로 만들어(세대 번호와 같은 역할) 끄기·초기화·종료 뒤 도착한 결과는 버린다. 앞선 요청이 아직 돌면 새 요청을 시작하지 않고 5초 뒤 다시 본다.
- 판정·해석·비교는 Qt·DB 없는 모듈 한 곳(예: `src/update_check.py`)에 두어 단위 테스트한다.

## 9. 내가 정한 것(사용자 확인 전 제안)

- 메뉴는 글자 꼬리표 대신 아이콘의 점(메뉴 폭 때문, 시안 ③에 반영).
- 오른쪽 열 줄 높이 36px(설정창 높이 때문, 시안 ⑤에 반영).
- 알림은 앱 실행마다 새 버전이면 한 번(저장하지 않음 → 아침에 앱이 켜질 때 한 번씩 다시 보임).
- 확인 시점(60초 뒤·24시간마다·켠 직후 5초)과 실패 시 1시간 뒤 1회 재시도.
- 내보내기 제외, 끌 때 정보 지움, 숨김·잠금 중 발견하면 다음 표시 때 알림.
- 리디렉션 없는 Release 목록 주소 사용(보안 규칙상 리디렉션을 따르지 않으므로).
- 스위치를 켜고 끈 일은 기존 감사 로그(`security.audit`)에 "인터넷 접속 켬/끔"으로 남긴다(망 정책 확인용). 확인 요청 자체는 감사 로그에 남기지 않고, 실패만 오류 로그에 분류(시간 초과·연결·HTTP 코드·형식)로 남긴다(`app_error` 로거는 ERROR 이상만 기록하므로 `.error()`로 쓴다).
- 브라우저 열기 기능은 스위치와 무관(§2 비목표).

## 10. 만드는 사람에게 맡기는 것

- 알림(토스트) 구현 방식: qfluentwidgets `InfoBar`를 꾸미거나 자체 위젯. 시안 ①의 모양·크기·동작이면 된다. 중간·크게 크기에서의 기준 위치(캘린더 판 가로 가운데·머리줄 아래)의 세부.
- 물결 애니메이션 구현(타일 뒤 오버레이에 둥근 테두리를 그려 퍼뜨림 등)과 갱신 빈도(초당 30회 이하 권장).
- HTTPS 전용 opener를 `fetch_data.py`와 공유할지 따로 둘지(EXE에는 `fetch_data.py`가 들어가지 않는다).
- 개발용 미리보기: 최신 버전을 가짜로 넣어 ①~④를 보는 도구(예: `tools/dev_update_check_preview.py --latest v4.7`, 합성 데이터 폴더). `tools/dev_holiday_theme_preview.py`처럼 `build.spec`·`build_app.py`에서 빼고 `tests/test_source_layout.py`로 고정한다. 배포 EXE에는 버전을 바꾸는 옵션·환경 변수를 두지 않는다.

## 11. 검증

**자동(pytest, 네트워크 없음)**
- 태그 해석·비교: v4.6<v4.7, v4.6<v4.6a, v4.5a<v4.6, v4.9<v4.10, 형식 오류 → 없음.
- 응답 해석: 정상, `upcoming_release` 참, `tag_name` 없음/형식 오류, 배열 아님, 256KB 초과, JSON 오류, HTTP 3xx·4xx·5xx·시간 초과 → 모두 '새 버전 없음'이고 예외가 밖으로 나가지 않음.
- opener: 리디렉션·HTTP 처리기 없음, HTTPS 프록시만. `urlopen` 미사용(기존 검사).
- 스위치: 기본 꺼짐, 켜고 끄면 키 저장, **꺼져 있으면 요청이 한 번도 없음**(가짜 opener로 확인), 켠 뒤 예약대로 요청, 끈 뒤 늦은 결과 무시·표시 지움.
- 내보내기·가져오기 왕복에서 이 키가 빠짐(데이터 변경 왕복 테스트).
- 설정창: 줄 순서, 오른쪽 열 36px, `minimumSize().height() ≤ 560`.
- 화면: 새 버전일 때만 ⋮ 점·메뉴 아이콘 점·④ 꼬리표·강조, 점 테두리가 테마 머리줄 색, 움직임 끔이면 애니메이션 미시작, 창 닫힘·잠금 때 정지, 알림은 실행당 한 번·잠금 중 미표시·받기가 주소를 연다(가짜 `QDesktopServices`).
- 하네스: UI는 `quick --tests <관련 파일>`, 설정 키·내보내기 제외는 `data`.

**자동(EXE, release)**
- 실패가 화면에 보이지 않는 기능이라 EXE에서 안 돌아도 알 수 없다. 그래서 `release` 격리 실행에 시나리오를 더한다: 합성 데이터에서 스위치를 켜고 닫힌 포트를 HTTPS 프록시로 준 EXE가 약 60초 뒤 `error.log`에 `새 버전 확인 실패: connection`을 남기는지 본다(인터넷 불필요). 버전을 바꾸는 옵션은 EXE에 넣지 않는다.

**수동(실제 EXE, 합성 데이터)**
- 인터넷 PC: 스위치 켬 → 현재가 최신이면 아무 표시 없음, 75초 뒤 `error.log`에 확인 실패 없음(TLS까지 성공했다는 근거. `smoke_release.py --live-update-check`). 개발용 미리보기로 v4.7을 넣어 ①~④ 확인(중간·크게, 공휴일 테마 하나 이상, 움직임 끔).
- 업무망 PC(또는 망 차단): 스위치 켬 → 아무 표시·오류 없음, 앱 조작 지연 없음.
- 스위치 꺼짐: 네트워크 요청 없음(방화벽/프록시 기록으로 확인 가능하면 확인).
