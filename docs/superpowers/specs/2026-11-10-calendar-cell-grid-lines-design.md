# 캘린더 날짜 칸 구분선(A안 · 가는 격자선) 설계

작성일: 2026-11-10 / 상태: **구현**(v4.9 개발 범위, 2026-11-10, [작업 기록](../../work/2026-11-10-ui-feedback-bundle.md))

> **구현 때 바뀐 결정(사용자 2026-11-10)**: 세 크기 모두에 넣되 **설정 스위치로 켜고 끄며 기본은 꺼짐**이다(아래 '설정 스위치는 넣지 않는다'를 대신한다). 키 `calendar_grid_lines_enabled`(`"1"`/`"0"`, 키가 없으면 꺼짐, 마이그레이션 없음, Export 포함). 설정창에 빈 행이 없어 화면 표시 마지막 행을 나눠 `공휴일 테마 [스위치] · 칸 구분선 [스위치]`로 둔다. 최초 크기 선택 미리보기는 그대로 둔다(약 0.15배 그림이라 1px 선이 보이지 않는다). 끄면 v4.8과 같은 모양(틈 2px, 채움 6px 모서리)이다.
>
> 구현 방식: 칸 틈을 1px로 줄이고(요일 머리줄 격자도 같이), 캘린더 영역 전체를 덮는 마우스 통과 위젯 `ui_calendar_grid.CalendarGridLines`가 그릴 때마다 칸 위치를 재어 틈 가운데에 장치 1픽셀 선을 긋는다(칸·여러 날 막대 아래 층). 채움은 칸 QSS의 `margin: 2px; border-radius: 5px`다(배경만 줄고 칸 안 배치는 그대로임을 실측). 색 `#E3E6EA`는 시안 값 그대로이고 실제 EXE 100/125/150% 확인은 수동 확인 목록에 있다.

## 배경

- 사용자 의견(2026-11-10): 캘린더에서 날짜끼리 구분이 잘 안 된다. 칸 안쪽 선(테두리)이 있으면 좋겠다.
- 지금 모습: 칸 사이 간격 2px, 선 없음. 오늘·고른 날만 둥근(6px) 채움이다.
- 개발자는 선을 없앤 디자인을 원했지만, 사용자 의견을 받아 선을 넣는 시안을 만들어 보기로 했다.
- 같은 칸에 남은 이전 결정: 2026-10-11 중간·크게의 고른 날 2px 테두리(디자인 점검 15번)를 사용자 요청으로 채움으로 되돌렸다([UI 계약](../../UI_PATTERNS.md) Calendar Scale). 그래서 이번 선은 **날짜를 나누는 구분선**일 뿐이고, 고른 날 표시는 채움 그대로 둔다.

## 결정: A안

- **선**: 칸과 칸 사이에만 1px 실선을 긋는다. 색은 `#E3E6EA`이다.
  - 지금 쓰는 두 회색의 중간 밝기다. 일정 패널 위 구분선 `rgba(206,210,216,120)`(흰 바탕에서 약 `#E8EAEC`)보다 조금 진하고, 캘린더 영역 테두리 `rgba(206,210,216,180)`(약 `#DCDFE3`)보다 옅다.
  - 시안에서 비교한 색: `#ECEEF1`·`#E3E6EA`·`#D5D9DF`·`#C4CAD3`. 최종 색은 실제 EXE에서 100/125/150% 배율로 보고 정한다.
- **바깥 틀 없음**: 격자 바깥(맨 위·맨 아래·좌우 끝)에는 선을 긋지 않는다. 캘린더 영역의 기존 테두리는 그대로 둔다. 요일 머리줄과 첫 주 사이에도 선을 긋지 않는다.
- **빈 칸**: 이번 달 밖의 빈 칸(숫자 없는 칸)에도 선은 이어진다. 그래야 격자가 끊기지 않는다.
- **채움은 선에서 2px 안쪽**: 오늘(기본 크기의 남색 칸)·고른 날·공휴일 테마 칸 바탕의 채움은 선에서 2px 떨어뜨리고 모서리는 5px로 둥글게 한다(지금은 6px). 선에 붙은 각진 덩어리가 되지 않게 해서 앱의 둥근 느낌을 지킨다.
- **그대로 두는 것**: 중간·크게의 날짜 숫자 위치(왼쪽 위 26×26), 오늘 남색 원, 일정 칩, '+N 더', 기본 크기의 색 네모·'+N', 요일 글자. 여러 날 막대는 지금처럼 칸 위 층에 그려져 세로선 위를 지나간다.
- **고른 날**: 채움만 쓰고 테두리를 더하지 않는다(15번 되돌림 결정 유지).

## 구현 전에 정할 것

- **적용 크기**: 아래 둘 중 하나를 고른다.
  1. 세 크기 모두에 선을 넣는다(시안 그대로). 크기를 바꿔도 모양이 같다.
  2. 중간·크게에만 넣고 기본 크기는 지금대로 둔다. 기본 크기는 칸이 작고 숫자가 가운데에 있어 지금도 구분이 되는 편이고, 일정 칩이 왼쪽에 붙는 중간·크게에서 경계가 더 흐리다.
- **최초 크기 선택 미리보기**: `ui_first_run.py`는 캘린더를 실제 비율의 벡터 그림으로 보여 준다. 미리보기에도 선을 그릴지 정한다.

## 구현 방향(참고, 구현 때 확인)

- **칸 테두리로 선을 긋지 않는다.** QSS 배경은 테두리 상자까지 칠한다. 그래서 칸(`#calendarDayButton`)에 `border-right`·`border-bottom`을 주면 채움이 선에 붙고, '2px 안쪽 둥근 채움'이 되지 않는다.
- 후보 방법:
  - 날짜 격자 간격을 `calendar_grid.setSpacing(2)` → `1`로 줄인다. 요일 머리줄도 `header_layout.setSpacing(2)` → `1`로 맞춰 열 정렬을 유지한다.
  - 그 1px 틈에 선을 그리는 **표시 전용 위젯**을 둔다. `CalendarSpanOverlay`(`ui_calendar_spans.py`)처럼 격자 영역에 맞추고, 마우스를 통과시키고, 칸의 실제 위치로 선 자리를 계산한다. 여러 날 막대 층보다 아래에 둔다.
  - 채움을 2px 안쪽에 그리는 방법은 구현 때 확인한다. 예: QSS `margin`이 `QWidget`+`WA_StyledBackground`에서 채움을 줄이는지, 아니면 칸 안에 채움용 자식 위젯을 둘지.
- **배율**: 125/150%에서 1px 논리 선은 1.25/1.5 장치 픽셀이 되어 흐리거나 두께가 들쭉날쭉할 수 있다. 장치 1픽셀 cosmetic 펜과 픽셀 격자 맞춤을 검토한다.
- **공휴일 테마**: 테마 칸의 연한 바탕과 오른쪽 위 6px 점(`_place_theme_dot`, 5px 안쪽)이 2px 안쪽 채움 안에 들어오는지 확인한다. 머리줄 장식은 관계없다.
- 칩 영역이 2px 안쪽 여백 때문에 좁아져 말줄임이 바뀌는지 본다(`QSizePolicy.Ignored` 정책은 유지).

## 바꾸지 않는 것(데이터·계약)

- **표시 전용**이다. DB v19·Export v4·salt·암호문·설정 키·일정 저장값(본문·canonical 3색)을 바꾸지 않는다. `database` 쓰기 함수를 부르지 않는다.
- 설정 스위치는 넣지 않는다. 나중에 '선 끄기'가 필요하면 별도 결정이다. 그때는 새 키+기본값 fallback, 마이그레이션 없음, 설정창 800×560 무스크롤 계약을 따른다.
- 7열 같은 stretch, 칩 가로 `QSizePolicy.Ignored`, 세로 화면에서 열 너비 차이 1px 이내, 요일 제목 정렬([UI 계약](../../UI_PATTERNS.md), [검증](../../TESTING.md)).
- 여러 날 막대 위치 규칙(`CalendarSpanOverlay.bar_rects`), 공휴일 테마 판정, Win+D·창 위치 복원.
