# v3.1 설정창 · 크게/중간 모드 개선 설계

- 작성일: 2026-06-13
- 대상 앱: 기후노트 (MyDesktopCalendar) v3.1
- 스키마: 변경 없음 (DB·설정 키 그대로)
- 디자인 출처: Claude Design handoff 번들 `설정창 리디자인.dc.html` **시안 A (Fluent 정돈형)**

## 1. 배경 / 문제

사용자가 실제 앱(v3.1)을 쓰며 비주얼·동작 이슈를 직접 골랐다.

**설정창**
1. 맨 위 크고 굵은 "설정" 텍스트가 불필요.
2. 섹션 헤더(화면 표시·데이터 등)가 본문 대비 약해 그룹 구분이 잘 안 됨.
3. 하단 크레딧(버전·만든이)이 줄바꿈됨.
4. 데이터 초기화에 PIN 입력이 번거로움.
5. 모니터 콤보 가로폭이 좁음.
6. "화면 위치" 섹션이 위아래로 답답함.

**앱 종료 / 크게·중간 모드**
7. 앱 종료 버튼을 두 번 눌러야 완전히 종료됨(한 번이면 설정창이 남음).
8. 중간·크게 모드에서 `< 연월 >` 네비게이션이 너무 오른쪽으로 치우침.
9. 크게 모드 우측 D-Day 미니패널이 세로 스크롤 리스트라 공간 낭비가 큼 + 카드에 삭제(X) 수단이 없음.
10. 크게 모드 집중 미니카드에 종료(X) 수단이 없음.

## 2. 목표 / 비목표

**목표**: 위 1~10을 해결한다. 설정창은 시안 A에 충실하게 맞추되, 앱의 기능 제약(4모서리 위치, 800×560 무스크롤)은 유지한다.

**비목표 (YAGNI)**
- 화면 위치 3×3(9방향) 도입 — 앱은 4모서리만 기능 지원. 시안의 3×3은 미적용.
- 설정 항목 추가/삭제·섹션 재배치. 기능 불변.
- 설정창 크기 변경/스크롤 도입(800×560 고정·무스크롤 유지).
- DB 스키마·설정 키 변경.

## 4. 상세 설계 — 그룹 1: 설정창 (`ui_settings.py`)

### 4.1 상단 "설정" 제목 제거 (이슈 1)
`_build_ui()`의 `title = TitleLabel("설정", self)` 블록(현 390–393행)과 `outer.addWidget(title)` 제거. `outer` 상단 여백을 약간 조정(12 → 14 정도)해 첫 섹션 카드가 너무 붙지 않게. OS 타이틀바 "설정"은 그대로(`setWindowTitle`). 깨지는 테스트 없음.

### 4.2 섹션 헤더 또렷하게 (이슈 2)
구조(`panelHeaderBar` + `StrongBodyLabel#panelHeader` + 블루 아이콘)는 **유지**(테스트 의존). 약해 보이는 원인은 Malgun Gothic이 목업의 Pretendard 700보다 가볍게 렌더되는 것. 보정:
- 헤더 글자색을 인라인 QSS 대신 **qfluentwidgets 네이티브 `header_label.setTextColor(QColor("#1A1A1E"))`로 고정**한다. `FluentLabelBase`는 `themeChanged` 시 `setTextColor(lightColor, darkColor)`를 재호출하므로, 네이티브 경로로 색을 박아두면 테마 재적용(`main.py`의 1분 주기 `_check_theme`) 후에도 흔들리지 않는다. 폰트 크기/굵기(14px/700)는 인라인 `#panelHeader{font-size:14px;font-weight:700;}`로 유지(색 지정은 제거해 네이티브와 충돌 방지).
- 헤더 바 배경은 시안 A `#FBFCFD` 유지(딥네이비 풀바로 되돌리지 않음). 실행 검증 후에도 약하면 글자색을 `#0F1115` 수준으로 한 단계 더, 그래도 약하면 헤더 바를 살짝 더 진한 톤으로 단계적 상향.

### 4.3 하단 크레딧 한 줄 (이슈 3)
`author_label.setWordWrap(True)` → **`False`**. 폭 강제 방지를 위해 `setSizePolicy(QSizePolicy.Ignored, QSizePolicy.Preferred)`(또는 Maximum)로 두고, 푸터는 좌(라이선스)–중(크레딧 stretch)–우(앱 종료) 구조 유지. 크레딧 색/크기 12px `#9094A0`. 800px에서 한 줄로 들어가는지 **실행으로 확인**.

### 4.4 데이터 초기화 PIN 제거 (이슈 4)
- "데이터 초기화" 행에서 `self.reset_pin`(`_pin_edit`)과 그 컨테이너 제거. 행 컨트롤은 `factory_reset_btn` 단독.
- `_on_reset()`: `_validate_pin` 호출 제거. 곧바로 확인 `MessageBox`("모든 일정/메모/스티키가 영구 삭제됩니다…") → 수락 시 `db.reset_database()` + `reset_salt()` + audit + InfoBar. `dlg.deleteLater()`(0026_RESLEAK) 유지. `self.reset_pin.clear()` 호출 제거.
- `factory_reset_btn`의 objectName/QSS(`padding: 5px 14px 5px 34px`, `border-radius: 6px`, minWidth≥152)·색 규칙은 **그대로**(테스트 유지).
- **보안 영향**: 0011_IMPRAUTH(파괴적 기능 인증 후 실행)를 완화. 확인 팝업은 유지. 사용자 결정(사용성 우선)에 따른 의도적 변경임을 코드 주석 + 문서에 명시.

### 4.5 모니터 콤보 가로 ↑ (이슈 5)
`self.monitor_combo.setFixedWidth(180)` → **210**(시안 A `max-width:212px`).

### 4.6 화면 위치 세로 여백 (이슈 6)
"화면 위치" 행의 세로 답답함 해소. `_add_row`는 공통이므로 위치 행만 별도로 키운다:
- 위치 행 컨테이너(`pos_grid_frame`를 담는 row)의 `setMinimumHeight`를 ~40 → **60**으로(시안 A `min-height:60px`). 또는 `_add_row`에 `min_height` 인자 추가해 위치 행만 60 지정.
- 2×2 그리드는 유지(`_position_btns` 4개, 테스트 `len==4`).

## 5. 상세 설계 — 그룹 2: 앱 종료 + 크게/중간 모드

### 5.1 앱 종료 1번에 종료 (이슈 7) — `ui_settings.py`
- 증상: 1회 클릭 시 설정창이 남고 앱이 안 꺼짐, 2회째 종료.
- 현재 `_on_quit`은 `QApplication.quit()`만 호출. 설정창(top-level)을 닫지 않음 + 메인 `closeEvent`는 `event.ignore()`로 트레이 최소화.
- 수정 방향: `_on_quit()`에서 **설정창을 명시적으로 닫은 뒤 종료**.
  ```python
  def _on_quit(self):
      self.close()
      QApplication.quit()
  ```
- **근본원인 확정 절차(systematic-debugging)**: 코드 추론만으로 2회 클릭 원인을 단정하지 않는다. `python main.py`로 실제 실행해 재현 → 위 수정으로 1회 종료되는지 확인. 만약 `quit()`이 내부 이벤트루프(메뉴/모달) 때문에 안 먹으면 `QCoreApplication.instance().exit(0)` 또는 메인으로의 종료 콜백 경유로 보강. 실행 결과로 확정.

### 5.2 월 네비 가운데 정렬 (이슈 8) — `ui_main.py`
- 원인: `_build_top_bar`의 `top_bar.addStretch(1)`(nav 앞, factor 1) vs `top_bar.addStretch()`(nav 뒤, **factor 0**) 비대칭. 확장 시 폭이 커질수록 앞쪽 stretch만 늘어 nav가 우측으로 밀림.
- 수정: nav 뒤 `top_bar.addStretch()` → **`top_bar.addStretch(1)`**. 좌우 stretch factor를 1:1로 맞춰 `nav_group`이 `top_bar`(=headerSection=달력 그리드 폭) 중앙에 오게.
- `month_label` 92px/16px·`prev/next_btn`는 변경 없음(테스트 `pixelSize==16`, `width==92` 유지). compact 모드도 자연히 중앙 유지(허용).

### 5.3 D-Day 미니패널 3열 2행 + 삭제 (이슈 9) — `ui_dday_panel.py`, `ui_main.py`
- `DDaySidePanel`: `QScrollArea` 제거, 내부를 **`QGridLayout`(3열)** 로. 최대 5개가 2행(3+2)에 배치되어 스크롤 불필요. `setMaximumHeight`는 2행+제목에 맞게 재조정.
- `DDayMiniCard`: 미니 칩으로 축소(이름 1줄 ellipsis + D수치 + 우상단 작은 X). 더블클릭 편집은 유지. **X 버튼** 추가:
  - `delete_requested = Signal(int)` 신설. X 클릭 → 확인 팝업(parent 없는 top-level `Dialog` 또는 작은 `QDialog`, 잘림 방지) → 수락 시 `delete_requested.emit(widget_id)`.
- `DDaySidePanel`가 카드의 `delete_requested`를 받아 상위로 재전파(`delete_requested = Signal(int)`).
- `ui_main.py`: `self._dday_side_panel.delete_requested.connect(self._on_panel_dday_delete)` 추가. `_on_panel_dday_delete(widget_id)`:
  - `db.delete_dday_widget(widget_id)` → 숨은 플로팅 창 정리(`self._dday_windows.pop(widget_id).close()` 등 기존 삭제 경로 재사용) → `self._refresh_dday_panel()`.
  - 기존 플로팅 `DDayWidgetWindow._on_close`/`widget_closed` 경로와 정합되게(레지스트리 일관성).
- 빈 상태 라벨("표시할 D-Day가 없습니다.")은 그리드 비었을 때 표시.

### 5.4 집중 미니카드 종료 X (이슈 10) — `ui_focus_panel.py`, `ui_main.py`
- `FocusMiniCard`: 우상단 **X 버튼** 추가. `close_requested = Signal()`(집중은 1개라 id 불필요, 또는 source 식별). X 클릭 → 확인 팝업("집중 모드를 종료할까요?") → 수락 시 `close_requested.emit()`.
- `FocusSidePanel`: 카드의 `close_requested`를 상위로 재전파.
- `ui_main.py`: 패널 `close_requested` → `_on_panel_focus_close()`:
  - 단일 집중 위젯 종료 — 기존 플로팅 `FocusWidgetWindow._on_close`/`widget_closed(int)` 경로 재사용(`db` 기록 + `self._focus_windows` 정리) → `self._focus_side_panel.clear()`.
- 미러링 타이머(`FocusMiniCard._timer`)는 카드 제거 시 정지(`deleteLater` 전 `stop`).

## 6. 보안 코딩 규칙 (행안부 CODEMIND 4.5)

- 0026_RESLEAK: 새 확인 다이얼로그/팝업은 `deleteLater()`. 미니카드 타이머는 `stop()` 후 `deleteLater()`.
- 0023/0024: 새 예외 처리는 타입별 세분화 + 로깅. `except: pass` 금지.
- 0026: DB는 `_connection()` 경유(기존 `db.delete_dday_widget` 등 재사용).
- **0011_IMPRAUTH**: 초기화 PIN 제거로 이 규칙을 완화. 확인 팝업 유지 + 코드/문서에 사유 명시. `security/CODING_STANDARDS.md`(또는 반론서)에 "데이터 초기화: 사용성 결정으로 PIN 미적용, 확인 팝업으로 우발 실행 방지" 1줄 추가.
