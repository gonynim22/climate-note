# 일정 편집에서 색 바꾸기(B안 · 앞 색 원 눌러 바꾸기) 설계

작성일: 2026-11-10 / 상태: **구현**(v4.9 개발 범위, 2026-11-10, [작업 기록](../../work/2026-11-10-ui-feedback-bundle.md))

> **구현 때 정한 것**: 원은 작은 자리 위젯(`color_slot`, 폭 22px·위 여백 2px)에 담겨 행 앞 색 점 자리에 놓인다. 원은 Tab 포커스만 받고, 자리 위젯이 클릭 포커스를 받아 입력칸에 넘긴다(원만 두면 Qt가 부모를 거슬러 일정 목록에 포커스를 줘 편집이 끝났다). 키보드 순서는 입력칸 → 스마일 → 시계 → 색 원이고 원에서 Enter는 저장, Esc는 취소다. 요약 줄이 있어도 원은 입력칸 줄 가운데에 둔다. 팔레트 밖 색의 접근 이름은 "일정 색상 사용자 지정 색 — 누를 때마다 다음 색"이다. 편집기 입력칸과 요약 줄은 줄에 폭을 요구하지 않게 했다(1.5배 크게에서 원 때문에 1px 넘쳐 가로 스크롤이 생겼고, 긴 반복 요약은 이전부터 넘쳤다).

## 배경

- 사용자 의견(2026-11-10): 이미 추가한 일정을 편집할 때 색도 바꿀 수 있으면 좋겠다. 지금은 내용만 바꿀 수 있다.
- 지금 코드:
  - 인라인 편집기(`ScheduleInlineEditor`, `ui_schedule_emoji.py`)에는 색 원 3개 줄이 이미 있다. 그러나 **반복 일정일 때만** 보인다. `ui_main.py`의 `_on_edit_schedule`에서 `color=old_color if series_id else None`이고, 저장 판정도 `color_changed = bool(series_id and editor.color() != old_color)`다.
  - 저장 함수 `db.update_schedule(..., color=...)`와 `db.update_schedule_occurrence(..., color, ...)`는 일반 일정·이 날만 수정의 색도 이미 받는다.
  - 그래서 일반 일정은 내용만, 반복 일정은 색도 바꿀 수 있어 조작이 일관되지 않다.

## 비교한 시안

claude.ai 디자인 캔버스 「일정 편집 색 바꾸기 시안」(비공개, https://claude.ai/artifact/LMMGeZmi4d3tFjhKKT82UF). 기본 크기 캘린더에서 일정 줄을 두 번 눌러 실제로 편집·저장·취소하며, 저장하면 달력 칸의 색 네모가 바뀐다. B판은 Tweaks에서 설정의 일정 표시색을 바꿔 볼 수 있다.

| 시안 | 모양 | 판단 |
|---|---|---|
| A · 편집 줄 아래 색 원 3개 | 반복 일정의 색 줄을 일반 일정에도 보임, 편집 줄이 약 24px 높아짐 | 미채택 |
| **B · 앞 색 원 눌러 바꾸기** | 편집 중 줄 앞 색 점이 22px 색 원으로 바뀌고, 누를 때마다 다음 색 | **채택**(개발자 결정 2026-11-10) |

## 결정: B안

### 모양과 조작

- 일정 줄을 편집하기 시작하면 줄 앞의 16px 색 점(●) 자리에 **'일정 추가' 줄과 같은 색 원**을 둔다.
  - 지름 22px(`SCHEDULE_CONTROL_DIAMETER`), 1px 검은 테두리, 마우스를 올리면 2px다(`SmoothCircleButton`).
- 원을 누를 때마다 3슬롯 순서(1→2→3→1)로 다음 색이 된다. 입력줄의 `_on_cycle_schedule_color`와 같은 규칙이다.
- **색은 설정 › 일정 색상에서 고른 표시색으로 보인다**(`schedule_display_color`·`get_schedule_palette`). 저장값은 지금처럼 3슬롯 원래 값이다.
- 원은 편집 영역의 일부다.
  - 눌러도 편집이 끝나지 않고, 글자 입력 포커스도 입력칸에 그대로 둔다.
  - 키보드로는 Tab으로 원에 가서 Space로 다음 색을 고른다.
- **저장**: Enter 또는 편집 영역 밖으로 포커스 이동. 내용과 색을 함께 저장한다.
- **취소**: Esc. 내용과 색 모두 편집 전으로 돌아간다.
- 저장 전에도 원에는 고른 색이 바로 보인다. 저장 뒤에는 목록의 색 점, 기본 크기 달력 칸의 색 네모, 중간·크게의 일정 칩·여러 날 막대, 검색 결과가 새 색으로 바뀐다.
- 편집 중인 줄의 높이는 그대로다. 시각 열·스마일·시계·입력칸의 순서와 크기도 지금 그대로다.
- 원의 이름(접근성)과 툴팁:
  - 이름: "일정 색상 하늘 — 누를 때마다 다음 색"처럼 표시색 이름을 넣는다.
  - 툴팁: "누를 때마다 다음 색"

### 반복 일정

- 반복 일정의 '반복 전체 수정'에 있던 색 원 3개 줄도 같은 색 원 하나로 바꾼다. 일반 일정·반복 전체·이 날만 수정이 모두 같은 조작이 된다.
- 이 날만 수정은 지금처럼 그 날 사본에 색까지 저장한다. 반복 전체 수정 뒤에도 이 날만 수정한 회차는 그대로 남는다([반복 회차 수정 설계](2026-10-25-recurring-occurrence-edit-design.md)).

## 데이터(지켜야 할 것)

- 저장은 기존 `schedules.color` 열의 3슬롯 원래 값(`#FFD166`·`#4CC9F0`·`#FF6B6B`)으로만 한다.
  - 새 열·새 설정 키·마이그레이션은 없다.
  - DB 스키마 버전·Export 형식 버전·salt·본문 암호문을 바꾸지 않는다.
  - 다른 일정 행을 일괄로 바꾸지 않는다(AGENTS 'canonical 3슬롯' 계약).
- 색이 실제로 바뀐 때만 `color` 인자를 넘긴다. 내용만 고친 저장은 색을 건드리지 않는다.
- **팔레트 밖 색**(이전 파일에서 가져온 사용자 색):
  - 원은 그 색을 그대로 보여 준다.
  - 누르면 1번 슬롯부터 순환한다(입력줄과 같은 규칙).
  - 누르지 않고 저장하거나 Esc로 취소하면 원래 값을 그대로 둔다.
- 설정에서 표시색을 바꾸면 저장값은 그대로이고 화면만 새 표시색으로 보인다(지금과 같다).

## 구현 방향(참고, 구현 때 확인)

- `ui_main.py`의 `_on_edit_schedule`
  - 편집기에 늘 `color=old_color`를 넘긴다. 일반 일정도 넘긴다.
  - 저장 판정을 `color_changed = editor.color() != old_color`로 바꾼다.
  - 일반 일정 저장 경로(`db.update_schedule`)에도 바뀐 색을 넘긴다.
- `ScheduleInlineEditor`
  - 색 원 3개 줄(`color_buttons`)을 행 앞 색 원 하나로 바꾼다.
  - 행의 기존 색 점(`color_dot`)은 편집 중에 숨기고, 편집기가 가진 색 원을 그 자리에 둔다.
  - 원은 스마일·시계 버튼처럼 편집기 포커스 검사(`_check_focus`)와 `installEventFilter` 대상에 넣는다.
  - 클릭해도 포커스를 가져가지 않게 `Qt.TabFocus`로 둔다.
  - 잠금·트레이 숨김 중에는 `can_edit()`가 거짓이라 바뀌지 않아야 한다.
- 일정 추가 줄의 색 원과 같은 위젯·순환 함수를 함께 쓰면 두 곳의 모양이 어긋나지 않는다.
- 저장 실패 때 편집 원본(내용·색)을 유지하고, 날짜·월 이동과 정상 종료를 보류하는 기존 계약은 그대로다.
