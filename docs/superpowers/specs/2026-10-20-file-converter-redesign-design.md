## 1. 배경과 목표

- 지금 앱은 HWP → HWPX 하나만 된다. 화면도 파일 목록·버튼 위주라 흐름이 한눈에 들어오지 않는다.
- 사용자 결정(2026-10-19~20):
  - 문서에 한정하지 않고 **자주 쓰는 파일을 저용량으로** 변환한다. 확장자는 필수적인 것만 넣는다.
  - Filee(KnifeLemon)에서 영감은 받되 따라 하지 않는다. 도넛 메뉴, 커서 위 형식 고르기는 쓰지 않는다.
  - 화면은 **D안**이다: 넣으면 바로 → 알맞은 형식 추천 → 결과 비교.
  - ① 빈 화면에는 '자주 하는 일' 카드를 두지 않는다. 창 전체가 넣는 칸이다.
  - ② 추천 화면에는 '쓸 곳(용도)' 선택이 없다. 카드 안에 '추천' 뱃지도 없다.
  - ① 빈 화면에 **변환 관계도** 버튼을 둔다. 누르면 창 안에 임시 창이 뜬다.
  - HWP → 그림, 외부 HWP 엔진(rhwp 등) 묶기는 **보류**한다. 용량 +19MB와 시작 속도 문제 때문이다.

## 2. 범위

바꾸는 것:
- `ui_document_converter.py`: 화면 전체를 새로 짠다. 클래스 이름과 `ui_main` 연결 메서드 이름은 그대로 둔다(§9).
- 새 모듈
  - `file_conversion.py`: 형식 표, 변환 함수, 출력 검사
  - `file_conversion_worker.py`: 작업 프로세스 진입점
  - `file_conversion_runner.py`: 부모 쪽 일괄 작업 관리
- `main.py`: `--file-convert-worker` 분기 한 줄을 추가한다. 기존 `--hwp-convert-worker`와 같은 위치·같은 방식으로, DB/보안/트레이 import 전에 분기한다.
- `ui_mini_apps.py`: 타일 이름 `문서 형식\n변환` → `파일\n변환`, 설명 문구만 바꾼다.
- 표시 이름: 창 제목 `파일 변환 · 기후노트`, 제목줄 `파일 변환`, 접근성 이름 `파일 변환`. 주머니 타일 실행 접근성 이름은 `파일 변환 실행`이다.
- 아이콘 **그림만** 바꾼다: `resources/icons/mini_apps/document_converter.svg`(§5 '아이콘')
- 표시 버전 **v4.4**: `app_info.py`의 `APP_VERSION`. 출시일과 EXE 이름은 release 때 정한다.
- 관련 문서와 시험(§12, §13)

바꾸지 않는 것:
- **HWP → HWPX 경로 전부**: `hwp_conversion.py`, `hwp_conversion_worker.py`, `hwp_conversion_runner.py`. 화면만 새 화면에서 이 runner를 부른다.
  - 설치 확인, Job 격리, 보호 문서 거부, HWPX 검사, 90/105초 제한, 이름 확정 방식이 모두 그대로다.
- DB(v18), Export(v3), salt, 설정 키, 바로가기 6슬롯. **데이터 영향은 없다.** 목록·결과·선택값은 모두 메모리 전용이다.
- 창 틀: `MiniAppTitleBar`, 내용 480×620, 그림자 여백 24, 낮은 화면 압축 규칙(`fit_to_screen`)
- 앱 id `document_converter`, 아이콘 파일 이름, 보라 그라데이션 `#9775FA→#6741D9`, 미니앱 아이콘 규칙(AGENTS.md '미니앱 아이콘')
- 수명 계약
  - 잠금·트레이·사이드바/메인 숨김·화면 변경·초기화 준비·정상 종료 때 작업·큐·파일창·임시 창을 취소한다.
  - 초기화 성공 후에만 목록을 버린다.
  - 결과 파일을 자동으로 열지 않는다.
  - 파일 선택과 끌어 놓기는 같은 등록 경로를 쓴다.
  - 폴더 드롭과 폴더 재귀는 제외한다.
- 의존성과 lock. 새 패키지를 넣지 않는다. Pillow는 지금처럼 빌드에서 제외한다(`build.spec` excludes `PIL`).

## 3. 지원 형식 (확정 범위)

| 원본 종류 | 원본 확장자 | 바꿀 수 있는 결과 | 엔진 | 추가 용량 |
|---|---|---|---|---|
| 사진 | `.jpg` `.jpeg` `.png` `.webp` `.bmp` | JPG · PNG · WEBP · BMP(서로), 작은 JPG, ICO, PDF | Qt 이미지 플러그인, `QPdfWriter` | 0 (이미 번들) |
| PDF | `.pdf` | 쪽마다 PNG · JPG | Qt `pdf` 이미지 플러그인(`imageformats/qpdf.dll` + `Qt6Pdf.dll`) | 0 (이미 번들) |
| 한글 | `.hwp` | HWPX | 설치된 한글 + 공식 HWPX 변환기(기존) | 0 |
| 표·글 | `.csv` `.txt` | UTF-8(BOM 포함) · EUC-KR(CP949) | Python codecs | 0 |

확인한 사실(2026-10-20, 프로젝트 `.venv` PySide6 6.11.2·마지막 빌드 `build/build/Analysis-00.toc`):
- Qt 읽기 형식: bmp, gif, ico, jpeg/jpg, pdf, png, svg, tiff, webp 등. 쓰기 형식: bmp, ico, jpeg/jpg, png, tiff, webp 등.
- 빌드에 이미 들어 있는 것
  - `imageformats/`의 qgif·qicns·qico·qjpeg·qpdf·qsvg·qtga·qtiff·qwbmp·qwebp
  - `Qt6Pdf.dll`
  - `platforms/qoffscreen.dll`
- `QImageReader(path)`로 여러 쪽 PDF를 열면 `format()`은 `pdf`, `imageCount()`는 쪽 수로 나온다. `setScaledSize()`와 `jumpToImage()`도 동작했다(합성 2쪽 PDF로 확인).
- `PySide6.QtPdf` 모듈(`QtPdf.pyd` 241KB)은 지금 `build.spec` excludes에 있다. 위 플러그인 방식이면 필요 없다.
- PDFium 고지는 이미 `licenses/Qt-THIRD-PARTY-NOTICES.txt`에 있다. 새 라이선스 항목은 없다.

범위 밖(사용자 확인):
- 동영상·음성, HEIC·RAW·GIF 애니메이션·TIFF 여러 쪽, 전자책, 압축 파일
- HWP → 그림/PDF/DOCX/TXT, HWPX → HWP
- PDF → HWP/DOCX/TXT, PDF 합치기·나누기
- 오피스(DOCX·XLSX·PPTX) → PDF

## 4. 형식 표 한 곳 (`file_conversion.py`)

②의 추천·다른 형식, ①-1의 관계도, 파일 받기 필터가 **같은 표**를 읽는다. 화면과 관계도가 서로 어긋나지 않게 하기 위해서다. Qt 위젯 import는 넣지 않는다(`QtGui`의 `QImage`·`QImageReader`·`QImageWriter`·`QPdfWriter`·`QPainter`만).

- `KINDS`: 원본 종류. `image` / `pdf` / `hwp` / `text`. 종류마다 확장자, 표시 이름, 배지 색을 둔다.
- `TARGETS`: 결과 형식. 형식마다 아래 값을 둔다.
  - id: `jpg`, `jpg_small`, `png`, `webp`, `bmp`, `ico`, `pdf_bundle`, `pdf_png`, `pdf_jpg`, `hwpx`, `utf8`, `cp949`
  - 이름, 한 줄 태그, 설명 한 줄, 버튼 문구, 설정 목록, 출력 이름 규칙
- `recommend(kind, source_formats)`: `(추천 최대 3개, 다른 형식 목록)`을 돌려준다(§6).
- 배지 색(시안과 같은 값)
  - 사진: 청록 `#0B6576` / `#DDF1F4`
  - PDF: 갈색 `#9A3412` / `#FCEBDD`
  - 한글: 파랑 `#1D4ED8` / `#E6EEFD`
  - 표·글: 초록 `#17673A` / `#E3F3E8`
- 관계도 선 색: 사진 `#5FA8B4` · PDF `#D08A5E` · 한글 `#7C9CF0` · 표·글 `#6FB38A`

     - 정보(12px 보조색): 예 `JPG 사진 · 4.2 MB · 4032 × 3024`, 여러 개면 `JPG 사진 3개 · 합계 12.0 MB`
     - 크기·쪽 수는 실제로 읽은 값만 쓴다. 추정 값은 쓰지 않는다.
   - 오른쪽
     - `다른 파일`(링크형 버튼): 목록을 비우고 ①로 간다.
     - 여러 개면 그 앞에 `목록` 버튼을 둔다. ①-1과 같은 겹침 패널 틀로 파일 목록과 각 줄의 `×` 빼기를 보여 준다. 이 패널은 시안이 없다. ①-1의 값을 그대로 쓴다.
2. **추천**
   - 소제목 `추천`(12px 굵게 `#4E5663`) 아래에 카드 **최대 3개를 한 줄**에 둔다. 너비는 같게, 간격 8.

3. **다른 형식**
   - 소제목 아래 칩 그리드 **4열**, 간격 6

     - 넘으면 이 칸 안에서만 세로 스크롤한다(최대 높이 70).

4. **설정 칸**(고정 높이 96, 바탕 `#F4F5F8`, radius 10, 여백 12)

### 화면 전환과 끌어 놓기

- ①에 넣으면 ②로 간다.
- ②에 같은 종류를 넣으면 목록에 더한다. 다른 종류는 뺀다.
- ③에 넣으면 새 목록으로 ②에 간다.
- 진행 중에는 받지 않는다.
- **한 번에 한 종류만 받는다.**
  - 처음 받은 파일들 중 가장 앞 파일의 종류가 기준이다. 다른 종류는 빼고 한 줄로 알린다. 예: `한 번에 한 종류만 바꿀 수 있어요 · PDF 1개는 뺐어요`
- 개수·크기 제한은 기존과 같다. 최대 100개, 파일당 100 MiB, 중복 경로는 제거한다.

## 6. 추천과 설정

사진(원본 형식으로 정한다. 형식이 섞이면 '여러 형식' 규칙):

| 원본 | 추천(순서대로) | 다른 형식 |
|---|---|---|
| JPG | 작은 JPG · PNG · PDF | WEBP · BMP · ICO |
| PNG | JPG · 작은 JPG · PDF | WEBP · BMP · ICO |
| WEBP | JPG · PNG · PDF | 작은 JPG · BMP · ICO |
| BMP | JPG · PNG · PDF | 작은 JPG · WEBP · ICO |

- 여러 형식을 넣고 그중 하나와 같은 형식을 고르면, 그 형식인 파일은 `이미 PNG예요`로 건너뛴다. 실패가 아니라 건너뜀으로 센다.

| 원본 종류 | 추천 | 다른 형식 |
|---|---|---|
| PDF | PNG · JPG | 없음(줄 숨김) |
| 한글 | HWPX | 없음 |
| 표·글 | 지금 인코딩이 아닌 쪽 하나(UTF-8 또는 EUC-KR) | 없음 |

| 형식 | 설정 | 태그 / 설명 |

| EUC-KR | 없음 | 예전 프로그램용 / 표현할 수 없는 글자가 있으면 바꾸지 않아요 |

## 7. 변환 규칙

사진:
- 읽기는 `QImageReader`로 하고 `setAutoTransform(True)`를 켠다. 휴대폰 사진의 회전 정보를 반영하기 위해서다.
- 할당 한도는 Qt 기본 256MB를 유지한다. 넘으면 `사진이 너무 커서 열 수 없어요`.
- 투명 픽셀이 있는 사진을 JPG·BMP로 바꾸면 흰 바탕에 합성한다.
- 메타데이터(EXIF·위치 정보)는 결과에 옮기지 않는다.
- 크기 줄이기
  - 긴 변 기준으로 비율을 유지하고 `Qt.SmoothTransformation`을 쓴다.
  - 원래 긴 변이 기준보다 작으면 키우지 않는다.
- ICO
  - 정사각이 아니면 투명 여백으로 정사각에 맞춘다.
  - 16·32·48·256 네 크기를 한 파일에 담는다.
  - Qt 기본 `ico` writer가 여러 크기를 한 파일에 못 쓰면, ICONDIR 머리 + PNG 항목으로 직접 작성한다. 구현 시 확인한다.
- PDF 묶기
  - `QPdfWriter` 300dpi를 쓰고, 사진은 비율을 유지해 가운데에 맞춘다.
  - 여백: 없음 0, 좁게 8mm, 보통 15mm
  - '사진 크기대로'는 사진마다 그 사진 비율의 쪽이다.

PDF:
- `QImageReader`의 `pdf` 형식으로 `imageCount()`와 `jumpToImage(i)`를 쓴다.
- 크기는 쪽 크기(pt) × dpi/72로 `setScaledSize`에 넣는다.
- 한도: 최대 300쪽, 쪽당 최대 50MP. 넘으면 그 PDF는 실패로 처리하고 이유를 쓴다.
- 암호가 걸렸거나 읽을 수 없는 PDF는 `열 수 없는 PDF예요(암호·손상)`.
- frozen EXE에서 플러그인이 로드되는지 반드시 확인한다(§13). 안 되면 `PySide6.QtPdf`를 excludes에서 빼고 `QPdfDocument.render`로 바꾼다. 늘어나는 용량은 `QtPdf.pyd` 약 0.25MB다.

표·글:
- 판정 순서
  1. UTF-8 BOM이 있으면 → UTF-8
  2. `utf-8` strict로 풀리면 → UTF-8
  3. `cp949` strict로 풀리면 → EUC-KR
  4. 아니면 `글자 인코딩을 알 수 없어요`
- 줄바꿈은 바이트 그대로 유지한다. 바이트를 풀고 다시 묶을 뿐 줄바꿈을 바꾸지 않는다.
- UTF-8 출력은 BOM 포함(`utf-8-sig`)이다.
- EUC-KR 출력 코덱은 `cp949`다. 화면 표기는 `EUC-KR`로 하고 툴팁에 `CP949`를 적는다.
- 표현할 수 없는 글자가 있으면 바꾸지 않고 실패 처리한다. 대체 문자를 넣지 않는다.

HWP:
- 기존 `ConversionRunner`(파일당 작업 하나)를 차례로 부른다. 계약은 그대로다.

## 8. 출력 이름과 원본 보존

- 원본은 읽기만 한다. 작업 폴더(`.climatenote-conv-*`, 저장 폴더 안)에서 만든 뒤, 부모가 확정할 때만 옮긴다.
- 이름 규칙(`<이름>`은 원본 확장자를 뺀 이름)

| 결과 | 이름 |
|---|---|
| 형식 바꾸기 | `<이름>.<새 확장자>` |
| 작은 JPG | `<이름> (작게).jpg` |
| ICO | `<이름>.ico` |
| PDF 묶기 | 한 장이면 `<이름>.pdf`, 여러 장이면 `<첫 이름>_묶음.pdf` |
| PDF → 사진 | 새 폴더 `<이름>_쪽별` 안에 `<이름>_001.png` … |
| HWPX | 기존 그대로 `<이름>.hwpx` |
| 인코딩 | `<이름>_UTF-8.csv` / `<이름>_EUC-KR.csv`(원래 확장자 유지) |

- 이름이 겹치면 ` (1)` ` (2)`를 붙인다. `hwp_conversion.publish_result`와 같은 방식이다.
  - Windows `os.rename`의 비덮어쓰기에 기대어 경합까지 막는다.
  - 확장자를 받도록 공용 함수를 새로 둔다. `publish_result` 자체는 바꾸지 않는다.
- `_쪽별` 폴더
  - 작업 폴더 안에서 폴더째 만든 뒤 한 번에 `os.rename`한다.
  - 같은 이름 폴더가 있으면 ` (1)`을 붙인다.
- 정리: 정상·실패·취소 모두 자기 작업 폴더만 지운다. 정리 실패는 표시한다. 완료된 결과와 원본은 지우지 않는다.

## 9. 작업 프로세스와 화면 연결

- 사진·PDF·표 변환도 **별도 작업 프로세스**에서 한다. 이유는 두 가지다.
  - 손상·악성 파일이 이미지·PDF 디코더를 죽여도 앱이 함께 죽지 않게 한다.
  - 큰 파일을 처리하는 동안 화면이 멈추지 않게 한다.
- 진입점: `main.py --file-convert-worker <작업 폴더> <Job 이름>`
  - 작업 목록은 부모가 작업 폴더의 `job.json`에 쓴다. 입력 경로, 형식 id, 설정이 들어간다.
  - Job 가입과 `go` 파일 대기 방식은 `hwp_conversion_worker.worker_main`과 같다.
  - 프로세스 안에서 `QGuiApplication(["climatenote-worker", "-platform", "offscreen"])`를 만든다.
- **일괄 하나에 프로세스 하나**다. 단일 EXE(onefile)는 프로세스를 띄울 때마다 묶음을 다시 푸는 비용이 있어서, 파일마다 띄우지 않는다. 실제 비용은 §13에서 잰다.
- 진행
  - 작업 프로세스는 항목마다 `items/<번호>/` 아래 결과 파일과 `result.json`(`ok`·`message`)을 쓴다.
  - 부모(`FileConversionRunner`)는 200ms 타이머로 다 된 항목을 읽어 하나씩 확정(§8)하고 진행을 갱신한다.
- 제한
  - 항목 하나가 60초 넘게 진척이 없으면 Job을 닫아 끝낸다. 남은 항목은 `취소`, 그 항목은 `시간 초과`다.
  - `KILL_ON_JOB_CLOSE`를 쓰고, 자기 작업만 끝낸다.
- 취소·숨김·잠금·종료
  - Job을 닫는다.
  - 이미 확정된 결과는 남긴다. 늦게 도착한 결과는 확정하지 않는다.
- `ui_main` 연결 이름은 바꾸지 않는다.
  - `_open/_hide/_discard_document_converter`
  - 창 메서드: `cancel_conversion()` · `hide_owned_popups()` · `fit_to_screen()` · `shutdown()` · `setEnabled()`
  - `hide_owned_popups()`는 파일창, 저장 폴더 창, ①-1·목록 겹침 패널을 모두 닫는다.

## 10. 오류 문구 (사용자에게 보이는 것)

- 원본 경로·본문은 넣지 않는다. 화면에는 파일 이름과 이유만 보인다.
- 문구
  - `지원하지 않는 형식이에요`
  - `100 MB 이하 파일만 바꿀 수 있어요`
  - `사진을 읽을 수 없어요(손상)`
  - `사진이 너무 커서 열 수 없어요`
  - `열 수 없는 PDF예요(암호·손상)`
  - `쪽이 너무 많아요(300쪽까지)`
  - `글자 인코딩을 알 수 없어요`
  - `EUC-KR로 나타낼 수 없는 글자가 있어요`
  - `이미 PNG예요`(건너뜀)
  - `시간이 너무 오래 걸려 멈췄어요`
  - `저장 폴더에 쓸 수 없어요`
  - HWP는 기존 문구를 그대로 쓴다.

## 11. 접근성과 키보드

- 모든 칸·카드·칩은 실제 버튼이다. Tab 순서는 위에서 아래다. Enter·Space로 누를 수 있다.
- 고른 카드·칩은 `setChecked`(체크 가능한 버튼)로 상태를 드러낸다.
- 접근성 이름: 예 `작은 JPG, 가볍게 보내기, 선택됨`
- Esc 순서: 겹침 패널 → 열린 설정 목록 → 창 닫기
- 글자 대비 4.5:1 이상. 시안 색은 모두 통과한다.
