# 설계: 화면 글자 따기 (걷어낼 수 있는 다섯 번째 미니앱)

작성일: 2026-10-08 / 상태: 사용자 설계 승인, spec 검토 대기
관련 시안 (로컬 전용, `output/`은 저장소에 포함되지 않음):
- [동작 예시 HTML](../../../output/design/screen-text-capture-20261008/screen-text-capture-demo.html)

## 1. 배경과 목표

- 사용자는 2주 안에 마감되는 공무원 AI 개발 공모전(주제: 행정업무 효율화)에 기후노트로 출전하려 한다. 현재 앱은 AI로 개발했지만 실행 중에는 AI를 쓰지 않는다.
- 업무 PC는 내부망이라 클라우드 AI를 쓸 수 없다. 따라서 PC 안에서 도는 소형 모델만 가능하다.
- 기능 후보를 비교한 결과, 이미지·스캔 문서의 글자를 다시 타이핑하는 일을 줄이는 **화면 글자 따기**를 고른다. 수동으로 하면 몇 분, 표는 그 이상 걸리지만 이 기능으로는 몇 초면 된다.
- 목표
  - 화면 영역을 고르면 PC 안의 소형 모델이 한국어 글자를 읽는다.
  - 표는 칸을 유지한 채 한글·엑셀로 복사한다.
  - 공모전 뒤에도 언제든 **폴더 하나와 등록 한 줄을 지워** 앱을 원래 상태로 되돌릴 수 있다.

## 2. 사용자 결정 (2026-10-08)

| 항목 | 결정 |
|---|---|
| 엔진 | 소형 모델 탑재 (PaddleOCR 한국어 ONNX + onnxruntime). Windows 내장 OCR은 비교 기준으로만 쓴다 |
| 범위 | 기본 흐름(영역 선택 → 인식 → 수정·복사) + 표 모양 유지 복사. 전역 단축키·파일 끌어놓기·스티키 보내기는 제외 |
| 형태 | 미니앱 주머니의 다섯 번째 앱 |
| 삭제 | 개발자가 코드에서 쉽게 걷어내는 구조. 사용자용 숨김 설정은 없음 |
| 흐름 | 타일 → 도구 창 → [영역 고르기] → 결과는 같은 창에 표시 |
| 주머니 | 앱 개수에 맞춰 높이를 늘림 (5~6개 = 3줄) |
| 실행 위치 | 앱 프로세스 안의 백그라운드 스레드. 모델은 처음 인식할 때 불러옴 |

## 3. 범위

### 포함
- 선택형 미니앱 등록부와 메인 창 공용 연결부(10개 수명 지점)
- 주머니 높이 자동 확장
- `screen_text/` 패키지: 도구 창, 화면 캡처, 인식 엔진, 줄·표 재구성, 아이콘, 모델
- `build.spec`의 폴더 유무 자동 감지

- 표시 버전 `v3.9`(Windows 3.9.0.0)과 `release` 1회

### 제외
- 전역 단축키, 이미지 파일 끌어놓기, 스티키로 보내기, 클립보드 이미지 붙여넣기
- PDF 읽기, 기울어진 스캔 자동 보정, 여러 줄 병합 셀 복원, 손글씨
- 사용자용 앱 숨김·삭제 설정
- 기존 미니앱 4개의 코드·UI 변경과 공용 창 틀 추출
- GitLab push와 Release 게시

### 불변 계약
- DB v17, Export v2, salt, 암호화 키 유도, 기존 설정 키, 바로가기 6슬롯을 바꾸지 않는다. **새 설정 키, 테이블, 컬럼을 만들지 않는다.**
- 런타임은 오프라인 전용이다. 네트워크를 쓰지 않고 onnxruntime 텔레메트리를 끈다.
- Qt 6.11.2를 유지한다. lock에는 이 기능에 필요한 패키지만 추가한다.

## 4. 구조와 걷어내기

### 파일 구성
```
optional_mini_apps.py      등록부: MiniAppSpec 정의와 OPTIONAL_MINI_APPS 목록
screen_text/
  __init__.py              APP = MiniAppSpec(...) 만 둔다. numpy·onnxruntime import 없음
  window.py                도구 창 (Qt)
  capture.py               화면 멈춤·영역 선택 오버레이 (Qt)
  engine.py                인식 (numpy + onnxruntime, Qt 없음)
  layout.py                줄·표 재구성, 불확실 표시, 출력 형식 (순수 Python)
  icon.svg                 주황 아이콘
  models/                  위치 모델, 한국어 인식 모델, 사전, LICENSE, MANIFEST.json(출처·버전·SHA-256)
tests/test_optional_mini_apps.py   공용 연결부 검사 (가짜 앱 사용, 걷어낸 뒤에도 남음)
tests/test_screen_text_*.py        글자 따기 전용 검사
```

### 등록부와 공용 연결부
- `optional_mini_apps.MiniAppSpec` 필드는 다음과 같다.
  - `app_id`, `title`, `accessible_name`, `description`, `icon_path`
  - `create_window(parent) -> QWidget`
- 선택형 앱 창은 다음 메서드를 제공한다.
  - `show_near(anchor, available)`, `hide_owned_popups()`, `cancel_work()`, `fit_to_screen()`, `shutdown()`
- `OPTIONAL_MINI_APPS = (screen_text.APP,)`. 앱을 빼면 빈 튜플이다.
- `MiniAppsPocket`은 `optional_apps` 인자로 받은 앱을 기존 4개 뒤에 타일로 붙인다. 열기 요청은 공용 신호 `optional_app_requested(str)`로 보낸다.
- `MainCalendarWindow`는 선택형 앱 창을 `app_id` 기준 사전으로 들고, 다음 도우미를 둔다.
  - `_open_optional_mini_app(app_id)`
  - `_hide_optional_mini_apps()`, `_disable_optional_mini_apps()`, `_discard_optional_mini_apps()`, `_fit_optional_mini_apps()`
- 기존 10개 지점(열기, 사이드바 숨김, 크기 변경, 데이터 초기화 전, 초기화 성공, 트레이 숨김, 종료, 화면 변경, 잠금, 메인 창 Hide 이벤트)에 기존 4개 앱 처리와 나란히 한 줄씩 추가한다. 기존 4개 앱의 코드는 바꾸지 않는다.
- `screen_text`를 import하는 곳은 `optional_mini_apps.py`, `build.spec`, `tests/test_screen_text_*.py`뿐이다. 이를 테스트로 확인한다.

### 빌드
- `build.spec`은 `screen_text/` 폴더가 있을 때만 다음을 넣는다.
  - `screen_text/models`, `screen_text/icon.svg`를 datas로
  - `onnxruntime`을 hiddenimports로
  - `numpy`를 excludes에서 빼기
- 폴더가 없으면 지금과 같은 빌드가 된다(numpy 제외).
- 모델 파일(약 18MB)은 저장소에 포함한다. 클론 직후 인터넷 없이 빌드할 수 있게 하려는 것으로, `holidays.py`를 추적하기로 한 결정과 같다. 대가로 나중에 걷어내도 git 이력에는 남는다.

### 걷어내기 절차 (`docs/SCREEN_TEXT.md`에 같은 내용 기록)
1. `screen_text/` 폴더 삭제
2. `optional_mini_apps.py`에서 등록 줄 삭제 (`OPTIONAL_MINI_APPS = ()`)
3. `tests/test_screen_text_*.py` 삭제
4. `AGENTS.md`·`README_detail.md`의 해당 항목과 라이선스 고지 정리
5. (선택) `requirements*.txt`와 lock에서 onnxruntime·flatbuffers·protobuf 제거
6. `full` 검증 → 빌드 → EXE 크기와 numpy 미포함 확인

## 5. 화면 흐름

### 주머니
- 타일 이름은 `화면 글자\n따기`, 접근성 이름은 `화면 글자 따기 실행`, 도움말은 `이미지·스캔 속 글자를 읽어 복사`다.
- 아이콘은 AGENTS.md 아이콘 규칙을 따른다. 예비 색인 주황 `#FF9A4D→#D9480F`을 쓰고, 도형은 스캔 모서리와 글자 줄이다.
- 주머니 본체 높이는 `60 + 110 × 줄 수`로 정한다(2줄 280px, 3줄 390px). 폭 252px, 타일 104×100px, 그림자 여백은 기존과 같다. 작업 영역보다 크면 기존 규칙대로 목록만 스크롤한다.

### 도구 창
- 기존 도구 창과 같은 흰 카드·그림자 틀을 쓴다. 내용 460×560px(그림자 포함 508×608px)이고, 좁은 화면은 기존 `fit_to_screen` 규칙을 따른다.
- 처음 상태
  - 안내: "복사할 수 없는 이미지나 스캔 문서의 글자를 읽습니다"
  - [영역 고르기] 버튼(기본 포커스)
  - 표시: "인터넷 없이 이 PC에서만 처리"
- 인식 중: "읽는 중…"과 [취소]를 표시한다. 첫 인식이면 "처음 한 번은 모델을 불러오느라 조금 더 걸립니다"를 함께 표시한다.
- 결과 상태
  - 고른 영역의 미리보기(최대 높이 90px)
  - 탭 [글자] / [표 모양]. 표가 감지되면 표 모양 탭이 기본이고, 없으면 글자 탭만 보인다.
  - 상태 표시: `확인 필요 N곳` 또는 `확인 완료`
  - 편집 가능한 결과. 글자 탭은 텍스트 편집기, 표 모양 탭은 표 편집기이며 불확실한 곳은 노란 배경이다.
  - 버튼 [복사](기본), [다시 고르기]
- 불확실한 단어나 칸을 사용자가 고치면 노란 표시를 해제하고 개수를 갱신한다.

### 영역 고르기
1. [영역 고르기]를 누르면 도구 창을 숨기고 200ms 뒤 각 화면을 `QScreen.grabWindow(0)`으로 찍는다.
2. 찍은 화면 전체의 98% 이상이 거의 검은색(휘도 8 미만)이면 캡처가 막힌 것으로 본다. 오버레이를 띄우지 않고 "보안 프로그램이 화면 캡처를 막아 글자를 딸 수 없습니다"를 표시한다. 우회를 시도하지 않는다.
3. 화면마다 멈춘 화면을 어둡게 덮은 오버레이(`Tool | Frameless | StaysOnTop`)를 띄운다. 끌어서 사각형을 고르고 크기를 표시한다. Esc나 오른쪽 클릭은 취소다.
4. 선택은 시작한 화면 안으로 제한한다. 8×8 논리 px보다 작으면 무시한다. 잘라내기는 해당 화면의 device pixel ratio로 실제 픽셀 좌표를 계산한다.
5. 놓으면 오버레이를 닫고 **찍어 둔 화면 전체 이미지를 바로 버린다.** 잘라낸 이미지만 인식에 넘기고, 도구 창을 다시 표시한다.

### 복사
- 글자 탭: 일반 텍스트만 넣는다.
- 표 모양 탭
  - `text/plain`: 표 위아래 문장 + 탭으로 구분한 표
  - `text/html`: 같은 내용의 `<table>`
  - 엑셀은 탭 구분으로 칸이 나뉘고, 한글은 HTML 표를 표로 붙인다(업무 PC 수동 확인 항목).
- 복사 뒤 상태 표시줄에 "복사했습니다"를 잠깐 표시한다.

### 오류 안내
- 글자를 찾지 못하면: "고른 영역에서 글자를 찾지 못했습니다"
- 모델 파일이 없거나 SHA-256이 다르면: "인식 모델을 확인하지 못했습니다"를 표시하고 [영역 고르기]를 비활성화한다.
- 인식 중 예외: 오류 종류만 로그에 남기고 "글자를 읽지 못했습니다. 다시 시도해 주세요"를 표시한다.

## 6. 인식 엔진 (`engine.py`)

- 입력: 너비, 높이, RGB 바이트. 출력: 글자 상자 목록 `(x, y, w, h, text, score, char_scores)`. Qt를 import하지 않는다.
- 모델
  - 위치 모델: PP-OCR 계열 mobile det (2~5MB)
  - 인식 모델: `korean_PP-OCRv5_mobile_rec` (약 13MB)와 사전
  - 정확한 파일은 첫날 실험으로 확정한다. `MANIFEST.json`에 출처 URL, 버전, 크기, SHA-256, 라이선스(Apache-2.0)를 기록한다.
- 불러오기
  - 처음 인식할 때 SHA-256을 검사하고 `InferenceSession`을 만든다. 불일치하면 실행을 거부한다.
  - CPU 실행만 쓰고 `intra_op_num_threads = min(4, cpu 수)`로 둔다.
  - 텔레메트리 끄기 API를 호출한다(실험 때 1.30에서 존재 확인).
- 위치 찾기
  - 긴 변을 960 이하(32의 배수)로 맞추고 ImageNet 평균·표준편차로 정규화한다.
  - 확률 맵을 0.3으로 이진화한 뒤 numpy만으로 연결 요소를 나눈다(scipy·OpenCV 없음).
  - 요소마다 기울지 않은 사각형을 만들고, 평균 확률 0.6 미만은 버린다. 남은 상자는 DB 방식 비율로 넓힌다.
- 작은 글씨 확대
  - 선택 영역의 예상 글자 높이가 작으면 확대한 뒤 위치를 찾는다.
  - 기본은 2배이고 실험으로 확정한다. 긴 변이 4000px를 넘으면 줄인다.
- 글자 읽기
  - 상자를 잘라 모델 입력 높이에 맞춰 비율을 유지한 채 크기를 바꾸고, 묶어서 추론한다.
  - CTC greedy로 해독하고, 글자별 확신도와 평균 점수를 낸다.
- 취소: 위치 찾기와 읽기 묶음 사이마다 취소 여부를 확인한다.

## 7. 줄·표 재구성과 불확실 표시 (`layout.py`)

- **줄**: 상자 중심의 y로 정렬하고, 세로 겹침이 작은 쪽 높이의 50% 이상이면 같은 줄로 묶는다. 줄 안에서는 x로 정렬한다.
- **표 판단**: 줄의 상자 x 구간이 표의 열 띠와 1:1로 대응할 때만 그 줄이 표에 들어간다. 구간 하나가 열 띠 2개 이상과 겹치거나 열 띠 하나가 구간 2개 이상과 겹치면 그 줄에서 표가 끝난다. 표의 모든 행은 상자 2개 이상이고, 표는 행 2개 이상·열 띠 2개 이상이다. 테두리 유무는 따지지 않는다.
- **칸 배정**: 상자는 중심 x가 속한 열 띠에 넣고, 어느 띠에도 속하지 않으면 가장 가까운 열 띠에 넣는다. 한 칸에 여러 상자가 들어가면 공백으로 잇고, 빈 칸은 빈 문자열이다. 여러 줄 병합 셀은 첫 칸에만 들어간다.
- **출력**: 일반 텍스트(칸을 공백으로), 탭 구분 텍스트, HTML 표. HTML은 글자를 escape하고 스타일 없는 `<table>`만 쓴다.
- **불확실 표시**: 자동으로 고치지 않는다.
  - 평균 점수가 0.80 미만인 상자(기준값은 실험으로 확정)
  - 숫자 열(비어 있지 않은 칸의 절반 이상이 "숫자 같은" 칸)에서 숫자 같으면서 숫자를 포함하고 비슷한 영문자(`l I O o S B`)도 포함한 칸. 분류에만 `l I → 1`, `O o → 0`, `S → 5`, `B → 8`로 바꿔 보며 글자는 바꾸지 않는다.

## 8. 수명 처리

| 트레이 숨김, 사이드바 숨김, 크기 변경, 데이터 초기화 전, 메인 창 Hide 이벤트 | 오버레이 닫기, 인식 취소, 창 숨김 |
| 화면 변경 | 오버레이 닫기(선택 취소), 창을 화면 안으로 맞춤 |
| 초기화 성공, 종료 | `shutdown()`: 인식 취소, 결과·미리보기·모델 세션 폐기, 창 삭제 |
| 사용자가 창 닫기 | 인식 취소, 모델 세션 해제. 결과는 다음 열기까지 유지 |
| 잠금 중 열기 요청 | 기존 `_mini_apps_allowed()` 검사로 차단 |

- 늦게 도착한 인식 결과는 실행 번호를 비교해 버린다.
- 오버레이는 ShowDesktopKeeper 감시 대상이 아니다.

## 9. 데이터 보호와 보안

- 모니터 전체를 찍은 이미지는 선택이나 취소 즉시 버린다. 잘라낸 이미지와 결과는 메모리에만 둔다. 임시 파일을 만들지 않는다.
- 로그에는 오류 종류만 남기고 글자나 이미지는 남기지 않는다.
- 캡처는 [영역 고르기]를 눌렀을 때만 하고, 클립보드에는 [복사]를 눌렀을 때만 넣는다.
- 모델은 SHA-256을 확인한 번들 파일만 불러온다. 외부 경로나 사용자 지정 모델은 받지 않는다.
- 보안 프로그램의 캡처 차단을 감지하면 안내만 한다.

## 10. 의존성, 라이선스, 크기

- 직접 의존성에 `onnxruntime`을 추가한다(1.30.0, MIT). 하위 의존성은 `flatbuffers`, `protobuf`이고, `numpy`는 이미 lock에 있다.
- 최종 버전은 로컬 OSV 검사에서 알려진 취약점이 없는 것으로 고른다.
- lock 갱신, 전체 재검증, EXE 재빌드, 검증 스냅샷 갱신을 한 묶음으로 처리한다.
- `licenses/THIRD_PARTY_NOTICES.txt`에 PaddleOCR 모델(Apache-2.0), onnxruntime(MIT), numpy(BSD-3), protobuf(BSD-3), flatbuffers(Apache-2.0)를 추가한다.
- EXE 크기는 약 59MB에서 100MB 안팎으로 늘 것으로 예상한다. release에서 실제 크기와 시작 시간을 이전 EXE와 비교해 기록한다.

## 11. 검증

### 자동
- `test_screen_text_layout.py`: 합성 상자로 줄 묶기, 표 판단(테두리 없는 표 포함), 칸 배정, 일반·탭·HTML 출력, HTML escape, 불확실 규칙
- `test_screen_text_engine.py`
  - 연결 요소, 상자 넓히기, CTC 해독을 합성 배열로 검사
  - MANIFEST 불일치 시 실행 거부
  - 실제 모델로 테스트 중 Qt가 그린 합성 한국어 문장·표 이미지의 글자 정확도가 기준 이상인지 검사(기준은 실험 결과로 정함)
- `test_screen_text_ui.py`
  - 도구 창 상태 전환
  - 가짜 스크린샷 주입으로 선택, Esc, 오른쪽 클릭 취소, 화면 경계 제한, DPR 잘라내기
  - 검은 화면 차단 안내
  - 복사 MIME(텍스트+HTML)
  - 노란 표시 해제
  - 첫 인식 안내와 취소
- `test_optional_mini_apps.py`
  - 가짜 선택형 앱으로 10개 지점 수명 처리
  - 주머니 3줄 높이, 빈 등록부일 때 기존 252×280과 타일 4개
  - `screen_text` import 위치 제한
- UI 검사는 100/125/150% 합성 배율로 실행한다.
- `release`: 전체 pytest, 새 EXE 빌드, 격리 실행 3개 시나리오를 거친다. 이어서 EXE 안의 모델 SHA-256, onnxruntime·numpy 포함, Qt 6.11.2 DLL, mingw DLL 부재, 크기를 기록한다.

### 수동 (업무 PC)
- 보안 프로그램의 캡처 차단 여부(`Win+Shift+S`로 사전 확인)
- 한글에 HTML 표로 붙는지, 엑셀 칸이 유지되는지
- 혼합 DPI·KVM 환경, 실제 스캔 이미지의 품질과 속도
- 공모전용 실측: 같은 표 옮기기를 타이핑과 이 기능으로 시간 비교

## 12. 첫날 실험과 진행 기준

- 산출물은 `output/` 아래에 두고 제품 코드로 쓰지 않는다.
- 표본: 합성 공문 본문, 테두리 있는 표·없는 표, 9pt 작은 글씨, 스캔 느낌 이미지를 각각 100/125/150%로 캡처한 이미지
- 측정
  - 소형 모델과 Windows 내장 OCR의 글자 정확도와 처리 시간
  - 모델 로딩 시간
  - 확대 배율과 불확실 기준값
- 진행 기준
  - 소형 모델이 Windows 내장 OCR과 비슷하거나 낫고, 일반 선택이 체감상 기다릴 만한 시간이면 진행한다.
  - 그렇지 않으면 사용자에게 결과를 보이고 큰 모델 또는 Windows 내장 OCR 전환을 다시 결정한다.

## 13. 위험과 대응

| 위험 | 대응 |
|---|---|
| 소형 모델의 한국어 품질 부족 | 첫날 실험을 통과해야 진행. 불확실 표시와 미리보기로 사람이 확인 |
| 업무 PC가 캡처를 막음 | 사전 확인. 막히면 기능을 시연할 수 없으므로 즉시 보고 |
| 서버 push 보안 검사(OSV)가 새 의존성을 거부 | 로컬 OSV로 버전을 고르고 결과를 기록 |
| EXE 크기·시작 시간 증가 | release에서 측정·기록. 걷어내기 절차로 되돌릴 수 있음 |
| 한글 버전이 HTML 표 붙여넣기를 지원하지 않음 | 탭 구분 텍스트는 그대로 들어감. 안내 문구를 추가할지 수동 확인 뒤 결정 |
| 혼합 DPI 캡처 좌표 오류 | DPR 잘라내기 테스트와 수동 확인 |
| 2주 일정 | 범위를 이 문서로 고정하고, 제외 항목은 공모전 뒤로 미룸 |
