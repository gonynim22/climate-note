# 투명도 두 갈래(캘린더 / 스티키) 설계

작성일: 2026-11-10 / 상태: **구현**(v4.9 개발 범위, 2026-11-10, [작업 기록](../../work/2026-11-10-ui-feedback-bundle.md))

> **구현 때 정한 것**: 새 키 이름은 `widget_opacity`다. 값 칸은 34px이 아니라 38px(13px 굵은 '100%'가 35px)이고, 입력 중 글자는 11px(38px 칸의 글자 영역에 '100%'가 들어가는 크기)이며, 값은 제 슬라이더 쪽(왼쪽)에 붙인다. 묶음 안 간격은 이름-슬라이더 4px, 슬라이더-값 0px, 묶음 사이 10px로 행 안 278px에 든다. 56px 슬라이더의 실제 이동 거리는 손잡이 22px을 빼고 34px다. 이전 Export 파일(위젯 키 없음)을 가져오면 파일에 있는 키만 덮어쓰므로 이 PC의 위젯 키는 그대로 남고, 키가 없던 PC는 가져온 캘린더 값을 따른다.

## 배경

- 사용자 의견(2026-11-10): 전체 투명도를 스티키 노트와 같이 쓴다. 달력, 일정 확인 칸, 스티키 노트의 투명도를 따로 조정하고 싶다.
- 지금: 설정 키 `app_opacity` 하나(`"30"`~`"100"`, 기본 `"100"`). `MainCalendarWindow._apply_app_opacity()`가 메인 창과 떠 있는 스티키·D-Day·집중 창에 같은 값을 `setWindowOpacity`로 준다([UI 계약](../../UI_PATTERNS.md) '전체 투명도').
- 세 갈래가 아니라 **두 갈래**로 정했다(개발자 결정 2026-11-10). 달력과 일정 칸은 세 크기 모두 같은 창 안에 있다. `setWindowOpacity`는 창 단위로만 먹으므로, 둘을 나누려면 한 창 안에서 부분 투명 효과(`QGraphicsOpacityEffect`)를 써야 한다. 그러면 다음 위험이 생긴다.
  - 그리기가 느려지거나 화면이 깨진다.
  - 일정 인라인 편집·이모지 팝업·한글 입력기와 부딪친다.
  - 기본 크기에서는 한 카드의 위아래가 따로 흐려진다.

## 비교한 시안

claude.ai 디자인 캔버스 「투명도 분리 작동 시안」(비공개, https://claude.ai/artifact/8NrpiVtreArVdyDGH91iLF). 판마다 바탕화면 위 설정창(화면 표시 패널)·캘린더·스티키·D-Day를 놓고, 슬라이더가 실제로 투명도를 바꾼다.

| 시안 | 설정창 '투명도' 행 | 판단 |
|---|---|---|
| A · 두 줄 슬라이더 | 캘린더·스티키 슬라이더를 위아래로, 행이 약 20px 높아짐 | 미채택 |
| **B · 한 줄에 둘** | 지금 행 높이(36px)에 슬라이더 두 개를 나란히, 값 더블클릭으로 직접 입력 | **채택**(직관적) |
| C · 대상 고르기 | [캘린더\|스티키] 버튼 + 슬라이더 하나 | 미채택 |

## 결정: B안

### 나누는 범위

- **캘린더 값**: 메인 창 전체에 준다. 달력, 일정 칸, 사이드바가 들어가고, 크게 크기에서 오른쪽 열에 쌓이는 일정·D-Day·집중·스티키 미니 패널도 들어간다(같은 창 안이라 따로 줄 수 없다).
- **스티키 값(위젯 값)**: 떠 있는 스티키·D-Day·집중 창에 준다(개발자 결정 2026-11-10). 셋 다 바탕화면에 따로 떠 있는 작은 위젯이라 한 묶음으로 다룬다.
- 크게 크기에서는 D-Day·집중·스티키가 메인 창 오른쪽 열의 미니 패널로 들어간다. 그때는 같은 창이라 캘린더 값을 따른다.
- 설정창, 미니앱 창, 메뉴·팝업은 지금처럼 투명도를 받지 않는다(코드에서 `setWindowOpacity(1.0)` 고정).

### 설정창

- 화면 표시 패널의 '전체 투명도' 행을 **'투명도'** 행으로 바꾼다. 행 높이 36px은 그대로다(800×560 무스크롤 유지).
- 한 줄에 `캘린더 [슬라이더] 80%`, `스티키 [슬라이더] 100%`를 나란히 둔다.
  - 이 행만 라벨 폭을 116px → 52px로 줄인다. 컨트롤은 오른쪽 정렬이라 다른 행과 열이 어긋나지 않는다.
  - 시안 치수: 라벨 글자 12px, 슬라이더 56px, 값 칸 34px, 두 묶음 사이 10px. 패널 안쪽 폭(약 343px)에 맞춘 값이다.
- 슬라이더는 지금처럼 움직이는 즉시 저장·적용한다.
- '스티키' 글자에는 툴팁 "스티키·D-Day·집중 위젯"을 둔다. 슬라이더 하나가 세 위젯을 함께 바꾼다는 것을 알리기 위해서다. 글자는 '스티키'로 둔다(B안 폭에 맞고, 사용자 의견의 표현이다).

### 숫자 더블클릭 입력(사용자 요청 2026-11-10)

슬라이더가 짧아 한 칸씩 맞추기 어려운 것을 보완한다.

- 값(`80%`)을 두 번 누르면 그 자리가 숫자 입력칸(숫자만, 3자리까지, 뒤에 `%` 고정)으로 바뀌고 글자가 모두 선택된다. 키보드는 값에 포커스를 두고 Enter 또는 F2.
- **확정**: Enter 또는 포커스 이동. 30 미만은 30, 100 초과는 100으로 맞춘다. 비었거나 숫자가 아니면 이전 값을 유지한다.
- **취소**: Esc를 누르면 입력 전 값으로 돌아간다.
- 확정 값은 슬라이더 위치·저장·적용에 똑같이 반영된다.
- 값에는 툴팁 "두 번 눌러 직접 입력"을 둔다. 마우스 커서는 글자 입력 모양이다.

## 데이터(지켜야 할 것)

- **기존 키 유지**: `app_opacity`는 이름·의미를 바꾸지 않고 **캘린더 값**으로 계속 쓴다. 지우거나 옮기지 않는다.
- **새 키 하나 추가**(예: `widget_opacity`, `"30"`~`"100"`). 스티키·D-Day·집중을 함께 다루므로 이름에 '스티키'를 넣지 않는다. 마이그레이션에 넣지 않는다.
  - 키가 없으면 `app_opacity` 값을 따른다(fallback). 그래서 업데이트 직후 화면은 바뀌지 않는다.
  - 위젯 키가 없는 상태에서 캘린더 슬라이더를 처음 움직이면, 그 직전에 위젯 키를 현재 값으로 먼저 저장한다. 위젯이 덩달아 바뀌지 않게 하기 위해서다.
- **Export/Import**: `app_opacity`가 Export에 들어가므로 새 키도 같이 넣는다(`EXPORT_EXCLUDED_SETTINGS`에 넣지 않는다). 새 키가 없는 이전 Export 파일을 가져오면 fallback이 적용된다.
- **구버전 EXE**: 새 키를 모르므로 무시하고 `app_opacity` 하나로 모두 그린다. 데이터는 바뀌지 않는다.
- DB 스키마 버전·Export 형식 버전·salt·암호문·다른 설정 키는 바꾸지 않는다.

## 구현 방향(참고, 구현 때 확인)

- `ui_main.py`
  - `_apply_app_opacity()`를 캘린더 값(메인 창, 크게의 미니 패널 포함)과 위젯 값(`_sticky_windows`·`_dday_windows`·`_focus_windows`)으로 나눈다.
  - `_register_floating_widget()`는 세 위젯 모두 위젯 값으로 새 창을 연다.
  - 가져오기·초기화 뒤 다시 적용하는 경로(`_apply_app_opacity()` 호출 지점)도 두 값을 모두 다시 읽는다.
- `ui_settings.py`
  - '전체 투명도' 행(`opacity_slider`·`opacity_value_label`)을 두 묶음으로 바꾼다.
  - 값 라벨은 더블클릭에 입력칸(`LineEdit`+숫자 검증)으로 바뀌는 작은 위젯으로 만든다.
  - 콜백은 `on_opacity_changed` 하나를 유지하되, 어느 쪽이 바뀌었는지 넘기거나 둘 다 다시 적용한다.
- **슬라이더 폭**: Fluent `Slider`의 손잡이 크기 때문에 56px 트랙이면 실제 이동 거리가 짧다. 실측해서 너무 짧으면 라벨 글자를 줄이거나 값 칸을 좁힌다.
- **설정창 높이**: 행 높이를 바꾸지 않아도 설정창 최소 크기를 실측한다(행 추가 회귀 사례가 있다).
