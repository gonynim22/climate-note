# 일정 시각·알림·반복·기간 (v4.1) 설계

작성일: 2026-10-16 / 상태: 사용자 검토 대기
시안: `output/design/schedule-features-20261015/index.html` (확정 시안, 1차 시안의 정할 것 세 가지는 추천안으로 확정)

## 1. 목표와 범위

- **목표**: 일정에 ① 시작 시각, ② 여러 날 기간, ③ 반복, ④ 알림을 더한다. 지금 화면을 해치지 않고, 기존 사용자의 데이터는 업데이트 EXE를 처음 실행할 때 한 값도 바뀌거나 사라지지 않는다.
- **버전**: 표시 `v4.1`, EXE `기후노트_v4.1.exe`, Windows `4.1.0.0`, DB 스키마 v18, Export 형식 v3.
- **사용자 확정 사항(2026-10-16)**: 세부 설정은 스마일 옆 시계 버튼, 기간은 중간·크게에서 이어진 막대, 알림은 앱 카드. 데이터는 절대 달라지면 안 된다.
- **범위 밖**: 끝나는 시각(시간 범위), 격주·n일 간격·요일 여러 개 반복, 공휴일 제외 반복, 반복 일정의 '이 날만 고치기', 날짜 옮기기(끌어다 놓기), Windows 알림 센터 연동, 알림 소리 설정, 설정 창 변경.

## 2. 근거로 확인한 현재 구조

- 일정 표는 `id, date, content(암호문), created_at, color` 다섯 열이다. 오래된 DB는 `color`가 `ALTER`로 뒤에 붙어 DDL 모양이 사용자마다 다르므로 **표를 다시 만들지 않고 열 추가만** 한다.
- 시작 순서는 `main._initialize_database`: 읽기 전용 건강 검사 → `backup_before_v35()` → `backup_before_migration()` → `migrate()` → `backup_database()` (`main.py:133-152`).
- `backup_before_migration()`은 `0 < version < CURRENT`이면 `backups/calendar_pre_v{CURRENT}_v{version}.db`를 검증 스냅샷으로 만들고, 실패하면 예외로 마이그레이션을 막는다 (`database.py:2208-2248`). 회전 삭제 대상(`calendar_auto_*.cnbak`)이 아니다.
- 건강 검사는 `0 < version <= CURRENT`만 통과시킨다 (`database.py:233`). 따라서 **v4.0a EXE는 v18 DB를 보면 읽기 전용 검사에서 멈추고 아무것도 쓰지 않는다**.
- Import는 `format_version > EXPORT_FORMAT_VERSION`을 거절한다 (`database.py:1513-1521`). 반면 v2 파일의 모르는 키는 조용히 무시한다. 그래서 새 정보는 v2에 끼워 넣지 않고 v3로 분리한다.
- 암호화 키 마이그레이션은 `UPDATE ... SET content`만 하므로 새 열과 무관하다 (`database.py:416-544`).
- 화면은 `_refresh_calendar()`가 칸 위젯을 매번 새로 만들고 (`ui_main.py:2350-2426`), 일정 변경 뒤에는 `_refresh_cell_for_date()`로 한 칸만 갱신한다 (`ui_main.py:2585-2611`). 반복·기간은 여러 칸에 걸치므로 월 전체 갱신이 필요하다.
- 기존 '전체 날짜' 함수(`get_all_schedule_date_colors/counts`, `get_schedules_for_month`)는 시험 27곳이 원본 행 의미로 고정하고 있다.
- **스파이크(버린 코드)**: `BEGIN IMMEDIATE` 안에서 열 6개 `ALTER`와 `PRAGMA user_version = 18`을 묶었다. 중간 예외 시 열 0개·v17로 완전히 되돌아갔고, 성공 시 기존 행 값은 그대로이며 새 열은 기본값만 들어갔다 (Python 3.13 sqlite3, SQLite 3.49.1).

## 3. 데이터 계약

### 3.1 스키마 v18 (일정 표에 열 추가만)

| 열 | 정의 | 뜻 | 기존 행 값 |
|---|---|---|---|
| `start_time` | `TEXT NOT NULL DEFAULT ''` | `HH:MM`(24시간) 또는 `''`=하루 종일 | `''` |
| `end_date` | `TEXT NOT NULL DEFAULT ''` | 기간 끝 `YYYY-MM-DD`(> `date`, 최대 365일 뒤) 또는 `''`=하루 | `''` |
| `repeat_rule` | `TEXT NOT NULL DEFAULT ''` | `''`·`daily`·`weekdays`·`weekly`·`monthly`·`yearly` | `''` |
| `repeat_until` | `TEXT NOT NULL DEFAULT ''` | 반복 끝(포함) `YYYY-MM-DD`(≥ `date`) 또는 `''`=계속 | `''` |
| `repeat_skip` | `TEXT NOT NULL DEFAULT ''` | '이 날만 삭제'한 날짜들, 오름차순·중복 없음·쉼표 구분 | `''` |
| `alarm_before` | `INTEGER` (NULL 허용) | 알림 기준 시각보다 몇 분 앞인지. NULL=알림 없음 | NULL |

- `date`는 지금처럼 일정의 시작 날짜(반복의 기준 날짜)다. `content`·`color`·`id`·`created_at`의 뜻과 값은 그대로다.
- **불변식**: 반복(`repeat_rule ≠ ''`)이면 `end_date = ''`다(반복은 하루짜리만). `repeat_until`·`repeat_skip`은 반복일 때만 값이 있다. `repeat_skip`은 500개 이하이고 각 날짜는 `date` 이상이다. `alarm_before`는 시각이 있으면 `{0, 10, 30, 60, 1440}`, 하루 종일이면 `{0, 1440}` 중 하나다.
- 새 열은 날짜·색처럼 **평문**이다. 본문(`content`) 암호화와 키 유도·salt는 바꾸지 않는다. 시각·반복은 이미 평문인 날짜와 같은 수준의 메타데이터다.

### 3.2 마이그레이션 v17 → v18

```python
SCHEDULE_V18_COLUMNS = (  # 이름 → 상수 SQL (f-string 없이 고정 문자열)
    ("start_time",   "ALTER TABLE schedules ADD COLUMN start_time TEXT NOT NULL DEFAULT ''"),
    ("end_date",     "ALTER TABLE schedules ADD COLUMN end_date TEXT NOT NULL DEFAULT ''"),
    ("repeat_rule",  "ALTER TABLE schedules ADD COLUMN repeat_rule TEXT NOT NULL DEFAULT ''"),
    ("repeat_until", "ALTER TABLE schedules ADD COLUMN repeat_until TEXT NOT NULL DEFAULT ''"),
    ("repeat_skip",  "ALTER TABLE schedules ADD COLUMN repeat_skip TEXT NOT NULL DEFAULT ''"),
    ("alarm_before", "ALTER TABLE schedules ADD COLUMN alarm_before INTEGER"),
)
```

- `migrate()`의 마지막에 `if version == 17:` 블록을 둔다. 앞 단계의 열린 트랜잭션이 있으면 먼저 `commit()`하고, `BEGIN IMMEDIATE` → `PRAGMA table_info(schedules)`로 없는 열만 추가 → `PRAGMA user_version = 18` → `COMMIT`. 예외면 `ROLLBACK` 후 다시 올린다.
- **멱등**: 열이 이미 있으면 건너뛴다. v18 열이 있는데 `user_version`이 17인 DB(외부 도구로 버전만 내린 경우 등)도 오류 없이 v18이 된다.
- 새 설치·초기화(v0 경로)도 같은 블록을 거쳐 같은 스키마가 된다. v0의 `CREATE TABLE`은 고치지 않는다.
- `CURRENT_SCHEMA_VERSION = 18`. 기존 사용자는 시작 시 `backups/calendar_pre_v18_v17.db` 검증 스냅샷이 먼저 만들어지고, 이것이 실패하면 마이그레이션 없이 시작을 멈춘다(기존 계약).
- 마이그레이션은 기존 행의 값을 읽거나 쓰지 않는다. 날짜·암호문·ID·`sqlite_sequence`·다른 표·salt는 바이트 단위로 같다.

### 3.3 건강 검사와 구버전

- `inspect_startup_data_health()`
  - `version > CURRENT_SCHEMA_VERSION`이면 새 코드 `schema_newer`를 반환한다.
  - `version <= 0`이면 지금처럼 `schema_invalid`다.
  - `version >= 18`인데 일정 표에 v18 열 6개 중 하나라도 없으면 `schema_invalid`다.
  - 그 밖의 검사(무결성·암호문 전수 복호화·salt)는 그대로다.
- `main._data_health_error_message("schema_newer")`: "더 새 버전의 기후노트에서 쓰던 데이터입니다. 최신 버전으로 실행해 주세요." + 기존의 "데이터와 기존 백업은 변경하지 않았습니다…" 문구. 앞으로 v4.1 사용자가 v4.2 이후 데이터를 만나는 경우에 대비한다.
- **v4.0a 이하 EXE로 되돌리면**: 시작 전 검사가 `schema_invalid`로 멈추고 데이터·백업은 바뀌지 않는다(실제 v4.0a EXE로 확인). 이때 v4.0a는 '데이터 보호를 위해 실행을 중단했습니다 — 기존 데이터베이스의 구조 또는 무결성을 확인하지 못했습니다. 데이터와 기존 백업은 변경하지 않았습니다…' 창과 [데이터 폴더 열기][종료]를 띄운다. 손상처럼 읽히고 '새 버전으로 실행하라'는 말이 없지만 이미 배포된 문구라 바꿀 수 없다. 그래서
  - v4.1은 예전 형식 DB를 올린 실행에서 한 번 업데이트 안내창을 띄운다(§4.11).
  - README_detail·배포 안내에 이 창의 문구를 그대로 싣고 '데이터 손상이 아니라 새 버전 형식이라서 뜨는 창이며 v4.1을 실행하면 된다'고 적는다.
  - Windows 자동 실행 경로는 v4.1이 켜질 때 v4.1로 바뀌고, v4.0a는 시작 단계에서 막혀 경로를 되돌리지 못한다. 그래서 부팅 때 구버전이 뜨는 일은 없고, 옛 EXE·바로가기를 직접 눌렀을 때만 이 창이 뜬다.
- 꼭 되돌려야 하면 `calendar_pre_v18_v17.db`를 쓰되 업데이트 이후 입력분은 빠진다. 앱을 완전히 종료하고 데이터 폴더를 보관한 뒤 `calendar.db`·`calendar.db-wal`·`calendar.db-shm`을 지우고 스냅샷을 `calendar.db`로 복사한다(WAL을 남기면 옛 DB가 손상될 수 있다). 이 절차를 README_detail에 적고 릴리스 리허설에서 실제 EXE로 따라 해 본다.

### 3.4 규칙의 뜻 (`schedule_rules.py`, Qt·DB 없는 순수 모듈)

- **시각 입력**: `9`→`09:00`, `14`→`14:00`, `930`→`09:30`, `1430`→`14:30`, `9:5`·`24:00`·`1260`은 거절. 저장은 항상 `HH:MM`.
- **기간**: `date`부터 `end_date`까지(양 끝 포함) 매일 나타난다. 시각이 있으면 첫날에만 시각으로 보이고, 나머지 날은 하루 종일로 보인다.
- **반복**: 기준은 `date`이고 `date` 이전에는 없다. `repeat_until`(포함)까지, `repeat_skip`의 날짜는 뺀다.
  - `daily`: 매일
  - `weekdays`: 월~금. 기준 날짜가 주말이면 그 날은 제외된다.
  - `weekly`: `date`와 같은 요일
  - `monthly`: `date`의 일. 그 날짜가 없는 달은 그 달의 마지막 날이다(앱의 날짜·시간 계산기와 같은 월말 보정).
  - `yearly`: 같은 월·일. 2월 29일은 평년에 2월 28일이다.
  - 공휴일에도 나타난다(공휴일 제외는 범위 밖).
- **알림 시각**: 기준 = 그 날짜의 `start_time`(하루 종일이면 09:00), 알림 = 기준 − `alarm_before`분. 기간 일정은 첫날만, 반복 일정은 나타나는 날마다 알린다. `repeat_skip`·삭제된 날은 알리지 않는다.
- **차선 배정**(막대용): 한 주 안의 기간 조각을 시작 열 오름차순, 같은 시작이면 긴 것 먼저, 그다음 일정 ID 순으로 놓는다. 겹치지 않는 가장 위 차선을 준다.
- **검증 함수 하나**(`validate_options(date, options)`)를 DB 쓰기·Import·UI 저장이 모두 쓴다. 실패는 `ValueError`이고 쓰기를 시작하지 않는다.
- **규칙을 바꾸거나 끌 때**: 반복을 끄면 끝 날짜·건너뛴 날도 함께 지운다. 반복 종류를 바꾸면 건너뛴 날만 비운다(옛 규칙의 날짜가 남지 않게). 끝 날짜는 유지하되 새 기준보다 앞서면 지운다.

### 3.5 저장 API (`database.py`)

- 기존 함수의 의미는 유지한다.
  - `get_schedules(date)`는 그 날 **나타나는** 일정(원본 하루 일정 + 기간 + 반복)을 돌려준다.
  - 기존 키 `id, date(원본 시작일), content, created_at, color, _decryption_failed`는 그대로 두고 아래 키를 더한다.
    - `options`(`ScheduleOptions`), `occurrence_date`(그 날), `span_start`·`span_end`(기간이면 처음·끝, 하루·반복이면 둘 다 그 날), `start_time`, `shows_time`(그 날 시각을 보이는지: 기간은 첫날만, 반복은 나타나는 날마다)
  - 정렬: 시각 없이 보이는 것(하루 종일·기간의 둘째 날 이후) 먼저 ID 순, 그다음 시각 있는 것을 시각·ID 순. 기존 행만 있으면 지금과 같은 ID 순이다.
- 새 함수
  - `get_occurrences(start, end) -> dict[str, list[dict]]`: 달력 한 화면용(본문 복호화 포함). 후보는 `date <= end AND (date >= start OR end_date >= start OR repeat_rule != '')`로 고르고, 펼치기는 `schedule_rules`가 한다.
  - `skip_schedule_occurrence(schedule_id, date)`: 반복 일정이고 그 날 실제로 나타날 때만 `repeat_skip`에 더한다(최대 500개).
  - `get_alarm_occurrences(after, until)`: `after < 알림 ≤ until`인 알림 목록. 본문 복호화 실패한 행은 내용 없이 '내용을 읽을 수 없는 일정'으로 둔다.
- 확장(키워드 전용, 기본값은 지금과 같은 동작)
  - `add_schedule(date, content, color=DEFAULT, *, options=None)`
  - `update_schedule(schedule_id, content=None, color=None, *, options=None)`: `options`를 주면 여섯 열을 한 번에 바꾼다.
- 원본 행 함수 `get_all_schedule_dates/colors/counts`·`get_schedules_for_month`는 지우지 않는다. 문서 문자열에 "원본 시작일 기준(반복·기간 미전개), 화면은 `get_occurrences`"를 적고, 화면은 더 이상 쓰지 않는다.
- `search_all`의 일정 결과에 `end_date`·`repeat_rule`을 더한다(표시용).
- **읽기는 관대하게, 쓰기는 엄격하게**: 저장된 값이 규칙에 어긋나면(알 수 없는 반복·정수가 아닌 알림 등) 읽을 때 기본값처럼 다뤄 화면이 멈추지 않게 한다. 쓰기(추가·수정·Import)는 `validate_options`를 통과해야 한다. 세부 설정이 기본값인 일정(기존 일정 전부)은 날짜 문자열을 지금처럼 그대로 비교하므로, 형식이 조금 다른 옛 날짜도 지금과 똑같이 보이고 내보내기·가져오기된다.

### 3.6 Export v3 / Import v1~v3

- `EXPORT_FORMAT_VERSION = 3`. 일정 항목에 `start_time`(문자열), `end_date`(문자열), `repeat_rule`(문자열), `repeat_until`(문자열), `repeat_skip`(날짜 문자열 목록), `alarm_before`(정수 또는 null)를 **항상** 쓴다.
- Import
  - v1·v2 파일은 지금과 똑같이 받고 새 열은 기본값이다.
  - v3 파일은 각 일정에 대해 형식 검사 후 `validate_options`를 통과해야 한다. 하나라도 틀리면 지금처럼 **아무것도 쓰지 않고** 거절한다.
  - 모르는 키는 지금처럼 무시한다.
- 설정 섹션: `privacy_pin`처럼 새 키 `schedule_alarm_seen_at`도 Export에서 빼고, Import에서 받아도 쓰지 않는다(다른 PC의 시계를 옮기지 않는다).
- v4.0a 이하는 v3 파일을 '지원하지 않는 format_version'으로 거절한다(일부만 들어가는 일 없음).

### 3.7 설정 키

- 새 키 `schedule_alarm_seen_at`(`YYYY-MM-DDTHH:MM:SS`): 여기까지의 알림은 처리했다는 표시다. 없으면 '지금'으로 본다.
- **쓰는 때**: 알림 카드를 띄울 때와, 알림이 켜진 일정이 하나라도 있을 때의 정상 종료(`prepare_for_quit`) 때뿐이다. 종료 때는 '지금'이 아니라 마지막으로 확인한 시각을 남긴다(그 뒤 종료까지의 알림은 다음 실행에서 놓친 알림으로 보인다). 앱을 켤 때나 초기화 직후에 키가 없다고 바로 쓰지는 않는다. 그래서 알림이 없는 기존 사용자 DB는 시작·종료만으로 한 바이트도 바뀌지 않는다(릴리스 'existing' 시나리오의 설정 표 해시 비교와 기존 시험 `test_calendar_display_roundtrip_preserves_existing_rows_and_salt`를 그대로 통과).
- 기존 키는 지우거나 바꾸지 않는다.

## 4. 화면 설계

### 4.1 입력줄의 시계 버튼

- 입력줄 순서: `[색 원 → 스마일 → 시계 → 본문 → 추가]`.
- `ScheduleOptionsButton`은 스마일처럼 26×26 클릭 영역에 22px 원을 `QPainter`로 그린다. 선 1.0px, 바늘 1.4px, `#475569`. 값이 하나라도 있으면 `#2563EB`와 오른쪽 위 6px 점을 그린다.
- 마우스 클릭과 Enter·↓ 키로 연다. 잠금·트레이 숨김 중에는 열지 않는다(스마일과 같은 `_schedule_emoji_allowed` 조건).

### 4.2 세부 카드 `ScheduleOptionsPopup`

- **창**: 미니앱 주머니와 같은 `Qt.Popup | FramelessWindowHint | NoDropShadowWindowHint`, 반투명 배경, `WA_NoMouseReplay`, 그림자 여백 16px.
  - 카드는 흰 바탕·`#D9E1EC` 1px·모서리 12px, 그림자 blur 20·아래 4·`rgba(24,46,76,80)`. 폭은 330px.
  - 표시 때 `popup_border_fix.remove_dwm_border(self)`로 Win11 DWM 테두리를 지운다.
- **팝업 안에 팝업을 만들지 않는다**: 드롭다운·`QCalendarWidget`·`RoundMenu`를 쓰지 않는다. 모든 선택은 같은 카드 안의 칩·입력칸·작은 달력이다.
- **구성**(왼쪽 30px 이름표 + 오른쪽 내용)
  - 머리: '세부 설정'(13px 굵게 `#172B4D`), 오른쪽 '모두 지우기' 글자 버튼(데이터 초기화와 헷갈리지 않게).
  - 시각: `[하루 종일][시각]` + '시각'일 때 62px 입력칸. 새로 켜면 기본 `09:00`이고 입력칸에 포커스가 간다. 입력 중에는 검사만 하고(틀리면 빨간 테두리) Enter·다른 곳 누르기·카드 닫기 때 반영한다. 틀린 채로 끝나면 마지막 올바른 값으로 되돌린다(입력 중간값 `246`→`02:46`이 저장되지 않게).
  - 알림
    - 시각이 있으면 3칸 격자 `[없음][정시][10분 전] / [30분 전][1시간 전][하루 전]`.
    - 하루 종일이면 `[없음][당일 오전 9시][하루 전 오전 9시]`.
    - 시각 모드를 바꾸면 `0`·`1440`만 유지하고 나머지는 '없음'이 된다.
  - 기간: `[하루][여러 날]`. '여러 날'이면 '10월 21일(수) ~ 23일(금) · 3일' 문구와 작은 달력이 카드 안에 펼쳐진다.
    - 시작은 고른 날로 고정이고, 그 앞날과 365일 뒤 이후는 흐리게 막는다.
    - 기본 끝은 다음 날이다.
  - 반복: 3칸 격자 `[안 함][매일][평일] / [매주][매월][매년]`. 아래에 '매주 목요일'·'매월 31일 (없는 달은 마지막 날)' 같은 설명 한 줄.
    - '안 함'이 아니면 '끝' 줄 `[계속][날짜까지]`가 생기고, '날짜까지'면 같은 작은 달력이 펼쳐진다(기본 한 달 뒤).
  - 배타 규칙
    - '여러 날'이면 반복 칩 중 '안 함'만 고를 수 있고 '여러 날 일정은 반복할 수 없습니다'를 보인다.
    - 반복이면 '여러 날'을 막고 '반복 일정은 하루만 고를 수 있습니다'를 보인다.
  - 작은 달력은 한 번에 하나만 펼친다.
  - 바닥: 'Esc · 바깥을 누르면 닫힘' + 파란 `[완료]`.
- **칩 모양**: 높이 26px·모서리 13px·12px 글자.
  - 평소: `#CBD5E1` 테두리, `#334155` 글자.
  - 고름: `#EFF6FF` 바탕, `#2563EB` 테두리, `#1D4ED8` 굵게.
  - 막힘: `#F8FAFC` 바탕, `#E2E8F0` 테두리, `#A3ACB9` 글자.
  - 포커스: 2px `#2563EB`.
  - QSS는 `#scheduleOptionsCard QPushButton[segment="true"]`처럼 객체 이름으로 범위를 좁힌다(메뉴로 번지지 않게).
- **작은 달력 `MiniMonthPicker`**: 일요일 시작, 요일 머리 11px. 날짜 버튼은 30×24이고 공휴일·일요일 빨강, 토요일 파랑이며, 공휴일은 `holidays.is_holiday`의 실제 자료만 쓴다. 범위는 연한 파랑, 끝은 진한 파랑. 앞뒤 달 버튼이 있다.
- **반영**: 칩을 누르는 즉시 값이 바뀌고(`options_changed` 신호) 알약이 따라 바뀐다. Esc·바깥·완료는 닫기만 한다. '모두 지우기'는 모두 기본값.
- **수명**
  - 이모지 팝업 규칙을 그대로 따른다: 한 번에 하나만 열리고, 닫히면 `deleteLater`로 정리하며, 늦게 도착한 선택은 무효화하고, 포커스 복원은 버튼 소유 타이머로 한다.
  - 높이가 바뀌면(달력 펼침) 화면 작업 영역 안으로 위치를 다시 맞춘다.
  - 잠금·트레이 숨김·초기화 직전 폐기·크기 전환·미니앱 열기·종료 때 닫는다(이모지 팝업을 닫는 모든 곳, §4.10).

### 4.3 알약 줄 `ScheduleOptionsPills`

- 입력칸 왼쪽 끝에 맞춘 한 줄이고, 값이 있을 때만 보인다(없으면 숨김이라 지금 배치와 같다).
- 알약은 높이 22px·모서리 11px·`#F1F5F9` 바탕·`#E2E8F0` 테두리·11px `#334155`이고, 최대 150px에서 말줄임한다.
  - 시각: 시계 아이콘 + `15:00` 또는 `15:00 · 10분 전`.
  - 하루 종일 알림: 종 아이콘 + `당일 9시` 또는 `하루 전 9시`.
  - 기간: 달력 아이콘 + `~10.23 · 3일`.
  - 반복: 반복 아이콘 + `매주 목` / `매일` / `평일` / `매월 15일` / `매년 10.15`, 끝 날짜가 있으면 `· ~12.31`.
- 알약을 누르면 카드가 열리고, ×는 그 항목만 지운다(시각 ×는 알림도 지운다).
- **보류 중 값**: 기간은 끝 날짜가 아니라 '며칠짜리'로 기억한다. 그래서 날짜를 바꿔도 같은 길이로 따라간다. 반복 끝 날짜가 새 날짜보다 앞서면 '계속'으로 돌린다.
- 추가에 성공하면 비우고, 실패하면 남긴다.

### 4.4 목록 줄

- 행 구성: `[색 점][시각 열][본문 묶음(본문 + 반복·종 아이콘, 늘어나는 칸)][기간 글자][휴지통]`. 아이콘은 본문 바로 뒤에 붙는다. 편집할 때는 본문 묶음과 기간 글자를 숨기고 그 자리에 편집기를 넣는다.
- **시각 열**: 그날 시각이 보이는 일정이 하나라도 있을 때만 생긴다(40px 고정, 13px `#475569`). 시각 없는 줄은 11px `#94A3B8` '종일'이다. 시각 있는 일정이 없는 날은 지금과 픽셀 단위로 같은 배치다.
- 아이콘은 12px `#94A3B8`, `QPainter`로 그린다(새 그림 파일 없음).
- 기간 글자는 11px `#94A3B8` `10.21~10.23`이고, 해가 다르면 `26.12.30~27.01.02`.
- 툴팁: 본문 전체 + '매주 목요일 반복 · 끝: 계속' + '알림: 10분 전' 줄.
- 본문 라벨은 `Qt.PlainText`로 고정한다(본문의 `<…>`가 서식으로 해석되지 않게).
- 정렬은 §3.5. 날짜 머리의 '총 N개'는 나타나는 일정 수다.
- 추가 직후 새 줄은 1.2초 동안 `#EFF6FF` 바탕을 보인다.

### 4.5 더블클릭 편집

- `ScheduleInlineEditor`는 `[스마일][시계][본문]` 한 줄 + 아래 요약 한 줄(11px `#5B6577`, 넘치면 말줄임)이다.
  - 요약 예: `10:00 · 10분 전 · 매주 월요일 · 모든 날에 적용`.
  - 값이 없으면 요약 줄은 숨긴다.
- 편집기·스마일·시계·두 팝업을 하나의 편집 영역으로 본다. 팝업이 열려 있는 동안은 포커스가 나가도 저장·종료하지 않는다(기존 규칙 확장).
- **저장 조건**: 본문 또는 세부 설정이 바뀌면 `update_schedule(..., options=...)`. 저장 실패 시 편집기를 유지하고 날짜·월·검색 이동·목록 재구성·데이터 작업·종료를 보류한다(기존 계약 그대로).
- 반복 일정을 고치면 시리즈 전체가 바뀐다. 기준 날짜는 시리즈의 `date`다.
  - 다른 날에서 반복을 끄면 카드에 '반복을 끄면 첫 날짜(10월 5일) 하루만 남습니다'를 보인다.
- 저장 뒤에는 월 전체 칸과 목록을 다시 읽는다(순서·표시가 바뀔 수 있어서). 목록 재구성은 편집 종료 콜백이 끝난 다음 이벤트 루프로 미루고, 그사이 다른 줄 편집이 시작됐으면 그 편집이 끝날 때까지 미룬다(새 편집기가 바로 닫히지 않게).
- 형식이 다른 옛 날짜(예: `2026-7-1`)의 일정은 세부 설정을 둘 수 없으므로 시계 버튼을 끄고 본문만 고친다. 그 날짜를 고른 입력줄의 시계 버튼도 꺼진다.

### 4.6 반복 일정 지우기

- 반복이 아닌 일정은 휴지통이 지금처럼 바로 지운다.
- 반복 일정의 휴지통은 그 버튼 옆에 `RoundMenu`를 연다: `이 날만 삭제`(달력 아이콘) / `반복 전체 삭제`(빨간 반복 아이콘, RoundMenu는 항목별 글자색을 바꾸지 않는다).
- 우클릭 메뉴
  - 반복 일정: `편집 / ─ / 이 날만 삭제 / 반복 전체 삭제`
  - 반복이 아닌 일정: 지금처럼 `편집 / 삭제`(기존 시험 고정)
- 메뉴는 기존처럼 `closedSignal` 뒤 `deleteLater`로 정리하고, 잠금 중에는 열지 않는다.

### 4.7 달력

- **기본 크기**: 칸의 `[숫자 / 색 네모 / +N]` 구조와 규칙을 그대로 둔다. 다만 개수와 색은 '나타나는 일정'으로 센다(기간·반복이 그날 칸에 반영된다).
- **중간·크게 하루 칩**
  - 칩 크기(10/16/2, 13/22/3px)와 말줄임은 그대로다.
  - 시각이 보이는 일정은 `"14:00 " + 본문`이고, 굵게 쓰지 않는다(기존 `elidedText` 그대로).
  - 칩 라벨도 `Qt.PlainText`로 고정한다.
- **기간 막대**: 새 `CalendarSpanOverlay`(`ui_calendar_spans.py`)를 쓴다.
  - 생성: `calendarSection`의 자식이고(메인 창이 `self._calendar_section`으로 참조를 보관) 마우스 이벤트를 통과시키며, 칸 위에 올린다. 영역은 `calendar_grid` 영역이다.
  - 그리기: `paintEvent`가 그때의 칸 위치(`_chips_container`의 위치를 오버레이 좌표로 변환)를 읽어 그린다.
    - 칸 안쪽 여백은 시작 6px·끝 4px(칩과 같은 선)이다.
    - 주가 이어지는 쪽은 칸 끝까지 각지게 그려 2px 칸 사이를 덮는다.
    - 모서리 4px, 글자는 칩과 같은 크기(중간 10px·크게 13px), 왼쪽 여백 4px, `#1a1a1a`, 말줄임. 줄의 첫 조각마다 이름을 쓰고, 시각이 있으면 첫날 조각에 `09:00 출장`.
  - 칸 쪽 처리: `CalendarDayButton.set_events(events, span_lanes=…)`.
    - 그 날을 덮는 막대의 차선 목록을 받아, 보이는 차선만큼 칩 자리를 비우는 고정 높이 빈칸을 넣는다.
    - 칸에 들어갈 칩 수(`fit`)에서 1을 뺀 수까지만 막대 차선을 보이고, 나머지 막대는 그날 `+N 더`에 더한다.
    - 오버레이는 칸이 알려 주는 '보이는 차선 수'만 그린다(같은 주의 칸은 높이가 같다).
  - 다시 그리는 때: `_refresh_calendar`, 월 데이터 갱신, `calendarSection` 크기 변경(이벤트 필터).
  - 기본 크기에서는 숨긴다.
  - 칸 열 너비 계약(7열 같은 stretch, 칩 가로 Ignored)에 오버레이는 영향이 없다(레이아웃 밖).
- **갱신**
  - 새 `_refresh_month_data()`는 보이는 달의 `get_occurrences`를 한 번 읽어 **기존 칸 위젯을 다시 만들지 않고** 개수·색·칩·막대만 바꾼다.
  - 일정 추가·편집·삭제·이 날만 삭제 뒤에 부른다.
  - `_refresh_cell_for_date(date)`는 남겨 두고(시험 사용) 이 함수를 부른다.

### 4.8 검색

- 일정은 지금처럼 원본 한 줄(시작 날짜)로 보이고, 누르면 그 날짜로 간다.
- 본문 칸 끝에 표시용 꼬리를 붙인다: 반복이면 ` (매주 목요일 반복)`, 기간이면 ` (~10.23)`. 저장값은 바꾸지 않는다.

### 4.9 알림

- **엔진 `ScheduleAlarmScheduler`**(`ui_schedule_alarm.py`, `QObject`, 메인 창 소유)
  - 단발 `QTimer`를 '다음 알림까지'와 60초 중 짧은 쪽으로 맞춘다. 2일 안에 알림이 없으면 60초마다 다시 본다(시계 변경 대비).
  - 확인할 때마다 `get_alarm_occurrences(기준, 지금)`을 읽는다. 기준은 메모리에 둔 '마지막 확인 시각'이다. 시작할 때만 저장된 `seen_at`에서 출발하고(`max(seen_at, 지금 − 12시간)`, 키가 없으면 '지금'), 확인할 때마다 '지금'으로 옮긴다. 그래서 가져오기로 들어온 과거 알림은 다시 울리지 않는다.
    - 확인 창은 항상 최대 12시간이다(`max(기준, 지금 − 12시간)`).
    - v4.5 후속(2026-10-25 사용자 결정): 저장/메모리의 마지막 확인 시각이 미래이면 차이 크기와 무관하게 현재부터 다시 센다. 같은 실행의 (일정 ID, 날짜, 알림 시각) 표시 키는 유지한다. 재시작을 사이에 둔 중복 가능성은 남는다. 보정만으로 DB에 쓰지 않으며 알림 표시·알림 있는 정상 종료 때 보정한 마지막 확인 시각을 저장한다.
    - 이번 실행에서 이미 띄운 (일정 ID, 날짜, 알림 시각)은 빼고 남은 것을 카드에 더한다.
    - 그다음 `seen_at = 지금`을 저장한다(알림이 있을 때만).
  - 시작·절전 복귀(`nativeEvent`의 `PBT_APMRESUMESUSPEND`)에서는 2분보다 오래된 것을 '놓친 알림'으로 보인다.
  - '5분 뒤 다시'는 메모리에만 두며 종료하면 사라진다. 다시 알릴 때 그 일정·날짜·알림 시각이 아직 그대로인지 확인하고, 지워졌거나 바뀌었으면 알리지 않는다.
  - 일정 추가·편집·삭제·가져오기·초기화 뒤 다시 계산한다.
  - 시계를 흉내 낼 수 있게 `now=` 함수를 받는다(시험용).
- **카드 `ScheduleAlarmCard`**
  - 창: 부모 없는 `Qt.Tool | FramelessWindowHint | WindowStaysOnTopHint | NoDropShadowWindowHint`, 반투명, `WA_ShowWithoutActivating`, `WA_DeleteOnClose`. 포커스를 빼앗지 않고 작업 표시줄에 나타나지 않는다. 표시 때 DWM 테두리를 지운다.
  - 위치: 캘린더가 있는 화면(숨김이면 저장된 대상 화면)의 작업 영역 오른쪽 아래, 12px 안쪽.
  - 모양: 폭 320px, 흰 카드·`#D7DAE2` 1px·모서리 12px·그림자, 왼쪽 4px 띠는 첫 일정의 표시색.
    - 머리: 종 아이콘 `#2563EB` + '일정 알림' 또는 '일정 알림 N건', ×.
    - 한 건: 제목 15px 굵게(`15:00 부서 회의`, 하루 종일이면 본문만) + 설명 12px.

      - 하루 종일: '오늘 하루 종일' / '내일 하루 종일'
      - 끝에 ` · 10월 15일 (목)`을 붙인다.

  - 누르면: 카드 본문을 누르면 확인 처리하고, 잠금이 아니면 캘린더를 보이게 한 뒤 그 날짜로 이동한다.

## 8. 위험과 대응

- **업그레이드 중 전원 차단**: 스냅샷이 먼저 생기고, 열 추가는 한 트랜잭션이다. 다음 실행은 v17로 보고 다시 시도한다.
- **구버전으로 되돌린 사용자**: 시작이 막히지만 데이터는 그대로다. 안내 문구와 스냅샷 경로를 문서에 남긴다.
- **팝업 수명 회귀**(이모지·주머니에서 반복된 종류): 팝업 안 팝업을 없애고, 같은 소유·무효화 패턴과 시험을 쓴다.
- **칸 막대 위치 어긋남**: 칸 위치를 그릴 때마다 읽는다. 크기 변경·배율 시험과 합성 PNG를 남긴다.
- **알림 누락·중복**: `seen_at`은 띄울 때와 종료 때 저장한다. 강제 종료 뒤 재실행 때 이미 띄운 알림이 한 번 더 보일 수 있다(누락보다 중복을 택함). 이 점을 문서에 적는다.
- **반복 펼치기 성능**: 화면은 한 달(달력)·하루(목록)·최대 이틀+60초(알림) 범위만 펼친다. 시험에 매일 반복 1,000개의 한 달 펼치기 5초 상한을 둔다(본문 복호화는 행마다 한 번).
- **서버 보안 검사**: 새 SQL은 모두 상수 문자열과 `?` 바인딩만 쓴다. 외부 통신·새 의존성은 없다.
